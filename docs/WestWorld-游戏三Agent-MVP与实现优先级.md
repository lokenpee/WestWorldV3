## 1. 产品目标与分期方式

玩家从已有小说的第一章进入世界，以自由输入改变故事。导演理解玩家意图，决定当前发生什么；编剧维护未来发展；写手将当轮结果写成小说。玩家偏离原著后，故事仍能继续，既有事实、人物认知和行为后果保持连贯。

原著提供人物、地点、关系、事件及时间线等资产。世界书提取与整理已由用户初步构建，游戏侧先复用；资产是否足以还原第一章当时的状态，接入时仍需核对。后文的上游改进单独列出，避免把世界书提取重新安排成游戏 MVP。

本文的 P0／P1／P2／P3 表示**游戏实现优先级**。原项目中“P1 提取、P2 整理、P3 故事串联”表示**上游处理阶段**，本文统一称“资产提取阶段”“资产整理阶段”“原著串联阶段”。

| 游戏优先级 | 交付目标 | 排序理由 |
|---|---|---|
| P0：可连续游玩的 MVP | 第一章开局、三 Agent 协作、自由行动、一次申诉、存档恢复、最后一轮改写 | 先验证完整体验和事实一致性 |
| P1：长期剧情与运行质量 | 编剧持续维护计划、事件因果、人物认知、长期偏好，完善检索、上下文与异常处理 | 解决玩长之后容易失忆、重复、失真和变慢的问题 |
| P2：后台世界与复杂长期运行 | 后台事件、多线演化、大跨度时间、多分支，以及进一步的记忆和预算优化 | 建立在前台回合与长期计划稳定的基础上 |
| P3：叙事质量研究与可选实验 | 编剧前瞻推演、规划执行分离、重大结果独立复核、上下文自动选择 | 收益需要实验验证，不作为 MVP 前提 |

文内 G0、G1、G2、G3 是便于调整排期的局部条目编号，不是需求池编号。同一能力可以分期：例如 P0 具备可恢复的长期记忆，后续再优化记忆整合和检索效率，不能因优化后置而让 MVP 没有记忆。

### 1.1 始终成立的产品规则

- 玩家可以提出行动、一串行动或包含 NPC 反应的剧情设想；期望的结果不自动成为事实。
- 合理性审核通过表示可以尝试，实际结果可以成功、失败或部分成功。
- 已成立的世界事实优先于未来计划和文学表达。原著未来也不能覆盖本局已发生的变化。
- 导演决定当前场景，编剧调整未来，写手表达已确定的内容；程序校验、保存和恢复状态。
- 写手每轮执行；编剧在开局及重大剧情变化时执行。普通回合不强制调用编剧。
- 写手正文可以先显示，但本轮全部任务完成并保存前，下一轮输入保持锁定。
- MVP 只支持改写最后一条 AI 回复，并恢复到该轮玩家行动之前重新执行。
- 原著外的合理发展可以继续。成熟的新人物、新地点和多线生成能力后续完善，不能以此为由强迫玩家回原著。

## 2. P0 的三个 Agent 设计

### 2.1 导演：有长期记忆的现场主持者

**定位。** 导演像持续陪伴玩家的“系统”，能够理解“按上次那个办法”“去赴之前那个约”，结合本局经历、当前处境和人物动机安排本轮发展。持续性由会话、持久记录和工具共同实现，不要求把全部历史一直放在模型上下文里。

**每轮输入。**

| 输入 | 用途 |
|---|---|
| 当前玩家输入、适用的申诉或改写说明 | 理解行动对象、目的与期望，区别玩家行为和对 NPC 的设想 |
| 当前场景与必要世界状态 | 核对时间、地点、人物存亡与位置、物品、关系及已发生事件 |
| 本局有效交流、相关旧事与记忆 | 识别指代、承诺、目标及未完成事项，排除已作废回合 |
| 当前涉及的简短资产档案 | 读取人物性格、说话习惯、关系及环境 |
| 自动检索的候选目录 | 获得标题、摘要、关联理由与引用 ID，再自主选择详细资料 |
| 编剧当前有效计划 | 判断行动对后续剧情的影响，不能把计划当作事实 |

**本轮工作。**

1. 接收程序发现的候选资料，必要时读详情、原文或继续查询。
2. 判断玩家输入能否尝试；拒绝时给出依据并进入一次申诉流程。
3. 根据当前事实确定行动结果、NPC 反应和现场行动链。
4. 确定本轮关系、信息、位置、物品等变化，以及玩家下一次可介入的位置。
5. 比较实际结果与未来计划的关键前提，判断是否需要编剧重规划。
6. 将场景演出方案交给写手，将状态变更交给程序，必要时向编剧提供影响说明。

**场景演出方案。** 以下是交付内容的语义要求，正式字段与格式待评审。

| 内容 | 导演需要决定什么 |
|---|---|
| 场景目标 | 推进什么冲突，本轮写到哪里停下 |
| 人物意图 | 在场人物各自希望获得什么 |
| 关键事件 | 哪些行动与回应发生，必须保持怎样的因果顺序 |
| 关系变化 | 谁对谁的态度或关系发生变化 |
| 信息变化 | 谁知道了什么、仍误解什么；本轮向玩家呈现哪些信息 |
| 场景结果 | 实际结果及后果，哪些玩家期望没有成立 |
| 写作依据 | 相关资产、历史事实和需要承接的正文引用 |

例如甲当众质问乙，乙否认并转移嫌疑，丙担心秘密暴露而隐瞒，丁指出漏洞，甲转而要求搜查；最终只是嫌疑加深，没有确凿证据。导演决定这条发展链，不必为每个人逐句写对白。

**决策范围。** 导演只安排当前玩家行动的合理后果，不能预定玩家接下来三次如何选择。多人物连续对话可在一轮中完成，到下一次适合玩家介入的位置停止。本轮读取了隐藏资料，也不意味着玩家或 NPC 自动获知。

**输出与记忆。** 输出审核结论、场景方案、拟议状态变化、重大影响标记及依据。玩家表达、审核和申诉可作为交流记录保存；真正发生的事件随有效回合提交。拒绝、推测和废弃版本都不能混成有效事实。

### 2.2 写手：每轮独立的文学表达者

**定位。** 写手不维护自己的长期会话和世界记忆。它拿到足够的本轮材料，写成连贯的小说正文。

| 必要输入 | 具体内容 |
|---|---|
| 导演场景方案 | 本轮行动链、结果、关系与信息变化、停止位置 |
| 近期正文及上一轮事实 | 正文用于接续对白、动作、情绪与文风；摘要用于交代事实，二者不能完全互相替代 |
| 涉及的资产与状态 | 人物性格、口吻、关系、地点环境、伤势、持有物等 |
| 本轮相关的历史 | 旧经历、承诺、曾透露的秘密及证据，无需整段历史都加载 |
| 写作要求 | 本轮文风与长度等要求；长期偏好功能采用后，将相关偏好一同提供 |

十轮前的“绝不透露你的身份”若影响当前对白，就应随本轮材料提供。写手无需自行记住十轮历史。

**可以自由创作：** 具体措辞、对话展开方式、反驳语言、表情、动作描写、情绪与叙述节奏；在不破坏必要因果顺序的前提下安排表达。可以写出多人的连续互动，不需要每一句都重新调用导演。

**必须保持：** 导演确定的结果、关键行动链、关系变化、知情范围与停止位置。导演确定乙成功误导甲，写手不能改成甲识破乙；不能制造影响状态的关键事实，不能为悬念新增未发生的历史事件，也不能代替玩家决定下一次行动。

**交付与检查。** 输出本轮正文。发现越出框架的关键事实时如何校验、修复或交回导演，列入 P0 评审问题；不能仅因正文流畅就视为回合成功。具体输入组装责任、格式和自由细节范围待定。

### 2.3 编剧：维护未来发展的规划者

**定位。** 编剧负责近期与长期剧情方向、人物发展、冲突、伏笔和重规划。MVP 先提供最小可用计划，持续创作档案和复杂依赖管理在 P1 完善。

| 项目 | MVP 要求 |
|---|---|
| 输入 | 当前有效事实、原著参考、已有计划、导演本轮结果与影响依据、相关记忆 |
| 初始工作 | 围绕第一章建立可修改的近期矛盾和发展方向，避免写死唯一分支 |
| 重规划工作 | 根据导演已确定的重大结果，修订、取消或替换受影响的未来安排 |
| 输出 | 有版本的未来计划、适用条件、变更原因及后续可参考方向 |
| 持久内容 | 当前有效计划及必要依据由程序保存；不依赖单次模型上下文延续 |
| 会话方式 | 长期会话、分阶段调用以及每次选用哪些历史记录待设计；不预设必须与导演同样组织 |

**调用时机。** 开局需要初始计划；之后仅在导演识别重大影响时调用。普通对话、动作姿势或措辞改变不触发。关键人物死亡、重要事件前提失效、长期人物目标或篇章结局受影响时，进入重规划。阈值用样本细化。

**与导演、写手的关系。** 导演确定本轮事实后，编剧与写手可以并行：写手写本轮，编剧改未来。编剧不能推翻当轮已确定结果，也不直接编写本轮每句对白。其计划完成并保存后才能开始下一轮。

**后续能力归属。** 事件依赖、计划生命周期、伏笔及多线揭示属于编剧的 P1 设计；两阶段记忆整合放在 P2；前瞻推演与规划执行分离放在 P3。计划不足时是否增加触发、规划跨度多大，尚待评审。

### 2.4 程序：三 Agent 共用的状态与执行管理

程序区分各个存档、保存本局状态、准备每次模型调用的材料，并控制能用哪些工具。它还记录哪次请求正在处理、何时允许发送下一条行动，以及出错后从哪一版继续。模型提出变更，程序检查后写入；不能让模型任意改库。

| 对象 | 保存内容 | 使用要求 |
|---|---|---|
| 原著资料 | 人物、地点、关系、原著事件与原文引用 | 游戏侧只读参考，原著未来不是当前事实 |
| 本局状态 | 人物存亡、位置、时间、物品、关系、事件、承诺和关键事实 | 各存档隔离，是行动判断依据 |
| 未来计划 | 编剧安排、条件、变更原因与版本 | 与事实分别保存，失效后不继续沿用 |
| 人物认知 | 某角色知道、相信或误解的内容及来源 | 不随其他角色获知真相而自动更新 |
| 回合与任务 | 输入、审核、申诉、导演结果、正文、计划、前后版本及任务状态 | 三方使用同一有效回合结果；晚到旧结果无效 |
| 原始历史与工作记忆 | 消息、工具结果、证据、摘要、笔记及引用 | 原始内容持久保留，工作上下文按需组装 |

这些是业务对象与责任划分，字段类型、存储位置、索引、备份兼容及事务协议在实施设计中确定。

## 3. P0 玩家流程与提交规则

### 3.1 开局

选择已具备资产的书籍，创建独立游玩存档，从第一章主角所在位置进入。确定当时的环境、在场人物与可知背景，建立最小状态和编剧初始计划，生成开场正文，再开放玩家行动。

初始资产若包含全书后期信息，需要按开局时间和知情范围组织输入，不能在开场提前泄密。初始化任务的具体先后与并行方式待设计。

### 3.2 正常回合与一次申诉

1. 玩家提交行动或剧情设想，程序保存回合前恢复依据，锁定新回合输入。
2. 程序准备状态、资产与候选线索；导演审核并按需查证。
3. 审核不通过：本条消息显示已撤回，提供一次申诉／重新编辑入口，不产生世界变化。
4. 申诉通过：导演根据玩家最初输入的全文和申诉说明确定这次采用的行动，三项内容分别保存供回看，并进入正常编排。
5. 申诉失败：维持撤回，关闭本条申诉入口，玩家可以重新发出新输入。
6. 审核通过后，导演确定实际结果和场景方案，再判断重大影响。
7. 写手始终生成正文；有重大影响时，编剧与写手并行更新未来计划。
8. 写手完成可以先展示正文。全部必要任务成功、校验和保存完成后，解锁下一轮。

“想刺杀皇帝”可能允许尝试，但不保证成功；“开局凭空成神”没有世界依据则拒绝。玩家写出的 NPC 行为先作为提议审核，不直接兑现。

### 3.3 最后一条 AI 回复改写

入口位于最后一条 AI 回复的消息菜单，玩家提供改写方向。系统恢复到该轮玩家行动之前的状态、有效记忆、计划和对话历史，使上一版结果及未完成任务失效，然后重新经过导演审核、现场编排、写手生成与按需编剧重规划。

改写不能只替换文字。例如原结果为“皇帝死亡”，新版本不成立时，当前世界、记忆和计划都不能残留死亡事实。任意历史节点回溯、分支树和分支切换界面放在 P2。

### 3.4 回合一致性与存储候选

MVP 必须做到：世界、正文、计划和有效对话指向同一回合；重复提交不会重复扣物品或推进时间；旧编剧任务不能覆盖新版本。

建议评审“回合前快照＋本轮临时状态＋全部成功后统一生效”。回合需要可恢复的前后状态，只有版本编号不够；定期完整快照加增量变更可减少复制开销，具体算法待选。

改写可创建候选新分支，成功后切为有效分支，旧分支保留历史但不参与当前判定。新分支尚未激活时如何接收任务结果，需要与提交协议一起设计，不能简单拒绝所有非当前分支写入。

写入时将执行有效性、分支／回合修订、基础版本检查与保存放在同一原子操作内。取消 API 不等于任务一定不会晚到，仍须拒绝过期结果。

### 3.5 失败后的行为：P0 必须评审的选择

原文保留两种方向，本文不将其合并为已经确定的规则：

| 方向 | 行为 | 需要明确 |
|---|---|---|
| 保留进度后有限重试／恢复 | 核对已提交结果，继续未完成任务；避免重复副作用 | 可保留哪些中间结果，如何恢复输入，何时终止 |
| 最终失败则整轮作废 | 从 S100 执行，全部成功提交 S101；最终失败丢弃临时结果并回到 S100，等待重新输入 | 是否先允许内部重试，何为最终失败，提前展示的正文如何撤回 |

无论选哪种，编剧失败都不能造成永久锁定；刷新、取消、超时、提交中断必须有明确反馈和恢复入口。回退须包括业务、对话、记忆与计划，诊断日志可以保留但不能继续影响世界。

游戏回合的最终作废策略，不自动适用于原著串联等长任务。

## 4. P0 实现清单与依赖顺序

下表保留原文 17 项 MVP 能力，重组为便于实施的工作包。实现方案仍须评审。

| 编号 | 工作包与交付内容 | 依赖与完成检查 |
|---|---|---|
| G0-01 | 每局身份、独立存档、世界线及最小世界状态 | 同书两局隔离；关闭恢复后时间、位置、物品、关系与事实正确 |
| G0-02 | 现有资产映射、查询与受控提交工具 | 基于 G0-01；能读取开局资料和本局状态，记录变更前后值与来源 |
| G0-03 | 三层记忆及基础两层检索 | 保存原始历史、相关笔记与证据；推理前发现候选，导演可自主继续读取；可恢复旧约定 |
| G0-04 | 三 Agent 交接结构与独立提示词 | 场景、事实变更、影响说明、正文输入与计划版本可校验；正式字段待定 |
| G0-05 | 第一章初始化、编剧最小计划、开场正文 | 基于状态和角色接入；不泄露后期秘密，开场完成后可行动 |
| G0-06 | 自由输入、合理性审核、撤回与一次申诉 | 多行动及 NPC 设想可区分；拒绝不改世界，申诉版本可追溯 |
| G0-07 | 导演现场编排与重大影响识别 | 成功／失败／部分成功有依据；停在玩家可介入处，普通细节不触发编剧 |
| G0-08 | 写手正文与编剧按需重规划 | 写手保持确定结果；编剧只改未来，玩家离开原著也可继续 |
| G0-09 | 回合任务版本、并行、输入锁和一致提交 | 导演后下游并行，正文先显示时仍锁输入；全部完成保存才解锁 |
| G0-10 | 最后一条回复改写与旧任务失效 | 从玩家行动前恢复，全流程重跑；世界、正文、记忆与计划一起替换 |
| G0-11 | 基础失败恢复、重复提交保护与关闭恢复 | 先选择第 3.5 节策略；失败、刷新、重试和晚到结果不破坏状态 |
| G0-12 | 日志、版本追溯与 MVP 验收 | 保存输入、工具结果、模型与提示词版本、状态及计划版本，运行第 10 节样本 |

开发依赖建议为：G0-01／02 → G0-03／04 → G0-05／06／07／08 → G0-09／10／11 → G0-12 完整验收。日志和测试随各项建立，最终集中验收。提交、恢复设计应在 Agent 获得写入能力前明确，不能拖到最后补。

基础记忆、结果校验和有界失败处理属于 P0 必需能力；P1 的同类条目用于深化方法和复用检查，不表示 P0 可以无校验或无限重试。MVP 不安排全书人物每轮模拟、逐个 NPC 常驻 Agent、完整物理引擎或成熟伏笔评分。

## 5. P1：长期剧情与运行质量

### 5.1 编剧、导演与叙事能力

| 编号 | 能力 | 目标行为与评审要点 |
|---|---|---|
| G1-01 | 结构化创作档案 | 保存阶段目标、主要矛盾、人物目标、备选场景、伏笔及回收意图、未完事项和计划版本；恢复后能解释正在铺垫什么 |
| G1-02 | 计划生命周期 | 支持保留、改写、提前兑现、延后、转后台、取消、新建篇章并记录原因；已解决冲突不能换皮重演 |
| G1-03 | 因果检索与事件依赖 | 按人物、事件、地点、资源、目标与时间找关联；维护本局事件前提、参与者、依赖、结果和替代路径 |
| G1-04 | 人物认知与动机深化 | 保存知道／相信什么、目标、承诺及行动；谣言和秘密需要传播依据；P0 已要求的知情隔离继续有效 |
| G1-05 | 原著外人物、地点与故事线 | 合理新内容保存到本局，支持长期离开主线生活；创建权限与状态校验待设计 |
| G1-06 | 编剧触发与交接深化 | 在重大影响之外评估阶段目标达成、计划失效、长期未推进和计划不足；明确导演影响说明、编剧适用范围 |
| G1-07 | 事实演化与叙事揭示分离 | 记录发生时间与获知时间，编剧规划线索逐步揭露及多线交织，导演确定当前观察，写手遵守揭示范围；倒叙是否启用待定 |
| G1-08 | 用户长期偏好 | 导演、编剧按需读取偏好，写手由本轮输入接收；减少反复纠正，不将偏好变成世界事实 |

**事件依赖例子。** E1 甲背叛乙，E2 乙发现背叛，E3 两家决裂。玩家说服甲放弃背叛，E1 前提失效、E2 需要重评；E3 可能由另一冲突触发，但必须重新论证，不能自动删除或为维持结局强造冲突。条件可能不止一个，需要区分必要条件与替代触发。编剧从事实向后推后果，从创作目标向前安排铺垫，冲突时修改目标。

**长期偏好待定内容。** 明确设置与对话确认如何采集，适用于存档、书籍还是跨书籍；如何查看、纠正、撤销；本轮指令与旧偏好如何处理；三角色如何共享；回合回滚是否影响偏好。验收需验证新偏好持续生效，撤销后旧值不再使用。

### 5.2 记忆、上下文与工具返回

| 编号 | 能力 | 方案与检查 |
|---|---|---|
| G1-09 | 结构化笔记与历史回读深化 | 执行中保存进度、决定、发现、未解问题及证据引用；摘要漏细节后仍能按引用找回 |
| G1-10 | PreCompact 压缩前触发 | 压缩前可整理重要记录；自动／强制压缩、程序／模型执行、失败和重复保存规则待定；先核查本地 Pi 支持 |
| G1-11 | 分层压缩与历史选取 | 工具输出预算 → 微压缩／局部折叠 → 必要时模型摘要；原始消息、工具结果、摘要和折叠记录分别保留，动态组装请求 |
| G1-12 | 可逆上下文第一步 | 先试验导演工具结果 Raw 完整／Abstract 摘要两种表示，按 ID 恢复；不因切换表示重写摘要，外部内容仍可能需要读库 |
| G1-13 | 工具结果整理与分层读取 | 程序批量查询、精确去重、合并、按范围查询、分页和按 ID 读取；完整候选保持可访问，语义排名不能作为唯一排除手段 |

清理只能移除工作上下文中的冗余，不能删除外部原件或当前判断仍依赖的证据；工具调用与结果需要配对。各 Agent 历史分别管理，写手不因使用共用机制而新增长期会话。

例如 500 条候选先返回目录，允许继续翻页、换条件或读全文。排名靠后、没有相同关键词的事件仍可能关键。“可重新读取”不等于“一定被发现”。语义相关性和伏笔判断需结合内容，完全重复去重仍要保留来源，不能把相似事件合并。

### 5.3 运行机制与错误处理

| 编号 | 能力 | 方案与评审要点 |
|---|---|---|
| G1-14 | 长任务清单、可验证单元、检查点与独立完成校验 | 评估按单元领取、检索、提交、程序核实再更新进度；保存当前对象、已提交结果、疑点和检查点，恢复先核对数据库 |
| G1-15 | 异常分类与恢复协调 | 区分上下文超限、输出耗尽、纯思考、超时限流、截断参数和无进展；设置有限恢复，不统一重发 |
| G1-16 | 循环检测与重复结果引用 | 检测重复调用、A-B-A-B、相同错误及无进展；先警告观察，再决定强制暂停；完整结果保留，重复大段输出换引用 |
| G1-17 | 结构化结果有限修复 | 格式／类型错误保留调查结果并局部修复；业务冲突交回导演判断；修复后仍执行权限、版本及业务校验 |
| G1-18 | 请求级工具快照 | 单次请求看到的工具定义、校验、路由实现与执行配置保持一致，下一请求再加载新版本；实时取消和权限校验仍有效 |
| G1-19 | 工具等待与执行耗时分离 | 记录入队、开始、结束时刻，分开统计等待与执行；并行区间不能直接相加成回合耗时 |
| G1-20 | 记录现行方案的质量、成本与耗时 | 用一致样本比较剧情一致性、检索召回、调用次数、Token、耗时和重试；用现行方案的测量结果判断后续实验是否值得保留 |

G1-14 的四项为候选评估内容，不强制全部建设，也不把原著串联的单元大小直接套给游戏回合。重点检查“数据库已写入但进度未更新就中断”，评估事务和幂等提交。完成状态由代码核实实际提交、剩余对象及业务条件，不能只相信模型说完成；允许保留哪些疑点需定义。

| 失败类别 | 候选处理 |
|---|---|
| 输入上下文超限 | 清理旧工具结果，必要时压缩，再有限重试 |
| 输出 Token 耗尽 | 检查有效结果和已提交状态，调整输出预算或任务复杂度 |
| 长时间只有思考 | 检查停止原因、正文、工具调用与思考用量；终止无进展请求，评估降低思考强度或拆小任务 |
| 超时、限流 | 按错误类型退避与有限重试 |
| 工具参数截断 | 禁止执行不完整调用，记录错误并按有效状态恢复 |
| 连续无业务进展 | 停止自动消耗，保留可恢复状态；游戏回合按已选失败规则处理 |

缩短输入不一定解决纯思考耗尽输出的问题。模型档位需经网关映射，并核对实际请求和响应是否生效。恢复前检查已有写入，不能重复执行副作用。局部格式修复次数不照搬参考源码的默认值，须与总恢复次数、预算一并设计。

循环指纹可含工具名、规范化参数、结果哈希、数据版本和进展版本。参数变化、数据更新、新证据、分页、轮询及保存后复查都可能是正常行为，不能仅看工具名重复或没有写库就判定无进展。短引用所指内容已不在上下文时，仍要提供回读通道。

## 6. P2：后台世界与长期运行扩展

| 编号 | 能力 | 目标与依赖 |
|---|---|---|
| G2-01 | 后台事件调度 | 按游戏时间、事件条件、NPC 目标及约定推进重要事项；依赖状态、计划与因果管理 |
| G2-02 | 前台／后台故事切换 | 后台变化经消息传播或因果联系进入玩家视野；回到旧地能发现变化，但不能凭空知道远方秘密 |
| G2-03 | 多线事件与长期伏笔台账 | 维护并行发展、未兑现承诺、回收状态及失效原因；需要对应证据和版本 |
| G2-04 | 大跨度时间推进 | 旅行、隐居、种田三年等批量推进，在需玩家选择的关键节点停止，不能替玩家作重大人生决定 |
| G2-05 | 多分支历史与恢复增强 | 分支树、版本比较、多轮回溯、切换及异常修复；超过 P0 最后一轮改写范围 |
| G2-06 | 两阶段叙事记忆整合 | 成功回合提取局部长期影响与事件引用，规划更新时按新增／修改／删除增量整合综合认识 |
| G2-07 | 按任务预取记忆 | 任务开始时启动相关检索并缓存，后续需要时使用，避免每个工具循环重复检索 |
| G2-08 | 动态推理预算与全任务预算 | 研究任务内调整思考强度、每次调用更新剩余额度、临近额度保存结果及代码硬停止 |
| G2-09 | 长篇上下文检索持续优化 | 按更长故事评估旧因果、多个角色认知、计划和日志的召回，调整覆盖率、预算与延迟 |

后台只结算重要变化，普通细节在不冲突时延后展开，不要求逐人逐秒模拟。

**记忆整合。** 两人经历冲突、威胁后合作，应保存关系发展和证据；不能自动推断敌意仍在，也不能因同一人物参与就合并成同一故事线。综合认识与事实分开，改写后需处理失效来源。可由运行层定时或按规划触发，无需新增常驻 Agent，具体频率待定。

**预取。** 首轮必要资料仍要就绪；尚未完成的异步结果不能声称已进入模型请求。需明确等待或正常检索的选择、缓存归属与失效条件。

**预算。** 单次输出上限与全任务额度分别管理。预算耗尽不是任务完成；接近上限可优先完成有效结果或保存未完成状态，硬限由程序执行。需确定输入、输出、思考、缓存、重试和摘要是否计入、缺失用量如何处理、收尾预留多少。服务商实验性任务预算与应用层统计分别评估，不能假定 Pi 或当前模型已支持。

## 8. 上游资产改进与游戏接入依赖

以下保留原文关于“原著串联阶段”的两项改进，建议与游戏 P1 因果能力联动评审，独立排期；不重做已经初步完成的世界书流水线。

| 方向 | 保留的需求 | 对游戏的作用与待定内容 |
|---|---|---|
| 按明确线索串联 | 围绕特殊人物、物品、地点、组织查事件；提取阶段补充线索及事件关联 | 减少漫无目的搜索；需确定特殊线索、别名统一、字段索引及旧书补齐方式 |
| 两个已知节点间补查 | 由相关端点形成关键词，在涉及及必要中间章节搜索片段，再核对缺失事件或细节 | 为因果和伏笔补依据；章节范围、停止条件、原文权限及补节点／新建节点权限待设计 |

数据流分别为“原文 → 事件与线索提取 → 关联保存 → 定向候选检索 → 内容核对串联”和“已知端点及缺口 → 章节与关键词 → 命中片段 → 核对证据 → 补充关联或保留未解”。

同一人物或物品出现不证明同属一条事件线。完整原著允许回头核对早期细节，但保存全书或长期记忆不保证自动发现伏笔。用跨章线索和缺环样本比较正确串联、召回、请求次数、Token 与耗时，再选实现方案。

## 9. 共用技术约束与复用检查

### 9.1 记忆与资料加载底线

三层职责沿用原文：数据库维护权威状态；外部记录保存人物认知、目标、伏笔、计划和证据索引；工作上下文只承载本次需要的消息、结果和摘要。压缩只能改变工作视图，不改前两层。

摘要必须区分怀疑、否认、证实和未执行计划；摘要与有效记录冲突时回读并纠正上下文，不据错误摘要改世界。先保证重要资料可找回，再精简冗余。

程序在导演推理前根据场景实体和已有关系发现候选，导演再判断意义并深入查询。当前行动、场景及必要状态直接加载；人物物品地点提供简短档案；历史候选先给标题、摘要、关联理由与 ID；完整事件、关系细节和原文按需读取。索引缺失可能漏检，MVP 的具体候选覆盖范围需评审。

“黑鹰徽章 → 阿尔德家族 → 王室旧案”用来验证程序能发现导演未点名的旧案。读取秘密不更新任何角色认知；发现候选不等于确认事实。批量检索与按任务直接返回部分详情可减少逐条调用，加载条数不能机械固定。

### 9.2 框架、模型与结构约束

- 复用 pi-ai 统一模型调用，pi-agent-core 作为导演、编剧的工具与循环底座；写手是否需要完整循环按任务决定。
- 复用现有会话、检索、压缩、网关、状态和 trace 能力。核对本地锁定版本，不能依据上游 main 直接认定接口和默认行为一致。
- 使用 TypeBox 等结构约束检查交接与提交；类型合法不等于剧情合理。
- 提示词独立 Markdown 保存并版本化，写清角色、检索路径与交付要求；三角色可采用不同模型，经统一配置调用。
- 沿用本地数据库，原著只读，游戏变化保存于独立存档。记录的重放可复现保存结果，重新请求概率模型不保证生成相同文字。
- 请求前上下文组装、工具执行前后校验和循环结束判断的复用点需查代码；不另造一套 Agent Loop。PreCompact 和恢复控制器是否需应用层扩展分别核查。
- 工具读写范围需登记；快照、恢复与游戏新增对象的备份兼容在实施设计中说明。

优先检查原文提到的 retrieval.ts、context.ts、compaction.ts、runtime.ts、gateway.ts 和 trace.ts 的实际职责与现有能力。本文未进行实现审计，不以研究建议推断某项能力当前缺失。

细粒度读写锁调度仍不列入实施待办；工具并发先复用已有能力。本次保留的优化是等待耗时与执行耗时分开记录。

## 10. 验收与评测样本

**检索对照。** 使用独立人工标注的跨章关联；A 提供完整可分页候选，B 使用拟议整理／筛选。候选召回率＝进入候选的正确关联数÷应找出的正确关联数；采用 Recall@K 时明确 K。Token 节省率＝1−B 消耗÷A 消耗。还要核对最终串联正确性，不能由筛选算法自己定义真值，也不能仅用节省成本证明质量合格。

**性能对照。** 相同任务、模型及统计口径下记录模型调用、上下文用量、工具排队与执行、总 Token、恢复次数和总耗时。并行阶段按实际时间区间分析，避免重复累计。验收阈值在评审后确定，本文不预设通过数值。
