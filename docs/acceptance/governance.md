| 中型需求 | 判断既有搜索排序调整 | 精简提案、差异规格、任务，包含模块处理和针对性验收 |
| 大型需求 | 判断新增游玩能力或共享接口变化 | 完整方案、影响、依赖任务及跨模块验收 |
| 能力扩展 | 按游玩设计登记一个已确认的后续能力 | 明确身份、工具、读写、存储、备份和验收，能复用共用接口 |
| 原任务去向 | 打开[旧计划入口](../分阶段实现与人工验收计划.md) | 进入当前变更任务或历史检查记录 |
| 需求池 | 从[需求池](../../openspec/需求池.md)选择一个编号 | 看见整体状态、资料入口、缺口和下一步；详细结论及进度由链接提供 |
| 字段与流程 | 查看[接入设计](../../openspec/changes/adopt-openspec/design.md)和两种工作流模板 | 字段增改、读写和生效时点、完整触发分支可审查；无变化项有依据 |
| 独立接手 | 只提供需求编号和仓库，让接手者读取关联材料 | 能复述已确认目标、数据和触发逻辑，定位任务及验收；游玩等未完成设计的需求明确列出缺口 |

## 自动检查

- `npm run governance:check`：文档与资源归属、链接、规则入口、工作流依赖及运行时资源哈希。
- `npm run openspec -- validate --all --strict`：规格、场景及变更格式。
- `npm run openspec -- schema validate project-local`、`project-full`：两种工作流结构。
- `npm run typecheck`、`npm run build`：工具依赖接入后的工程兼容。

自动结果由接入任务引用；用户检查结论在本文件记录。当前业务功能的真实模型验收继续按资产主线验收任务执行。
