# 资产主线集中验收

状态：开发检查通过，待用户验收。

启动本地服务后打开[工作台](http://127.0.0.1:5173/)，先导出当前书籍备份，再按下表操作。

| 范围 | 操作 | 核对结果 |
| --- | --- | --- |
| P1提取与人物称谓 | 提取少量章节，查看顶部两类章节状态，补提取失败项，并核对人物称谓 | 单项失败后继续后续章节，成功项保留；稳定别名与通用称谓分别归档 |
| P2整理 | 继续实际书库的AI整理并查看报告 | 成功项保留，失败项独立；合并与整编结果明确，原文证据可回查 |
| P3串联与复核 | 继续串联，再做全书复核，查看跨窗线索与事项 | 有效进度复用，疑点保留；查证回收后更新原事项，具体结果可查看 |
| 并行恢复 | 同书同时启动P2/P3，分别取消、切书、刷新或在另一标签继续 | 任务和费用归属独立，提交只生效一次，执行权失效后旧任务停止写入 |
| 事件网络 | 在节点或事件线中切换网络，选择事件线、节点、章节和孤点 | 图与资产一致，共享节点只画一次；手机上可缩放、定位和打开详情 |
| 完整恢复 | 导出当前书籍，恢复为副本，在另一浏览器打开 | 原文、人工成果、来源、报告、会话、进度及事件网络完整；继续处理复用有效确认 |

## 自动检查范围

开发检查覆盖单元测试、浏览器操作、严格类型检查、静态检查和生产构建。模型调用使用固定响应，世界整理的具体步骤见对应验收页。

- 固定响应贯通导入、提取、世界整理、串联、全书复核、网络、导出和恢复。
- Edge与Firefox之间恢复和再次导出，恢复后的有效复核结果直接复用。
- 200章、2000节点、100条事件线及长会话的备份、恢复和布局；千节点网络的搜索与末项定位。
- 表情与扩展汉字位于切块边界时，分章和UTF-8备份往返保持完整。
- 当前备份结构、旧格式4备份、损坏文件、来源与关联、消息链和摘要边界检查。

真实模型对人物身份、事件因果和伏笔回收的判断，由用户结合原文验收。游玩功能按施工计划后续接入。
