# 世界资产整理验收

状态：自动合并来源、别名纠正及整编语义复核待用户验收。按下列步骤进行真实书库验收。

打开[独立验收页](http://127.0.0.1:5173/?acceptance=world)，点击“装载世界资产样本”，选择“世界资产整理样本”。样本已有全书提取成功凭证，包含7个人物、3个地点及一章原文。

## 代码整理

1. 点击“代码整理”。完整同名项自动按组融合，固定样本中的两份沈青、两份陆川各合为一份，人物7→5，地点仍为3条。
2. 查看剩余异名候选，张三与张三丰按原文保持分开。别名、包含和去后缀匹配仍需人工核对实际成员。
3. 如需检查异名融合，另建经确认同一人的异名测试资料，选择成员、主名与保留编号后，可直接确认、预览或加入待合并队列。
4. 查看整理报告，核对同名自动来源、保留编号、来源与减少数量，以及零模型调用。
5. 合并后分别查看统计章节进度、保存统计和刷新候选的提示；结束后代码整理、AI整理和人工编辑恢复可用。
6. 刷新页面后重开报告，确认成功组保留，已完成任务遗留的执行锁能够自动清理。

代码入口按完整主名相同执行自动融合；异名候选的实际成员由人工选择。AI入口在重新装载的原始样本上按原文证据核实身份。

## 一键机械合并

1. 点击代码整理，等待完整同名项处理结束。逐组核对剩余异名成员，切换后再返回，确认勾选和预览选择保留。
2. 选择主名、保留编号后点击“加入待合并”。核对队列中的成员、保留编号和待办数量，资产此时保持原样；可移除待办后重新选择。
3. 刷新页面，确认待办仍在。点击代码整理与AI整理之间的“一键机械合并”，观察每次只处理一组，其他候选保持待确认。
4. 查看合并报告，核对各组合并结果、来源和零模型调用；当前候选与出场统计在队列结束时更新。
5. 执行期间点击停止。当前组保存后停止，未处理项保留；继续时跳过成功组，原人工确认不受统计修订影响。
6. 入队后修改某个成员的正文，再执行队列。该组显示待重新核对，其他组照常处理；点击重新核对、确认加入后补该组。
7. 导出待执行或部分完成队列，恢复为副本后继续。核对成功组保留，副本与原书分别保存；统计未完成时通过“完成合并收尾”补齐。
8. 在375像素宽度查看队列和报告，检查成员、停止、移除与重新核对入口可操作。

## AI整理

1. 重新装载样本。在设置页保存自己的整理模型、地址和密钥，再返回该样本。
2. 点击“AI整理”。查看人物、地点核实与按需整编的阶段和进度。
3. 运行中尝试编辑本书人物、地点，查看锁定反馈；另一书的查看与编辑保持可用。
4. 完成后查看整理报告。原文明示沈青与老沈为同一船夫，人物应合并为5条；青石客栈与青石栈合并，地点应保留2条。药师和镖师陆川分别保留，张三与张三丰分别保留，青石客栈后院单独保留。
5. 展开“查看合并依据”，核对原因和逐字原文。查看保留编号、别名、来源与前后数量。
6. 导出书籍备份并预检，确认资产、来源、事实底稿及报告可以保存和恢复。
7. 先运行代码整理，再运行AI整理。确认自动同名融合结果仍可参与有证据的异名合并，人工指定的主名与保留目标继续有效。
8. 查看“别名核实与纠正”，核对保留与移除的称呼、原文依据、实际指向及相关节点待办。主名和已核实别名共同计入出场统计，人工人物层级保持原值。
9. 查看“资料整编与复核”，展开修改字段核对原资料与当前资料。实际改动项显示独立AI复核结论，无变化项单独记录；整编条数只统计实际更新。
10. 在复核等待时取消，刷新后继续，确认复用已保存稿件；修改资料后继续，确认旧稿标为资料已变化。导出并恢复副本后核对报告和继续操作。

真实模型可以将把握不足的分组保留为待复核，报告按实际覆盖和结果显示状态。

## 故障与界面

| 操作 | 预期结果 |
| --- | --- |
| 全书提取未完成 | 两个整理入口显示前置说明并保持禁用 |
| 没有配置密钥时运行代码整理 | 可查候选、预览和确认，全程本地执行 |
| 预览后资料被其他标签修改或删除 | 确认拒绝，提示刷新预览 |
| AI提交后模型失败或点击取消 | 保留已提交组，报告列出失败或取消结果；请求停止后恢复编辑 |
| 整编遗漏事实编号或清空已知字段 | 在统一请求预算内修正；仍失败时保留原资料并记录部分完成 |
| 事实编号完整，但语义复核发现遗漏、重复、矛盾或新增内容 | 稿件保留，原资料保持原值，报告说明问题，其他资产继续处理 |
| 复核请求失败后再次继续 | 直接复核已保存稿件，生成用量保持累计且不重复生成 |
| 同一人物含“性情沉稳，处事果断”和“为人沉稳，遇事果决” | 展示稿归并为一种表述，其他独有信息继续保留，事实底稿和来源完整 |
| 地点描述含相同含义及不同时期的变化 | 同义描述归并，不同时期的状态分别说明 |
| 配置百万上下文，整编输入超过6000 token但仍在模型容量内 | 资料进入整编，输入和输出预留共同按当前模型容量核对 |
| 输入与输出预留真正超过模型上下文 | 报告具体估算量和容量，原资料保留 |
| 已有旧规则整编标记，再次运行AI整理 | 符合条件的档案按新规则整编，新规则下依据未变则跳过重复整编 |
| 同时启动本书的另一个整理任务 | 执行权检查拒绝重复运行 |
| 切书或切设置页后返回 | 原书任务及结果保持归属，报告可重开 |
| 375像素窗口 | 两个入口、取消、候选选择、预览和报告均可操作；长列表在区域内滚动 |
| 42组机械合并完成后查看按钮并编辑人物 | 队列显示待处理0组，统计与候选收尾结束后恢复代码整理、AI整理及人工编辑，刷新后状态一致 |

## 分批与继续

1. 点击AI整理，观察每批资料数量及整体已核实进度。每个资产独立按世界资产整理决策提前收尾；未完成项保留待办，后续资产继续。
2. 在下一批请求中取消，刷新后点击“继续AI整理”，核对已处理范围保留，剩余资料继续核实。
3. 报告显示身份核实的已完成和待处理数量。展开“批次与实际请求”，查看各批分配数量、实际请求、已核实范围、提交确认、查询记录与校验反馈。
4. 单项失败显示资产编号与原因，后续资产继续核实。本轮有失败项时显示“部分完成”，仅有未完成项时显示“已暂停”；点击继续处理剩余项。累计用量包含原运行和继续后的新增请求。

## 原文与收尾验收

- 查看含“爸爸、姑父、娘娘”等旧别名的人物：稳定别名保留，通用称谓显示在身份说明中。只有“太后”主名的档案仍可查看与人工选择。
- 核对两个都被称为“娘娘”的人物：自动人物关联和代码候选不会仅凭这一称谓关联或合并；“林姑父”等限定称呼仍可用于检索。

- 按资产编号读取原文后，带逐字证据的合并能够提交；来自不同章节的同一人物可核实合并。
- 超过20章的来源通过游标持续向后读取，返回内容能定位到章节和章内位置。引文可覆盖连续读取的多页；缺页时反馈补读位置，改写引文时反馈逐字核对要求。
- 连续多个资产提交失败，后续资产仍得到核实；报告标明失败资产，继续操作只重试剩余项。
- 部分资产待重试时，成功资产仍完成按需整编；再次继续保留这些资产的核实与整编结果。
- 先核实若干资产，再合并其中一组：其他成功项保持完成，队列继续向后处理；保留目标与被合并成员的状态同步更新。
- 某项先失败、随后被其他任务成功合并：当前失败列表清除该项，历史批次显示后续已处理。
- 继续旧报告时，因目录中其他资产变化而被退回的成功项恢复有效状态；实际内容或原文变化的资产仍需复核。
- 第6轮或剩余60秒出现收尾提醒；未完成项保存为待办，当前响应正常返回后停止新请求。
- 合并后查询旧编号能得到当前资产；出场统计更新后，仍有效的核实进度保留。

## 开发检查

业务检查覆盖名称规则、严格相似度阈值、候选保持原资料、代码确认与过期预览、证据合并、取消与编辑锁、事实覆盖整编、部分失败及备份结构校验。浏览器检查使用真实Pi运行库配合固定响应，覆盖两个入口的完整操作及开发版、生产版和窄屏布局。

开发版与生产版浏览器检查覆盖代码确认、预览、AI证据合并、暂停刷新后继续及工具探测。单元测试覆盖原文分页、实际片段校验、旧编号映射、单资产提前收尾及覆盖依赖。
