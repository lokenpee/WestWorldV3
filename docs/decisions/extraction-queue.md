# 逐章提取与失败补提取

## 背景

全书提取需要持续处理各章，并分别展示世界资产和叙事资产的结果。章节失败应留下明确状态，方便后续单独补提取。

## 选定方案

按章节顺序执行两个子步骤。每项首次请求和最多两次重试共用3次实际请求额度，网络重发与结构修正均计入；鉴权等不可重试错误直接记为该项失败。失败保存后继续下一项，全书队列每轮只经过每项一次。

同书通过浏览器独占锁与数据库执行记录防止重复提取。请求前、保存时和步骤交界主动核对执行者、运行编号与其他阶段资源，仍由当前任务持有时续期；定时续期作为补充。其他执行者已经接管时，旧任务停止写入。本地存储错误按中断显示，保留成功记录。

章节概览位于书名下方，每章左侧分别显示两类资产的待提取、提取中、成功、失败或中断状态。成功以持久成功凭证确认，失败或中断项可单独补提取；同书队列运行时补提取按钮禁用，点击成功项保持已有结果。

## 替代方案

仅延长执行权有效期仍依赖后台定时器；在章节外再次重试会放大实际请求次数；失败后重跑整章会重复已经成功的另一类资产。采用主动续期与子步骤级补提取。

## 后果

全书结束后可保留部分失败项，用户从章节状态块补提取，或用继续提取补齐全部待办。原文、人工修改、合并与删除决定继续保留。
