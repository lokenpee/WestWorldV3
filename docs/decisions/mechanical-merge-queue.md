# 已确认组的机械合并队列

## 背景

人物和地点需要先处理重复提取的完整同名档案，再核对异名候选。多组合并保留每组的规则来源、保存结果和未完成项。

## 选定方案

点击代码整理，先按完整主名相同自动融合人物和地点，姓名前后空白统一处理；包含、别名及去后缀匹配继续作为人工候选。身份文字差异继续融合进资料，结构化字段冲突保留记录。自动组记录同名规则来源，沿用已指定的保留编号；已有异名队列保留原成员选择。

异名候选由用户核对成员、主名和保留编号后加入队列。切换候选保留勾选和预览选择；已入队成员不能重复分配给其他组，待办可移除。

一键机械合并位于代码整理与AI整理之间。最多三组并行准备资料，写入按组顺序提交。每组的资产、人物关联、来源映射、合并记录与队列完成状态在同一事务保存。单组资料冲突记录原因后继续下一组；重新核对并加入后只补该组。

执行前核对确认时的成员内容。出场统计与自动层级引起的派生变化保留确认；名称、正文、来源或人工层级变化时重新核对。全书统计集中在队列停止或完成时更新，界面分别显示合并、统计章节、保存统计及刷新候选。关联更新复用姓名与编号索引，读取依赖按组批量失效；任务查询按阶段筛选，统计批量保存。候选扫描复用归一化称呼，并跳过相似度上界达不到阈值的比较。

运行期间持有本书世界资产执行权，人物、地点人工修改及同书提取或AI整理等待其结束；叙事阶段沿用实际读取依赖检查。停止请求等待当前组保存完，再停止安排下一组并完成统计。统计尚未保存时保留收尾待办。

队列与确认依据随书籍持久保存。刷新后继续时跳过已合并组；旧执行者失去执行权后停止写入。运行展示根据持久状态与有效执行权计算，任务停稳后恢复操作；已结束任务的遗留锁自动清理，中断任务保留待办。备份恢复为副本时转换仍有效的确认依据，已失效的确认继续等待重核。机械合并使用本地数据，报告显示零模型调用。

## 替代方案

共享表的写事务按[浏览器事务规则](https://www.w3.org/TR/IndexedDB/)排队执行，因此资料准备采用有限并发，关联与来源提交按组保存。整队一个事务会延长占用并让单项问题回滚其他组；仅保存在页面中会丢失刷新后的待办。因此采用逐组事务和持久队列。

## 后果

用户可集中核对后统一执行，并按报告处理失败组。成功结果即时生效，统计在收尾后更新；同书编辑在队列停稳后恢复。
