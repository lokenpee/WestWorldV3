# 节点参考引文与人物关联

## 背景

模型可能改写引文。节点需要持续保存和整理，人物删除或合并也需要同步反映在节点中。

## 选定方案

- 节点参考引文可为空。精确匹配时记录原文位置，未匹配时保存提示。引文未定位不会触发模型修正或使提取失败。
- 人物关联保存稳定编号，名称用于显示。初始称呼唯一时自动关联，真实同名时按身份选择。
- 节点编辑统一使用“涉及人物”，支持按姓名、别名和身份搜索、多选及移除。选择直接绑定人物编号；同名人物显示身份和编号。搜索保留已选人物，表单中的选择即时显示。
- 人物资料中找不到的称呼可暂存，显示待关联提示。同名称呼有多份资料时提示选择具体身份，其他人物的选择和保存保留该称呼。
- 存储继续保存行动人物与对象人物两类关联。编辑时合并显示，保存时保留已有归类，新选择的人物记入行动人物；同一人物在界面和事件线汇总中只显示一次。
- 已有对象中的人物进入“涉及人物”。其余对象保留原始记录，并以“涉及对象：……”补充到详细经过，同一内容只补充一次。新增的物品、地点和行为方向通过概述与详细经过表达。
- 删除人物会从相关节点移除该编号和名称；改名同步显示名称；合并将成员编号替换为保留人物编号和主名，并去重。
- 人物变更与关联节点更新在同一事务中提交。代码维护人物关联字段，原文章节与参考引文保留。
- 关联更新允许发生在世界资产命令中。叙事任务提交时比较节点修订号，发现资料变化后重新读取。
- 事件线人物集合由当前成员节点关联生成。

## 其他方案与后果

只按姓名替换容易改错同名人物，因此关联更新以编号为准。引文作为回查辅助，定位状态用于提示；事件名称、概述、章节和人物引用继续执行各自校验。

分别编辑姓名、编号和关联结果会重复操作；只保存一串姓名会失去稳定身份。统一选择入口并保留两类存储关联，使人物操作与现有查询共用原有数据。

人工和自动合并共用相同的关联更新规则。合并后节点显示保留人物，删除后节点保留其他参与者。

## 实现与验证

资产编辑表单统一读写两类人物关联，复用人物匹配与事务保存。人物选择组件放在现有资产功能目录，沿用表单样式。依赖与数据库表结构沿用现有配置。

- [x] 旧节点的两类人物、别名和同名身份在统一入口正确显示；搜索保留选择，移除后保存及刷新一致。
- [x] 暂存称呼可保存、移除和绑定身份，选择其他人物时仍保留。
- [x] 旧对象内容在详细经过中可见，多次保存保持一份；参考引文、章节原文和其他事件字段保持完整。
- [x] 改名、合并、删除和事件线人物汇总按稳定编号更新；并发冲突、域锁与窄屏操作通过检查。
- [x] 单元测试、浏览器测试、类型检查、静态检查和生产构建通过。
