# 用 OpenSpec 统一需求与规格治理

状态：已接受，依据用户2026-11-03对接入方案的确认及“开始吧”指令。

## 背景

项目已有规格、技术资源、架构决策和验收材料。用户需要在每次需求实施前知道文档变化、模块影响、实施方法及验收效果，也需要其他开发 Agent 能从文档继续工作。

## 选定方案

采用仓库内锁定版本的 OpenSpec 管理能力规格及中大型变更，完整接入已有材料。开发治理由[仓库指令](../../AGENTS.md)维护，工具配置、模板和技能引用。产品行为、技术定义、历史证据和验收各有明确归属，入口见[规格导航](../v2/00-阅读入口与术语.md)。

需求按影响分级，游玩通过共用接口和能力登记逐步细分。具体规则由仓库指令及相应契约维护。

## 替代方案

继续维护自定义变更流程会重复实现提案、任务和归档机制。仅渐进接入局部规格会让上线前仍需在多套入口之间判断归属。用户选择完整盘点、职责适配及统一任务入口，保留已有技术资料。

## 后果与验证

文档维护需要同步受影响的契约及引用；工具升级后恢复项目规则入口并检查一致性。运行时引用的资源单独登记，文档调整需核对其内容变化。

实施及验收跟踪于[接入任务](../../openspec/changes/adopt-openspec/tasks.md)，检查方法与结果见[治理验收](../acceptance/governance.md)。作用位置为仓库指令、OpenSpec 目录、现有文档入口及治理检查脚本。
