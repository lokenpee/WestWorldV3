# 按阶段锁定人工编辑，并统一实际请求预算

## 背景

2.2 原规格允许 P2/P3 与同域人工编辑交错，增加冲突恢复复杂度；PRD“重复三次”与 AI 规格“限流五次、修正另计”不一致。用户明确改为 P2 运行时不能人工改世界资产、P3 运行时不能人工改叙事资产，并授权统一重试策略，随后批准分阶段计划并要求开始执行。

## 决策

编辑与并行行为由[任务恢复规格](../../openspec/specs/task-recovery/spec.md)维护，请求与修正预算分别见[模型](../../openspec/specs/model-access/spec.md)、[提取](../../openspec/specs/extraction/spec.md)、[世界整理](../../openspec/specs/world-organization/spec.md)和[叙事整理](../../openspec/specs/story-organization/spec.md)。

## 替代方案

- 保留全域实时编辑：自由度更高，但同域冲突和恢复路径更多，用户已明确收紧。
- P2/P3 完全串行：依赖检查更简单，但改变了仍保留的并行要求，因此仅在中间交付暂不开并行入口。
- 网络与修正各有独立重试额度：可容忍更多失败，但实际请求数难预测，容易章节层再次放大；采用共享有界预算。

## 后果

用户需等相应阶段停稳才能编辑该域；未保存输入必须保留。跨域变化仍可能触发 P3 重查，因此锁减少复杂度但不消除一致性问题。请求预算耗尽可能更早给出失败，允许用户明确手动补缺；不悄悄无限循环。
