# 按阶段锁定人工编辑，并统一实际请求预算

## 背景

2.2 原规格允许 P2/P3 与同域人工编辑交错，增加冲突恢复复杂度；PRD“重复三次”与 AI 规格“限流五次、修正另计”不一致。用户明确改为 P2 运行时不能人工改世界资产、P3 运行时不能人工改叙事资产，并授权统一重试策略，随后批准分阶段计划并要求开始执行。

## 决策

- 同书 P2 持有 world 锁时拒绝人物/地点所有人工写；P3 持有 narrative 锁时拒绝节点/事件线所有人工写，包含即时字段与合并。任务自身绑定 owner 的合法写入仍允许。
- UI 与领域命令事务同时校验，拒绝返回 `ASSET_DOMAIN_LOCKED`，不改变数据。启动/写入竞争在事务内判定；取消在途工作停稳并释放 owner 锁后才开放编辑。
- 保留 P1 期间人工编辑、跨书编辑、只读、备份和 P2/P3 并行。跨域实际读依赖、revision、幂等账本不能删除。崩溃沿用有界租约恢复，不在刷新时盲目解锁。
- direct 每逻辑调用最多 3 次实际 Provider 请求，首次、网络重发和至多一次结果修正共用预算；章节层不再包重试。P2身份核实按[世界资产整理决策](world-organization.md)收尾；P3按[叙事整理的排队与恢复](story-organization.md)执行预算；更小的探测预算优先。
- 暂时错误为 network/server/rate_limit；鉴权、内容限制、不支持等不自动重试。取消可中断退避；预算耗尽不补发免费修正。
- 采用阶段验收用例先行；核心业务测试失败→实现通过→回归→用户验收。每阶段验收后再推进。

## 替代方案

- 保留全域实时编辑：自由度更高，但同域冲突和恢复路径更多，用户已明确收紧。
- P2/P3 完全串行：依赖检查更简单，但改变了仍保留的并行要求，因此仅在中间交付暂不开并行入口。
- 网络与修正各有独立重试额度：可容忍更多失败，但实际请求数难预测，容易章节层再次放大；采用共享有界预算。

## 后果

用户需等相应阶段停稳才能编辑该域；未保存输入必须保留。跨域变化仍可能触发 P3 重查，因此锁减少复杂度但不消除一致性问题。请求预算耗尽可能更早给出失败，允许用户明确手动补缺；不悄悄无限循环。
