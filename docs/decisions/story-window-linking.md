# 叙事窗口串联

## 背景

全书提取后，事件节点需要按章节顺序组织成事件线。窗口有重叠，已有事件线和同书会话需要持续复用。

## 选定方案

按原章划分每100章一个窗口，步长80章。同一原章的所有切块进入相同窗口。窗口内按章节、节点顺序分配任务，每个任务最多100个节点，实际工具读取使用各工具的分页上限。

项目调度窗口与保存进度，Pi原生智能体负责工具循环。任务输入中的工作记忆记录实际版本与指纹；追加事件线时复用已读取、版本一致的旧成员，新成员与证据节点按实际详情校验。所有窗口使用本书同一叙事会话，现有受控工具负责创建、追加、更新及合并事件线。相同成员集合的重复创建复用现有线，补充节点按章节、名称与参考引文核对已有资料。

串联期间持有本书叙事与会话执行权。业务修改、提交确认和会话消息沿用现有事务接口。每个子任务保存逐项依据；窗口保存节点范围、来源指纹与成员快照，当前资料匹配时可跳过有效检查点。

窗口全部通过后记录为“窗口串联完成”，P3保留在全书复核前的暂停位置。全书复核使用后续的全书覆盖清单完成。

## 替代方案

按章块计数会把长章切块拆入不同窗口，因此使用原章。每窗新建会话会丢失先前的线索与工具确认，因此复用同书会话。重复创建全部事件线会增加重叠成员，因此以已有线的追加和更新为先。

## 后果

用户可查看窗口起止、节点覆盖、判断依据和提交确认。取消或失败保留已提交的线与检查点。当前节点、事件线和原文仍是业务数据来源，会话摘要用于检索线索。
