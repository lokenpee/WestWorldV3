# 保全文本并通过生命周期日志发布完整导入

## 背景与方案

阶段2要把TXT保存为独立书籍。书架与书库在两个IndexedDB数据库中，不能假称跨库原子；自定义正则也不能阻塞整个页面。沿用04 ALG-01/ALG-FIX：编码、分章、正文与元数据先校验，单书事务完整写入后才发布书架。

- `src/features/import/text.ts` 实现UTF-8严格优先、GBK回退，去一个开头BOM、换行规范化、默认/自定义正则、序文、4000字符无标题分段及10000字符长章切块。所有字符数使用UTF-16单位，拼接精确还原规范化输入。
- `PreviewLoader`和页面请求编号共同保护异步成功及失败结果；新文件开始处理即清旧预览。改正则后旧预览标为过期，不能导入。
- 分章放入原生Web Worker，10秒仍未结束则终止并提示调整正则/文件；用户可切页，组件卸载会终止预览。它是预览资源保护，不是对所有文件处理速度的SLA。
- 预览与已保存章节展示全部条目，滚动查看，不截掉第201章及以后。取01-PRD FR-02“全部解析章节”口径，替代06旧“最多200行”条款。
- `src/lib/storage/importService.ts` 写T02 preparing日志，再将chapters/chapterTexts/P1初始进度同书事务提交；日志置ready后，全局事务选择未占用书名、添加books并删日志。每次导入独立UUID，同名加全角编号后缀。
- 日志带owner与5分钟租约，活动时每30秒续租；跨标签BroadcastChannel用于存活探测。只在过期且旧owner不响应时通过CAS接管；无广播能力时仍必须等待租约过期。
- ready恢复核对每章原文、归属、次序、字符数与P1总数后发布；preparing/cleanup_pending仅清理对应未发布书库。已经可用的书籍绝不因异常日志被删除。删除阻塞时保留日志，不假报清理完成。
- `ImportRecovery`在应用启动检查日志，并提供可见的恢复重试。遇到其他活跃导入，保留其日志和数据。
- 先只开放“仅导入”。P1真实提取仍在阶段7交付，不调用模型或伪造资产。

## 替代方案与后果

先写书架再填书库会暴露半本书；一次大内存状态无法持久恢复，因此采用既定生命周期日志。把所有库合并会违背已确定分库模型，不在本阶段改架构。同步主线程执行正则较简单，但无法在异常正则占用CPU时及时结束，故使用原生Worker，无新增依赖。

全量章节列表可查看全部内容。导入失败清理受浏览器存储权限与其他连接影响，失败保留日志供恢复。备份恢复与整书删除共用生命周期日志，分别处理完整书库发布与删除清理。

## 验证

- 文本测试：序文、空白前缀、编码、换行、长章、无标题、零宽/非法正则、UTF-16、异步新旧文件。
- 仓储测试：完整写入后发布、同名并发、准备/发布失败、过期恢复、活跃owner保护、恢复竞争、删除阻塞和保留已有书。
- 浏览器测试：选择与拖放、编码重读、过期预览、原文弹窗、刷新、同名新书自动选中、201章、375px、故障清理与生产Worker。

执行结果统一登记在阶段2验收单，不能以这些测试替代后续P1/P2/P3验收。
