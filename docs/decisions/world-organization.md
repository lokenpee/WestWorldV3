# 世界资产整理的两个入口

## 背景

人物和地点需要按名称查找候选，也需要结合原文判断身份。用户可以自行确认候选，或调用模型核实。

## 选定方案

代码整理和AI整理提供独立入口，全书提取完成后可使用。

代码整理先自动合并完整主名相同的档案，再按名称归一化、包含和别名相似度展示异名候选。用户核对异名成员后可直接确认，或加入队列统一执行，预览按需打开。自动同名组沿用已指定保留条目；其余默认保留编号最早的条目。异名组由用户选择主名，预览可调整保留编号。代码融合资料、来源与关联，并保存规则来源及整理报告。

用户也可逐组加入待合并队列，再一键顺序合并，操作与恢复按[机械合并队列决策](mechanical-merge-queue.md)执行。

AI整理直接使用Pi智能体查询精简资料，按需读取详情及原文，提交有证据的合并，并按[人物称呼规则](character-names.md)核实或纠正别名。多人合称、类型错误和提取错误列出依据、涉及编号及建议动作，交由用户复核。用户可以直接运行AI整理，也可以先完成代码整理。

自动同名融合保存自动来源，沿用已有人工主名与保留目标。人工确认合并保存人工决定。AI异名核实继续处理自动融合结果；真正的人工保护保持有效。旧自动标记按同名队列、提交记录、来源映射和当前资料版本核对，能追溯的自动标记恢复自动来源，来源不清的保护保留。

同字段存在多条不同表述，或单个事实条目包含多句时进入语义整编，短句同样核对；单条简短且无冲突的资料保持原样。整编读取完整事实底稿和已有展示稿，把相同、近义或包含关系的信息归为简洁表述，独有信息、时间变化和真实分歧继续保留。事实编号与来源保存在底稿中，多条事实可以对应同一句展示文字。

实际有变化的整编稿先保存，再独立调用一次AI复核，检查遗漏、重复、矛盾、无依据新增和称呼错误。结构校验与复核均通过后更新展示资料。无变化的稿件记录结果并更新完成标记，整编条数按实际更新计算。

复核与生成共用每项3分钟处理目标，复核最多一次实际请求。到达目标后等待在途响应正常返回，再保存结果或待办；单次网络请求采用60秒超时。复核未通过或调用失败时保留原资料并继续其他资产，报告显示具体问题和前后对照。继续时复用已保存的待复核稿；依据已变化则重新生成，当前资料已无需整编时将旧稿标为过期。复核未通过的稿件按反馈重新整编。整编、复核用量分别累加到同一报告，事实底稿与原文持续保留。

整编输入按当前模型上下文容量核对，计算提示词、完整事实、工具结构及消息开销，并预留输出空间。输出预留根据已有展示稿与完整编号列表估算，受模型输出能力约束。输入与预留之和超过模型上下文时，报告估算量和容量并保留原资料。配置百万上下文时使用对应容量。

完成指纹包含整编策略、提示词、称呼、完整事实和冲突记录。规则变化后旧完成标记重新接受整编；相同规则和依据跳过重复整编，身份合并结果继续保留。

身份核实存在失败或未完成项时，已核实成功的资产继续整编。整编保留身份核实结果，后续继续只处理剩余项。

每次启动时固定当前待办顺序，逐项向前处理，已被合并的成员跳过。目录查询用于寻找候选；完成状态只依赖当前资产、实际打开的详情和原文。提交时仍核对完整读取结果，保证写入依据有效。

身份合并与覆盖进度在同一事务中保存：保留目标记为完成，被合并成员退出待办，其他已完成项对这些成员的引用转到保留目标。当前失败列表清除已成功处理的资产，历史批次保留原始反馈并显示后续是否已处理。自身内容或实际依据发生其他变化的资产进入待复核。

AI身份核实一次安排最多3个待办，逐个执行，每个资产独立计时。每项以3分钟、8次模型请求为收尾目标，网络重发计入次数，单轮可调用多个工具。第6轮或剩余60秒时提醒模型停止扩展调查，提交证据充分的结果与未完成项。目标时间结束后等在途响应和工具执行完，再保存待办并停止该项的新请求；单次网络请求采用60秒超时。已提交成果保留，未完成项在本轮让位给后续资产，用户继续时再处理。

原文按指定资产来源或离散章节读取，返回带章节编号和章内位置的片段，使用游标续读。合并依据须落在实际返回的片段中。不同章节的资料仍可属于同一实体。合并后的旧编号查询映射到当前资产。

覆盖进度保存资产业务内容与实际读取依赖，频次等派生统计变化保留身份核实进度。出场统计在收尾时逐章计算，计算过程让出执行时间，最后核对版本并短事务写入。单项提交校验失败记录为失败，继续其他资产；本轮结束后，用户点击继续只重试失败或未完成项。报告保留资产编号、失败原因、实际请求和提交确认。密钥、存储或执行权等全局故障停止当前运行。

两条路径复用当前资产表、融合规则、版本检查和来源映射。AI运行期间持有本书世界资产执行权，取消等待在途请求停止后释放；已提交成果与报告保留。

## 替代方案

把代码步骤与AI步骤固定串联，会让只需要本地整理的用户进入模型调用。按别名、包含或相似称呼自动融合会混淆异名候选，因此这部分采用人工确认；完整主名相同按自动规则处理。单项长期循环会拖住后续资产，直接到点取消又可能丢失当前响应，因此采用提前收尾和持久待办。

## 后果

两类报告分别记录时间、前后数量、合并组、来源、冲突与用量。AI报告还能回查合并与别名证据、资料前后对照、独立复核结论及待复核稿件。没有变更时仍保留报告。
