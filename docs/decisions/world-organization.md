# 世界资产整理的两个入口

## 背景

人物和地点需要按名称查找候选，也需要结合原文判断身份。用户可以自行确认候选，或调用模型核实。

## 选定方案

代码整理和AI整理提供独立入口，全书提取完成后可使用。

代码整理按既有名称归一化、包含与别名相似度规则生成候选。用户核对实际成员后可直接确认合并，预览按需打开。同名成员默认保留编号最早的条目；名称不同时在候选栏选择主名，预览还能调整保留条目与主名。代码融合资料、来源与关联，保存整理报告。扫描、预览和确认均使用本地数据。

AI整理直接使用Pi智能体查询精简资料，按需读取详情及原文，提交有证据的合并。冗长、重复或冲突资料按事实底稿整编，校验覆盖后替换展示文字。用户可以直接运行AI整理，也可以先完成代码整理。

身份核实存在失败或未完成项时，已核实成功的资产继续整编。整编保留身份核实结果，后续继续只处理剩余项。

每次启动时固定当前待办顺序，逐项向前处理，已被合并的成员跳过。目录查询用于寻找候选；完成状态只依赖当前资产、实际打开的详情和原文。提交时仍核对完整读取结果，保证写入依据有效。

身份合并与覆盖进度在同一事务中保存：保留目标记为完成，被合并成员退出待办，其他已完成项对这些成员的引用转到保留目标。当前失败列表清除已成功处理的资产，历史批次保留原始反馈并显示后续是否已处理。自身内容或实际依据发生其他变化的资产进入待复核。

AI身份核实一次安排最多3个待办，逐个执行，每个资产独立计时。每项以3分钟、8次模型请求为收尾目标，网络重发计入次数，单轮可调用多个工具。第6轮或剩余60秒时提醒模型停止扩展调查，提交证据充分的结果与未完成项。目标时间结束后等在途响应和工具执行完，再保存待办并停止该项的新请求；单次网络请求采用60秒超时。已提交成果保留，未完成项在本轮让位给后续资产，用户继续时再处理。

原文按指定资产来源或离散章节读取，返回带章节编号和章内位置的片段，使用游标续读。合并依据须落在实际返回的片段中。不同章节的资料仍可属于同一实体。合并后的旧编号查询映射到当前资产。

覆盖进度保存资产业务内容与实际读取依赖，频次等派生统计变化保留身份核实进度。出场统计在收尾时逐章计算，计算过程让出执行时间，最后核对版本并短事务写入。单项提交校验失败记录为失败，继续其他资产；本轮结束后，用户点击继续只重试失败或未完成项。报告保留资产编号、失败原因、实际请求和提交确认。密钥、存储或执行权等全局故障停止当前运行。

两条路径复用当前资产表、融合规则、版本检查和来源映射。AI运行期间持有本书世界资产执行权，取消等待在途请求停止后释放；已提交成果与报告保留。

## 替代方案

把代码步骤与AI步骤固定串联，会让只需要本地整理的用户进入模型调用。名称候选直接自动合并，会把同名异人或地点整体与内部区域作为同一对象处理。因此采用独立入口和明确确认。单项长期循环会拖住后续资产，直接到点取消又可能丢失当前响应，因此采用提前收尾和持久待办。

## 后果

两类报告分别记录时间、前后数量、合并组、来源、冲突与用量。AI报告还能回查命令中的原文证据，整编底稿保存在原资料中。没有变更时仍保留报告。
