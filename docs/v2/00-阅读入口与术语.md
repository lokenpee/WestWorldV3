## 统一术语

| 术语 | 英文 / 标识 | 定义与边界 |
|---|---|---|
| 书籍 | Book | 一次导入形成的独立资产工作空间；同一小说重复导入也是不同书 |
| 原章节 | root chapter | 章节标识第一个点前的部分；长章切块在窗口和频次中合计为一个原章 |
| 章节 / 切块 | Chapter | 持久化处理单元；`1` 为普通章，`1.1` 为切块；标识不等于原标题数字 |
| 原文 | ChapterText | 完整保留规范化输入的分章文本，含首标题前序文 |
| 编译 | Compilation | 从章节到资产与事件线的模型/代码处理流程，不是打包前端 |
| 预览列表 |  | 正则拆分的章节会在提取小说的模块下方列表中预览展示，这个列表不仅能看到章节名字和字数还能看到章节资产提取的情况，提取失败时还能点击旁边的按钮手动调用AI重新提取 |
| P1 | extraction | 全书按章依次提取世界资产与叙事资产；成功即落表、刷新UI；全书完成前不启P2/P3 |
| P2 | world asset merge | 世界资产整理：代码候选经用户选择确认后合并，预览可选；或独立启动AI核实、合并与按需整编；各自保存报告 |
| P3 | narrative linking / global review | 同书持续Agent会话：100章窗口、重叠20章高置信串联→全书孤点/伏笔/缺环复核 |
| 世界资产 | world assets | 本基线指人物、地点和人物关系资料；无独立世界规则实体表 |
| 叙事资产 | narrative assets | 事件节点和事件线；不等于可游玩剧本引擎 |
| 当前资产 | current assets | 数据库里立即可用的业务记录，提取、人工CRUD和P2/P3直接操作同一份数据 |
| 人物 / 地点实体 | characters / locations | P1成功即写入的权威实体表，跨章同名可暂时多条；后续直接编辑和合并 |
| 单书资产库 | book database | 按bookId隔离；含当前资产、原文、进度和会话；无草稿/发布双层 |
| 事件节点 | Node | 某章中的一个事件，含概述、详细经过、称呼、引文及顺序 |
| 事件线 | EventLine | 节点的有序集合及起因/经过/结果；多线可共享节点 |
| 散落节点 | orphan | 没有事件线成员归属的节点，仍须画出 |
| 章节轴 | chapter timeline | 原文出现次序；不表示故事世界的绝对时间或因果 |
| 主名 / 别名 | name / aliases | 当前保留名称与其他称呼；出场统计只计最终主名 |
| 层级 | roleWeight | 主要人物/重要配角/NPC/路人；默认由频次分位计算，人工设置优先 |
| 合并事实底稿 | mergeFacts | 可追溯字段事实列表，用于按需整编与检查覆盖 |
| 故事编辑 | story_editor | P3事件组织职责；不是游玩中的旁白角色 |
| 资产整理 | asset_editor | 人物地点整理职责，不读取故事编辑记忆 |
| 故事会话 | StorySession | 持久故事编辑消息链；不是玩家游玩存档 |
| 工作记忆 | editor memory | 摘要、判断、复核事项和依据，不是世界权威事实 |
| 检查点 | checkpoint | 批次范围与依据指纹，用于跳过仍有效的已完成检查；不是游戏回滚点 |
| 上下文压缩 | compaction | 旧消息转摘要供模型读取；原始持久消息仍保留 |
| 结构化返回 / 最终总结 | submit_result | direct仅收集结构化输出，由调用方提交；Agent仅总结已生效commitIds，不重复写业务 |
| 受控写工具 | commit_asset_changes / commit_story_changes | Pi Agent执行中调用共用命令服务，验证后直接写当前数据并返回持久确认 |
| 降级 | degraded | AI部分失败仍保留本地结果；不能标作完整检查通过 |
| 样本范围 | testScope | 2.1旧测试范围；不能解锁2.2正式阶段，不影响当前实体可用 |
| 直接模型调用 | direct | pi-ai执行API+Prompt和有界校验修正，无自主工具循环；结构化返回函数不等于Agent |
| Agent | agent | pi-agent-core管理执行循环/AgentState，底层请求仍pi-ai；应用持久化长期记忆/业务状态，工具可受控读写 |
| Schema | TypeBox / JSON Schema | 对象结构和类型约束；语义忠实度不由其自动保证 |
| 备份 | `.wwv2` | 带manifest、JSON数据和分章原文的ZIP包，不包含设置库凭据 |

## 使用方法

先按仓库指令判断需求级别，再读取相关能力及其技术和验收链接。中大型需求在 OpenSpec 中建立变更，任务引用对应需求与场景；小修改按简化路径处理。

- 工具命令：`npm run openspec -- list --specs` 查看能力，`npm run openspec -- list` 查看活动变更。
- 规格校验：`npm run openspec -- validate --all --strict`。
- 治理检查：`npm run governance:check`。
- 项目依赖以根目录 package-lock.json 为准；资源中的旧运行配置用于历史取证。
