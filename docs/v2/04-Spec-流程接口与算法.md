# 流程接口与算法

## 1. 接口边界与返回约定

页面以书籍编号调用领域服务。服务读取当前书的数据和执行权，在事务外调用模型，再在提交事务内校验版本及实际输入。按入口查参数、回包与错误，请读[业务服务接口](项目技术说明.md#业务服务接口)和[本机存储协议](项目技术说明.md#本机存储协议)。界面触发条件见[操作契约](09-操作与自动触发契约.md)，模型工具按任务查[工具及回放契约](11-AI工具返回与回放契约.md)。

## ALG-01 解码、正则和分章

1. 用户选择一个 TXT 文件。自动模式先严格按 UTF-8 解码，解码失败再用 GBK；也可手选编码。程序去掉开头的 BOM，将换行规范为 LF，空文件或纯空白文本在预览前报错。
2. 分章规则接受正则正文或 `/正文/标志`，自动补齐 `g` 和 `m`。默认规则识别带汉字数字、阿拉伯数字或空格的章、回、卷、节、部、篇标题。空规则、无效正则或零长度匹配会返回具体错误。
3. 有第一个捕获组时用它作标题，否则使用整个匹配。标题前有非空正文时保存为章号 `0` 的序文；只有空白时将其并入首章。标题章按出现顺序从 1 编号。没有匹配标题时按最多 4,000 个 UTF-16 单位分段。
4. 单章超过 10,000 个 UTF-16 单位时切块，编号为 `章号.块号`。在上限末尾 10%（最多 1,000 单位）内优先找换行，再找带闭引号的句末；缺少自然边界时在安全位置切分。切块保留全部字符和代理对，`order` 从 0 排序，`charCount` 等于 JavaScript 字符串长度。
5. Web Worker 生成规范化全文及连续的 `start/end` 区间，预览每页显示 100 条。10 秒超时会终止预览并提示修改正则或文件。更换文件、应用正则或重读编码后重新从第一页展示。保存时按区间或章节自带的文本读取全部章节。[分章与解码](../../src/features/import/text.ts) · [预览线程](../../src/features/import/parseInWorker.ts)

## ALG-02 P1逐章提交、即时刷新与恢复

P1 有两类子步骤。世界任务返回人物、地点及关系事实，叙事任务返回带原文章节位置的事件节点。“一起提取”同时启动两类任务，各自按章顺序运行。也可只启动一类、暂停一类或选择单章。请求前保存任务和正文快照。提交时再次核对本书执行权、该章原文及 `章号:子步骤` 凭据。已完成的子步骤可直接跳过；结果为空同样写成功凭据。[提取服务](../../src/features/extraction/service.ts) · [任务存储](../../src/features/extraction/taskStore.ts)

P1 新增人物后，用新增的主名、有效别名和编号筛选需要重新绑定的关系与节点。对有变化的关联更新修订号。节点保留涉及人物的原称呼及编号绑定。显式重提前预览本次影响的成员、关系、事件及故事线；清理后发生中断，可按保存范围继续。叙事重提可复用本章已删除的节点编号并递增修订。[受影响的关联](../../src/features/extraction/affectedBindings.ts) · [重提清理](../../src/features/extraction/reextract.ts)

## ALG-03 阶段启动与独立恢复

| 入口 | 准入与后续处理 |
|---|---|
| P2 三步整理 | 启动前检查全书提取和本书执行权。识别重复人物、优化人物资料、整理人物关系分别启动和继续，每步记录自己的运行；再次启动已运行过的步骤时，可选择从头检查或复用有效结果。单人物资料／关系入口按选中人物处理。[世界整理服务](../../src/features/world/service.ts) · [步骤面板](../../src/features/world/WorldPanel.tsx) |
| P3 主流程 | 首次运行要求全书提取凭据齐全且执行权可用。先处理完整同名人物；如已有不能接续的叙事成果，要求在重建副本启动。按原文顺序逐个串联节点，随后进入事件复核。故事线自动调度关闭。[启动检查](../../src/features/story/narrativeService.ts) · [调度器](../../src/features/story/narrativePlan.ts) |
| 独立事件复核 | 已有事件时可在当前书直接开始；检查本书执行权，跳过逐节点串联及初始向量准备。暂停后继续保留当前任务与队列。取消会结束本书运行中或暂停的 P3 主流程和独立复核；再次开始独立复核，以现存事件重建队列和会话。[独立复核与取消](../../src/features/story/narrativeService.ts) |

同一本书一次只运行 P1、P2、P3 中的一个阶段，P1 内部的两类任务可并行。不同书籍独立取得执行权。[按书检查执行权](02-架构与技术规格.md#ar-07-并发锁与事件)

## ALG-04 名称归一化、聚组与融合

“代码整理”先按同类型的完整主名去首尾空格分组，符合条件的同名组执行机械合并。剩余候选使用标准化主名、别名及其出现频率筛选。名称标准化依次合并空白、去已登记的卷章／版本后缀、转小写并删除规则中的标点；结果为空时退回原名。主名包含只用于人物，整组别名相似度、主名与别名相同、稀有共享称呼等规则保留各自的候选理由。人物通用称谓通过称呼规则过滤。异名候选由用户核对成员和保留主名后确认或入队。[候选算法](../../src/features/world/candidates.ts) · [正则与阈值](resources/algorithm-parameters.json) · [机械合并](../../src/features/world/mechanical.ts)

执行合并时检查成员、保留目标及版本，合并描述、别名与来源章，保存字段事实底稿和冲突记录。人物合并还会更新关系事实、人物对和节点人物绑定。删除并入成员、改写来源映射和记录结果在同一业务事务完成。[融合事务](../../src/features/assets/mergeCore.ts) · [关系维护](../../src/features/assets/relations.ts)

P2 的 AI 第一步按页识别疑似重复人物，记录待核对组供用户处理；另两步按人物整理资料、核实关系，允许从人物详情直接启动。已保存的修改、依据、费用和工作进度可分别回看。[三步入口](../../src/features/world/WorldPanel.tsx) · [组织服务](../../src/features/world/organization.ts)

## ALG-05 主名出场与层级

1. scope=(processedIds或所有正文标识)去点后按原章去重。称呼取主名及已核实的稳定别名，trim后转小写；通用称谓过滤遵循人物称呼规则，不用sourceChapters代替文本计数。
2. 称呼按长度降序、locale顺序排序，转义后以`|`组成gu正则。正文小写，matchAll非重叠匹配、长名优先；命中多人共有称呼时跳过，不再把歧义长称呼拆给短名。
3. 唯一命中人物时mentions+1、原章加入Set；chapters为覆盖Set大小，scopeChapters为scope大小；同人物主名与已核实别名汇总。
4. higher为章节数更大或同章节提及更大者数，same为两项都相同者数；percentile=`(higher+(same-1)/2)/max(1,实体数-1)`。
5. 多个人全部同频→NPC；否则<0.1主要、<0.3重要、<0.8 NPC、其余路人。只有一个人物时不是flat，按公式可为主要人物。
6. roleWeightSource为manual或agent时保留层级，仍更新frequency；其他来源写frequency与对应层级，来源设为frequency。地点记录频次但不加人物层级。

P1收尾在内存保存按章节统计的词项次数，以本机存储正文version及有效词集合判断是否复用；不缓存全文或人物最终层级。正文改变只重算对应章，词集合改变重新扫全书，归属变化按当前人物重新汇总；待提交version=0不复用。版本和正文在同一读视图取得，正文没有存储版本时完整扫描。计算累计占用时间达到小段预算时让出主线程，缓存命中不逐章固定等待；缓存丢失只触发重新计算。

“人物自动分层”对全书当前人物执行本算法，不受搜索及层级筛选影响。独立入口不依赖P2运行记录、Agent会话或模型配置；取得本书world租约后计算，分章计算时让出主线程，保存前核执行权及全部人物/地点的集合和revision，统一事务写入。分层完成后释放本次租约。

计算与复用见[频次算法](../../src/features/assets/derive.ts)、[分章缓存](../../src/features/assets/frequency.ts)及[独立分层事务](../../src/features/world/statistics.ts)。

## ALG-06 逐节点串联与两步事件复核

1. 调度器按章序、节点顺序读取首个待处理节点。输入包含当前节点、随后最多五个节点的概览和召回的候选事件。检索同时考虑线索、人物、地点及文本相似度，融合并重排后最多装入十件；远程向量或重排失败时记录降级并使用本地排序。[候选分数与上限](项目技术说明.md#候选事件如何装入当前节点) · [候选与预取](../../src/features/story/eventCandidates.ts)
2. 串联时可查前文节点的经过、节点详情和事件卡。已展示的后文帮助理解剧情，写入时只允许当前及更早的节点成为成员。`edit_events` 校验成员、理由及任务权限后写入事件。需要新建、沿用或保留节点时，按本任务的确认条件结束。任务详情从已成功的回执读取本次成果。[串联读写边界](../../src/features/story/eventWorkflow.ts) · [任务成果](../../src/features/story/eventTaskOutcome.ts)
3. 节点串联完成后，宏观复核 `review_boundaries` 优先比较共享成员的疑似组，再处理具体核心线索候选。可据证编辑、新建、撤销事件，确认记录对应事件对及版本。微观复核 `review_sequence` 按首个成员的位置逐件核对，只可更新当前事件。需跨事件处理时带证据转回宏观；剩余待核实项用尽其他任务后暂停，用户可继续。[组队](../../src/features/story/eventReviewGroups.ts) · [两步调度及确认](../../src/features/story/twoStepReview.ts) · [复核材料](项目技术说明.md#两步事件复核)

## ALG-07 人工更新、合并与删除

人工资产编辑按类型、书籍、预期修订及资产域执行权校验。成功更新修订并同步必要的关联；冲突时界面需重新读取当前值。人物改名、合并、删除会联动节点及关系。大纲中的事件通过事件工具修改，事件变更会同步已有故事线的成员与反向归属。[资产服务](../../src/features/assets/service.ts) · [事件编辑](../../src/features/story/eventWorkflow.ts) · [大纲同步](../../src/features/story/outline.ts)

## ALG-08 当前实体及人物引用读取

事件网络按章节列和节点顺序布点，按线及事件成员绘制路径，共享节点只有一个图上位置；未归线的事件也可形成路径。人物关系图以人物为节点、有效人物对为边，使用 Worker 计算力导向布局并处理节点碰撞。[事件布局](../../src/features/network/layout.ts) · [人物关系图布局](../../src/features/character-network/layout.ts) · [布局线程](../../src/features/character-network/layout.worker.ts)

## ALG-10 导出、恢复和删除

导出先读取一致的单书数据快照，在副本内处理活动状态，校验表间引用、编码并压缩为格式 15 的 `.wwv2`。预检按格式 4–15 检查清单、路径、哈希、章号、记录归属及引用。恢复在新书 ID 下发布。删书先检查占用，跨书架／书库操作使用生命周期日志处理中断。P3 重建副本走专用接口，保留原书。[备份服务](../../src/features/backup/service.ts) · [编解码](../../src/features/backup/codec.ts) · [导入与删除恢复](../../src/lib/storage/importService.ts)

## ALG-11 进度与事件投影

P1 显示章节及子步骤的状态和用量；P2 按运行、步骤和人物查看已处理项、请求及报告；P3 显示串联节点或复核任务、请求链和真实写入结果。切换书、运行或任务时按对应 ID 重新读取。浏览器刷新会丢失控制器，持久化的任务、快照、回执与资产仍可读取；继续时由对应服务检查租约及有效进度。[P1 进度](../../src/features/extraction/ExtractionPanel.tsx) · [P2 详情](../../src/features/agents/P2OrganizationPanel.tsx) · [P3 详情](../../src/features/story/NarrativeExecutionPanel.tsx)

## ALG-12 共用Pi模型入口与写命令生命周期

P1 直接调用提取模型，校验结构化输出后由调用方写入；P2 整理和 P3 事件任务由 Agent 使用任务允许的工具。模型参数及回包约束取决于任务，模型端不指定书库或执行权。工具声明、提示词和返回字段见[项目技术说明](项目技术说明.md)，回放见[工具契约](11-AI工具返回与回放契约.md)。

### ALG-12.1 运行与子任务身份

运行按 `bookId/runId` 归属，子任务另有 `taskId`。P1 将任务和正文快照分表保存。P2 存储当前工作项和请求记录；P3 同时记录运行内任务摘要及单独的叙事任务记录，恢复时取回任务输入、观测版本和已有工具结果。[P1 输入快照](03-Spec-数据与存储.md#12-p1独立任务与正文快照) · [P3 请求恢复](../../src/features/story/narrativeService.ts)

### ALG-12.2 写入前意图与提交后确认

通用命令按运行内的 `operationKey` 和载荷指纹去重，提交前核对租约、读集及业务版本；已提交的相同命令返回原确认。P3 事件工作流在事务内以 `taskId:toolCallId` 查回执，核对运行与工具参数签名后重放。首次成功写入时同步业务、计划、任务状态和 `narrative_receipt`。编辑工具保存事件，`confirm` 保存判断和本任务进展。[通用事务](../../src/features/agents/commands.ts) · [P3 事务](../../src/features/story/narrativeTools.ts)

### ALG-12.3 每个崩溃位置的恢复

| 中断点 | 对应服务如何恢复 |
|---|---|
| P1 任务已注册、资产未提交 | 继续时查任务及成功凭据，仍需处理的子步骤基于本书原文校验。 |
| 通用命令仅有待提交意图 | 核对意图状态、执行权和当前依赖。已有成功确认时复用原确认。 |
| P3 写入成功、工具反馈丢失 | 按活动任务、原始请求和工具回执重建反馈。当前对象版本或任务类型已经变化时按调度规则重查。 |
| 另一标签仍持有效执行权 | 新执行者等待或提示占用。取消、暂停、超时之后仍须由事务核对当前所有者。 |
| 恢复整书副本 | 还原消息和运行记录，重写书籍归属并清理原运行执行权；由用户明确继续处理。 |

### ALG-12.4 覆盖项身份、派发与排序

P1 的成功单位是章和子步骤。P2 三步分别跟踪识别页、资料人物、关系人物和相关人物对。P3 串联逐节点确认，宏观复核跟踪比较过的事件对版本，微观复核跟踪逐件事件版本。[P2 组织状态](../../src/features/world/organization.ts) · [P3 调度](../../src/features/story/twoStepReview.ts)

### ALG-12.5 版本、事实指纹与查询依赖

人工改动使用 `expectedRevision` 对照当前记录。P2 复用按工作项检查内容依据，写入另核对读集和版本。P3 保存活动任务看过的对象版本和工具依据，事件编辑前核对当前版本及本任务可操作范围；检索候选或上下文截取仅是输入的一部分。[P2 复核](../../src/features/agents/organizationReview.ts) · [P3 观察与回执](../../src/features/story/narrativeTools.ts)

### ALG-12.6 总结、删除/合并和全阶段完成

P2 以各步骤的工作项与任务工具收束本次执行。P3 的完成状态由程序核验 `confirm` 及待办，宏观一次完成该组比较，微观一次完成该版本事件。撤销事件后原版本退出队列，新增和有变化的事件按新版本参与后续核对。已提交的业务结果保留；取消、暂停与继续见 ALG-03。[两步复核实现](../../src/features/story/twoStepReview.ts) · [事件工具](../../src/features/story/eventWorkflow.ts)
