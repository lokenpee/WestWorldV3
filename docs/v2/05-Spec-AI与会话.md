# AI、工具与会话

工作台按书运行三类模型任务。P1 从章节原文提取人物、地点和叙事节点，P2 核对人物身份、资料与关系，P3 逐节点串联并复核事件。[模型任务与权限](项目技术说明.md#模型任务与权限)

## AI-00 Pi 模型与执行模式

聊天模型统一经 `@earendil-works/pi-ai` 调用。需要模型自主取资料、保存结果或继续下一轮时，应用使用 `@earendil-works/pi-agent-core` 的 Agent。两包在本仓库锁定为 1.0.2。模型服务加载已保存的配置并解析本次调用，应用负责保存业务数据、会话、用量和工具回执。[项目依赖](../../package.json) · [模型服务](../../src/features/models/service.ts) · [模型网关](../../src/features/models/gateway.ts)

| 执行方式 | 模型收到什么 | 结果何时生效 |
|---|---|---|
| 直接调用（direct） | 本次提示词、输入消息，以及任务所需的结构化输出声明。P1 使用提取模型，文本整编和通用会话摘要使用整理模型。 | 调用方校验结果后保存。P1 的世界和叙事子步骤各有自己的成功凭证。 |
| 智能体（Agent） | 整理模型、当前任务材料、允许使用的工具和本任务的对话记录。 | 读工具返回当前资料。写工具在执行时保存，完成工具只推进它所确认的工作项。 |

## AI-01 聊天模型与检索模型

提取和整理角色共用聊天服务配置及该服务的凭据，分别选择模型名。可选协议为 Chat Completions、Responses 和 Anthropic Messages。连接页可拉取模型目录，也可手填模型名。提取测试和整理测试分别发起实际的直接调用和 Agent 基础调用。另有独立的整理工具读写测试。[设置入口](../../src/features/models/ModelSettings.tsx) · [模型解析](../../src/features/models/registry.ts)

P3 的向量模型和重排模型各有服务地址、模型名和凭据。向量服务收 `POST /embeddings`，重排服务收 `POST /rerank`，按输入索引核对响应，单次请求超时 30 秒。检索失败时记录降级，使用本地候选顺序继续。设置页可按角色拉取目录并实测保存。[模型与检索服务](项目技术说明.md#模型与检索服务) · [检索适配器](../../src/features/models/eventRetrieval.ts)

## AI-02 任务提示词与输入材料

| 任务 | 系统规则与首包内容 |
|---|---|
| P1 世界资产、叙事资产 | 分别装入[世界提取](resources/v2.2/prompts/active/p1-world.md)和[叙事提取](resources/v2.2/prompts/active/p1-narrative.md)，首条用户消息为章节名称、空行、完整本章原文。程序在任务快照中另存章节编号和输入指纹。 |
| P2 三步人物整理 | 识别重复人物读目录及疑似组，优化资料读当前人物展示字段，关系整理读该人物的关系工作项。各步装入自己的正文，所选人物、阶段和范围由程序绑定。[任务提示词选择](../../src/features/world/organizationPrompt.ts) |
| P3 逐节点串联 | 装入[串联规则](resources/v2.2/prompts/active/p3-event-link.md)、当前节点、后文概览与候选事件。默认从关键词与向量候选中融合排序并重排，最多装入十件。事件卡带成员编号和名称。[候选检索](../../src/features/story/eventCandidates.ts) |
| P3 两步事件复核 | [宏观规则](resources/v2.2/prompts/active/p3-event-boundaries.md)配疑似组事件卡和组内成员时间表。[微观规则](resources/v2.2/prompts/active/p3-event-sequence.md)配当前事件、按原文顺序排列的成员和待核实或转回意见。按需用工具补读。 |

装载器按任务选择正文，原生工具声明独立传入。文本整编、摘要和工具探测的正文、参数来源与示例见[提示词装载](项目技术说明.md#提示词装载)及[调用清单](resources/v2.2/prompt-call-manifest.json)。

## AI-03 直接提交与修正

P1 要求一次回复恰好包含一个 `submit_result`，参数按当前子步骤的 Schema 校验。原文缺失、字段类型错误或业务校验失败会记录到该章对应子步骤。结构修正时保留原章节消息，追加各工具调用对应的反馈及实际错误。P1 最多两次修正。其他直接调用取各自的 `repairPrompt` 和修正预算。文本推荐字数只作写作提示。[提取与参数校验](../../src/features/extraction/contracts.ts) · [提取任务与保存](../../src/features/extraction/service.ts) · [字段规则](../../AGENTS.md#字段数据流与触发逻辑)

## AI-04 Pi Agent执行、读写工具与最终结果

| 当前工作项 | 写入与完成条件 |
|---|---|
| P2 识别重复人物 | 模型读取目录并用 `save_identity_groups` 保存疑似组，`navigate_identity_pages` 记录阅读进度。疑似组供人工核对与机械合并。 |
| P2 优化人物资料、整理人物关系 | `submit_profile_review` 和 `submit_relation_review` 分别提交资料与关系，`done` 区分中途保存和结束当前人物。关系批次可部分成功。详情分别显示已保存项与失败项。 |
| P3 事件整理 | `edit_events` 把本次变更写回事件。每项任务以 `confirm` 核对当前节点、疑似组或单件版本。普通文字回复会提示继续。若同一轮编辑失败，程序要求先修正，再接受确认。 |

运行由程序绑定书籍、职责、任务、执行权和可用工具。其他书籍的模型配置可以共用，各自的资料和运行记录按书隔离。运行入口与写入事务均检查执行权。暂停、取消和执行权丢失后的处理按对应流程记录。[P2 任务和工具表](项目技术说明.md#模型任务与权限) · [通用运行器](../../src/features/agents/runtime.ts) · [P3 运行器](../../src/features/story/narrativeService.ts)

## AI-05 错误分类、退避与用量

模型服务记录本次逻辑调用和每次实际请求，区分鉴权失败、限流、网络、服务端、上下文容量、校验、预算、取消等原因。可重试错误执行有界退避，`Retry-After` 的整数秒优先。等待可中断。用量按实际尝试累计输入、输出及缓存读写，缺少可用价格时界面显示费用未知。工具校验失败的回包单独记录。[分类、退避和计费](../../src/features/models/policy.ts) · [实际请求跟踪](../../src/features/models/gateway.ts)

首页 P3 不设固定业务轮数，每次聊天请求超时 120 秒。两步事件复核请求高推理强度，串联请求低推理强度，网关按模型能力传递。已写回的事件和工具回执在后续失败时保留。[P3 调用选项](../../src/features/story/narrativeService.ts)

## AI-06 查询工具与可见范围

P2 人物识别目录与首页 P3 使用固定工具表。其他支持发现的 P2 工作项可用 `get_tools` 查看允许但尚未激活的工具，`get_tools_detail` 取得参数并在下一轮启用。人物资料和人物关系按所选任务限范围读取。两步人物整理各自的原文读取次数随该人物及该步进度保存。[通用工具参数目录](项目技术说明.md#通用工具参数目录) · [按需发现与作用域](../../src/features/agents/tools.ts)

P3 串联可查节点、事件及前序节点，复核可按编号和条件查全书节点或事件。搜索组内关键词须全部命中，组间任一组命中即可。节点详情、搜索、编辑和确认各有不同的结果形状。名称、默认字段、读写范围和示例见[P3 事件工具](项目技术说明.md#p3-事件工具)及[工具返回与回放](11-AI工具返回与回放契约.md)。

## AI-07 事件复核的进度与依据

首页 P3 的恢复依据是运行计划、具体任务快照、工具回执和事件版本。宏观记录已比较的事件对及版本，微观记录已主审的事件版本、转回证据和待核实问题。改动使受影响的事件重新参加核查。有遗留问题可暂停后重试。[两步复核](../../src/features/story/twoStepReview.ts) · [运行计划](../../src/features/story/narrativePlan.ts)

## AI-08 持久消息、投影与压缩

- **首页 P3。** 程序按任务保存原始消息。每个新任务重建输入。同一任务恢复时按编号取回原消息与回执，并配对工具调用和结果。程序用简短记录替换超出保留范围的完整轮次。宏观组内成功读取节点或事件的轮次保留原生调用与返回，直到该组结束。[按任务装载消息](../../src/features/story/narrativeService.ts) · [请求中的对话记录](../../src/features/story/narrativeContext.ts)
- **通用会话。** 使用通用压缩的运行器按模型窗口和保留预算选择较早的完整对话，调用整理模型生成摘要，再组合摘要、近期消息及当前任务。用户可在会话详情查看原始消息。上下文恢复会配对调用和结果，缺记录时给出中断标记。[上下文估算和配对](../../src/features/agents/context.ts) · [会话压缩](../../src/features/agents/compaction.ts)

首页 P3 默认保留最近两轮，宏观组内读证据的轮次额外保留。通用压缩按 Token 估算，预留量取窗口四分之一并限制在 128–32768 之间，近期消息预算取剩余容量的三分之一并限制在 64–150000 之间。摘要、近期消息和当前任务一起进入后续请求。[大纲任务默认值](../../src/features/story/narrativePlan.ts) · [通用窗口计算](../../src/features/agents/context.ts)

## AI-09 请求与任务成果

在「整理详情」中按书籍、运行和任务选择具体请求，可查看系统规则、模型收到的材料、原生工具声明、回包和已保存的修改。固定请求样例列出相应任务的输入形状。[P3 请求详情](../../src/features/story/NarrativeRequest.tsx) · [请求样例](resources/v2.2/request-examples/index.json)

## AI-10 P3 事件整理与完成依据

1. **逐节点串联** `link_node` 按原文次序处理当前节点。已归入事件或提供独立保留原因后，模型才能确认并推进。
2. **宏观分组** `review_boundaries` 比较疑似有交叠或相关线索的事件，可新建、修改或撤销。程序按最新事件及其版本选择下一组。
3. **逐件主审** `review_sequence` 核对当前事件的经过和成员，只能更新当前件。可完成、登记待核实事项，或带事件编号、证据节点和原因转回宏观核查。

首页的独立「事件复核」直接从现有事件开始后两步。主流程完成事件阶段后停在故事线整理之前。[事件工具与确认](../../src/features/story/eventWorkflow.ts) · [两步复核规则](项目技术说明.md#两步事件复核)

## AI-11 业务写入与回执

P3 以任务编号和工具调用编号定位 `narrative_receipt`。同一次 `edit_events` 的变更和回执一同保存，重试先核对原参数。给模型的短回包与供界面还原变更的完整记录分别生成。P2 通用命令以运行和操作键识别原提交，合并和关系工具按各自回执说明已生效的范围。[P3 工具执行](../../src/features/story/narrativeTools.ts) · [P3 回包投影](../../src/features/story/eventToolReply.ts) · [P2 提交账本](../../src/features/agents/ledger.ts)

## AI-14 请求组装与恢复

P1 的每次请求可由系统规则、当前章和 `submit_result` 声明核对。P2 按当前步骤预装目录、人物或关系资料，并把允许的工具作为原生声明交给模型。P3 保存系统规则、当前任务材料及工具快照，恢复时装载当前任务的对话。缺少反馈的写调用优先按其原回执恢复。工具错误会指明可修正的操作和字段。[提示词清单](resources/v2.2/prompt-call-manifest.json) · [样例索引](resources/v2.2/request-examples/index.json) · [P3 任务材料](../../src/features/story/narrativeInput.ts)

## AI-15 模型连接与工具读写测试

设置页的「测试连接」用短文本检验所选角色能否生成回复。「整理工具测试」顺序运行两个独立的内存样本。每套最多三次请求、30 秒。世界资产套输出预算为 1024 Token，叙事套为 2048 Token。

| 套件 | 通过时可核对的结果 |
|---|---|
| 世界资产 | 读取样本人物及证据，合并两条同名人物。校验目标版本、原编号去向与唯一提交记录，再核对最终总结中的提交编号。 |
| 叙事资产 | 使用正式串联任务的系统规则和工具，从 `get_nodes` 读取样本，经 `edit_events` 保存归属，再由 `confirm` 确认。检查实际生成的事件与编号。 |

每套显示读写次数、实际请求次数及提交确认。失败提示指出停在哪一步。[世界资产探测](../../src/features/agents/probe.ts) · [事件串联探测](../../src/features/story/eventProbe.ts)

## AI-16 按书运行与会话生命周期

| 场景 | 当前行为 |
|---|---|
| 切书或离开工作台 | 任务仍由启动时的书籍和运行编号绑定。回到书籍时从其运行记录读回进度。 |
| 暂停或页面中断 | 有可继续计划时恢复原运行和会话，检查执行权、当前工作项与已存回执后再调用模型。 |
| 取消 P3 | 结束该书未结束的主流程及独立复核。已写回的资产和运行记录继续可查。再次开始独立复核时，按现有事件建立新运行、新会话和新队列。 |
| 从头重建大纲 | 对已有整理成果的书，主流程在新书副本启动。暂停的当前主流程可在原书继续。独立复核直接更新当前书。 |
