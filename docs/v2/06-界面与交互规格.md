## 1. 视觉基准与公共组件

基准视口为1440×1000，字体使用锁定Tailwind默认sans/系统回退，技术编号及日志用默认mono。桌面保持既定布局；小于768px书架/列表/详情上下排列，按钮换行，长内容区域内滚动，全部操作可达。

编辑区、详情区与弹窗按当前窗口可用高度布局，标题和保存、取消、删除等主要操作在同一窗口内保持可见，长内容在区域内部滚动。优先调整明显占高的模块：短文本和空字段使用紧凑高度，长文本提供展开查看。沿用既有布局与字段顺序，按内容需要调整局部尺寸。界面交付检查1440×900、1366×768和375×812视口下的标题、操作栏与长内容，展开和收起保留未保存输入。

## UI-01 外壳与状态生命周期

顶层标签依次“资产”“游玩”“设置”，默认资产。点击仅切组件，不改URL、不创建路由。允许任务进行时切顶层标签，异步核心任务依旧运行；切离并不等于取消。

会话内容从本书持久记录恢复，组件卸载只释放展示状态。切书后显示目标书历史，原书后到的回复、工具结果和费用仍归原书；窗口选择与运行身份分别管理，具体规则见05 AI-16。

ui-store默认：activeView=assets、bookId=null、assetTab=characters、selectedAssetId=null；setBookId/setAssetTab清selectedAssetId，但工作台实际右侧选择由局部selected管理。assetTab跨顶层切换仍留在全局内存，工作台局部selected/trying/filter等在卸载或key变化时重置。

assets页加载书架后第一次自动选择最新书；首次选择逻辑只执行一次。showImport只改变右侧；从设置恢复备份仅更新bookId和提示，不自动切回资产。

## UI-02 书架、导出与整书删除

书架标题“资产书架 n”，上方“＋ 导入小说”。书籍卡：书名、状态及n章/块、四类资产数量，下方进入/导出/删除。选中且非导入状态卡边neutral-700/白底阴影；未选neutral-200/白60%。加载摘要时章数显示“…”。空态“还没有资产。导入小说后会出现在这里。”

底部显示“导出目录：尚未选择”或句柄name；“建议选择项目下 exports 文件夹”；“选择导出目录”；删除影响说明。路径title保留`E:\WestWorldV2\exports`，不把它当作授权目标。

任务状态按bookId+stage+runId隔离。书卡可在任务中切换，切书不取消任务；仅正在确认的导入/删除/文件写入禁用其本地弹窗按钮，不用全局running锁住整个书架。

| 操作 | 禁用 / 触发 / 结果 |
|---|---|
| 书卡/进入/导入小说 | 目标书删除中或本地导入提交中禁用；其他阶段任务运行仍可切书 |
| 导出 | 可导出处理中一致快照；活动P1/P2/P3不必结束；提示“处理中快照” |
| 删除 | 本书任一阶段/发布持有活租约时禁用，显示具体任务；别书任务不影响 |
| 选择目录/保存到目录 | 浏览器不支持或本地文件操作busy时禁用；成功保存句柄/文件后提示 |
| 下载备份 | 本地导出busy禁用，成功提示“已请求下载：文件名” |
| 删除→先导出 | 关闭删除弹窗打开同书导出，完成不自动删除 |
| 删除→确认 | 服务再次核三个资源，成功只删目标书；竞争失败保留弹窗说明 |
| 弹窗取消 | 文件写入/删除实际提交中禁用，否则可取消 |

遮罩点击和Escape没有专门关闭处理，不添加这两种关闭方式。弹窗role=dialog/aria-modal，标题分别“导出 {书名}”“删除 {书名}？”。失败保留弹窗并显示role alert；侧栏普通消息role status。完整提示文案以文案资源为准。

## UI-03 TXT导入页

右侧滚动区域内max-w-3xl=768px居中、p8。标题“导入小说”，说明只支持.txt和GBK探测。按顺序显示：正则卡、拖放框、错误提示、预览卡。

| 控件 | 类型 / 初值 | 行为与条件 |
|---|---|---|
| 章节分隔正则 | text、mono-xs、id chapter-regex；默认regex字符串 | busy禁用；修改清error但不更新preview |
| 应用正则并重新预览 | button | busy禁用；使用当前已解码文本重切 |
| 恢复默认 | button | busy禁用；还原输入并重切；不清已选文件 |
| 选择文件/拖放区 | file accept .txt,text/plain /首文件 | 选择与拖放统一按busy禁用，并校验单个TXT及非空内容 |
| 按UTF-8/GBK重读 | button | 解码原始bytes并按当前正则重切；不自动改磁盘文件 |
| 仅导入 / 导入并开始P1提取 | button | busy或正则与预览不一致或0章时禁用；仅导入busy文案“正在导入…” |
| 换一个文件 | button | 将preview=null；不清正则；未额外busy禁用 |

拖放框border2/dashed、p8、居中文字。预览显示文件名、编码大写、总章数；表格列#左/章节名左/字数右，表头sticky，列表限高滚动。阶段2统一采用01 FR-02的全部解析章节口径，不截断第201章及以后，每章可打开原文；当前实现限高320px。错正则在红底卡报错，过期旧预览在正则卡提示，不得导入；处理新文件或重新预览失败时清除可导入结果。

## UI-04 工作台、阶段入口与进度

布局：阶段操作区→内容标签与工具栏→当前列表/网络/记忆与详情栏。P1显示“P1 逐章提取全书”，P2显示“P2 世界资产整理”，并列提供“代码整理”和“AI整理”；P3显示“P3 串联与复核事件线”。

| 控件 | 前置/禁用 | 结果 |
|---|---|---|
| 开始/继续P1 | 本书无活动P1/P2/P3/删除；有章节 | 依次提取全书；完成后只解锁两个下游入口 |
| 代码整理 | 全书P1成功凭证齐备，无活动世界整理或提取任务 | 自动列出候选，用户勾选实际成员后直接确认，可按需预览；本地合并并保存报告 |
| AI整理 | 全书P1成功凭证齐备，无活动世界整理或提取任务；已保存整理模型 | Pi核对资料与原文→有证据的合并→按需整编→报告；可独立启动 |
| 开始/重新串联P3 | 全书P1完成且current，无活动P3/删除 | P2运行时仍可点击；原会话窗口扫描→全书复核 |
| 各卡取消 | 仅该任务running | 只取消对应run；另一阶段继续 |
| 查看合并报告 | 该书存在P2报告 | 打开最近报告，可选历史报告 |
| 试跑一章 | 无本地试跑请求；有书 | 独立无写试跑，不生成P1凭证、不解锁阶段 |
| 六内容标签 / 增删改查 / 手动合并 | 查看可用；人工写按同书world/narrative域锁禁用 | P2锁人物地点、P3锁节点事件线，含即时保存；保留表单，解锁后再核revision |

代码整理候选栏并列展示“预览代码合并”“确认机械合并”“收起候选”。选择至少两条同名成员后可直接确认；名称不同时在候选栏选择主名。预览为可选操作，可调整保留条目和主名后返回；确认使用当前展示成员的版本，并在事务中校验。确认成功后候选栏保持展开，刷新剩余候选并选中下一组，使用就地成功提示；整理报告通过按钮查看。

窗口串联区以紧凑卡片显示“串联事件线”、运行中的“取消串联”、已完成窗口数及当前节点覆盖。中断后提供“继续串联事件线”，已完成后提供“重新串联事件线”。窗口起止、判断依据和提交确认收在“窗口进度与串联依据”，展开区域按窗口高度限高。窗口完成显示“窗口串联完成”，全书复核使用独立的覆盖进度。

P1未完时P2/P3显示禁用原因“请先完成全书P1提取（成功x/y章块）”；失败/取消可继续。列表数据提交即生效；不显示旧“草稿/入库/入库测试草稿”等状态或按钮。P2/P3独立显示running/completed/failed/degraded/cancelled/paused、validity及费用；P2成功不代表P3成功。

P1列表来自响应式数据库查询，成功子步骤提交即显示，最迟每章结束更新一次；保持筛选、滚动与选中ID，不因新行插入跳回顶部。空态为“尚无人物/地点，P1完成章节后会逐步显示”，不再等待合并。P2按入口分别显示代码候选确认、AI身份核实与整编进度，以及人物和地点前后数；P3分别显示窗口x/y（含本窗已读节点页）及全书孤点/线/事项覆盖。失败/跳过分开列示，百分比不等于质量或全部成功。

四类资产数量使用紧凑卡片，桌面一行、窄屏两行。章节概览按窗口高度限制列表区域，章节标题和完整原文入口保留。提取运行时展开逐章结果；任务结束后保留进度、成功与失败数量、用量和错误提示，详细结果通过“查看章节结果”展开，展开列表按窗口高度限高。

提取卡显示已保存与待处理的子步骤数量。取消、失败或暂停后显示“继续提取”；确认任务执行权期间禁用启动并显示等待说明。刷新后恢复已保存进度与待处理步骤的失败原因，后续请求由用户点击继续触发；恢复状态保持紧凑摘要布局。

实时日志每任务2000条、费用4位；清日志只清当前选中的任务。刷新后从持久运行恢复摘要/报告，日志不伪造；owner失效时显示“已中断，可继续”，点击才恢复。

## UI-05 资产列表、增删改查与批量合并

前四标签人物/地点/事件节点/事件线显示当前数量；人物保留层级筛选。各列表提供名称/摘要关键字检索和“新增”，检索仅过滤展示不改变处理范围。行显示ID、名称、来源章、人工/提取标记及相关原字段；新增数据及时进入查询结果。

资产管理在查看列表时按工作区可用高度限高，类型标签、搜索、筛选和合并操作保持可见，条目列表独立滚动。少量条目按内容占高；数量增加时延长列表内部滚动范围。

### 新增与详情编辑

人物编辑保留列表旁的详情布局，标题与操作栏固定在编辑区两端，中间字段独立滚动。身份、外貌、性格、背景和原话片段默认显示1–2行，按需展开为较大的编辑框；展开与收起使用同一份输入内容。

| 对象 | 新增必填 | 编辑字段/自动生成 |
|---|---|---|
| 人物 | 主名；来源章可选，无章时来源说明必填 | 沿用主名/别名/身份/ageText/性格/背景/外貌/原话；层级即时保存；relations仍只读展示 |
| 地点 | 名称；来源规则同人物 | 别名与描述；来源、频次、冲突和事实底稿可查看 |
| 节点 | 名称、概述、所属章节；参考引文可选 | 经过、涉及人物、时间、状态变化/事实/行动等；参考引文匹配时定位，未匹配也可保存；涉及人物支持搜索、多选及按身份区分同名，章内顺序由代码计算 |
| 事件线 | 标题、至少一个已存在节点 | 起因/经过/结果/状态，成员多选；chapters/timeRange/节点反向引用派生 |

人工ID由代码生成U-UUID，创建来源manual。普通表单点保存生效；层级和线状态即时保存但也执行revision比较。空必填或无效引用在字段下报错，表单输入保留；保存中仅禁用本次保存。成功详情立即读取新revision和值，不保留BUG-16旧对象回显。

节点的“涉及人物”合并展示行动人物与对象人物，按稳定编号去重。搜索匹配姓名、别名、身份和编号；已选人物可直接移除，筛选保留选择。资料中找不到的称呼可以添加并暂存，提示待关联；同名时提示选择身份，选择其他人物保留该称呼。人物选择与提示随当前表单变化，不另设关联结果栏目。存储保留已有两类人物归属，新选人物进入行动人物。已有非人物对象保留原始记录，并在详细经过中补充“涉及对象：……”且只出现一次；新增物品、地点及行为方向通过概述和详细经过表达。

已选人物与人物搜索结果分别使用逐行列表，展示各自数量，随窗口高度限制列表区域并独立滚动。搜索框保持在列表外，增加人物时扩展列表内部滚动范围，选择与移除仍按人物编号处理。

正在编辑时数据库变化：无未保存输入则刷新详情；有未保存输入则保留表单并提示“此条目已被更新，请重新载入后保存”，提供“重新载入”按钮，不静默覆盖。条目被并入显示新目标与“查看保留条目”；已删除显示不可保存提示。关闭未保存表单仍可直接关闭，不增加强制拦截。

### 人物/地点批量手动合并

1. 点击列表“手动合并”，行前出现复选框，工具栏显示已选n项、“确定合并”“退出合并”。仅同类选择，少于2项禁用确定。行复选不打开详情；选中集合按ID保存，筛选变化不悄悄漏掉隐藏选择，展示“含隐藏m项”。
2. 点击“确定合并”打开预览对话框，列出全部所选条目/来源/冲突/融合结果。先选保留条目keepId，默认第一条但明确展示；主名相同可自动带入，不同名称必须显式选择所选主名/别名或输入新名。提示其他名称将转别名；选择主名不等于更换keepId。
3. 最终按钮“确认机械合并”调用与P2相同的本地融合，不调用AI。执行前再次核全部revision和存在性；无效主名或冲突不提交，保留选择，提示刷新预览。
4. 成功保留目标ID，累计资料/来源和别名，删除其他当前行并写并入映射，清多选、关闭预览并展示目标与减少条数。P1继续执行。取消预览不写数据；退出多选才清选择。

详情旧“把这条并入…”快捷入口可复用同一预览（预选当前与目标），不能保留绕过revision/主名选择的旧逻辑。没有自动拆分或撤销，预览提示“无法直接撤销，可先导出备份”。并入或删除直接作用当前实体并刷新查询；受影响阶段显示“整理结论需重查”，当前数据仍可用，不删除P1成功凭证。

### P2合并报告

AI整理按批次显示当前核实范围及总进度。暂停、取消或中断后显示“继续AI整理”，读取本书已保存的待办与有效覆盖；执行权到期后入口自动重新检查可用状态。报告显示剩余数量、各批实际请求、查询记录、提交确认和最近校验反馈，详情在报告内容区内滚动。

P2完成/降级/失败/取消后保存报告；当前正在查看该书时自动打开，若在别书则在原书卡显示“新合并报告”，返回后可打开，不在别书弹错报告。并发结束报告按runId排队，不覆盖现有对话框。

报告显示状态、各类型前后数量、减少条数、机械/AI合并分组、每组旧条目→保留ID与主名、别名/来源、整编前后token估算、冲突/失败/跳过及费用。无变更显示0项；失败明确“已保留机械及已提交AI结果”。提供查看目标条目、历史报告选择与关闭；报告可刷新后重开。手工合并成功显示轻量摘要，同样可追查持久报告。

## UI-06 事件网络

## UI-07 编辑记忆和会话

## UI-08 单章试跑弹窗

## UI-09 设置页

max-w-3xl居中、p6/space4/overflow-auto；按模型与API、编译、数据、关于顺序。每节白底border/rounded-lg/p4。

模型区按连接、模型选择和高级设置排列。连接区提供常见服务商选择，自动填入服务地址和调用协议；地址可编辑。密钥使用密码框，留空保留该服务商已存凭据，清除使用独立按钮。“拉取模型”和“测试连接”直接放在连接区。

提取与整理模型分别提供下拉选择、手工填写及就近的测试按钮。可以先保存地址和密钥并拉取列表，再选择模型；普通保存保留当前配置进度，生成前校验对应角色的模型名称。列表按服务商、地址和协议归属显示，保留用户选择。

输入有修改时，相关按钮明确显示“保存并拉取”或“保存并测试”，先保存页面当前配置，再由统一模型入口读取已存配置调用。输入与保存值一致时直接拉取或测试。请求运行时固定原配置快照，保存新值从下一次调用生效。

服务商标识、协议选择和整理上下文容量放在折叠的高级设置中。容量为整数且不小于8192，留空采用模型资料。保存与调用状态分别反馈；缺少当前服务的凭据或本次所需模型时，显示对应填写提示。

两种执行模式共用已保存配置，不增加另一组Agent地址/Key。提取测试通过正式direct的pi-ai边界；归并工具测试通过pi-agent-core及同一pi-ai解析结果，探针工具隔离真实书数据。目录拉取只是发现接口，连接成功不能冒充生成/工具能力通过。协议/模型能力不受支持、Pi错误、取消、校验失败按同一错误规则显示；不再以原始HTTP 2xx（含空响应）单独判提取测试成功。

“整理工具测试”依次显示世界资产与叙事资产的读取、写入、总结步骤，支持取消。每套结果显示实际请求次数、读取和写入次数，以及可展开的提交确认；结果区域按窗口高度限高。输入有修改时按钮显示“保存并测试工具”，先保存当前配置再测试。

状态行idle不显示、loading灰、success绿、error红；成功预览detail前60、失败前300。模型配置保存窗口不合法时显示“上下文容量须为不小于 8192 的整数，或留空使用默认值”。保存/清Key后refresh会重载模型表单内容，可能丢未保存输入。

编译区提示“P1按章顺序执行；P2/P3可同时运行”；旧并发参数不再作为P1并发控件展示。“清空日志窗口”仅清当前选择任务的内存logs。数据区导出busy或无书禁用；导入label/file按busy禁用，选后input.value=''允许同文件再次选；预检成功显示书名与当前实体统计、确认（busy禁用）/取消，失败显示错误列表。提交前取消清预览；提交中取消只请求停止，等待日志/事务结果，不伪报成功。

关于固定文案“WestWorld V2 · v1.0 —— 导入小说 → 提取世界资产与叙事资产 → 编辑 → 事件网络可视化。”及游玩下一阶段说明。存储使用量/额度按MB一位，额度文案“可用”对应quota字段，非真正quota减usage。

## UI-10 游玩入口与书籍会话窗口

游玩会话按[工程计划](../分阶段实现与人工验收计划.md)的接入步骤交付。入口启用前显示占位状态；启用后按以下规则运行。

- 窗口明确显示当前书名，从本书游玩会话读取历史、工具结果和摘要状态。空会话显示“还没有开始游玩”。
- 用户在同一窗口输入内容、接收智能体回复、查看工具执行和压缩状态，并取消当前运行。消息区沿用滚动列表、玩家与回复分侧显示的布局。
- 首次进入创建本书会话；再次进入、切页返回或刷新后恢复已保存历史。展示完整消息，模型输入使用AI-08定义的有效上下文。
- 无书时提示先选择书籍；会话加载和恢复完成后开放发送。发送时先确定本书会话与运行身份，显示准备、生成、工具执行、压缩、完成或中断状态。
- 切书后立即使用目标书的窗口。其他书的回复和工具进度留在其所属会话，返回原书可以查看。
- 同书当前运行的重复发送按运行状态提示，取消等待任务停稳后恢复操作。刷新后的中断提供明确继续入口，已提交的工具结果按持久确认显示。
- 自动压缩展示正在整理上下文、完成或失败状态；用户滚动历史时仍可查看完整消息。压缩失败保留原历史并提供重试反馈。

书籍、会话和运行的生命周期以05 AI-16为准，存储与事务按03第5节，游玩具体工具按接入时的业务契约验收。

## UI-12 任务、恢复与探测反馈的明确规则（2026-10-24）

沿用已有阶段启动/继续/取消入口，不新增后台自动执行。每个阶段独立显示运行状态、当前phase、已检查/已跳过/待处理数量；不要把task完成显示成整书阶段完成。

| 情况 | 数据依据与用户反馈 |
|---|---|
| 正常处理 | 计数来自T20当前phase覆盖项；已检查=有效checked，跳过=deleted/redirected等skipped，待处理=pending/assigned/stale。进度比例=(checked+skipped)/total，total=0时完成度100%且显示“本阶段无待处理项”；不得用模型自报数量替代 |
| 子任务partial | 显示“本批已保存，仍有N项待处理”；继续分派后续task，原确认不重复写；P2本轮尝试完后保留剩余项供用户继续，单项失败显示编号与原因；其他阶段按各自停止规则处理 |
| 资料持续变化 | 同项3次失效后显示“资料持续变化，剩余N项”，保留当前资产与报告；用户继续才重查，正常编辑不被永久禁用 |
| 取消 | 立即阻止新请求/新写；已提交部分显示“已取消，已保存N次提交”；在途未提交操作不得显示成功；等事务明确结束后释放租约 |
| 刷新/重开 | 活owner仍在则显示“该阶段正在另一页面运行”；owner失效显示可恢复暂停，点击继续先核意图/账本再请求模型；不自动续跑付费调用 |
| 并发冲突 | 只提示受影响对象/批次需重查；无关项覆盖保留，人工已保存内容不回滚；不清空整个阶段全部进度 |
| 任务总结保存失败 | 即使模型说completed，也显示“结果已提交，完成状态尚未确认，可继续核实”；业务确认与阶段终态分别展示 |
| 归并探测 | 同一loading期间先asset后story，显示当前套/读/写/总结步骤；两套均满足AI-15才成功。一套失败显示该套与失败步骤，不宣称全部工具可用；取消后销毁内存fixture |

错误展示不得含API Key；Prompt、任务快照及工具参数中的原文仅属于该书。阶段报告可以展示待核实决定与跳过原因，但needs_review表示已检查仍需人工判断，不得显示为“原文事实已确定”。
