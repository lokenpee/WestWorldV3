## 2. 状态转移

| 对象 | 当前 | 事件 | 守卫 | 下一状态 | 效果 |
|---|---|---|---|---|---|
| P1 | idle/failed/cancelled/paused | 用户开始/继续 | 有章、资源可得 | running | 只补缺凭证子步骤 |
| P1 | running | 成功子步骤事务 | signal未取消且无凭证 | running/completed | 资产+凭证+来源+进度原子；全书齐备才完成 |
| P2或P3 | idle/stale/failed/paused/cancelled/completed | 启动/重跑 | 全书P1 current，同stage可得 | running | P2/P3可同时running；原会话续用 |
| P2 | running | 整组融合成功 | 全部revision一致 | running | 写world域并同步维护节点人物关联；报告同步追加 |
| P2 | running | 流程结束 | AI均完成或有部分失败 | completed/degraded/failed | 始终存报告；不修改P3状态 |
| P3 | window_link | 全部窗口覆盖后用户启动复核 | 分页全读且批有效 | global_review | 同sessionId，全书孤点/线/事项队列 |
| P3 | global_review | 队列遍历完 | 无失败/未读/过期依赖 | completed | 可保留有说明孤点/疑点；不要求节点全归线 |
| 任一阶段 | running | 取消 | 仅目标signal | cancelled | 保留提交，另阶段不变 |
| 持久运行 | running | 刷新后owner失效 | 租约与存活规则 | paused视图 | 用户点击才续跑；不伪造日志 |
| 阶段结果 | completed/current | 相关输入变化 | 依赖实际命中 | completed/stale | 本阶段需重查；不清P1提取凭证 |
| 资产 | revision=n | 保存/合并 | expectedRevision=n | revision=n+1 | 不一致返回CONFLICT；dirty表单保留 |
| 来源映射 | live/merged | 人工合并/删除 | 合法同类目标 | merged/deleted | 提取恢复不复活 |

## 3. 写后断线的恢复实例

Pi Agent以operationKey=window-0-page-1调用commit_story_changes，事务写节点/线、memory_update、checkpoint及appliedCommands并生成commitId。若随后工具反馈丢失，原消息链保留未完成调用；恢复同书Pi上下文后重试同operationKey，命令服务返回alreadyApplied=true和原commitId，不二次补点/合线或增加记忆revision。最终submit_result只总结commitIds。

direct提取与Agent写服务共用领域校验和当前数据表；没有新草稿/发布层，也不会因Agent末轮回复失败回滚已提交结果。
