# 字段级数据流与状态转移

书籍、章节、资产、运行和会话分别使用稳定 ID。正式书库由本机服务持久化，设置页提供浏览器数据迁移。表名、接口和物理文件对应关系见[存储协议](项目技术说明.md#本机存储协议)，用户操作见[工作台入口](09-操作与自动触发契约.md)。

## DF-01 · 小说预览与保存

1. 选择文件后，在浏览器读取字节，按指定编码或自动检测解码，以正则定位章节和原文区间。预览保留完整解码文本、章名、顺序、字符数和区间，每页显示 100 章或块。切换文件或重新分章时只接受最新请求的结果。[导入预览](../../src/features/import/ImportPanel.tsx)
2. 点击“仅导入”时校验预览，新建书籍 ID，登记 `preparing` 导入日志。在同一单书事务内写 `chapters`、按编号关联的 `chapterTexts` 及 `compileProgress` 的 P1 初始行（`status=idle`）。
3. 核对落盘后，日志转 `ready`，在全局事务发布 `books`、处理重名并清日志。失败则清理未发布资料。尚待清理的日志留给恢复服务。界面选中新书，P1 等待用户手动启动。[写入与发布](../../src/lib/storage/importService.ts)

## DF-02 · 全书P1、取消与恢复

| 触发 | 读取和转换 | 提交及恢复位置 |
|---|---|---|
| 一起提取或继续 | 读取章节和当前有效提取凭据，按章顺序分别调度 `worldAssets` 与 `narrativeAssets`，两路可并行 | `pipelineRuns` 保存运行及执行权，`extractionTasks` 保存任务、章节与步骤。输入正文按 SHA-256 在 `extractionInputs` 存一份，每个任务引用自己的 `snapshotId`。 |
| 当章结构化返回 | 校验步骤对应的字段和引用，世界资产生成或更新人物、地点、关系资料，叙事资产生成事件节点 | 成功的资产写入与依据凭据、来源映射和进度一起提交。回到同一书时，`extractionReceipts` 标识已经完成哪些章节子步骤。 |
| 暂停、取消和重提 | 暂停保留范围。取消停止本书提取。继续按保留任务和凭据查缺。显式整类重提前预览受影响资产与阻碍，确认后清理一次。 | 重提世界资产会清理相应人物、地点、关系和 P2 结果并使 P3 进度失效。重提叙事资产清理相应节点、大纲事件、故事线及 P3 结果。单章入口按章节和步骤确定范围。成功凭据齐全后可由用户启动下游。 |

例如第 3 章的世界资产已完成，叙事步骤失败，普通“继续提取未完成章节”只补该章的叙事步骤。点击单章的世界或叙事按钮时，`extractChapter(bookId, chapterIndex, step)` 查询该章该类的成功凭据。有凭据则替换该范围的资料，无凭据则补提。[任务和输入快照](../../src/features/extraction/taskStore.ts) / [按范围清理](../../src/features/extraction/reextract.ts) / [提取服务](../../src/features/extraction/service.ts)

## DF-03 · P2、P3 执行权与事件提交

P2 工作台和 P3 主流程检查全书 P1 覆盖和本书执行权。P3 主流程首次运行先机械合并完全同名的人物组，再检查是否仍有待处理的同名组。P3 独立复核要求本书已有事件且可取得执行权，可以在没有全书 P1 凭据时启动。两种 P3 入口都要有已配置的整理模型。任务、请求和回执均带有本书或本次运行的身份。[P2 工作台](../../src/features/world/WorldPanel.tsx) / [P3 启动与恢复条件](../../src/features/story/narrativeService.ts)

| P3 环节 | 实际输入 | 写到哪里及何时生效 |
|---|---|---|
| 逐节点串联 `link_node` | 按原文位置装入当前节点。关键词、向量检索和重排产生候选事件。检索模型不可用时记录降级并采用本地结果。 | `edit_events` 按本次操作在 `storyEvents` 新建或更新事件，检查成员范围和版本。编辑提交立即对事件列表生效。`confirm` 另行记录当前节点完成或保留未归属的依据。 |
| 宏观分界 `review_boundaries` | 读取候选组的事件卡、成员并集时间表，以及需要时补读的事件或节点。 | 以当前版本记录已比较事件对。同批可创建、修改或撤销事件。成员、受影响的线和节点派生关系随业务写入同步。 |
| 微观经过 `review_sequence` | 按原文位置调度存续事件，装入本件与顺序成员。 | 只更新当前事件。确认按事件 ID 和版本保存。带编号与证据的 `return_to_macro` 优先送回宏观，`pending_review` 登记待核实事项。队列结束仍有遗留则暂停。 |
| 首页继续、重建或独立复核 | 主流程运行从 `compileProgress.P3.runId` 关联 `pipelineRuns`。独立复核从本书 `reviewOnly` 运行读取 | 暂停后继续原进度。不能继续且已有 P3 成果时，主流程创建清理旧 P3 资料的独立副本。独立复核直接使用当前书上的事件并写回。取消后重开独立复核创建新运行、新会话和新队列。 |

主流程第一阶段完成后以 `paused` 和 `awaitingStorylines` 停在故事线整理前。独立复核完成时可记录自己的完成状态。[工具事务与回执](../../src/features/story/narrativeTools.ts) / [两步复核](项目技术说明.md#两步事件复核)

## DF-05 · P2 候选合并、人物识别与资料整理

| 操作 | 输入与判断 | 结果和后续读取 |
|---|---|---|
| 代码整理或机械合并 | 读取本书人物、地点名称与候选。符合条件的同名组自动执行机械融合。余下疑似组由用户挑选成员、确定主名并确认或加入队列。 | 每组完成后保留目标 ID，重写来源映射和关联，记录运行或合并报告。已提交组可在历史查看，队列按组恢复。 |
| 人物识别（`scan`） | 读取人物目录、疑似组和按需核实的资料，用 `save_identity_groups` 保存疑似组 | 结果作为工作台候选，用户可确认机械合并或标为“不是同一人”。 |
| 人物资料（`profiles`）与关系（`relations`） | 读取当前人物、原文或当前关系。分别通过 `submit_profile_review` 和 `submit_relation_review` 提交依据、改动及完成状态。 | 各步骤独立运行，可暂停和继续。重新开始可选全部重做或复用适用的已完成结果。单人物运行能从人物详情启动。执行记录按运行、人物和请求查阅。 |

步骤按运行 ID 记录状态，资料和关系的执行明细可按人物定位。[P2 工具与权限](项目技术说明.md#模型任务与权限) / [运行服务](../../src/features/world/service.ts) / [整理面板](../../src/features/world/WorldPanel.tsx)

## DF-06 · 人工新增、修改与并发保护

普通编辑先保存在表单，服务收到 `bookId, kind, id, expectedRevision, input` 后，在同一写事务中检查世界或叙事域锁，读取当前行，校验引用、写入行及派生内容。域被占用时返回 `ASSET_DOMAIN_LOCKED`，修订不符返回 `CONFLICT`，条目缺失返回 `NOT_FOUND`。界面保留尚未提交的输入。新增走创建接口，首个修订为 1。已有人物的层级和故事线的状态可即时提交。[编辑器](../../src/features/assets/AssetEditor.tsx) / [事务实现](../../src/features/assets/service.ts)

人物、地点、节点、故事线复用人工编辑接口。事件列表从 `storyEvents` 读卡片和成员详情，第一阶段事件字段通过 P3 工具写入。对已归线的事件，故事线编辑器也能以线 ID、事件 ID、事件修订号和节点 ID 列表修改该事件成员。

## DF-07 · 批量手动合并、来源映射与删除

1. 选择同书同类型的至少两条人物或地点，读取成员 ID、当前修订号、选定的保留 ID 和主名，生成预览。
2. 确认时重新校验全部成员及域锁。在一笔事务中写保留记录、融合资料、来源映射、报告，并调整人物关联和派生数据。成员改变则拒绝该组，可重新预览。
3. 人工删除经确认后写来源生命周期为 `deleted`。合并的来源记录指向保留 ID，状态为 `merged`。普通编辑、删除和合并都保留 P1 已成功凭据，供后续补缺使用。[合并逻辑](../../src/features/assets/merge.ts) / [来源与修订校验](../../src/features/assets/service.ts)

## DF-08 · 节点/线删除及引用清理

节点删除后重新计算线成员，并按存续节点清理事件的 `nodeIds`。遇到按事件组织的大纲，按 `eventIds` 汇总节点、章节与时间范围，再回写节点的 `eventLineIds`。有变化的行更新修订号。删除一条线后其余事件和节点仍可单独查阅。宏观复核撤销事件时，清理故事线对该事件的引用。`replacement_event_ids` 记录去向。变更和关联维护在同一写事务内完成。[叙事关系推导](../../src/features/story/outline.ts) / [事件操作范围](项目技术说明.md#编辑操作与字段)

## DF-09 · 当前实体直接生效与人物引用读取

列表和详情从当前书的 `characters/locations/nodes/storyEvents/eventLines` 读取。节点保存人物名称、稳定 ID 与绑定，人物合并或删除时重算受影响绑定。节点所属事件由事件成员读取，大纲故事线的节点由线内事件派生。线上的人物从成员节点引用汇总。节点、事件、故事线的字段检索按查询选项装载相应关联数据，返回当前页、匹配数和总数。[查询与分页](../../src/features/assets/assetPage.ts) / [关联字段检索](../../src/features/assets/narrativeSearch.ts)

## DF-10 · 备份与恢复

| 环节 | 输入、写入及恢复 |
|---|---|
| 导出 .wwv2 | 读书架元数据和单书表的一致快照，原文按章写 TXT，其余表写 JSON，生成 SHA-256 清单并压缩。当前 `formatVersion=15`，`appVersion` 取应用包版本。范围含关系、提取任务及输入、事件、运行和会话。进行中任务以可恢复状态导出，排除全局设置、凭据和租约。 |
| 预检 | 读取版本 4–15，核对清单、校验和、正文及跨表引用。按包格式转换人物关系、提取或叙事字段。失败显示具体文件或字段并阻止确认，成功保留已准备数据供恢复使用。 |
| 恢复 | 生成新书 ID、重写书籍引用并校验。完成目标书事务后发布书架项。成功后可选择新书，已有原书保留。异常由导入日志清理或恢复。 |
| 磁盘恢复副本 | 本机存储服务单独保存自动恢复副本，设置页可查询最近保存、最近备份时间和错误，也可立即生成。业务提交已成功时，备份失败会单独报告。 |

## DF-11 · 整书删除与资源边界

书架先读取删除阻碍，用户确认后服务再次检查本书活动租约。取得删除权并登记 `deleting` 日志后，撤下该书、移除其存储并清理日志。失败时保留可重试的记录。下一次读取书架会从余下书籍选取当前书。其他书、全局设置和已导出的文件仍独立存在。[删除与恢复](../../src/lib/storage/importService.ts)

## 状态转移

| 对象与操作 | 下一状态或记录 | 用户可见结果 |
|---|---|---|
| 导入新书 | `preparing → ready → 发布`。失败进入清理或保留日志 | 书架只展示已完成发布的书 |
| P1 子步骤成功 | 对该章该类新增成功凭据，任务更新完成状态 | P1 计数、对应人物、地点或节点立即刷新。全书两路齐备时可手动开始 P2/P3 主流程 |
| P1 暂停 / 继续 / 取消 | 暂停保留提取范围。继续检查剩余子步骤。取消结束本书当前提取控制 | 已经写入的资料和成功凭据保留 |
| P2 人物步骤暂停或重开 | 暂停后继续原运行，重开按选择产生新运行、复用或重做适用单元 | 可按运行、任务、人物检查来源和结果 |
| P3 主流程完成逐节点串联 | 转入宏观分界，再逐事件微观复核。收到带依据的转回可再次进入宏观 | 进度分别显示宏观确认组数、微观已主审事件数 |
| P3 第一阶段完成 | 主流程 `paused` 且等待故事线。独立复核正常结束可以 `completed` | 结果已在本书或重建副本可见，第二阶段仍暂停 |
| P3 遇到未解决事项、暂停或取消 | 待核实事项保留到运行中。暂停可继续。取消结束本书可继续的主运行及独立复核 | 重开独立复核时重新分组，各次运行记录可查 |
| 同一资产保存 | 修订号匹配才执行，写后修订号增加。来源的合并或删除状态随事务保存 | 冲突提示重新载入，表单仍可查看 |
| 刷新后发现活动执行权 | 按租约、运行身份和当前任务判断能否恢复或接手 | 查到的持久进度继续展示，恢复运行需从对应阶段入口启动 |

## 写后断线的恢复实例

假设微观复核任务 T1 调用 `edit_events`，把事件 E1 的最新进展改为“信已送达”。程序在一个事务中写事件和 `pipelineRuns` 的 `narrative_receipt`。回执 ID 为任务 ID 与调用 ID 的组合，记录运行 ID、工具名、参数签名和结果。若事务已提交而回复丢失，同一任务以相同调用 ID 和参数重试时，从已保存的回执重建工具结果，不会再次改写 E1。同一调用 ID 配上不同参数会报错。一件事件完成主审由另一次 `confirm` 确认其版本。[回执检查与重放](../../src/features/story/narrativeTools.ts) / [微观确认](../../src/features/story/twoStepReview.ts)
