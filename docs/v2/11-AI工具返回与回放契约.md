# AI工具返回与交互回放

职责和有效来源见[统一入口](00-阅读入口与术语.md)。实现及验收状态见[覆盖索引](12-验收执行与覆盖矩阵.md)。

## 1. 当前工具与直接存储

工具按当前工作流开放。P3 串联与全书复核默认使用story_pages_v3，直接开放下述六工具；兼容接口仍登记在同一清单，数量元数据描述登记总量，不代表每次请求全部开放。参数/限额/投影见[工具清单](resources/v2.2/tool-contracts.json)，返回结构见[返回Schema](resources/v2.2/tool-results.schema.json)，payload与最终摘要Schema见[模型输出契约](resources/v2.2/model-output-contract.json)。

工具从当前characters/locations/nodes/eventLines读取，没有草稿和固定实体的选择参数。Agent由pi-agent-core执行，模型请求统一pi-ai。写工具的execute通过应用共用校验/事务服务修改当前数据，成功确认即生效；P3 的 finish_story_batch 由程序核对阅读进度和实际提交，结束当前阶段；兼容 Agent 的 submit_result 汇总 commitIds。direct模式的submit_result仍仅约束输出，由调用方共用服务提交；不得混淆两者语义。

通用分页data/totalCount/truncated/nextOffset，单次最多65536字节。精简人物/地点查询额外用after_id/nextAfterId稳定游标，按ID Unicode码点字典序；after_id与offset互斥，末页nextAfterId=null。处理边合并边删除时不能递增offset导致跳项，末次清单复核补新改项。

## P3 完整事件线工具

逐页串联与全书复核直接开放以下六个工具，不经过工具发现。实际参数及限制以 [tool-contracts.json](resources/v2.2/tool-contracts.json) 为准，返回以 [tool-results.schema.json](resources/v2.2/tool-results.schema.json) 为准。

| 工具 | 输入及结果 |
| --- | --- |
| search_story_context | 按当前节点、关键词、种类、章节范围或状态查摘要；无关键词可浏览，offset/nextOffset 翻页；返回命中的节点、事件线或线索 |
| get_story_detail | kind与ids；节点仅编号、名称、完整概述、章节及详细经过；事件线为概述和成员；正文按char_offset/maxChars续读，成员按memberOffset/memberLimit分页，返回missingIds及续读位置 |
| save_story_lines | operations支持create/append/update/merge；名称title、节点nodeIds、概述summary为核心，reason可选；append仅新增成员，update.nodeIds为完整成员，merge指定lineId和mergeLineIds；返回changed、lineIds及lines中逐线added/removed数量 |
| save_story_notes | notes 按 key 更新线索，workingSummary 可独立提交；省略的旧引用及证据保留；返回 changed |
| navigate_story_pages | direction=next/previous；currentPageId、reason、notes可选；程序绑定当前页，返回ok/complete/page/summary |
| finish_story_batch | reason、summary可选，items仅为旧工作项兼容且可省略；程序绑定当前任务、真实commitIds及阅读进度；返回accepted/status/commitIds/remaining |

两个写工具均校验实际读集、当前执行权和引用，在单个事务提交本次全部操作及命令凭据。任一操作失败整次回滚，不返回成功确认。成功的无变化操作返回 changed=false，commitId 表示命令已确认；它不代表有资料修改或整页检查完成。保存事件线无需附带记忆。相同标题与相同成员的重复新建复用原线，不同故事线允许共享相同节点。

事件线提供summary时替换整线概述，省略保留；旧线无summary时查询合并cause/process/result作为概述，原字段保留。merge省略概述时组合双方有效概述。现有状态保留，新建默认open；章节、时间范围与节点反向归属由程序维护。目录、搜索和详情中实际提供的对象均登记读取依据，不强制二次查详情。不用置信度阈值、字数或原文逐字匹配阻断保存。

命令键由程序生成，相同调用重放原回执。当前P3不声明也不允许执行原文、补点或旧综合提交工具；历史接口使用legacyParameters兼容。原始链路日志保留，恢复和压缩给模型的历史返回使用当前业务投影。

首次和恢复时提供完整阅读简报，导航返回的page也使用同一结构：`{phase,queue,page:{id,pageNumber,totalPages,type,ids,...},workItems,related,workingSummary,...}`。内层page.type为node_page、line_segment、line_summary或note_page，分段时补充lineId/segment/totalSegments。前进保存当前页检查指纹并返回下一个未检查页；回看只改变位置。后续页不会自动注入。导航回执随pipelineRuns.storyReading保存，重放不重复前进；complete=true时page=null，阶段可以正常结束。

finish_story_batch只能单独调用，不与写工具混在同一响应。它按实际剩余阅读页结束阶段，省略items或items=[]都合法；仍有未检查页时保留为未完成状态，已保存修改不回滚。旧story_lines_v2仍按逐项结论收尾，旧记录和会话保持可读。

## 3. 实际依赖、错误与提交

代码记录实际读取的ID/revision、redirect解析和原文指纹；分页同时记录参数/结果集合指纹，包含负查询变化。P2无关变更不使P3全批失败，命中本批依赖才CONFLICT重查。

只读错误沿用ABORTED/INVALID_ARGS/TOO_LARGE/INTERNAL/NOT_FOUND；写服务CONFLICT表示revision/预览失效。模型服务重试与一次结果修正沿用05，不把任意文本当作成功提交。

P2通过commit_asset_changes提交operationKey和分组payload，代码机械融合直接写当前实体。P3通过save_story_lines保存事件线，add_story_nodes和save_story_notes分别补点、保存记忆；程序生成operationKey并适配原叙事事务，校验边界见上文。兼容接口commit_story_changes继续接受Link payload并保留旧约束；new_nodes选择本书章节，参考引文可选且不匹配只记录提示。未知ID、跨书/类型、循环组等无效引用仍拒绝。

### 3.1 写工具、幂等与读写顺序

| 工具 | 参数/返回 | 业务作用 |
|---|---|---|
| commit_asset_changes | operationKey+IdentityGroupsSchema payload；返回ok/commitId/operationKey/alreadyApplied/summary | 世界实体、来源映射、报告、T20命令凭据同事务 |
| commit_story_changes | operationKey+LinkEventLinesResultSchema payload；返回同上 | 叙事实体、memory_update、事项/检查点/覆盖及命令凭据同事务；可仅写记忆 |
| submit_result（独立最终收集器） | AgentTaskSummarySchema | 验证commitIds属于当前run/子任务；不重复应用payload |

同一个operationKey的全部payload和命令账本必须同事务，不允许一个命令内部分组先写后报失败。写工具绑定代码传入bookId/runId/profile/phase/sessionId和实际读集，不接收模型任意指定的书或数据库路径。Pi sequential执行写工具；最终submit必须单独一批，混合批先拒绝后执行，不允许部分先写。

结构/作用域校验后先检查命令账本，已成功同payload直接返回原凭据，不再因成员已并入而执行新命令的存在性/revision校验。同(runId,operationKey)同payload返回原凭据；不同payload返回IDEMPOTENCY_CONFLICT。WRITE_SCOPE_DENIED、CONFLICT属于工具领域错误，不等同Provider服务错误。事务成功但反馈丢失时恢复原runId并用同operationKey重试，alreadyApplied=true；最终模型失败仍保留已写数据及报告。具体返回Schema见当前机器工具结果，成功/重放示例见examples.json。

| 消息 | 必备变量 | 约束 |
|---|---|---|
| P1_CHAPTER | 本章index/name/完整text | 独立世界/叙事请求，不含前章响应 |
| P2_IDENTITY | bookId/runId/kind/fullBook/游标 | 精简查询→受控写分组→最终总结确认；不内联全部详情 |
| P2_OPTIMIZE | 当前实体ID/字段事实ID/previous展示 | 完整事实覆盖；只按需读取长/重复档案 |
| P3_WINDOW | 当前页号/总页数、节点摘要、相关候选、工作摘要 | 每页最多10项及约4000 Token资料预算；AI主动翻页，可分次接入已有线 |
| P3_GLOBAL | 同书会话、当前阅读页、相关摘要、当前线/分段及工作摘要 | 孤立节点→每条线分段→整线概要→线索；按需读详情及原文，合理孤点可保留 |
| P3_MEMORY | 当前摘要/事项/依据/未处理项 | 仅作参考；过期复查；压缩后保留精确任务输入 |

同书串联/复核/继续/重查均追加同sessionId；新bookId独立Agent。当前P3保留单请求超时，不设置5分钟业务收尾；暂停后从持久阅读位置继续。Pi Agent管理循环/消息/工具调度，应用保存模型用量、原始Pi消息、长期记忆与业务commit。Pi agent_end只表示本次循环结束，阶段完成仍按阅读页检查指纹判断。

## 6. 可直接实现的工具定义

以下TOOL-01至TOOL-16为兼容工具的逐字段契约。当前工作流按工具清单和应用适配器选择可用工具；P3新任务使用本文件“P3完整事件线工具”节的六工具，旧工具不发送给新P3任务。

### 6.1 Pi适配及统一返回

每个工具必须包含name、description、parameters和异步execute；应用适配成Pi AgentTool时提供label。成功返回同时设`content=[{type:'text',text:JSON.stringify(result)}]`、`details=result`及`structuredContent=result`；outputSchema对应本工具成功返回结构。失败必须设置`isError=true`，仅在文本中写“失败”不会让Pi识别错误。structuredContent不送入模型，不能省略content里的JSON。执行前后分别验证参数和成功结果；意外异常转INTERNAL，不把堆栈/凭据送入模型。

bookId、runId、profile、phase、sessionId、租约owner和读集由应用闭包绑定，不是模型可传参数。所有工具默认additionalProperties=false，模型伪造bookId或数据库路径必须INVALID_ARGS。异步DB读取没有自身网络重试；服从当前能力的任务预算和 AbortSignal（取消信号）。只读工具无业务表写入，持久消息由运行器保存；写工具只有事务成功才返回成功确认。

```text
Page<T> = {data:T[], totalCount:integer>=0, truncated:boolean, nextOffset:integer>=0|null}
CursorPage<T> = Page<T> + {nextAfterId:string|null}
DetailPage<T> = Page<T> + {missingIds:string[]}
Oversized = {id?:string, fields_omitted:["oversized_detail"], hint:string}
Error = {error:错误代码, message:string, truncated?:boolean}
CommitAck = {ok:true,commitId:string,operationKey:string,alreadyApplied:boolean,summary:string}
```

`submit_relation_review` 使用逐项提交结果：`status=succeeded` 时 `ok:true`；有失败项时 `ok:false`、`done:false`、`complete:false`，工具同时设置 `isError:true`。其中 `status=partial` 保留已保存部分的真实 `commitId`，`failed` 说明未提交项；`status=failed` 无成功确认，不返回 `commitId`，不加入成功账本。`applied` 仅表示本次实际修改目标，合法无变化项可以成功确认；`cumulativeApplied` 表示本轮已修改目标。未核实是证据状态，不等于提交失败。只有 `complete:true` 表示人物结束；`done=false` 的成功保存仍需继续当前人物。精确结构见 `tool-results.schema.json`。

资料/关系查询允许省略人物编号，工具在首次查询时将实际人物写入读集参数；旧省略编号的读集在完成前补齐。结束清空 `activeWork` 后重读仍指向同一人物。空 `patch` / `changes` 加 `done=true` 从绑定工作项完成人物，分批 `uncertainPairs` 累积保留。提交账本可保存所属 `unitId`；重放返回原始结果，部分成功不能改为成功。旧轮恢复重新挂起同一个工作项时，仅在工作项身份相符、租约有效后恢复完成状态，不重新修改资产；不同工作项不能被旧回执完成。

列表允许Oversized替代超长行；事项工具的完整NoteView总长度受自身Schema限制，返回结构不得擅自用占位行冒充NoteView。分页先按条件求totalCount，再取offset/limit；truncated表示仍有行，不是错误；末页nextOffset=null。DetailPage缺失ID不算数据行，missingIds仅含不存在/已删，不含被条数/字节限额截掉的ID。单行超过64512字节返回Oversized，累计达到64512停止加入；最终JSON超过65536字节返回TOO_LARGE。数组空页为`{data:[],totalCount:0,truncated:false,nextOffset:null}`，CursorPage再加nextAfterId:null，DetailPage再加missingIds。只读详情没有分页参数时，调用方以尚未返回的ID继续请求。

### 6.2 成功投影字段全集

本表的string[]默认要求每元素string；`?`仅可省略，只有写明null才可为null。表记录字段定义直接引用03中对应逐表字典，不以源码类型名代替。

| 返回行/对象 | 精确字段与来源 |
|---|---|
| NodeSummary | id:string、name:string、summary:string、actors:string[]、chapterIndex:string；旧弱校验行可能缺name/summary/actors，目标新行不得缺。 |
| LineSummary | id:string、title:string、chapters:string[]、lineStatus:open/closed、cause:string、result:string、nodeCount:integer=nodeIds.length；旧弱校验行title/cause/result可缺。 |
| CharacterSummary | id/name:string，aliases:string[]，identityHint:string≤160，sourceChapters:string[]，revision:integer≥1，estimatedDetailTokens:integer≥0，duplicateScore:number∈[0,1]；全部必填。 |
| LocationSummary | 同人物精简行，将identityHint换为descriptionHint；全部必填。 |
| NoteView | 03 T14全部字段，加validity:current/stale；stale为当前依据不匹配，不改status。 |
| SessionSummary | id/title:string、kind:initial/review、status:active/archived、parentSessionId?:string、entryCount:integer、createdAt/updatedAt:string。 |
| HistorySummary | id:string、ordinal:integer、type:message/compaction/omit/commit、createdAt:string、preview:string（JSON.stringify(entry)前800字符）。 |
| HistorySlice | id:string、text:string、totalChars:integer、charOffset:integer、truncated:boolean、nextCharOffset:integer/null；text为单条JSON分段，单段本身不保证可JSON解析。 |
| MemoryResult | memory=03 T13；dataChanged:boolean；pendingCount:integer（active且review）；staleCount:integer（依据过期）；notes:NoteSummary[]最多10；recentCheckpoints:CheckpointSummary[]最多5。 |
| NoteSummary | id/key:string、kind:decision/review、status:active/resolved、statement:string、nodeIds/lineIds:string[]、validity:current/stale、truncated:boolean；statement前240字符，nodeIds/lineIds各前5项；任一被截短则truncated=true。 |
| CheckpointSummary | id:string、stage:string、phase:string、status:string、scopeCount:integer=scopeIds.length、updatedAt:string；旧历史stage/phase原样展示，不能算新覆盖。 |

指标明确化：estimatedDetailTokens对人物identity/appearance/personality/background/speechStyleSample或地点description按字段顺序以换行连接，计算`ceil(UTF16长度/2)`；不计原始底稿与工具JSON包装。duplicateScore取同字段去空白、长度≥20且非完全相同片段两两字符3-gram集合Jaccard的最大值，无有效配对为0。指标用于选择详情/整编，不能证明同人/同地点。此处为目标补充算法，不宣称旧工具已输出该指标。

### TOOL-01 · query_nodes

角色/阶段：两角色；P2/P3查询。单次最多200条/结果，最终JSON最多65536字节。

| 参数路径 | 类型/枚举 | 存在性 | 结构约束 | 含义/缺省 |
|---|---|---|---|---|
| chapter_range | string[] | 可省略 | minItems=2；maxItems=2 | 恰好2个章标识，两端包含；不等于P3零基半开窗口 |
| actor | string | 可省略 | — | 原文称呼精确匹配 |
| event_line_id | string | 可省略 | — | 限定所属线ID |
| offset | integer | 可省略 | minimum=0 | 行分页起点默认0；read_original中是字符起点 |
| limit | integer | 可省略 | minimum=1；maximum=200 | 默认100，实际min(limit,该工具maxResults) |

处理：chapter_range按章节数字段比较且两端包含；actor精确匹配actors或targets中的称呼；event_line_id取线成员，线不存在则空。多过滤条件AND。按chapterIndex、order排序；同值保留主键扫描顺序。

读写与副作用：T08/T09；记录实际节点版本及查询结果集合。

成功返回：Page<NodeSummary>；name/summary/actors/chapterIndex来自节点，summary最多240字符。

### 6.4 submit_result：最终收集器

Agent参数五项均必填：status=`completed|partial`、commitIds=唯一非空string数组、summary=非空string、remainingWorkIds=非空string元素数组、reviewedItems={workItemId,outcome,reason}数组；数组本身可空。reviewedItems与remainingWorkIds必须按第7节分割分配项。先校验提交ID属于当前run/子任务且已持久化，再检查completed无待覆盖项；通过返回`{accepted:true,status,commitIds}`并设置terminate=true。失败返回INVALID_ARGS且isError=true；不重演任何业务payload。该返回为2026-10-23补充目标契约。

direct只注册当前结构化输出Schema的同名收集器；没有AgentTool.execute循环，调用方解析响应、校验后调用业务服务。不得拿AgentTaskSummarySchema替代P1提取Schema，也不能以direct“没有执行写工具”为由漏掉调用方提交。

模型一次响应若同时调用submit_result和其他工具，必须在第一项业务副作用前拒绝整批。实现时在已await持久化assistant的message_end监听中检查该消息全部toolCall，记录该批阻断；beforeToolCall对该批每项返回block。仅在遇到submit_result时才拒绝会让前面的commit已经写入，不能满足本契约。

## 8. 防误合并与缺失原文的工具契约

commit_asset_changes.payload.groups[]新增必填字段如下；所有已有读集、人工保护、原子提交及幂等约束继续适用。

| 路径 | 类型/范围 | 执行要求 |
|---|---|---|

read_original遇“章节行存在但正文行不存在”时返回{error:"SOURCE_MISSING",message:"缺少章节原文：<按章顺序的ID>"}，不是成功的空text；无匹配章范围仍可以返回正常空结果。上层必须把缺原文视作不可提交的来源错误，不让缺失引文通过。

## 10. 模型声明与整理详情

模型工具声明只包含名称、简介和输入参数；`label`、`outputSchema`、`execute`是程序内部信息。人物整理的`submit_profile_review`及`submit_relation_review`由程序生成操作键，模型声明不含`operationKey`。关系提交依据放在每条`changes[].basis`，模型声明不再提供顶层默认`basis`；执行入口仍接受已有调用中的这些字段。按需发现的工具详情与下一次请求声明使用同一参数投影。

第二步人物资料预装及 `query_character_profile` 返回当前展示字段和来源章节，不携带 `mergeFacts`，内部字段清单也不列该项；库内事实及内容指纹保留原用途。七项资料字数由人物资料提示词约束，不增加工具参数、提交或存储长度校验。`submit_profile_review` 的 `no_change` 完成回执显示“本次未修改，已结束检查。”；本轮先前已有修改时仍按累计真实修改结果报告。

第一步只声明 `query_character_catalog`、`query_candidate_groups`、`get_character_detail`、`get_character_relation`、`query_locations`、`get_location_detail`、`save_identity_groups`、`navigate_identity_pages`。不提供原文查阅、实际合并、资料编辑、工具发现或单独总结工具；其他P2人物整理工作项也不提供或发现 `merge_assets`。目录查询search匹配姓名、别名和身份；候选查询按cursor续页。

`get_character_relation`：必填fromId，可选toId。只填fromId返回当前人物关系概览数组data，按对方编号排序；limit最多50，afterId为上页nextAfterId，总量totalCount和truncated说明分页情况。再填toId返回指定人物对；第一步仅返回fromId/toId、双方姓名、state、双向标签和directionUnclear，不携带evidence、版本或指纹。其他步骤的指定人物对查询仍返回完整证据、版本和指纹。人物详情不再兼带关系，也不视为已经读取全部关系的证明。

第一步恢复及压缩时，对历史人物详情、人物关系和旧原文结果进行同样的轻量投影；原始会话条目保留给整理详情，人物资料、当前页及保存候选的记忆继续可用。

第二、三步的read_original在当前轮按人物和步骤分别限一次成功读取。次数存于pipelineRuns.organization.originalReadUnits（可选string[]），值例如profile:C1-P001、relations:C1-P001。原文读取和标记在同一写事务生效；参数错误、缺失原文或事务失败不计次。暂停、刷新、恢复及备份导入保留标记；旧存档从同工作项任务的readSet.queries识别历史成功调用，新一轮重新计次。耗尽时返回普通成功工具结果：readLimitReached=true、message提示直接整理结论，text为空、segments/chapters为空、totalChars=0、truncated=false、nextCursor/nextOffset=null。不覆盖第一次读取的查询指纹及章节依据，不触发工具错误重试，不阻止保存和完成。其他阶段原文工具维持原规则。

`save_identity_groups`：groups为批量候选，每组必填完整memberIds和简短疑似说明reason，不要求证据、原文引用或预先查询详情；存疑可保存供人工选择。可选groupId更新原组、groupIds合并已有组；同批更新原组并新建其他组可拆组。已有组不足两人则撤销，人工已处理组返回ignored并保留原结论。成员来自已提供页或实际查询且仍存在。返回groups和summary、complete=false，不返回后页、不完成页。候选归类不写人物资产；用户确认后才由人工合并入口执行。

`navigate_identity_pages`：currentPageId绑定当前阅读页，direction为next或previous。next完成当前页并返回后页；previous只回看。结果page包含pageId、pageNumber、totalPages、people；仅末页next且所有页完成时page=null、complete=true，若尚有未完成页则返回该页。当前位置identityPageId与已提供页seenIdentityPageIds保存在organization；恢复时选择第一张未完成页。两工具由程序按run、unit、toolCallId和参数生成幂等键，同一调用重放不重复提交，不同调用允许回看后再次前进和组成员改回。候选和页状态在各自事务保存；既有租约、成员存在性及人工结论校验生效，自身保存不因之前候选查询结果变化而报读取冲突。

整理详情以实际消息时间线显示发送内容、API回复和工具执行结果。后续请求重复携带的相同上下文不再次铺开，变化的上下文和额外角色如实显示；可展开API分隔行查看该次完整实际发送内容。P2所有消息默认折叠，assistant展开含正文、思考和tool call；工具定义默认折叠。顶部统计与主面板当前人物统计共用请求去重和用量来源；底部按对象左右对照实际修改，理由在下。P2历史人物选择与完成替换见[数据与存储T17](03-Spec-数据与存储.md)。工具结果展示进入模型的`content`，不重复展开`details`和`structuredContent`副本。

网关在实际fetch前观测JSON发送体，不采集鉴权头。trace沿用开放的`input`：`messageFormat=provider-request/v1`表示消息来自发送体，`messages`保存协议消息投影，`toolSchemaSnapshotId`引用单份工具声明；可选`requestParameters`保存其余请求字段，`transportAttemptIds`关联同一逻辑请求的实际发送尝试。Responses的instructions和Anthropic的system映射为系统消息。旧pi-agent-message/v1日志只作为历史上下文展示，不补造未保存的HTTP内容。容量降级时消息、参数和工具定义按现有策略省略并显示不完整。
