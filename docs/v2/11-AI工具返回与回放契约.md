# AI 工具返回与交互回放

工作台按任务声明模型可以使用的工具。排查一次调用时，先看运行与任务编号，再看实际发出的工具声明、模型收到的回包和书库保存的结果。[模型任务与权限](项目技术说明.md#模型任务与权限) · [整理详情](06-界面与交互规格.md#ui-07-p3-整理详情与会话记录)

## 任务提交与完成条件

| 任务 | 写入结果 | 完成依据 |
|---|---|---|
| P1 逐章提取 | `submit_result` 返回本章的结构化结果。提取服务校验后写入人物、地点或节点。 | 对应章和子步骤的成功凭证。 |
| P2 识别重复人物 | `save_identity_groups` 保存疑似组和理由。人工确认机械合并后，程序更新保留实体及成员去向。 | `navigate_identity_pages` 确认目录已检查的页，最后一页完成后返回 `complete:true`。 |
| P2 优化资料、整理关系 | `submit_profile_review` 保存人物资料。`submit_relation_review` 分项保存人物对关系。 | 参数 `done` 表示模型是否请求结束当前人物，结果 `complete` 表示是否已结束。 |
| P3 事件整理 | `edit_events` 将整批事件修改、成员归属和回执写进同一事务。 | `confirm` 核对当前节点、宏观疑似组或微观主审事件的完成条件。 |

P1、文本整编和会话摘要均使用名为 `submit_result` 的结构化输出，参数由各自任务的 Schema 定义。设置页的人物合并探针使用 Agent 最终收集器，核对总结中的提交编号和隔离样本的真实修改。[模型输出契约](resources/v2.2/model-output-contract.json) · [提取校验](../../src/features/extraction/contracts.ts) · [设置页工具测试](../../src/features/agents/probe.ts)

## P3 查询与编辑回包

| 工具 | 可读范围和默认回包 |
|---|---|
| `get_nodes` | 按 `node_ids` 返回 `items`，默认字段为 `node_id,name,detail`。有缺失或超出可见范围的编号时附 `not_found_ids`。串联可查前序、当前及后文概览覆盖的节点，复核可按全书编号读取。 |
| `get_event` | 返回事件名、概况、最新进展、待解决问题、线索、状态及按原文次序排列的成员 `members[{node_id,name}]`。找不到时返回原编号和 `status:"not_found"`。 |
| `search_prior_nodes` | 串联专用，搜索当前节点之前的详细经过。默认返回 `node_id,summary`，从最近向前取最多 20 项。 |
| `search_nodes` | 复核专用，可限定两个节点之间的开区间，也可排除指定事件的所有成员。默认字段为 `node_id,name,summary`，最多 100 项。 |
| `search_events` | 在事件名称和概况中检索，默认返回 `event_id,name,overview`，最多 100 项。 |
| `edit_events` | 成功返回 `ok,created,updated`。新建项含编号和名称，更新项含编号。成员变化时附 `added/removed`，保存值与提交值有差别时附 `saved_fields`。串联另返 `current_node_assigned`，复核按实际改动给出删除的事件或失去归属的节点编号。 |
| `confirm` | 成功回包形如 `{"confirmed":true,"result":"completed"}`。每种任务的确认范围见下节。 |

三个搜索工具均以 `groups` 指定关键词组。组内所有词都须命中，组间只须命中一组。回包的 `total` 为命中总数，`truncated` 表示是否仅返回部分结果。传 `return_fields` 可指定返回字段，编号始终返回。[任务声明](../../src/features/story/eventToolsSchema.ts) · [查询和编辑](../../src/features/story/eventWorkflow.ts) · [模型回包](../../src/features/story/eventToolReply.ts)

例如，节点 N1 已属于事件 E1，模型根据本节点修订进展时，提交的操作和收到的回包如下。详情页会从完整回执中取出修改理由和字段变化。[编辑操作与字段](项目技术说明.md#编辑操作与字段)

```json
{"changes":[{"op":"update","event_id":"E1","fields":{"latest_progress":"账册已经交到县署。"},"reason":"当前节点写明账册的去向。"}]}
```

```json
{"ok":true,"created":[],"updated":[{"event_id":"E1"}],"current_node_assigned":true}
```

## P3 确认、失败与恢复

REQ-032 第二阶段拟按当前事件、当前分界组或当前故事线分别确认。事件确定归线时，同一次确认可保存其他可能归属；报告存疑，正式成员只收录有依据的归属。同一任务重复发送已保存的调用时，程序按调用编号及原参数返回已保存的结果。模型输入、逐项输出及错误示例见[拟议工具契约](../../openspec/changes/recast-p3-storyline-workflow/agent-contract.md#确认工具)和[预期交互](../../openspec/changes/recast-p3-storyline-workflow/requests.json)。

| 任务 | 允许的修改和确认 |
|---|---|
| 逐节点串联 `link_node` | 可创建或更新事件。当前节点已有归属时直接确认。保留为未归属节点时须给出 `unassigned_reason`。 |
| 宏观分组 `review_boundaries` | 可新建、修改或撤销事件。`completed` 确认本组当前版本的比较，`pending_review` 登记待核实事项。 |
| 逐件主审 `review_sequence` | 只可修改正在主审的事件。`completed` 确认本件当前版本。`pending_review` 登记待核实事项。`return_to_macro` 须给出涉及事件、证据节点和理由，再由宏观任务核查。 |

`nodeIds` 和 `clues` 按完整数组提交。程序核查本任务装入或读取的成员和版本，版本发生变化后须重读。同一轮内有编辑失败时，须先修正再确认。错误以 `isError:true` 返回，内容包括 `tool,code,reason,taskId,mode,part,hint`，按情况附操作序号和字段。[参数与确认分支](../../src/features/story/eventToolsSchema.ts) · [校验与写入](../../src/features/story/narrativeTools.ts)

程序以任务编号和工具调用编号定位 `pipelineRuns` 中的 `narrative_receipt`。回执含工具名、参数签名、完整结果及展示快照。重复调用先匹配签名，再返回已存结果。恢复同一工作项时，运行器用回执补齐配对的工具消息。独立复核取消后再次启动会建立新的运行、会话和任务队列。[运行与恢复](../../src/features/story/narrativeService.ts) · [事件任务成果](../../src/features/story/eventTaskOutcome.ts)

## P2 人物整理工具

人物识别的固定工具包括查人物目录、疑似组、人物或地点详情、人物关系，以及保存疑似组和目录翻页。支持按需发现的工作项可用 `get_tools` 列出本任务允许的工具，再用 `get_tools_detail({name})` 获取参数并在下一轮激活。书籍、职责与任务由程序绑定。模型工具声明对外提供名称、说明和输入参数。[工具注册与激活](../../src/features/agents/tools.ts) · [通用工具参数目录](项目技术说明.md#通用工具参数目录)

| 工具 | 提交与返回 |
|---|---|
| `query_character_catalog / query_candidate_groups` | 按游标读取人物或疑似组。目录可按姓名、别名、身份搜索，人物目录结果带页号和下一页游标。 |
| `get_character_relation` | 只传 `fromId` 返回该人物的关系概览，可按 `nextAfterId` 续页，每页最多 50 项。再传 `toId` 可核对指定人物对。目录识别步骤返回姓名、状态和双向标签，关系工作项可进一步读取证据和版本。 |
| `save_identity_groups` | 每组传完整 `memberIds` 和疑似理由 `reason`。可创建、更新、合并或拆分组，返回 `groups,summary,complete:false`。成员须来自已提供的目录页或实际查询。在当前页保存后可继续核对。 |
| `navigate_identity_pages` | `next` 标记当前页完成并给出后续页，`previous` 用于回看。所有页已完成时返回 `page:null,complete:true`。 |
| `query_character_profile / submit_profile_review` | 查询返回当前人物展示字段及来源章。提交时传 `patch`，可保存后继续，也可用空补丁结束一次无修改检查。是否写入和是否完成分别看 `changed` 与 `complete`。 |
| `read_original` | 资产工作项可按资产编号、章节编号或章节范围读取。返回文本、分段、来源章、续读游标。找不到所选章或正文时给出 `NOT_FOUND`。人物资料、关系步骤各自按人物限制一次成功读取，次数用尽后以 `readLimitReached:true` 和提示反馈。 |
| `submit_relation_review` | `changes[]` 对指定人物对执行设置或删除，依据随每项提交。`succeeded/partial/failed` 区分批次结果。`applied` 列本次修改，`cumulativeApplied` 列本轮累计，`failed` 指出失败项。部分成功时保留真实提交编号，可按失败项继续处理。 |

疑似组保存只更新候选。机械合并须经人工确认。直接合并工具 `commit_asset_changes` 会校验实际读过的成员、保留编号、保护字段及原文证据。用同一操作键再次提交相同参数时返回原确认。人物资料与关系提交的操作键由程序生成。[人物候选与翻页](../../src/features/world/identityCandidates.ts) · [资料和关系处理](../../src/features/agents/organizationCommands.ts) · [合并校验](../../src/features/agents/commands.ts) · [查询实现](../../src/features/agents/queries.ts)

## 查看一次模型请求

在书籍工作台打开「整理详情」或「P3 整理详情」，按人物、运行或事件任务定位请求。展开一轮可以看发送内容、模型回复、工具调用与返回给模型的 JSON。P3「查看逐项复核表」按宏观组或主审事件列出成果。「查看会话历史」可翻阅本书保存的原始条目。[P2 整理详情](../../src/features/agents/P2OrganizationPanel.tsx) · [P3 请求详情](../../src/features/story/NarrativeRequest.tsx) · [会话记录](../../src/features/story/SessionHistory.tsx)

本机存储的 `executionPage` 按运行和选择范围返回最近 20 次请求，可用 `startedAt/requestId` 游标向前加载。展开时由 `executionBody` 读取指定请求内容，统计覆盖整个选择范围。网关在发送前记录协议请求体和工具声明快照，鉴权头排除在采集范围外。容量受限时，详情会标出省略的部分。[请求与正文查询](../../src/features/local-storage/executionQueries.ts) · [请求采集](../../src/features/models/gateway.ts)

三个事件任务分别有可核对首包和原生工具的完整请求样例。[节点串联样例](resources/v2.2/request-examples/PROMPT-P3-NARRATIVE-V4-link_node.json) · [宏观复核样例](resources/v2.2/request-examples/PROMPT-P3-NARRATIVE-V4-review_boundaries.json) · [逐件主审样例](resources/v2.2/request-examples/PROMPT-P3-NARRATIVE-V4-review_sequence.json)
