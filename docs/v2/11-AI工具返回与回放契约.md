# AI工具返回与交互回放

职责和有效来源见[统一入口](00-阅读入口与术语.md)。实现及验收状态见[覆盖索引](12-验收执行与覆盖矩阵.md)。

## 1. 当前工具与直接存储

14种读工具、2种受控写工具；asset_editor使用9读+commit_asset_changes（10个业务工具），story_editor使用14读+commit_story_changes（15个业务工具）。submit_result另为无业务写副作用的最终收集器。参数/限额/投影见[工具清单](resources/v2.2/tool-contracts.json)，返回结构见[返回Schema](resources/v2.2/tool-results.schema.json)，payload与最终摘要Schema见[模型输出契约](resources/v2.2/model-output-contract.json)。

工具从当前characters/locations/nodes/eventLines读取，没有草稿和固定实体的选择参数。Agent由pi-agent-core执行，模型请求统一pi-ai。写工具的execute通过应用共用校验/事务服务修改当前数据，成功确认即生效；Agent最终submit_result只汇总commitIds。direct模式的submit_result仍仅约束输出，由调用方共用服务提交；不得混淆两者语义。

通用分页data/totalCount/truncated/nextOffset，单次最多65536字节。精简人物/地点查询额外用after_id/nextAfterId稳定游标，按ID Unicode码点字典序；after_id与offset互斥，末页nextAfterId=null。处理边合并边删除时不能递增offset导致跳项，末次清单复核补新改项。

详情查询旧并入ID时返回最终当前行与resolvedFrom；已删/不存在列入missingIds，不复活来源。分组提交使用已查询的当前同类ID。节点人物按稳定编号关联，同名时选择身份；人物删除/合并由共用命令同步更新节点编号与名称，事件线人物集合随之刷新。

## 3. 实际依赖、错误与提交

代码记录实际读取的ID/revision、redirect解析和原文指纹；分页同时记录参数/结果集合指纹，包含负查询变化。P2无关变更不使P3全批失败，命中本批依赖才CONFLICT重查。

只读错误沿用ABORTED/INVALID_ARGS/TOO_LARGE/INTERNAL/NOT_FOUND；写服务CONFLICT表示revision/预览失效。模型服务重试与一次结果修正沿用05，不把任意文本当作成功提交。

P2通过commit_asset_changes提交operationKey和分组payload，代码机械融合直接写当前实体。P3通过commit_story_changes提交operationKey和Link payload，每个event_line_ops带confidence>=0.85、reason、evidenceNodeIds；new_nodes选择本书章节，参考引文可选且不匹配只记录提示；节点/线/工作记忆/覆盖/命令凭据同事务提交。未知ID、跨书/类型、循环组、缺事实覆盖均拒绝。

### 3.1 写工具、幂等与读写顺序

| 工具 | 参数/返回 | 业务作用 |
|---|---|---|
| commit_asset_changes | operationKey+IdentityGroupsSchema payload；返回ok/commitId/operationKey/alreadyApplied/summary | 世界实体、来源映射、报告、T20命令凭据同事务 |
| commit_story_changes | operationKey+LinkEventLinesResultSchema payload；返回同上 | 叙事实体、memory_update、事项/检查点/覆盖及命令凭据同事务；可仅写记忆 |
| submit_result（独立最终收集器） | AgentTaskSummarySchema | 验证commitIds属于当前run/子任务；不重复应用payload |

同一个operationKey的全部payload和命令账本必须同事务，不允许一个命令内部分组先写后报失败。写工具绑定代码传入bookId/runId/profile/phase/sessionId和实际读集，不接收模型任意指定的书或数据库路径。Pi sequential执行写工具；最终submit必须单独一批，混合批先拒绝后执行，不允许部分先写。

结构/作用域校验后先检查命令账本，已成功同payload直接返回原凭据，不再因成员已并入而执行新命令的存在性/revision校验。同(runId,operationKey)同payload返回原凭据；不同payload返回IDEMPOTENCY_CONFLICT。WRITE_SCOPE_DENIED、CONFLICT属于工具领域错误，不等同Provider服务错误。事务成功但反馈丢失时恢复原runId并用同operationKey重试，alreadyApplied=true；最终模型失败仍保留已写数据及报告。具体返回Schema见当前机器工具结果，成功/重放示例见examples.json。

## 4. 消息变量与持续会话

| 消息 | 必备变量 | 约束 |
|---|---|---|
| P1_CHAPTER | 本章index/name/完整text | 独立世界/叙事请求，不含前章响应 |
| P2_IDENTITY | bookId/runId/kind/fullBook/游标 | 精简查询→受控写分组→最终总结确认；不内联全部详情 |
| P2_OPTIMIZE | 当前实体ID/字段事实ID/previous展示 | 完整事实覆盖；只按需读取长/重复档案 |
| P3_WINDOW | bookId/runId/sessionId/phase/window/节点ID/页游标 | 100/20计划；高置信才写线 |
| P3_GLOBAL | 同会话/phase/孤点线事项队列和剩余项 | 所有页遍历，按需跨窗/原文；合理孤点可保留 |
| P3_MEMORY | 当前摘要/事项/依据/未处理项 | 仅作参考；过期复查；压缩后保留精确任务输入 |

同书窗口/全局/继续/重查均追加同sessionId；新bookId独立Agent。所属能力的请求和时间预算不截断整书覆盖，可拆子任务续同会话。Pi Agent管理循环/消息/工具调度，应用保存模型用量、原始Pi消息、长期记忆与业务commit。Pi agent_end只表示本次循环结束，不代表未完成覆盖或业务写入成功。

## 6. 可直接实现的工具定义

本节所有16种业务工具均为应用注册的工具，Pi负责调度，不自带这些小说工具。工具由当前结构文件登记并在应用工具适配器创建；实现和测试入口见智能体能力规格。最终收集器另计：asset_editor实际注册11个名称，story_editor注册16个名称；两角色并集17个名称，业务工具并集16个。

### 6.1 Pi适配及统一返回

每个工具必须包含name、description、parameters和异步execute；应用适配成Pi AgentTool时提供label。成功返回同时设`content=[{type:'text',text:JSON.stringify(result)}]`、`details=result`及`structuredContent=result`；outputSchema对应本工具成功返回结构。失败必须设置`isError=true`，仅在文本中写“失败”不会让Pi识别错误。structuredContent不送入模型，不能省略content里的JSON。执行前后分别验证参数和成功结果；意外异常转INTERNAL，不把堆栈/凭据送入模型。

bookId、runId、profile、phase、sessionId、租约owner和读集由应用闭包绑定，不是模型可传参数。所有工具默认additionalProperties=false，模型伪造bookId或数据库路径必须INVALID_ARGS。异步DB读取没有自身网络重试；服从当前能力的任务预算和 AbortSignal（取消信号）。只读工具无业务表写入，持久消息由运行器保存；写工具只有事务成功才返回成功确认。

```text
Page<T> = {data:T[], totalCount:integer>=0, truncated:boolean, nextOffset:integer>=0|null}
CursorPage<T> = Page<T> + {nextAfterId:string|null}
DetailPage<T> = Page<T> + {missingIds:string[]}
Oversized = {id?:string, fields_omitted:["oversized_detail"], hint:string}
Error = {error:错误代码, message:string, truncated?:boolean}
CommitAck = {ok:true,commitId:string,operationKey:string,alreadyApplied:boolean,summary:string}
```

列表允许Oversized替代超长行；事项工具的完整NoteView总长度受自身Schema限制，返回结构不得擅自用占位行冒充NoteView。分页先按条件求totalCount，再取offset/limit；truncated表示仍有行，不是错误；末页nextOffset=null。DetailPage缺失ID不算数据行，missingIds仅含不存在/已删，不含被条数/字节限额截掉的ID。单行超过64512字节返回Oversized，累计达到64512停止加入；最终JSON超过65536字节返回TOO_LARGE。数组空页为`{data:[],totalCount:0,truncated:false,nextOffset:null}`，CursorPage再加nextAfterId:null，DetailPage再加missingIds。只读详情没有分页参数时，调用方以尚未返回的ID继续请求。

### 6.2 成功投影字段全集

本表的string[]默认要求每元素string；`?`仅可省略，只有写明null才可为null。表记录字段定义直接引用03中对应逐表字典，不以源码类型名代替。

| 返回行/对象 | 精确字段与来源 |
|---|---|
| NodeSummary | id:string、name:string、summary:string、actors:string[]、chapterIndex:string；旧弱校验行可能缺name/summary/actors，目标新行不得缺。 |
| LineSummary | id:string、title:string、chapters:string[]、lineStatus:open/closed、cause:string、result:string、nodeCount:integer=nodeIds.length；旧弱校验行title/cause/result可缺。 |
| CharacterSummary | id/name:string，aliases:string[]，identityHint:string≤160，sourceChapters:string[]，revision:integer≥1，estimatedDetailTokens:integer≥0，duplicateScore:number∈[0,1]；全部必填。 |
| LocationSummary | 同人物精简行，将identityHint换为descriptionHint；全部必填。 |
| NoteView | 03 T14全部字段，加validity:current/stale；stale为当前依据不匹配，不改status。 |
| SessionSummary | id/title:string、kind:initial/review、status:active/archived、parentSessionId?:string、entryCount:integer、createdAt/updatedAt:string。 |
| HistorySummary | id:string、ordinal:integer、type:message/compaction/omit/commit、createdAt:string、preview:string（JSON.stringify(entry)前800字符）。 |
| HistorySlice | id:string、text:string、totalChars:integer、charOffset:integer、truncated:boolean、nextCharOffset:integer/null；text为单条JSON分段，单段本身不保证可JSON解析。 |
| MemoryResult | memory=03 T13；dataChanged:boolean；pendingCount:integer（active且review）；staleCount:integer（依据过期）；notes:NoteSummary[]最多10；recentCheckpoints:CheckpointSummary[]最多5。 |
| NoteSummary | id/key:string、kind:decision/review、status:active/resolved、statement:string、nodeIds/lineIds:string[]、validity:current/stale、truncated:boolean；statement前240字符，nodeIds/lineIds各前5项；任一被截短则truncated=true。 |
| CheckpointSummary | id:string、stage:string、phase:string、status:string、scopeCount:integer=scopeIds.length、updatedAt:string；旧历史stage/phase原样展示，不能算新覆盖。 |

指标明确化：estimatedDetailTokens对人物identity/appearance/personality/background/speechStyleSample或地点description按字段顺序以换行连接，计算`ceil(UTF16长度/2)`；不计原始底稿与工具JSON包装。duplicateScore取同字段去空白、长度≥20且非完全相同片段两两字符3-gram集合Jaccard的最大值，无有效配对为0。指标用于选择详情/整编，不能证明同人/同地点。此处为目标补充算法，不宣称旧工具已输出该指标。

### TOOL-01 · query_nodes

角色/阶段：两角色；P2/P3查询。单次最多200条/结果，最终JSON最多65536字节。

| 参数路径 | 类型/枚举 | 存在性 | 结构约束 | 含义/缺省 |
|---|---|---|---|---|
| chapter_range | string[] | 可省略 | minItems=2；maxItems=2 | 恰好2个章标识，两端包含；不等于P3零基半开窗口 |
| actor | string | 可省略 | — | 原文称呼精确匹配 |
| event_line_id | string | 可省略 | — | 限定所属线ID |
| offset | integer | 可省略 | minimum=0 | 行分页起点默认0；read_original中是字符起点 |
| limit | integer | 可省略 | minimum=1；maximum=200 | 默认100，实际min(limit,该工具maxResults) |

处理：chapter_range按章节数字段比较且两端包含；actor精确匹配actors或targets中的称呼；event_line_id取线成员，线不存在则空。多过滤条件AND。按chapterIndex、order排序；同值保留主键扫描顺序。

读写与副作用：T08/T09；记录实际节点版本及查询结果集合。

成功返回：Page<NodeSummary>；name/summary/actors/chapterIndex来自节点，summary最多240字符。

空/缺失/截断：无匹配为标准空页，不报NOT_FOUND。

### TOOL-06 · get_character_detail

角色/阶段：两角色；include_facts受阶段限制。单次最多20条/结果，最终JSON最多65536字节。

| 参数路径 | 类型/枚举 | 存在性 | 结构约束 | 含义/缺省 |
|---|---|---|---|---|
| ids | string[] | 必填 | minItems=1；maxItems=20 | 同书ID数组，1–20个；不允许书ID或文件路径 |
| include_facts | boolean | 可省略 | default=False | 默认false；true仅应用绑定asset_editor/optimize权限 |

成功返回：CommitAck；new_nodes[].client_id只在本payload内，用正式ID替换后才可持久化。

空/缺失/截断：允许两个操作数组为空而只写memory_update；不能通过此工具改世界人物/地点、原文、配置或删书。

### 6.3 错误及调用方恢复

| 代码 | 适用/触发 | 返回后处理 |
|---|---|---|
| ABORTED | 开始前或执行中取消 | 停止本次请求；写事务已提交则不得报“未写入”，恢复时用原operationKey查确认。 |
| INVALID_ARGS | 结构错误、额外字段、after_id与offset并用、非法引用/引文/覆盖 | 无新业务写入；最多一次定向结果修正。 |
| NOT_FOUND | 指定同书会话或单条历史不存在 | 重查同书列表；普通资产详情使用missingIds，无需整请求失败。 |
| TOO_LARGE | 最终返回或写命令输入JSON超过65536字节 | 缩小ID/组/节点批；不能截掉半份写payload后执行。 |
| WRITE_SCOPE_DENIED | 错角色/阶段调用写工具；越权include_facts | 不执行；不能靠换工具参数提高权限。 |
| CONFLICT | 实际读集revision/查询结果集合、租约或手工保护目标变化 | 重新读取和判断；新payload用新operationKey；已成功同键重放优先返回原确认。 |
| IDEMPOTENCY_CONFLICT | 同run同operationKey换payload | 拒绝；查原确认或明确新操作键，不能覆盖账本。 |
| INTERNAL | 未预期异常或返回不符合声明Schema | 标工具失败，记录无密钥诊断；不把字段缺失视为模型正常回答。 |

原wrapper中的STALE_REFERENCE统一以CONFLICT暴露，不能出现有名字但没有返回分支的独立错误。机器error Schema与本表同步；工具不存在时Pi返回未知工具错误，不应转发到任何默认执行器。

### 6.4 submit_result：最终收集器

Agent参数五项均必填：status=`completed|partial`、commitIds=唯一非空string数组、summary=非空string、remainingWorkIds=非空string元素数组、reviewedItems={workItemId,outcome,reason}数组；数组本身可空。reviewedItems与remainingWorkIds必须按第7节分割分配项。先校验提交ID属于当前run/子任务且已持久化，再检查completed无待覆盖项；通过返回`{accepted:true,status,commitIds}`并设置terminate=true。失败返回INVALID_ARGS且isError=true；不重演任何业务payload。该返回为2026-10-23补充目标契约。

direct只注册当前结构化输出Schema的同名收集器；没有AgentTool.execute循环，调用方解析响应、校验后调用业务服务。不得拿AgentTaskSummarySchema替代P1提取Schema，也不能以direct“没有执行写工具”为由漏掉调用方提交。

模型一次响应若同时调用submit_result和其他工具，必须在第一项业务副作用前拒绝整批。实现时在已await持久化assistant的message_end监听中检查该消息全部toolCall，记录该批阻断；beforeToolCall对该批每项返回block。仅在遇到submit_result时才拒绝会让前面的commit已经写入，不能满足本契约。

### 6.5 具体回放（规范样例，未执行目标应用）

1. 本task分配C1-P001/C2-P001对应的两个workItem。本书B已有C1-P001(name=沈青,revision=2)、C2-P001(name=沈青,revision=1)，当前run=R、asset_editor/ai_identity、world租约有效。query_characters({limit:100})返回两行，运行器记录这两个版本。

## 7. 子任务绑定、最终逐项结果与恢复（2026-10-24）

> 当前修复要求：commit_asset_changes各组除原字段外，必须有confidence>=0.9和evidence；具体字段与硬校验见第8节。旧无证据示例仅历史说明，不能通过当前写服务。

模型参数仍不接收taskId/bookId/runId；应用在绑定工具时固定这些值。所有读工具记录本task实际读取及查询依赖，输入摘要也进入读集。写工具参数仍是operationKey+payload，不增加模型可伪造的expectedRevision；expectedReadSet由服务保存。

执行任何新写入前按04 ALG-12保存prepared命令意图；实际提交与taskId归属的账本确认同事务。prepared只表示收到待执行命令，**不能返回CommitAck**；CommitAck只能来自applied状态。恢复同run同key时同时核taskId；T1的键不能被T2复用，即使payload相同。已拒绝/放弃的旧键保留终态，不接受改payload后重新激活。

最终参数五项为status、commitIds、summary、remainingWorkIds、reviewedItems。reviewedItems每项含非空workItemId、outcome=changed/no_change/needs_review、1–1000字符reason。代码逐项核：ID属于分配集合、无重复、与remaining互斥、两者恰好覆盖全部分配项；changed有本task实际命令写集依据；commitIds精确等于本task成功账本确认。不能用同run别的子任务的K或仅凭模型文字“完成了”通过。

finalizer返回仍是{accepted:true,status,commitIds}，不重复修改业务。随后Coordinator原子保存task总结与覆盖状态；这次元数据事务失败时显示未确认完成并可恢复。completed必须remaining为空，partial须仍有剩余；合理孤点可no_change，已核实但还需人工判断可needs_review，不能强行闭合事件线来清空待办。

若模型一次混合提交业务写入和finalizer，整批在首个副作用前拒绝。step预算和唯一修正机会按05 AI-14统一；CONFLICT需要重读，INVALID_ARGS的修正payload必须新operationKey，不因使用新key获得额外模型修正机会。

需求验收例：T1已提交K1但最后反馈丢失，T2开始后不能把K1计入T2；恢复T1必须取原意图/确认而不是让模型重新猜参数。A@1、B@1都已检查后人工只修改A，A对应覆盖stale，B仍checked。固定输入/预期和适配器执行入口在[缺口专项验收](resources/v2.2/acceptance/README.md)。

## 8. 防误合并与缺失原文的工具契约

commit_asset_changes.payload.groups[]新增必填字段如下；所有已有读集、人工保护、原子提交及幂等约束继续适用。

| 路径 | 类型/范围 | 执行要求 |
|---|---|---|
| confidence | number，0.9–1 | 低于0.9拒绝；数字高不替代证据 |
| evidence | array，1–10项 | 每组必须有实际原文支持 |
| evidence[].chapterIndex | 非空string | 当前书真实章节且原文存在 |
| evidence[].quote | string，1–1000字符 | 对应原文连续逐字子串，不拼接/改写 |
| evidence[].memberIds | 非空唯一string[] | 本组成员子集；所有证据成员并集必须覆盖整组；每个引用成员至少有一个已知称呼在对应引文中 |

这些校验在保存prepared意图前后分别按结构和领域执行，确认阶段仍复验原文/成员版本。无证据、漏成员或伪引文返回INVALID_ARGS且不应用任何组；不同originId不能走“同名机械合并”旁路。用户明确的手工预览确认走人工服务，无需伪造AI证据。

get_node_detail和get_event_line_detail增加只读characterReferences：每个原actors称呼一项{name,status,characterId?,candidateIds}，status=resolved/not_found/ambiguous。resolved必须恰一候选且characterId为该ID，not_found为[]且无characterId，ambiguous至少2候选且无characterId；candidateIds去重按ID排序。节点actorIds与targetCharacterIds持久保存已绑定人物；同名待选择身份，线characterIds由当前成员节点关联派生。

read_original遇“章节行存在但正文行不存在”时返回{error:"SOURCE_MISSING",message:"缺少章节原文：<按章顺序的ID>"}，不是成功的空text；无匹配章范围仍可以返回正常空结果。上层必须把缺原文视作不可提交的来源错误，不让缺失引文通过。
