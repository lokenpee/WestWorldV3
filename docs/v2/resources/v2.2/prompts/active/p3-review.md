# P3 · 逐线复核因果脉络

## 任务

核对整本书事件线是否完整、前后承接是否成立，使后续游戏能追溯关键事件的前置条件、人物动机和结果。围绕当前对象细查，可分次查询、回看和保存。

复核依次处理散落节点、事件线和未解线索。每条事件线分段阅读，最后做一次整线核对；翻页由你主动调用工具。

## 铁律

1. 散落节点：查找它是否补足已有线的铺垫、发展或回收；独立事件可以保留独立，并说明判断。
2. 事件线分段：结合该线概览与此前关键结果，检查当前行动需要的条件是否已出现，人物目的是否能解释行动，当前变化怎样影响后续。发现漏接或误接时查询相关节点和原文。
3. 整线核对：读完各段后，将最初动机、关键转折和当前或最终结果连起来，检查中间是否缺少必要环节、叙述是否仍停留在早期发展。成员排好序不等于因果已经讲清。
4. 未解线索：搜索后文是否有回应，核对后更新原事项。区分仍待查证与原著未交代；实际改变过的事件线回查受影响部分。
5. 同节点可属于多条线。合线前核对双方脉络，保留有效发展；跨线影响可引用相关线或节点，不必因此合为一线。
6. 补环先找已有节点，原文确有漏提才补点。检查结论如实保留未明之处；故事仍在发展可保持open。

## 字段

| 字段 | 复核重点与更新方式 |
| --- | --- |
| title | 能否概括这条线的核心事件或目标 |
| nodeIds | 是否遗漏关键节点或混入别的事件；append增加成员，update提供完整成员调整 |
| cause | 触发条件、人物目的和必要前因是否准确；提供时替换，省略保留 |
| process | 关键节点造成的变化与后续承接，引用有关节点编号；提供时是完整替换 |
| processAppend | 补充新发现的发展段，保留旧经过 |
| processEdits | 按详情中的segment段号填写改后的text，只修订有关段落 |
| result | 当前已发生的结果及对后续的影响，是否与全线发展一致 |
| lineStatus | 按故事实际进展选择open或closed，与阅读进度分别判断 |
| 线索与结论 | 保存尚待查证的问题、原著未交代的缺口及依据；查清后更新原key |

例如“取得账册”使“揭露幕后者”获得证据，经过应保留这一条件，方便游戏判断跳过取账册后需要补足什么。文字可合理概括，参考引文是定位线索，可省略。完整替换、局部修订和追加发展可按需要组合，工具依此顺序保存。

## 工具

- search_story_context：搜索本书节点、旧线和线索，必要时换关键词或分页查找。
- get_story_detail：读取对象详情、事件线成员和经过段；processSegment用于单独读取某段。
- read_original：核实疑点和漏提事件。
- save_story_lines：分次追加节点、补充发展段、局部修订或合线；未提供的字段保留，合线保留双方已有脉络，任一来源仍open时默认保持open。
- save_story_notes：保存检查结论与未解问题，需要时更新工作摘要。
- add_story_nodes：根据已读原文补充漏提事件，返回编号后接线。
- navigate_story_pages：next完成当前页检查并取得下一页，previous回看。事件线各段检查后，整线概览页用于核对总体承接。
- finish_story_batch：结束当前阶段，说明检查结果和遗留问题；程序保留未读页面与已保存成果。

可以正常说明推理依据和取舍。无需每页重写全线或工作摘要，阅读、查询、修改可以分多次完成。
