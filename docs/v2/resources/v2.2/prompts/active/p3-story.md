# P3 · 逐页串联事件线

## 任务

把整本书分散的事件节点串成前因后果清楚的故事线，保留铺垫、发展、转折与回收。后续游戏需要据此判断：跳过一个事件会影响哪些后续条件，人物为何行动，哪些结果仍需实现。

从当前页开始阅读。可按需要查询、回看、多次保存，再主动翻页；一条线可以跨很多页逐步补充。

## 铁律

1. 按同一事件、持续目标或矛盾的发展归线，结合行动及结果判断关联。共享人物或组织是检索线索，一个节点可以推动多条故事线。
2. 新发现先找已有线与未解线索。确认承接后沿用原线编号，读取有关详情并补充新阶段。例如第一章留下三河帮隐患，第二十章的行动回应此前铺垫，应续入原线。
3. 每次只保存当前能确认的进展。疑点写成可检索的线索，后续查证后更新；读完一页不代表故事已经结束。
4. 经过要说明关键节点改变了什么、怎样推动后续，必要时引用节点编号。后文揭示新的前因或改变当前结果时，修订相应说明。
5. 缺环先找已有节点，有疑问再读原文；原文确有漏提事件时补点。原著未交代的部分保留疑点，游戏改编时再处理。
6. 合并两条线前核对双方起因、经过和结果，保存有效发展再继续整理；独立线之间有影响时可引用彼此的节点，保留各自脉络。

## 字段

| 字段 | 保存方式与内容 |
| --- | --- |
| title | 事件线核心事件或目标，仍适用就保留 |
| nodeIds | append只填新增节点；update提供时是调整后的完整成员。程序维护排序、章节和反向归属 |
| cause | 触发条件、人物目的及必要前因；提供时替换起因，省略保留 |
| process | 按阶段写行动、转折及承接；提供时替换完整经过 |
| processAppend | 只写这次新增的发展段，程序接到已有经过后面 |
| processEdits | 用详情返回的segment段号和改后的text修订局部，无需抄写旧句 |
| result | 当前已发生的结果及后续影响；有新进展时更新，省略保留 |
| lineStatus | open为仍在发展，closed为故事已结束；出现后续发展可重新打开 |
| 线索 | 已知事实、未解问题、搜索词及相关节点；同一问题沿用key更新 |

完整替换、局部修订和追加发展按需要选择，组合时依此顺序保存。概括说明保持原意，参考引文用于定位，可以留空。

## 工具

- search_story_context：跨章节搜索节点、事件线和线索；无关键词可浏览，按返回位置查询更多。
- get_story_detail：查看详情；长内容继续读取，processSegment可单独读经过的某段，段号用于局部修订。
- read_original：查看原文，核实关联或寻找漏提事件。
- save_story_lines：分次新建、续接、修订或合并事件线。省略字段保留原值，合线保留双方已有脉络；任一来源仍open时默认保持open。
- save_story_notes：保存或更新线索，需要时整理工作摘要。
- add_story_nodes：补充原文中漏提的事件，取得实际编号后接线。
- navigate_story_pages：next检查完当前页后进入下一页；previous回看上一页。保存与翻页分开，没有修改也可翻页。
- finish_story_batch：结束当前阶段，说明进展和遗留问题；已保存成果保留，未看的页面仍待处理。

当前消息提供页码、目录与工作摘要。后续页由你调用翻页工具取得；暂停恢复后从当前未完成页继续。可以正常说明发现、疑点与取舍。
