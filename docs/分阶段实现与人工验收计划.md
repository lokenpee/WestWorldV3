## 共同业务规则

- P2（世界资产整理）运行时锁定同书人物、地点的人工修改；P3（叙事整理）运行时锁定同书节点、事件线的人工修改。查看、搜索、原文、备份及其他书籍的操作可用。
- 阶段启动与人工保存均在事务中检查同书资源。取消等待在途工作停稳并释放本任务的锁，再恢复编辑；未保存输入保留。
- P1（逐章提取）每个子步骤最多3次实际请求，包含首次、网络重发和至多一次结果修正，共用额度。不可重试错误立即停止，章节层使用子步骤的请求结果。
- P2身份核实按[世界资产整理决策](decisions/world-organization.md)提前收尾；P3按[叙事整理的排队与恢复](decisions/story-organization.md)执行预算；探测使用规格规定的更小预算。取消能中断请求和退避等待。
- P2/P3支持并行，分别维护状态、资源、取消和费用，并按实际读取的资料保留跨阶段依赖检查。
- 已提交的资产立即生效，实体编号稳定。失败和取消保留已提交成果；完成状态按当前资料的有效覆盖判定。
- Pi运行库负责模型、消息与工具循环；应用负责本书会话保存、恢复、上下文投影和领域事务。具体要求以[按书运行与会话生命周期](v2/05-Spec-AI与会话.md#ai-16-按书运行与会话生命周期)为准。
- 本轮按已确认顺序连续推进，阶段自动检查通过后进入下一阶段；人工验收集中交付。每阶段提供固定样本、操作入口、点击步骤、预期结果与开发检查结果。

## 阶段0：统一规格、验证工程基础

开发步骤：

1. 对齐产品、架构、数据、流程与验收中的域锁和请求预算。
2. 固定 Pi（模型与智能体运行库）及结构校验依赖，验证浏览器内的模型接口、工具循环和取消。
3. 建立类型、静态、单元、浏览器及生产构建检查。

人工验收：查看[工程基础验收](acceptance/stage-00.md)中的规则和运行结果。

预期结果：各规格的锁与重试规则一致，规定依赖可用，检查入口可重复运行。

## 阶段1：应用外壳、本地书架

开发步骤：

1. 建立资产、游玩、设置三个入口和当前书籍选择。
2. 按书隔离本地数据库，加载书架、章节与资产数量。
3. 处理空书架、读取失败、跨标签刷新和手机宽度布局。

人工验收：按[书架验收](acceptance/stage-01.md)装载两本样本，切书、切页面、刷新，并在另一标签查看。

预期结果：书籍和选择正确，资料按书隔离；读取失败有重试入口，手机宽度下操作可达。

## 阶段2：TXT 导入与分章

开发步骤：

1. 识别 UTF-8（文本编码）和 GBK（中文编码），提供重读与分章预览。
2. 保留序文、切分长章，支持自定义分章规则和全部章节阅读。
3. 先完整保存章节与正文，再发布书架；失败按生命周期日志清理或恢复。

人工验收：按[文本导入验收](acceptance/stage-02.md)分别导入中文编码、长章、无标题与错误文件，刷新后打开原文。

预期结果：中文正确，序文完整，长章按规则切块；失败给出明确错误，已有书籍保留。

## 阶段4：人工批量合并

## 阶段5：备份、恢复、删除

开发步骤：

1. 获取全书一致快照，打包原文、资产、来源、报告和会话，并生成文件校验和。
2. 提供下载、目录保存、备份预检和独立副本恢复。
3. 取得删除资源后登记日志、隐藏书架项并删除目标库；阻塞或中断时提供恢复。

人工验收：按[备份验收](acceptance/backup.md)导出再恢复，选择损坏文件，删除一本书并检查另一书，模拟删除失败后重试。

预期结果：恢复资料完整且原书保留；损坏备份给出具体错误；删除只影响目标书，失败状态可恢复。

预期结果：检查范围可核对，合理孤点可保留；运行实例重建仍续接原会话。压缩后模型输入满足预算，原文、完整对话和工具结果保留；失败保留原历史与可继续状态。

## 阶段13：P2/P3 并行与恢复

已有基础：按书、按职责维护任务状态和取消控制，使用独立资源锁、会话与提交账本。本阶段围绕现有机制补齐检查和缺陷修复。

开发步骤：

2. [x] 验证人物合并、称谓整理、节点关联变化与P3读取并行时的提交检查；无关目录变化保留完成状态，实际依据变化重新核对。
3. [x] 验证提交成功但响应丢失、刷新或页面关闭后的恢复，保留业务成果并防止重复执行。
4. [x] 验证多标签执行权续期、过期接管与旧响应晚到，确保每个阶段只有有效执行者写入。
5. [x] 验证切书、切页、取消后晚到事件与组件重新订阅，结果保存和展示归属正确。
6. [x] 交付固定响应测试、浏览器检查与并行恢复验收步骤。

交付：并行恢复机制、针对性用例与[并行恢复验收说明](acceptance/parallel.md)。人工验收状态：待用户确认。修改范围为任务调度、提交与读取校验、会话、资源锁及页面订阅。

验收标准：一个任务取消不影响另一个；实际冲突有明确反馈；重复提交只生效一次；旧执行者失效后停止写入；切书后的状态和费用正确。
