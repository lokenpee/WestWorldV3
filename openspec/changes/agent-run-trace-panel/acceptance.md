# 验收

关联 [REQ-020](../../需求池.md)、[提案](proposal.md)、[设计](design.md) 和[任务](tasks.md)。实施方案已获批准并完成代码；自动检查、P2/P3 浏览器检查和真实模型验收已通过，用户验收待进行。

## 前置与样本

- P1 已完成、模型配置和执行权可用；使用 P2 人物整理和 P3 叙事整理的固定响应样本。
- 固定响应可注入 text、thinking、tool_call、tool_result、错误、取消、压缩和超长结果。
- 真实模型另由用户授权，使用 P2 单人/小批和 P3 小窗口；不以模拟结果代替真实质量。
- 面板入口：P2/P3 各自“运行详情”；不改现有 AI 整理、继续和报告入口。

## D. 审查补充场景

| 编号 | 操作与前置 | 必须结果 | 当前证据 |
|---|---|---|---|
| T15 最终输入采集 | 固定响应让 prepareRequest、transformContext、convertToLlm 都修改上下文；必要时注入原生 payload | 面板记录的是进入最终 `streamFunction` 的输入，不是 prepareRequest 的中间结果；原生 payload（如有）与 Pi 有效输入分开显示；两者不一致时能看出差异 | 开发检查通过 |
| T16 不可变快照与完整性 | 运行后修改提示词和工具 Schema，再回看旧请求；构造临时消息、超长输入和无法保存的输入 | 旧请求显示当时提示词和完整工具 Schema，不随当前定义变化；临时消息保存完整内容；无法完整保存时标 `completeness=partial` 和原因，不声称完整回放；不读取当前 Schema 冒充历史 | 开发检查通过 |
| T17 备份格式兼容 | 用格式11导出并恢复；用旧解码器/旧应用打开新备份；用格式10样本在新应用恢复 | 格式11包含日志、快照和引用，副本归属重写、无凭据；旧应用明确拒绝新格式而不是误读；格式10仍可读；旧格式缺日志显示“历史明细不完整” | 开发检查通过 |
| T18 请求、attempt 与用量 | 一次请求发生网络重试；触发压缩和修正；供应商返回缓存 token、未知费用 | 重试共享同一 requestId、attemptId 不同；压缩/修正有新 requestId 和 parentRequestId；估算输入、供应商输入、缓存和 unknown 分开显示，不以估算冒充实际，不把 unknown 记成 0 | 开发检查通过 |
| T19 容量与分页 | 生成数千条请求和大量 delta/工具结果；打开运行详情并滚动 | 列表虚拟化、请求分页读取，内存只保留当前窗口；长内容展开再取；达到阈值提示清理/导出；不自动删除，不限制 Agent 请求次数；业务运行不受面板容量影响 | 部分通过：最近 50 条分页和容量水位已测，虚拟化未实现 |
| T20 日志失败、刷新与中断 | 模拟 writer 写失败/队列过载；请求中刷新或关闭浏览器；完成后检查人物状态 | 写失败或丢弃未落库 UI 片段时 Agent 继续，done=true、工具提交、资产写入和换人不回滚；面板显示“未保存/日志失败”；刷新后显示已中断或可继续，不伪造运行中；已完成人物不因日志缺失判回未完成或重新提交 | 部分通过：容量降级与业务隔离已测，刷新/中断专项待补 |
| T21 日志与上下文隔离 | 同一 P2 任务分别关闭和开启 trace 运行；人物整理按 context/unit 加载、P3 投影、压缩和 resume 都包含观测条目 | 两次运行的模型实际 messages、业务工具调用次数、资产结果完全一致；request_trace/prompt_snapshot/tool_snapshot 不进入上下文、压缩、工作记忆或待办；观测条目不影响会话 leaf/ordinal 投影 | 开发检查通过 |
| T22 存储空间保护 | 模拟日志持续增长至软/硬水位，再提交人物资产；模拟 `storage.estimate()` 配额变化 | 软水位停止完整快照/超大结果并标 partial；硬水位停止新增日志；Agent 继续，人物资产可正常提交；业务写入优先于日志；已有日志不自动删除 | 开发检查通过 |
| T23 结构化消息回放 | 固定响应包含 toolCall（编号、名称、结构化参数）和 toolResult（内容块）；构造含多内容块和中文的历史输入 | 保存并回放 Pi 原始结构化消息，不丢失 toolCallId、工具名、参数结构或内容块；UI 预览由原始数据生成；引用读取校验哈希，不一致时标不完整 | 开发检查通过 |
| T24 引用一致性 | 模拟快照写入失败、请求记录成功但引用缺失、备份写入中途队列仍有日志、恢复时 snapshotId/entryId 丢失 | 请求记 `missingRefs`/`complete=false`；备份前 flush 并取一致快照，不导出半批记录；恢复逐项校验引用，缺失只标不完整，不用当前提示词/工具定义/会话内容替代，不产生伪造的完整回放 | 开发检查通过 |
