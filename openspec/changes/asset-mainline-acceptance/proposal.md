# 资产主线人工验收

## Why
现有开发检查与用户验收分开登记，集中完成真实书库及模型内容核对。

## What Changes
继承原计划未完成的人工检查，记录实际结果。发现缺陷时关联独立变更或本任务中的明确修复范围。

## Capabilities
无新增行为，沿用现有能力规格；本变更 skip_specs。

## Impact
验收覆盖提取、资产、世界整理、事件线、会话、并行、网络和备份。操作和预期见[集中清单](../../../docs/acceptance/mainline.md)，开发证据见对应验收页及[历史检查记录](../../../docs/acceptance/资产主线开发检查记录.md)。

## 确认依据
现有计划已记录开发检查及待人工验收；本次治理接入迁移任务状态，用户人工结论在实际验收后登记。

## 字段变化

应用字段无变化。本需求记录人工检查结果，结果写入对应验收记录，并由任务和需求池引用。

## 数据流转

用户按集中清单操作现有应用 → 核对实际数据与规格预期 → 将结论记入验收记录 → 更新对应任务；发现行为缺陷时关联修复变更。例如真实书库的合并依据有误，世界整理验收记录写明样本、实际结果与预期，相关任务保持未完成。

## 触发逻辑

用户开始人工验收时按清单准备样本并操作；真实模型调用由用户主动启动。成功项记录通过，失败项保存可复现步骤并进入修复；全部验收通过后按治理规则完成归档。重复检查引用最新结果，取消检查保留已经记录的证据。

## 接手说明

- 需求编号：REQ-002，状态见[需求池](../../需求池.md)；用户目标是核对资产主线的真实内容与操作效果。
- 运行入口和步骤：[集中验收](../../../docs/acceptance/mainline.md)；预期规格和测试入口：[覆盖索引](../../../docs/v2/12-验收执行与覆盖矩阵.md)；执行项：[任务](tasks.md)。
- 环境：启动仓库本地服务，使用用户配置的真实模型和小说；固定样本按各验收页准备。已有开发检查见各验收记录。
- 当前人工结论尚待用户给出，接手 Agent 可以协助准备和复现，按真实结果更新记录。此项无产品行为差异规格。
