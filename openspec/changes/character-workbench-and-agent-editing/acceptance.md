## 环境与运行入口

在仓库根目录，使用锁文件依赖。已安装依赖时直接运行；需要重建依赖时使用`npm ci`。开发入口`npm run dev -- --host 127.0.0.1`，打开命令实际输出的地址→书架→导入验收书→资产→人物。生产入口先`npm run build`再`npm run preview -- --host 127.0.0.1`。自动浏览器用仓库已有Playwright配置。

固定小书和大图样本由测试生成：源码在[tests/support/acceptance-book.ts](../../../tests/support/acceptance-book.ts)，执行`npx vitest run tests/acceptance-fixtures.test.ts`会把两份`.wwv2`写入系统临时目录`westworld-acceptance/`。小书含10人物、2条关系、2节点、1事件线和1地点；大图含2000人物、10000人物对和100孤立人物。小书从备份恢复入口载入即可，不需要重新调用P1。真实小说验收使用用户已完成P1的书，先导出备份再进行人工测试。

## 固定样本

书A包含第1、2、5、10章，P1完成凭证齐全，书B包含另一个同名张蕾用于隔离检查。所有实体有合法来源、初始revision=1，关系基础采用现有版本6事实结构。

| 代称 | 编号 | 主名、别名、身份 | 层级及用途 |
|---|---|---|---|
| A | C1-P001 | 张三；老张；船夫 | 主要人物，关系中心 |
| A2 | C5-P003 | 张三；账房张三；账房 | NPC，同名来源不继承A关系 |
| B1 | C2-P002 | 张蕾；长女；张三长女 | 重要配角，同名目标1 |
| B2 | C5-P001 | 张蕾；商人张蕾；商人 | NPC，同名目标2 |
| B3 | C10-P002 | 张蕾；刺客张蕾；刺客 | 路人，同名目标3 |
| C | C2-P001 | 李沁；阿沁；张三之妻 | 重要配角，丈夫/妻子 |
| D | C10-P003 | 赵六；小六；过客 | NPC，孤立人物和单向新增目标 |
| E | C1-P004 | 北京王；无别名；身份含贾府访客，背景含贾字 | NPC，搜索反例 |
| F | C1-P005 | 贾明；小贾；邻居 | NPC，姓名/别名搜索正例 |
| G | C1-P006 | 王五；贾老板；店主 | NPC，别名搜索正例 |

初始事实R1：A来源、目标称呼张蕾、正向父亲、反向女儿，因此连接B1/B2/B3；R2：A来源、目标李沁、正向丈夫、反向妻子。初始A恰有4人物对，旧有向结果8条；初始网络4条线。A2不继承A关系。这是验证旧全同名绑定的测试资料，不声称三位张蕾在原文中都是女儿。

第2章原文包括：“船夫张三是长女张蕾的父亲。李沁是张三的妻子。张三暗恋赵六，但赵六并不知情。”第5章包括：“商人张蕾与船夫张三没有亲缘关系。账房张三与船夫张三是不同的人。”第10章包括：“刺客张蕾杀害了张三的母亲。李沁在北京城的东门等候张三。”这些是人工构造的确定性测试句，给AI核对不同身份、修正关系及删除错误父女关系提供逐字依据。

地点L1为北京城，描述初始误写西门，证据支持东门。节点N1在第2章，N2在第10章，线EL1含[N1,N2]。为四类工具准备合法可变字段、明确预期和实际读原文范围。AI身份核实固定响应应保留B1/B2/B3为不同人，避免把关系测试误做人物合并。

独立变体：旧“父子”方向不明且端点可匹配；目标“失踪客”尚未入库；来源已删除；100个目标用于关系分页；A/B1、A/B2都删除用于合并；同书人工新建编号；格式4/5/6旧备份。每个用例重新恢复干净副本，避免前一步删除影响下一步初始计数。

大图样本：2000个不同编号人物，其中100主要、300重要配角、1200NPC、400路人；10000个唯一无自连人物对，另有100名孤立人物，图中覆盖同名、长名和单向。数据生成固定随机种子；人物计数与连接计数由数据校验断言。

## 验收缺陷修复与复验

- P2只有明确changed/no_change结论才计为checked；remainingWorkIds和needs_review留待继续，其他未尝试批次仍可推进。旧记录中缺少有效结论的checked项重新核对；提示词沿用共用总结Schema，身份核实统计与全资产核对进度分别读取各自记录。

- 关系候选和网络共用人物姓名/别名相关度搜索，50人后可继续显示，不静默截断。
