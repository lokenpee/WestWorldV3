# 变更提案

## Why

用户在 P1 已完成、开始 P2 整理的书籍中，希望直接维护人物及其关系，并通过人物网络探索资料。当前人物列表选中后才变成两栏；关系区只读、同名人物难以区分；P2 的写工具支持合并和别名核实，不能直接编辑全部资产。

本变更采用 project-full，整体为大型需求。需求池分为四个可独立追踪的目标：REQ-011 人物列表与编辑体验、REQ-012 人物对关系维护、REQ-013 人物网络、REQ-014 P2 全资产编辑工具。REQ-012 是新的人工维护能力，依赖 REQ-007 至 REQ-010 的关系事实与绑定基础，不重新定义 P1 提取。

## What Changes

1. 人物列表常驻左右结构，默认按层级、主名拼音和编号排序；人物搜索仅匹配主名、别名，搜索结果保持相关度排序。
2. 按两个具体人物编号维护一组关系。正反向分别填写、一次保存，允许单向；删除整组。姓名只是显示和搜索内容。
3. 人物卡片增加“人物列表”“人物网络”。网络约占左侧 70%，右侧约占 30%，使用同一个完整人物编辑器；列表默认左侧 30%、右侧 70%。未选中也保留右栏。
4. 黑底力导向人物网络支持缩放、平移、拖动、搜索定位、重新布局、关系高亮和本机布局恢复。选择和普通数据更新不重排网络。
5. P2 AI Agent 可以编辑人物、地点、事件节点、事件线的业务字段，并增删改人物关系；允许修改人工结果。工具具备明确字段参数、读取依据、版本检查、事务和持久确认。
6. 数据库与备份增加按人物对保存的编辑结果，保证人工删除经刷新仍有效，后续 AI 显式提交可以恢复。

业务名称：“人物对”指本书两个不同的有效人物编号，与当前从哪一人的编辑器进入无关；“人物关系网络”指这些人物对的可视图；“关系编辑结果”是一次人工或 AI 保存后该人物对的当前状态，包含已删除状态。

## Capabilities

### New Capabilities

- `character-network`：人物网络显示、稳定布局、视角持久化及编辑器联动。

### Modified Capabilities

- `asset-management`：ASSET-01 搜索与选择；新增人物两栏、未保存处理、人物对维护条款。
- `agent-session`：新增全资产编辑工具及逐字段输入、结果、证据规则。
- `world-organization`：P2 全资产核对阶段、显式编辑人工结果及报告。
- `task-recovery`：P2 跨世界与叙事资产的双域执行权、恢复与幂等。
- `book-backup`：版本 7 关系编辑结果的升级、导出和恢复。

## 讨论结论

### 已确认业务规则

1. 人物层级沿用主要人物、重要配角、NPC、路人。空搜索按这一顺序，再按主名拼音、编号自然顺序。非空搜索仅主名别名参与，保持原相关度算法中适用的姓名/别名规则。
2. 人物对是双向关系的共同编辑单位；每方向可有多项标签，至少一个方向非空。不同同名编号互不影响；既有多章原文依据保留可追溯。
3. 人物普通表单手动保存，层级选择即时保存；关系弹窗独立保存。切换人物、关闭、新增或离开人物编辑时，未保存内容提供保存并继续、放弃并继续、取消。列表/网络切换保留选中及输入。
4. 人工和 AI 使用同一当前数据，后提交的有效显式编辑生效；不存在人工关系永久保护。刷新、读取、自动索引重算不能视作新的编辑。AI 修改前重新读到当前状态及依据。
5. 网络初次无选择时显示全书；圆形节点按四层级大小区分，一对人物一条线；选择只高亮自身及邻接关系。旧方向不明的描述仍显示“方向未明确”，不编造反向含义。
6. 初次和主动重新布局运行力导向，碰撞间距优先，重要性中心引力为软约束。已保存位置优先恢复；关系变更只改线，层级变更只改大小，下一次重新布局再调整中心位置。
7. 列表和网络共享完整编辑器、校验与保存，不建立简版。布局视角按书存本机，不进入书籍备份。
8. P2 增加编辑能力；既有四类资产新增、删除及合并入口继续遵循其当前规则。本变更新增的删除工具针对人物关系；四类资产新工具是字段编辑工具。

### 实施决定及选择理由

采用“原关系事实 + 按人物对编辑结果”的方式：原文事实继续可追溯，编辑结果精确覆盖某一人物对；只改一条底层事实会同时影响多个同名目标，全部改成新关系事实又会丢失原来源归属。具体数据与合并算法见设计。

P2 全资产编辑需要核对目标资源的执行权。P2 继续持有世界租约，编辑节点或事件线时在提交事务内临时取得叙事资源；P3 占用则返回资源忙碌，保留该项待继续而不等待锁。这样保留现有 P2/P3 并行能力，也避免拿世界锁直接写事件。精确顺序见设计。

列表比例、字段的多标签输入、尺寸、缓存键及性能样本是本次授权内实施决定，详见设计和验收。尚未解决的业务问题：无。前置变更验收记录的一致性属于已有材料核对事项，不能伪造验收结论。
