# P2 整理报告分成代码与 AI 两栏

## 结论

P2 主区域不再常驻机械合并队列统计和明细；“查看整理报告”打开后分成“代码整理”和“AI整理”两个报告栏。代码整理栏显示队列、合并组和候选扫描结果，AI整理栏保持现有报告内容。

关联需求：REQ-017。级别：中型，采用 project-local。当前状态：待确认。

## Why

当前 P2 面板只要存在队列，就一直显示：

```text
待处理 0 组 · 已合并 12 组 · 失败 0 组
```

这行统计和下面的队列明细在操作区占用空间，且与“查看整理报告”里的代码整理结果重复。用户希望 P2 主区域只保留操作入口，把代码整理结果和 AI 整理结果分开展示。

## What Changes

1. 从 P2 主面板移除机械合并队列统计、队列明细和对应操作按钮；主面板只保留整理范围、代码整理、一键机械合并、AI整理、取消和“查看整理报告”。
2. “查看整理报告”改为两个分栏：
   - **代码整理**：显示待处理/已合并/失败组数、每组状态和失败原因、代码合并组、候选扫描摘要、零模型调用说明。
   - **AI整理**：保持现有 AI 报告内容，包括合并组、资产核对、修改前后值、别名核实、整编、費用和余项。
3. 打开报告时按以下顺序选择：
   - 从运行状态进入：优先选中传入的运行；该运行不存在或没有报告时回退到同类最新报告，再回退到另一类最新报告。
   - 普通打开：选择 `finishedAt ?? startedAt` 最新的报告；时间相同按运行编号排序。
   - 切换分栏保留本弹窗内各栏的选择；关闭重开后不跨会话保留。
4. 代码整理栏分为“当前队列”和“所选历史报告”两块：
   - 当前队列始终取最新队列运行，显示统计、成员、状态，并保留“移除待办”和“重新核对”操作。
   - 所选历史报告只读显示该次运行的合并组、候选摘要和失败信息，并标明运行时间和编号。
5. 代码整理每次扫描都保存候选摘要，供报告栏在刷新后继续查看；复用现有 `report.skipped` 字段，不新增存储字段。
6. 队列仍在后台持久保存和执行；移除主面板展示不改变入队、一键合并、失败重试和统计收尾逻辑。
7. 代码整理保存新扫描报告后，同步更新服务状态中的报告编号，使下一次打开报告能选中刚完成的结果。

## 实施方法

### 报告分类

| 分栏 | 运行来源 | 主要内容 |
|---|---|---|
| 代码整理 | `phase` 为 `mechanical`、`mechanical_queue` 的 P2 运行 | 当前队列、所选历史报告的合并组、候选摘要、失败原因 |
| AI整理 | 其余有 `report` 的 P2 运行 | 现有 AI 报告内容 |

代码整理运行没有模型调用，费用固定显示 0；AI整理沿用实际用量和费用状态。

### 代码整理栏结构

代码整理栏从上到下分为两块：

1. **当前队列**：始终取最新 `mechanical_queue` 运行，显示待处理/已合并/失败组数、队列成员、状态、失败原因，并保留：
   - “移除待办”：调用现有 `mechanical.remove`，成功后刷新当前队列和报告；
   - “重新核对”：关闭报告、回到主面板候选选择，复用现有 `reviewQueue` 流程；失败组重新入队后出现在当前队列。
   - 队列运行中或主面板忙碌时两个操作禁用。
2. **所选历史报告**：显示代码运行选择器，列出扫描报告和队列运行，标明时间、编号和类型。只读显示该次运行的合并组、候选摘要和失败信息，不显示操作按钮。默认选择最新代码报告；若最新是当前队列运行，历史块显示该次运行中已完成的合并组和候选摘要，并与上方当前队列使用同一运行编号和时间。

历史报告和当前队列分别标注来源，避免查看旧报告时把今天的队列成员当成旧报告内容。

### 默认选择

- 运行时间排序字段为 `finishedAt ?? startedAt`，降序；相同时间按运行编号降序。
- 打开报告时传入 `state.reportId`：
  - 运行存在且有报告：选中该运行所属分栏和运行。
  - 运行不存在、已删除或没有报告：回退到同类最新报告；同类没有时回退到另一类最新报告。
- 普通打开：代码和 AI 各自选择最新报告；默认分栏取时间更新的那一类。
- 只有代码报告时默认代码栏，AI栏显示空态；只有 AI 报告时相反；两类都没有时不显示“查看整理报告”按钮。
- 分栏内选择只在弹窗打开期间保留；关闭重开后重新按上述规则选择。

### 保存候选摘要

当前 `service.organize` 只在没有自动合并时保存扫描报告。改为每次代码整理都保存一份代码运行报告，把候选写成现有 `report.skipped` 字符串，每个候选组一条，例如：

```text
人物候选：北静王（C1-P001）、水溶（C2-P010）；命中：主名与别名相同；共享：北静王、北静郡王
地点候选：长安侯府（C3-P002）、长安侯旧宅（C4-P008）；命中：主名包含
```

同一轮已有机械队列运行时不覆盖队列运行，而是新增一份独立代码扫描报告。代码整理保存报告后同步更新服务状态中的报告编号，下一次打开报告优先选中刚完成的结果。

## 字段变化

无新增、修改或删除字段。`WorldReport.skipped` 继续保存候选与待复核摘要；`WorldRun.mechanicalQueue`、`WorldRun.report.groups` 沿用现有结构。旧报告无需迁移。

## 数据流转

用户点击代码整理 → 扫描当前人物/地点 → 自动合并完整同名项 → 生成候选摘要 → 写入代码运行 `report.skipped` → 更新服务报告编号 → 用户点击查看整理报告 → 按运行类型分栏 → 代码栏读取当前队列和所选历史报告，AI栏读取现有 AI 报告。

## 触发逻辑

| 触发 | 前置条件 | 顺序及状态 | 反馈与失败 |
|---|---|---|---|
| 点击代码整理 | P1完成，无世界/提取任务 | 自动同名合并→候选扫描→保存代码报告→刷新候选栏 | 扫描失败保留错误，不显示半份报告 |
| 点击查看整理报告 | 存在任一 P2 报告 | 指定运行优先→否则最新报告→用户切换代码/AI | 无报告时按钮不显示 |
| 切换分栏 | 弹窗打开 | 保留本弹窗内各栏选择 | 分栏无报告时显示空态 |
| 代码栏移除待办 | 当前队列有待处理/失败组，非运行中 | 调用移除→刷新当前队列和历史块 | 失败显示原因，队列不变 |
| 代码栏重新核对 | 失败组，非运行中 | 关闭报告→主面板选择候选→调整后入队 | 取消选择不改队列 |
| 刷新页面 | 报告已持久 | 重新读取运行记录 | 不自动运行整理 |

## 确认依据

2026-11-04，用户要求去掉 P2 主区域常驻的“待处理 0 组 · 已合并 12 组 · 失败 0 组”列表，把内容放进“查看整理报告”，并在报告内分成代码整理和 AI 整理两个报告。用户要求先写文档审核，再按文档实施。

2026-11-04 审核意见：移除主面板队列块会丢失移除待办和重新核对入口；历史报告会混入当前队列；默认选择和空态不确定。本稿已把两个操作迁入代码整理栏、分开当前队列与所选历史报告，并补充指定运行优先、最新排序、回退和空态规则。

## 不做什么

- 不改变机械合并队列的执行、恢复和统计逻辑。
- 不删除代码整理或 AI 整理的任何报告数据。
- 不新增备份字段或数据库版本。
- 不把代码整理候选自动合并。
