# AI疑似人物发现与人工合并方案

后续确认：分页与组编辑按[阅读流程](identity-reading.md)和任务19实施，下方每页保存时同时翻页的描述保留为此前方案依据。

## 用户要求与确认范围

2026-11-12，用户要求优化P2第一步，明确禁止AI直接合并人物；AI输出疑似组合，在代码合并候选所在位置展示，用户打开后手动合并。希望模型作为连续Agent分页阅读，每页用工具提取疑似组，后续页发现与已有组相关的人物时更新或合并疑似组；必须优化提示词，明确目的与要求。

沿用REQ-019，大型需求。2026-11-12用户以“开始吧，整合你我的，冲突的以我为准”确认实施；覆盖下述流程，补充优先规则：识别运行中人工合并按钮直接置灰，不自动暂停；第一步只提供归类和查阅工具，提示词禁止AI实际合并，其他无关工具不开放。实施任务见任务18。

## 现状与目标

改前第一步按人物ID每100人分页，每页独立工作上下文；扫描产生candidateGroups，随后独立candidate工作项可调用merge_assets直接合并，再登记结论并清空候选工作集。UI的代码候选由WorldPanel局部状态管理，与AI候选未形成统一人工确认列表。

目标流程：启动AI识别 → 连续Agent领取目录页 → 结合已读资料及已有疑似组判断，必要时查询历史人物/原文 → 批量保存新增或更新疑似组并推进页游标 → 同一位置实时展示候选 → 全书读完标记识别完成 → 用户选择成员、主名和保留对象，预览并确认实际合并。第一步不自动运行资料或关系整理。

### 推荐方案

1. 连续Agent保留当前轮对话；长上下文通过既有压缩能力保留工作摘要，可靠记忆来自可查询的已扫描人物目录、已保存疑似组和页进度。不能仅记已有疑似组：早先单独出现的人物也必须能在后续被找到。
2. 每页常规批量提交候选与页完成状态，可提交空候选。程序返回下一页信息，Agent继续；补查不限制为每页固定一次API。原文证据或身份冲突需要时才查询，不强制逐人查原文。
3. 后续人物可加入已有疑似组；两组疑似指向同一人时，只更新候选记录，不融合人物数据。A疑似B、B疑似C不能机械推断三者必然同人，需比较冲突并给出理由。
4. 第一阶段只开放读取和候选写入权限，不开放资产合并、删除、资料/关系编辑；P2其他步骤同样不能绕过用户确认直接合并。工具发现也不得重新开放合并入口，旧自动合并任务恢复须转入新规则，不能继续旧写入路径。
5. 代码与AI候选在原候选区展示，标注来源、成员、疑似理由及冲突。同成员组去重；候选更新保留稳定身份。人工处理支持选择部分成员、预览与确认合并，以及标记不是同一人；待核对候选不自动进入已确认机械执行队列。
6. 识别期间允许查看候选，人工合并、加入合并执行队列按钮直接置灰；不自动暂停识别。识别结束或用户主动暂停后才可操作，沿用既有同书执行锁。人工合并后继续扫描，按生命周期刷新失效编号与候选引用。
7. 候选和页进度持久保存，刷新/暂停不丢失。扫描完成不再清空未处理候选。人工确认后历史只记录实际合并，沿用用户此前不需要展示第一步完整Agent链路的要求。

## 提示词草案方向

目的：找出本书可能属于同一人物的多条记录，形成供用户核对的候选组；不能实际合并人物。

工作方式：逐页阅读姓名、别名和必要身份信息，结合此前读到的人物及已存候选判断；后续发现关联可更新已有组，不重复创建；不确定时按需读取详细资料或原文；每页完成后保存本页候选结果并领取下一页，扫描结束保留全部待人工核对候选。

判断要求：明确别名/本名对应和相互吻合的特有经历可支持同人；仅同名、相同官职、泛称或同场出现不能直接认定；年龄、亲属、身份、时间线中的实质矛盾须写明，不为凑组忽略反证；每组提供具体疑似理由和仍待核对的问题，不伪造置信度。不要求固定调用次数，允许工具之外正常说明。

## 字段、数据流及触发变化

字段变化：复用现有疑似组的编号、成员、理由、状态、版本和来源步骤，以及扫描页状态、人工结论和会话条目。疑似组改为持续保存，执行版本升级为5；备份的命令类型增加submit_identity_page，其他字段类型不变。具体赋值与读取见下方已确认实施设计。

数据流：人物当前资料 → Agent分页/历史查询 → 候选提议保存 → UI共同候选区 → 用户确认的成员与保留对象 → 既有合并事务更新人物、引用和生命周期 → 候选状态及实际合并历史刷新。候选合组仅更新提议；人工确认才产生真实资产合并。

触发：启动/继续识别仅推进扫描；提交候选不触发实体写入。用户点击确认合并才调用合并事务。运行中按钮置灰；主动暂停并释放执行锁后可人工处理，继续时按生命周期解析最新人物编号。重复启动沿用执行锁；取消后重扫新建运行并承接最新候选集；已否决候选保留人工结论，不被模型重新改成待处理。

## 验收计划与下一步

- 跨页样本：第一页沈青/老沈成组，第二页小沈加入同组；另测第一页只有单独人物，后页才出现别名对应，仍能发现。
- 无实体写入：AI无论候选是否明确，人物数量、资料和引用不变；实际合并及工具发现绕过均不可执行。
- 同名异人、同官职、矛盾年龄/亲属样本不被自动混为一组；有反证应在候选中可见。
- 候选与代码候选同位置显示，支持局部选人、预览、人工确认、不合并；未确认候选不能被执行队列自动消费。
- 刷新/暂停/继续保留进度及候选；人工合并后继续不会使用失效编号重复合并。
- 旧自动合并工作项继续时不能执行旧合并命令；备份导入保留人工待处理状态。

## 已确认实施设计

- 复用 pipelineRuns.organization.scanPages、candidateGroups、candidateDecisions；候选字段、状态及备份结构不增加新类型。候选不再扫描结束后清空。运行版本提升，旧resolve工作项转到扫描完成/待人工处理，不再执行自动合并。
- 新工具 submit_identity_page 接收 pageId、groups；每组含可选groupId、可选合并的candidate groupIds、memberIds和reason。程序生成幂等键；同一事务保存本页所有候选、完成页状态，返回当前候选变更和下一页。合并candidate记录只改变提议，完全不写人物。候选成员须存在且来自已提供目录或实际查阅。
- 第一阶段只有 submit_identity_page、query_character_catalog、query_candidate_groups、get_character_detail、get_character_relation、read_original 等查阅/归类工具；不开放工具发现、资产写入及单独总结工具。P2其他步骤也移除实际merge_assets，避免绕开人工确认。
- 第一阶段固定连续工作项 identity，跨页不终止Agent；页提交仅在最后一页 complete=true。历史消息按该工作项恢复，长上下文使用原压缩机制并保留当前页/候选可查询入口。目录查询支持名称、别名、身份搜索，分页和历史人物均可查，不只记已成组者。
- 人工候选列表汇总持久AI候选和当前代码候选，按成员去重。通过既有资产生命周期映射当前成员，已全部合并的组不再展示；支持原预览/确认/选取子集，并可将AI候选登记为not_same。新一轮识别承接既有候选及人工结论，原候选更新不覆盖人工否决。
- 实际合并仍走既有人工确认事务和历史，不把候选归类计为实体合并。识别时按钮禁用与既有执行锁共同生效；不新建自动暂停或自动确认流程。
- 例：第一页保存G1=[P001,P002]；第二页提交groupId=G1、memberIds=[P001,P002,P102]，只扩充G1，三个人物不变。用户结束识别后只选择P001/P002确认合并，生命周期将P002映射到P001；列表显示G1剩余[P001,P102]，全部成员合并后该组退出待核对列表，数量同步更新。
- 检查包括跨页组扩充、两候选合组、早页单人后页成组、刷新继续、候选持久化及人工否决、只读工具集合、AI不改人物、运行时人工按钮置灰、实际人工合并后候选收敛、旧resolve恢复及备份兼容。

按确认范围实施；不调用真实模型或修改正式书库，用户副本验收后再归档。
