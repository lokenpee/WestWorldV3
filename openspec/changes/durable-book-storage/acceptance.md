## 已完成的保存链路

本机 HTTP、SQLite、Windows DPAPI 凭据加密、网页存储适配、书架/资产/导入/配置/备份/删除、P1/P2/P3、Agent 日志和执行权均已接通。所有领域事务显式传入当前事务数据库，提交失败整体回滚。日志分页在 SQLite 内执行。

首次打开及设置页均提供旧数据迁移入口。迁移只读打开旧库，内存转换及核对后暂存，再与书架、完成标记一并提交；重复操作保留磁盘已有的后续修改。源库不会删除。手动导出目录的浏览器授权句柄单独保留在权限库，书籍及凭据不依赖该库。

主库自动保存；首次变更及时生成恢复副本，后续合并调度，最多每 5 分钟生成一次，保留最近 5 份。备份失败单独显示，主库提交结果仍有效，设置页可重试。

## 本轮发现并修复的问题

### 浏览器事务等待占满连接池

实际浏览器导入时，等待其他事务的请求占满同源 HTTP 连接，导致持有事务的请求无法继续读取或提交，页面持续加载。开始事务遇忙现在立即释放请求，由客户端稍后重试。浏览器导入及重启验收已覆盖该执行路径。

### BUG-46：旧整理收尾覆盖新任务

磁盘领域回归中，“取消废弃旧队列，下一次开始创建新 runId”暴露竞争：旧执行器的异步收尾可能晚于新任务启动，无条件清理执行权并设置停止状态。

修复后只更新属于当前 runId 的进度及租约；只有仍持有对应控制器的执行器能清理页面运行状态。收尾保存失败显示错误并保留可恢复状态。原有取消重开回归继续在 IndexedDB 与 SQLite 两种实现下运行。

## 用户验收

尚待用户在原浏览器中操作迁移入口并核对小说副本。建议按顺序检查：

1. 使用 E 盘启动脚本，首次页面点击“迁移浏览器旧数据”，完成后“进入磁盘书库”；检查书籍、章节、人物、事件线和模型配置。
2. 在书籍副本修改一个字段，暂停并继续已有整理，查看整理详情；可使用现有整书导入导出核对副本。
3. 关闭浏览器及服务，重新启动，确认书籍、修改、整理进度与模型配置仍在。
4. 设置页核对保存目录、最近保存和最近备份时间。

正式库迁移只由用户点击触发。用户确认前，REQ-023 保留活动变更，主规格不同步、不归档。
