# 本机持久化实施设计

## 结构与实施顺序

REQ-023 / BUG-45。项目为 `E:/WestWorldV3`，主数据目录为 `E:/WestWorldV3-data`；v0.6.0 / 7fdc57a 是改造前保存点。

网页继续负责交互与现有任务调度。本机存储服务负责SQLite、凭据加解密、事务、数据库升级和备份；关闭网页仍停止模型请求，不新增后台Agent。业务模块通过存储接口访问资产，IndexedDB适配保留用于旧数据读取和既有隔离测试。

先实现可独立验证的SQLite存储和事务接口，再接本机HTTP和网页存储适配，最后接迁移入口、配置和启动脚本。切换前必须验证全部写入入口，不能让部分功能写浏览器、部分功能写磁盘。

## 字段变化

业务对象字段沿用[数据契约](../../../docs/v2/03-Spec-数据与存储.md)，不改变人物、关系、事件线和完成指纹含义。

| 对象与存储位置 | 新增字段及含义 | 类型、默认与赋值 | 消费者与兼容 |
|---|---|---|---|
| SQLite元数据 | schemaVersion（数据库格式版本） | 整数，首次1，由服务升级事务维护 | 启动校验；未知新版停止打开，不重建空库 |
| SQLite记录 | scope（设置库或书籍）、tableName（逻辑表）、key（原主键）、value（业务JSON）、revision（存储版本） | 字符串/JSON/递增整数；服务写入 | 现有业务revision原样保留；存储版本用于并发检测 |
| 保存状态 | lastSavedAt（最近落盘时间） | ISO时间，成功提交时更新 | 设置页及保存反馈 |
| 凭据 | 加密后的key内容 | Windows DPAPI用户范围密文，由服务读写；不记录明文日志 | 原providerId不变；普通wwv2仍排除凭据 |
| 迁移清单 | source、bookId、digest、status、counts | 来源与哈希、阶段和表数量；迁移事务更新 | 重试识别已复制内容；失败保留原库 |
| 恢复副本 | 数据库快照文件及时间 | 变更后定期生成；保留最近5份 | 恢复前先验证格式和完整性；不从浏览器清理事件推断删除书籍 |

## 数据流转

读取：网页领域服务 → 存储查询接口（主键、索引、分页） → 本机服务 → SQLite → 当前对象与版本 → 页面。日志分页查询，不先拉取全部消息。

提交：领域服务读取当前资产 → 计算修改 → 事务接口检查预期版本/已有执行租约 → 同一SQLite事务写入资产、进度、幂等凭证 → COMMIT成功 → 返回结果与保存时间 → 刷新订阅。任何一步失败回滚，不报告已保存。服务重新启动读取原数据库，浏览器站点清理不触及磁盘。

例如事件线L1增加N2时，L1.nodeIds从[N1]变为[N1,N2]，N2的所属线及P3提交凭证同批写入；中间发生异常时三项均不改变。另一个窗口已修改L1时拒绝过时提交并提示重新读取，不覆盖新值。

浏览器事务目前有大量闭包隐式引用db和settings；适配时改为显式事务对象，并检查闭包内辅助函数、凭据表变量、执行权检查和嵌套事务。不能仅替换数据库构造器。

## 触发逻辑

| 触发 | 顺序、条件与反馈 | 失败及恢复 |
|---|---|---|
| 启动脚本 | 检查Node支持、E盘数据路径 → 启动同机服务 → 固定127.0.0.1地址打开网页 | 数据服务失败时明确报错，不能悄悄降级为空浏览器库 |
| 普通保存、整理提交 | 执行存储事务，成功后显示已保存 | 磁盘满、只读、冲突均保留错误，不能回报成功 |
| 新页面/清理站点后打开 | 从同一磁盘目录加载书架、配置和凭据 | 服务不可达显示重试，不创建另一份空书库 |
| 迁移旧浏览器数据 | 用户点击迁移 → 检查旧任务已暂停 → 复制及核对 → 启用已迁移书库 | 旧任务仍运行则提示先暂停；已有磁盘书籍不得静默覆盖；重试复用已验证部分；源库保留 |
| 自动备份 | 有提交时合并调度，最多每5分钟一次；首次及迁移成功后生成 | 备份失败单独显示，主库已提交结果仍有效；下次变更重试 |
| 删除书籍 | 沿用显式删除确认及运行锁检查 | 不把来源浏览器空库当作删除指令 |

## 接口与运行约束

本机服务只监听回环地址，同源接口校验请求来源；网页不能提交任意文件路径或SQL。支持读取、分页、提交及状态操作；表名及主键依据既有表结构。凭据解密仅用于当前服务配置和模型调用，不出现在书籍导出或错误详情中。

SQLite使用WAL与完整同步；格式升级有版本号且在事务内完成。备份通过SQLite一致性备份接口，不能直接复制正在写入的主文件。数据目录由本地启动配置决定，设置页只读显示当前位置，避免两个窗口各用不同目录。

## 已实现的接口及事务绑定

- `server.ts`作为本地Vite服务的同源`/api/storage`接口；只接收逻辑scope/table/key及固定操作名。启动脚本设置`WESTWORLD_STORAGE_DIR`，页面必须连接成功才初始化磁盘工作空间，无法连接时提供重试。
- `client.ts`实现现有业务使用的表查询接口，`transact`明确传入当前事务数据库；人物、关系、事件线、提取凭证、执行权辅助函数和模型凭据读取均使用该句柄。既有IndexedDB实现用于迁移源及隔离回归。
- 事务开始按scope串行占用服务内会话；变更暂存在该会话中，读操作叠加本次变更；结束时一次调用SQLite提交，失败丢弃全部变更。事务中不调用模型，空闲60秒会释放。服务退出时未提交会话不会写盘。繁忙的HTTP开始请求立即返回“待重试”，客户端等待后重试，不占用浏览器连接池阻塞持锁者。
- Agent原有快照、revision、执行租约和幂等凭证检查保留。读取日志的分页在SQLite执行，并按引用主键读取对应提示词快照；磁盘日志不再使用浏览器配额决定是否降级。
- 提交后通知当前页面，其他页面按磁盘revision变化刷新。自动备份提交后合并调度，首次及时生成，后续最多每5分钟生成一次；最近备份时间随数据库保存，设置页显示目录、保存时间及备份错误。

## 迁移与浏览器权限对象

用户点击迁移后，源库以无版本声明的Dexie打开并用只读事务取得快照，不执行升级及ready修复。版本5至8沿用整书备份的内存转换和校验；运行中的任务先要求暂停。数据暂存到`book:pending:<id>`，核对全部字段和表数量后，与书架及迁移完成标记在同一SQLite提交中发布；该提交同时清除暂存记录。未发布的暂存数据不会出现在书架。

迁移标记为`settings/appSettings`的`migration:book:<id>`，包含source/digest/counts/status。同一来源快照重复迁移会跳过已完成书籍，保留磁盘上的后续人工修改；不同快照与已有编号冲突时提示通过备份恢复副本。模型设置及凭据仅填充磁盘尚不存在的条目，凭据由服务加密。

`assets.exportDirectory`是FileSystemDirectoryHandle浏览器权限对象，不能JSON写入SQLite；它单独使用`<settingsName>-permissions`浏览器库，不参与书籍或模型配置持久化。清除浏览器数据后只需重新授权手动导出目录，自动恢复副本不受影响。原库该对象保留，不复制成无效JSON。

## 验收入口

Node环境已检查为v24.14.0，内置node:sqlite可用；最新测试数量及证据见验收记录。测试路径必须是系统临时目录或独立E盘临时测试目录，不能指向 `E:/WestWorldV3-data` 正式目录。

检查入口见[任务](tasks.md)及[验收](acceptance.md)。完成条件：旧库迁移数量及关联一致；正常关闭、服务重启、清站点数据后书架及假Key保留；事务失败全部回滚；重复提交幂等；P1/P2/P3暂停继续及备份恢复通过。真实模型不参与存储验收。用户副本自测通过后同步主规格和归档。
