# 书库持久保存与浏览器数据丢失恢复（讨论稿）

## 原意与状态

REQ-023，2026-11-12用户询问：目前数据均在浏览器IndexedDB，清理缓存/网站数据或其他情况下可能消失，有什么应对方法。目标是长期保留小说原文、整理结果和会话，降低已付出模型费用的成果丢失风险。当前只讨论选项，尚未选择实施路线，不授权迁移或改写正式书库。

整体暂按大型需求登记；若最终只选择已有备份能力的局部增强，再按最终数据和接口影响分级。关联REQ-010的备份兼容、REQ-019/020的整理结果和会话保存。

## 现状

- 单书IndexedDB保存原文、资产、运行记录和会话；全局库另存书架、模型配置和凭据。
- 已有`.wwv2`整书快照导出、校验、导入为独立副本，支持下载和授权磁盘目录写入。
- 目录句柄保存在浏览器设置库，清除站点数据后需要重新选择目录；已写出的普通磁盘备份文件仍可手工导入。
- 目前没有自动磁盘备份，也未发现navigator.storage.persist接入。现有单书备份不包含模型密钥/全局设置。

## 待选方向

1. 浏览器持久存储申请：减少存储压力下的自动驱逐，不能防用户清除站点数据，只作为补充。
2. 保留IndexedDB，增加授权目录自动备份：有修改时合并调度，关键任务完成后保存，保留多个版本，显示最近成功时间；失败/权限失效可见。页面关闭时不依赖卸载事件完成保存，恢复最多到最近成功备份。复用现有格式，另评估全局非敏感设置备份。
3. 本地服务或桌面应用，以用户数据目录中的SQLite等本地数据库为主存储：界面继续复用，业务提交通过本地服务事务保存，浏览器清理不删除主库。此路线需要数据库适配、全量迁移校验、任务并发与恢复改造及独立备份；不是把SQLite放进浏览器OPFS。

本次建议：用户已经使用本地启动脚本，并明确要求关闭浏览器后保留书籍与Key且不依赖手工导出，优先选择第三种中的本地服务，保留网页界面。授权目录自动备份是改动较小的备选，但保留浏览器主存储、最近备份间隔及目录权限恢复问题。云端备份/多设备同步属于可选后续选择，用户尚未要求上传数据。

## 2026-11-13 关闭浏览器后书架及密钥消失

关联 BUG-45。用户要求解决关闭浏览器后书籍及Key无法保存，并补充通过 `scripts/启动本地服务.bat` 自动打开。尚未提供浏览器名称、配置文件、是否无痕及实际打开地址。

已确认代码证据：
- `scripts/local-service.ps1` 默认固定 `http://127.0.0.1:5173/`，使用 `--strictPort`；端口占用报错，不自动换端口。当前只是启动Vite，没有磁盘数据服务。
- `src/main.tsx` 使用 `createWorkspace()` 默认固定库名；`workspace.ts` 的设置库为 `westworld_settings`，书库前缀为 `westworld_canon_`。
- `models/config.ts` 在IndexedDB事务内保存配置及Key；`ModelSettings.tsx` 保存后输入框留空，配置成功以“密钥已配置”识别，不能仅凭空输入框断言Key丢失。
- 本轮所查启动、设置及存储关闭路径没有发现“关闭网页即清空书库/密钥”的行为。关闭浏览器后书架为空的实际根因尚未证实；需区分站点数据清理、浏览器配置/访问来源变化及存储异常。

建议的具体行为，待用户确认路线：
1. 原启动脚本同时启动本机数据服务和网页。数据默认保存在当前Windows用户的 `E:/WestWorldV3-data/`，设置页可查看位置；与项目代码、浏览器缓存分离。
2. 本地SQLite为书架、原文、资产、运行进度、Agent会话及模型配置的主存储；每次保存和已成功整理提交在磁盘事务完成后回报成功。浏览器关闭/清理站点数据不删除磁盘主库。模型运行仍保持当前关闭页面后的停止及再次打开后续跑规则，不据此扩展后台Agent运行。
3. Key通过本机服务保存，使用Windows用户加密能力保护落盘凭据；书籍导出继续排除Key。模型调用所需凭据读取也须纳入适配，不在日志输出密钥。
4. 首次接入将当前能读到的浏览器旧数据复制到磁盘，核对数量、关联及进度后使用新存储；保留原库，不清空或覆盖已有磁盘书库。已丢失的数据只能从仍存在的旧库或既有备份恢复，不能凭空重建。
5. 自动生成轮换恢复副本，并显示最近成功保存时间；磁盘写入失败显示原因，不能回报已保存。备份频率、保留数量、迁移冲突及事务接口在完整设计中明确。

拟修改模块：本地启动脚本、本机存储服务、共享存储适配、模型配置/凭据、导入与备份，以及P1/P2/P3事务和恢复调用方；现有业务字段和整理要求沿用原契约。

验收方向：固定样本导入及设置假Key后正常关浏览器重开、关闭服务再启动、清理测试浏览器站点数据后重开，均恢复同一书籍、配置和Key；写入失败不假成功；迁移可中断恢复；使用固定模型响应检查P1/P2/P3已提交结果和暂停续跑，无真实模型费用。
