## 场景

| 编号 | 前置与操作 | 必须结果 | 当前证据 |
|---|---|---|---|
| T01 工具归属 | 同一人物连续两次请求，两次调用不同工具，第二次仍在运行 | 第一条请求只显示自己的旧工具；第二条只显示自己的新工具；工具不因新请求出现而跑到旧请求下 | 开发检查通过 |
| T02 展开稳定 | 实时运行时展开一条旧请求并向上滚动，等待新工具和下一请求 | 展开状态不被自动收起，滚动位置保持，工具不上下跳；有新请求时可点“回到最新” | 部分通过：移除受控开关并有“回到最新”，滚动位置专项待补 |
| T03 长内容 | 输入含数万字符、工具返回长结果、工具定义较多 | 展开后能读到完整保存内容；截断只出现在明确标记的降级/缺失场景 | 开发检查通过 |
| T04 空结果 | 工具尚未返回或结果为 undefined/null | 显示“等待返回/未记录”，不抛异常；面板其他请求仍可用 | 开发检查通过 |
| T05 输入展示 | 展开任一 API 请求的输入消息 | 系统/业务提示词、结构化消息、工具定义、估算/实际 token 可查看；长内容可滚动到底 | 开发检查通过 |
| T06 单一入口 | P2/P3 面板外部 | 不再同时出现“查看整理报告/请求与用量/运行详情”三个重复入口；一个“整理详情”打开连续 API 会话流，顶部统计、底部实际修改；报告可从内部打开 | 开发检查通过 |
| T07 P2 人物窗口 | 连续处理多个人物，再切换窗口 | 先按人物/工作窗口切换；人物窗口内可切资料/关系上下文；当前人物只显示自己的回合；目录、候选不混入人物窗口；姓名优先、UUID 在回合信息 | 开发检查通过 |
| T08 P3 会话 | P3 运行多个请求 | 保持一个持续会话按顺序展示，不出现 P2 人物窗口 | 开发检查通过 |
| T09 修改结果 | 一次 changed、一次 no_change，包含未完成提交工具 | 只展示实际写库 assetEdits 的字段前后值、理由、commitId、保存状态；提交工具参数以 TOOL CALL/TOOL RESULT 出现在会话流，不冒充已保存 | 开发检查通过 |
| T10 阅读位置 | 用户向上翻旧请求时持续实时更新 | 不自动折叠、不跳回顶部；仅对应请求更新；“回到最新”可用 | 部分通过：展开不再受控，滚动位置保持待专项浏览器测试 |
| T11 用量 | 打开同一个整理详情查看顶部统计和逐请求用量 | API 次数来自真实 request_trace，工具次数来自实际工具记录；Token/费用与请求对应，未知费用不显示为 0 | 开发检查通过 |
| T12 用户验收 | T01–T11 完成 | 用户确认界面和真实运行；未确认不归档、不提交 Git | 待用户验收 |
