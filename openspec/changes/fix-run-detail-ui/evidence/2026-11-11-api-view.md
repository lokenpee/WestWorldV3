## 已实现

- 每次请求一张卡片：发送给API → API返回 → 工具执行结果。消息及工具默认折叠，回复正文直接展示；删除第二套事件流、拼接“原始JSON”、重复标题和执行/会话UUID。
- 实际fetch发送体的消息与工具由只读观测回调记录；保留输入中的历史回复、工具结果及推理内容，不根据业务Prompt拼造发送内容。旧日志标为历史上下文。
- 模型工具声明不包含内部outputSchema/label/execute；日志消息不再另带toolsAdded。工具执行结果只显示content，避免details/structuredContent的重复副本。
- 资料和关系提交隐藏自动生成的operationKey；关系提交仅向模型提供逐条basis。内部执行兼容已有顶层basis和操作键，空修改结束、逐条证据、部分失败语义保持。
- 人物索引首次读取立即执行，修复刚打开详情时被连续日志更新反复推迟的问题；后续仍合并刷新。
- get_tools_detail使用同一参数投影；资料/关系Prompt同步填写方式并更新两份哈希。
