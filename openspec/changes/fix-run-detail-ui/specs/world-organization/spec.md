## ADDED Requirements

### Requirement: WORLD-ORGANIZATION-TRACE-02 当前进度与人物整理详情
系统 SHALL 保留 P2 顶部操作按钮和启动、暂停、继续逻辑，进度区只显示当前操作。资料和关系整理显示当前人物、该人物累计 API 次数和输入/输出 Token、已处理人数和总人数；用量与详情共用实际请求统计。

#### Scenario: 当前人物用量
- **WHEN** 当前人物出现新的 API 请求或用量返回
- **THEN** 主面板动态更新该人物统计，不混入其他人物；未知用量显示待返回，进度显示已处理和剩余人数。

#### Scenario: 选择历史人物
- **WHEN** 用户打开资料或关系整理详情
- **THEN** 默认显示当前处理人物；已完成人物下拉框和姓名/编号搜索覆盖历史记录，同书同人物同类型只显示最新完成且已保存的详情；手动选择历史后不会被实时进度切换。

#### Scenario: 查看实际修改
- **WHEN** 用户查看某人物的实际修改
- **THEN** 只展示该人物对应的 assetEdits，按对象左右对照修改前后，理由在下方；提交工具参数不能冒充实际写库结果。

#### Scenario: 查看合并历史
- **WHEN** 用户打开识别与合并记录
- **THEN** 代码自动合并与人工、AI 合并记录分区展示，包含资产列表批量合并；每组可展开已保存的合并结果，不显示该阶段 Agent 链路。

### Requirement: WORLD-ORGANIZATION-HISTORY-01 完成人物详情替换
系统 SHALL 在同书同人物同类型的新整理完成并保存完整链路后替换旧详情，实际清理已被替代的旧消息和观测日志，保留业务报告及防重复提交凭证。

#### Scenario: 完成后替换
- **WHEN** 新人物资料整理完成且全部请求已最终保存
- **THEN** 清理该人物旧资料详情，关系详情、其他人物和 P3 不变；保留仍被引用的快照，修复保留消息父链和会话叶节点；重复维护结果不变。

#### Scenario: 尚未保存完成
- **WHEN** 新人物任务失败、暂停、尚未完成，或新链路缺失、不完整、仍在写入
- **THEN** 保留旧完成详情及新任务续跑数据；有效租约和可继续运行的旧会话不得被清理。

#### Scenario: 维护失败与旧数据
- **WHEN** 完成后或打开详情时维护历史，且清理事务失败
- **THEN** 旧日志保留，本次业务成功不被改写为失败，后续维护可重试；旧备份导入后遵循相同维护规则。
