# P2 用户图稿实施方案

## 需求、确认与级别

REQ-019、REQ-020 / BUG-33。2026-11-12用户提供 `D:/mic/未命名绘图.drawio (1).html`，明确废弃此前建议的主面板步骤标签和详情侧栏方案。随后确认：主面板统计当前人物，历史已完成人物跨轮去重；新一次同类型整理完成并保存成功后替换旧详情/链路，失败暂停保留旧完成记录和当前续跑内容；资产及防重复提交凭证保留。用户最后回复“对的”确认覆盖规则。历史保留语义变化按大型、project-full执行。

## 确认的界面

- 顶部按钮位置、启动/暂停/继续业务逻辑不变；代码整理候选及手动合并界面沿用。
- 下方只展示当前操作。人物资料/关系卡片含名称、状态、当前人物、该人物API数/输入输出Token与人数进度。与详情共用统计来源、随请求更新。
- 整理详情以类型选择、已完成人物下拉和姓名/编号搜索替代长队列。跨历史同人物同类型只列最新完成记录；未完成人物不进入搜索，当前处理人物单独默认展示。用户手动选择历史后不被新进度抢走。
- 同页纵向展示概览、实际消息链、实际修改。消息默认全部折叠，展开assistant包含正文、思考和tool call；消息按真实角色及内容呈现，不用固定角色顺序丢弃其他消息。实际请求完整内容可展开。修改按对象展示，前后并排、理由在下。
- 代码自动合并、人工核验/批量合并及AI合并的历史展示成员和合并结果，不展示识别重复人物的Agent链路。

## 字段与兼容

不增加模型工具字段、数据库表或索引，不升级数据库/备份版本。人物历史按书籍ID＋人物ID＋资料/关系类型投影，完成状态来自现有organization条目。读取索引的可选派生布尔值detailReady表示该人物已有请求且全部final=true、complete不为false，不持久化、不导出；trace读取器赋值，人物选择器读取，新链路未完整时优先保留旧完成详情。请求统计以requestId去重合并已保存记录和内存TraceSession；未知用量不能当成零。合并历史从pipelineRuns的P2及manual_merge报告读取。

仅清理已被较新完成记录替代的P2人物详情消息、工作输入及观测请求/未被引用快照。业务报告、资产修改、应用命令凭证保留。当前工作项与有效租约拥有者的会话不得被历史清理破坏；必要时更新保留消息parentId和session.leafId，保证续跑链完整。旧数据在成功完成或详情加载的维护入口按同一规则去重；可恢复任务内容保留。备份导出只包含保留数据，导入的旧重复记录沿同一维护路径收敛，清理不跨书或触及P3。

## 数据流与触发

顶部操作→当前运行/工作项→当前人物→持久请求＋内存请求→统一统计→进度卡片与详情。例：贾珩本次2次请求，第二次流式返回时，卡片与其详情都显示2次；切到贾政历史时只改变详情选择，主卡仍展示贾珩。

人物成功提交→runtime完成并保存日志→确认人物checked且新链路已落库→短事务清理同类型旧详情。资料A完成后只替换资料A，不影响关系A；新资料A失败时，旧完成资料A继续可选。首次查看历史时也可执行维护，将已有重复历史收敛；页面读取失败显示读取失败而不是无记录。清理失败保留旧日志，不把本次业务成功改为失败；后续维护重试。

## 验收与接手说明

- U01：固定响应隔离书，启动第二/三步，卡片只显示当前步骤与人物；API/Token与人物详情一致；暂停状态文案真实。
- U02：同一人物两次完成仅一项，另一类型独立保留；未完成无法搜索，当前人物默认可见；手动选历史后更新不跳走。
- U03：system/user/assistant/tool/其他实际角色默认折叠；展开全文和tool call，未知内容不丢失；375px可读、修改前后可对照。
- U04：代码自动、核验后手动、资产列表批量合并均可查；查看合并结果无API区。
- U05：完成替换旧链路；失败/暂停保留旧完成与续跑消息；保留共享快照引用、有效消息链、业务凭证，P3/其他书/另一类型不受影响；重复维护无额外改变。

实施入口为任务6；测试用固定响应和独立IndexedDB，不调用真实模型，不修改正式书库，不自动提交Git。用户自测后才同步/归档。原图仅作布局资料，不执行附件脚本。
