# 事件网络交互与整理详情折叠

## Why
REQ-027：用户希望用滑轮浏览网络，点击节点就能看清所属事件线，并根据所在栏目编辑节点或事件线。顶部全书事件线按钮随数量增加无法浏览。REQ-020 / BUG-33：详情仍有默认展开的请求和消息，与已确认的逐条折叠要求不一致。

## What Changes
- 鼠标所在位置作为缩放中心，画布内滑轮只缩放网络；保留拖动、按钮和键盘。
- 删除全书事件线选择栏。点击节点聚焦所属线，其他线和节点变淡，可取消聚焦。
- 节点栏目打开节点编辑器；事件线栏目打开所属线编辑器。共享节点沿用包含它的当前聚焦线，否则仅列该节点所属线供选择；未选择前突出这些所属线。孤立节点在事件线栏目显示未归线提示。
- P2/P3 链路首次展示的折叠框全部收起；展开 assistant 查看回复和工具调用。实时更新保留手动展开状态。

无。

- agent-session：新增 TRACE-COLLAPSE-01，落实 REQ-020 默认折叠。

## 确认依据
2026-11-13 用户对上述五项方案回复“开始吧”。确认共享节点选择、孤点提示、编辑对象跟随栏目及默认折叠。按中型 project-local 实施。

## 讨论结论
不再提供全书事件线按钮条；局部选择器只列所点节点的所属线。已有聚焦线且包含该节点时沿用，否则选择后打开线编辑器。切换编辑对象前沿用现有未保存修改提醒；取消切换保留原编辑对象和聚焦。没有未决业务问题。

## 字段变化
持久化字段、工具参数、模型输入和备份格式无变化。网络组件增加当前点击节点、栏目、待选择所属线等内存状态；均来自现有节点与事件线关系。已有每书视图缓存继续只存查询、筛选、聚焦线与视口。折叠状态仍为组件内存状态，默认 false，由用户点击赋值。

## 数据流转
资产面板读取节点、事件线、章节 → 网络布局生成节点所属线 → 点击按栏目确定编辑对象 → 通过现有 navigate 未保存提醒 → 更新内存聚焦及编辑器 selection。只有用户在编辑器保存才走既有资产写入事务。例：N2 属于 L1/L2；在事件线栏目点击 N2，未聚焦时显示两条选择；选择 L2 后编辑 L2 并淡化 L1；节点栏目同操作编辑 N2。滑轮只改变视口，不改节点成员。

整理详情读取已保存请求/会话 → 现有消息投影 → 默认收起的 LazyDetails → 用户展开时渲染正文。原始记录和实际修改不变。

## 触发逻辑
| 触发 | 条件与顺序 | 状态、反馈及恢复 | 模型/下游 |
|---|---|---|---|
| 滚轮 | 可见画布，计算鼠标坐标并限制缩放范围 | 阻止页面滚动，更新视口；重复滚动连续缩放 | 无 |
| 点击节点/键盘选择/定位 | 依据栏目、节点所属线和当前聚焦线判断 | 单线直接编辑；共享线局部选择；孤点提示；未保存可保存/放弃/取消 | 无 |
| 选择所属线 | 当前节点含该线 | 节点栏目只更换聚焦，事件线栏目切换线编辑器 | 无 |
| 取消聚焦 | 当前有聚焦或待选线 | 恢复全部线正常颜色，保留编辑内容 | 无 |
| 打开整理详情 | P2或P3现有记录 | 所有折叠框收起；手动展开不随刷新重置，关闭重开恢复收起 | 无 |
