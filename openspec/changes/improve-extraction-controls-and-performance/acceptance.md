## 根因与修复

1. 人物关系每次读取按人物反复扫描全部关系和人物，并在排序比较中反复创建数字排序器。改为共享排序器、人物映射和邻接索引。
2. 执行锁和资产在同一个响应式查询中，开始、请求前校验和续期都触发整书关系投影。改为两个订阅，内容变更才生成关系投影。
3. P1进度及旁边P3面板读取了包含章节原文的历史运行，快照层再次复制和序列化。P1使用步骤摘要，P3按已登记执行权编号读取。世界保存及单章清空时的失效检查仅加载P2/P3运行。
4. 世界和叙事每步均重新扫描整书计算人物地点出场统计。世界批次收尾逐章让出界面，叙事步骤跳过该计算。

## 样本与执行

浏览器命令为 `npx playwright test --config playwright.workspace.config.ts --project development --project production --workers 2`。浏览器使用固定模型回复，导入 `tests/fixtures/A-三章短篇.txt`。大样本由提取浏览器脚本写入独立测试书库，并在开始与暂停期间记录帧间隔，JSON保存在Playwright该场景输出目录。

单元命令为 `npm run test`。类型检查为 `npm run typecheck`，静态检查为 `npm run lint`，生产包由 `npm run build`生成。治理为 `npm run governance:check`，差异规格使用仓库锁定的OpenSpec严格校验。
