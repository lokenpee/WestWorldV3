# 实施设计

## 字段变化
第1项不改字段及持久格式；ChapterDraft仍包含编号、名称、order、charCount和text，字符数仍按UTF-16。旧书不重切；新导入和用户重做预览采用新算法。第2至21项沿审查所列模块逐项实施，涉及任务记录、查询协议和存储索引时，在该项开始前补充具体字段及兼容方案。

## 数据流转
量化脚本从固定样本调用当前代码，输出JSON指标 → 保存优化前结果 → 修改当前项 → 相同脚本/样本输出优化后结果 → 对比并回归 → 有收益才提交。结果文件放本变更evidence目录；运行中数据库只放系统临时目录。

第1项：TXT规范化正文 → splitChapters识别章节 → splitCharacters在上限附近寻找自然边界 → 原字段生成预览 → 原导入事务保存。长章最大10000，无标题最大4000，无重叠、无吞字。例：旧分块把贾蓉拆为“贾/蓉”；新分块在附近句末或换行处结束，仍拼回全部原文。

## 触发逻辑
用户生成预览时使用新切分；取消、更换文件仍由既有Worker与请求身份处理。不重写已有书、不自动提取、不新增模型调用。算法在上限尾部10%且最多1000字符内寻找末个换行，再找句末及闭引号；余量不足以保持当前块数时使用原硬边界；始终避免拆UTF-16代理对。

## 逐项指标与顺序
每项均先记录基线，后做同样本对比及相关回归。实施顺序1–3、21、4–20；21优先落实用户刚确认的low档位及异常恢复，编号仍对应审查。

## Git与回溯
先保存所有已有项目源码/文档改动及版本；不提交API Key、正式库、用户PPTX。每项修改前记录HEAD，成功后只提交本项实现、测试及证据。无收益时按本项精确差异撤回，不用全库reset覆盖他人工作。未通过的尝试保留测试结果记录，不能把未测量项宣称完成。用户尚未要求远程推送，本轮保存本地提交。

## 第2项：预览分页与正文位置
预览内存新增ChapterRange：原编号/名称/order/charCount，加必填整数start/end（规范化全文UTF-16偏移，end不含；0≤start<end≤全文长度，连续覆盖）。Worker生成并返回一份全文和范围；点预览才切片，保存按批切片写入原chapterTexts。章节元数据显式选原字段，start/end不入库；无数据库或备份升级。旧ChapterDraft/text和splitChapters作为兼容入口继续有效。

例如原第二章text='乙'改为全文'甲乙'中的start=1/end=2，读取仍为'乙'。首次、换文件、应用正则和编码重读回第一页；每页100行，可往返全部章节，保存仍保存全部章。旧请求取消和晚返回防护不变；失败保留预览可重试。

## 第3项：备份准备会话
新增仅内存存在的准备会话，绑定本次文件；Worker持有已校验的原始BookData，页面只收到清单、数量、错误及准备句柄。新增prepareBackup/restorePrepared服务入口；旧inspectBackup(bytes)/importBackup(bytes)语义保留，不能转移并清空调用者原buffer。数据库及wwv2版本无变化。

文件→Worker解压/解析/转换/校验→页面预检信息→用户确认→同一准备结果生成新bookId的tables→原importData事务/关联校验/verifyReady发布。示例两次解压改一次；写入失败重试仍复用同一准备结果，各副本重新分配ID。导出前序列化与修复也在Worker；异步压缩保持原实现。

新文件、取消、卸载使旧准备结果失效，晚到旧结果立即释放。恢复中的操作继续拥有会话直至结束；失败保留可用准备结果供重试，成功释放。Worker错误回传，阶段进度可见，不新增固定10秒超时。旧库迁移先在Worker计算转换前摘要，主线程核对已迁移标记，只有需要时才在Worker进行原转换与编码校验；读取源库、落盘核对和发布逻辑不变。

## 第21项：P2低档思考与无行动截断恢复
正式P2各步骤的CallOptions.reasoning改为low，由现有模型能力映射发送；DeepSeek请求应实际包含reasoning_effort=low且thinking仍enabled。P3和探测档位无变化。原生思考、正文、工具调用和usage全部沿既有链路采集，不增加AI输出字段及内容核验，不改变8192上限、原文次数限制或正常任务请求自由度。

新增运行中计数，识别stopReason=length且只有非空thinking、无非空正文/工具调用的回复。首次只追加一条针对性续做提示；在没有成功工具执行之前再次出现则设置专门的暂停原因。成功工具结果清零；普通说明不触发也不清零；含正文或工具调用的length保持既有处理。该计数不入库，每次用户继续有一次新的续做机会。

例如两次纯思考截断原来进入第三次普通继续，新实现第二次后暂停；P2保留activeWork及当前人物，P3保留当前阅读页。已提交修改、appliedCommands、完整日志及用量不回退。用户继续仍走既有任务恢复，并使用当前程序的low选项。固定响应验证请求及恢复，真实模型速度和整理质量等待小说副本验证。

## 第4项：P1任务和正文快照独立保存
P1主运行记录不再携带不断增长的tasks数组；新增taskStorage='separate'标志和nextTaskOrdinal游标。P2/P3任务格式无变化。新增extractionTasks表，主键id由runId和taskId组成，保留原任务的状态、序号、调用、输入指纹、提示词哈希、次数、提交凭证及错误等信息，增加bookId/runId，按runId、[runId+ordinal]、[runId+status]索引。input保留章节编号和当时的章节名，以snapshotId替代正文。

新增extractionInputs表：必填id为正文SHA-256，bookId为所属书，text为原始任务正文，createdAt为创建时间。相同正文的两步骤共享快照；快照内容不随当前章节编辑改变。任务inputFingerprint仍按原步骤、提示词和章节输入计算，不改为正文哈希。例如同一章两步骤保存两条任务和一份正文，完成其中一项只修改该任务及运行汇总。

注册任务前计算快照哈希，注册事务原子写快照、任务、运行游标；完成事务和资产、凭证、用量一起更新。普通进度查询继续使用进度和凭证，不扫描全部历史。需要任务历史时按序读取元数据，正文按快照引用读取。暂停、异常与继续只更新相关任务；最新重试结果覆盖旧失败状态的展示语义保持一致。

旧P1运行仍可读取；继续、中断恢复或取消需要写入运行状态时，先一次性转换内嵌tasks，保留原正文、标题和inputFingerprint，在事务中写入新表并用紧凑记录替换原运行，避免先用旧大数组保存状态。普通只读进度不触发转换。转换失败回滚所有写入，重试不会重复生成任务。不能使用当前章节正文补写历史输入。计算哈希不得让IndexedDB事务提前结束。

浏览器书库升级至版本9，增加两表；本机存储登记相同表及索引。备份格式升至12，包含两表并校验任务所属P1运行与快照；格式4–11读入时补空表。备份中的运行中独立任务转为可恢复的暂停状态，恢复副本更新bookId而保留任务、快照引用及原输入指纹。旧浏览器库迁移支持版本9；计算迁移摘要时仅在两张新表均为空时省略它们，使旧源库仅升级空表不会被误判为数据变化。任一新表有内容则两表均计入摘要。

量化使用临时本机库、12章各10000字、两步骤共24个固定响应，记录真实存储请求累计字节、最大请求及主记录大小；比较脚本保持相同。兼容验收覆盖旧备份恢复后继续、两份新备份副本、原正文不变、失败回滚及旧迁移摘要兼容。正式书库和模型API不参与。

## 第5项：P1新增人物的关联更新范围
字段与备份格式无变化：仍写原characterRelations、nodes和revision。P1世界资产提交事务中，从新增人物主名及有效别名建立受影响称呼集合，筛选旧关系与节点，再调用原绑定函数；本批新关系也经过相同规则。人工改名、删除、合并等通用入口继续使用已有处理。

关系筛选覆盖目标称呼、已绑定目标对应人物主名以及原始/生命周期解析来源编号。节点筛选覆盖actors/targets和两侧绑定的原始mention；已有显示名不能代替原称呼。没有新增人物时无需重算无关旧关系和节点。例：旧节点“沈青”无编号，新增沈青后补齐；已有一名沈青时又新增同名人物，两者均加入候选关联；通过“沈公子”绑定旧沈青的关系也参加主名扩展。无关行保留引用及revision，失效通知仍只依据真实变化。

量化样本300人物、2000节点、6000关系，固定模型新增两名人物；计量实际交给原重绑定函数的记录数，结果必须与全量算法逐对象相等。另验证空增量、有效别名、已有目标主名扩展、生命周期来源和通用人工维护回归。仍在原资产/任务/凭证事务内提交，失败回滚，不新增请求或模型约束。

## 第6项：分章出场统计复用
业务字段、存储表、备份及模型工具无变化。缓存仅在运行进程内保存分章词项计数，按书籍、人物/地点名称集合和正文存储版本区分；不保存另一份全文。利用本机存储既有StoredRecord.version及keysOnly查询读取章节版本，只取未命中章节的正文。待提交的version=0不得作为可复用版本；版本与正文在一致读视图中取得。Dexie旧存储没有可靠正文版本，沿原全扫描流程计算。

统计仍使用最长名称优先、忽略通用称呼、同名多归属不计数的原算法。缓存词项计数后，按当前人物归属、来源原章及人工/Agent层级保护规则汇总。因此相同词集合新增同名归属无需重读正文，但统计要重新归属；有效词集合变化必须重新检查全书，因为长词可能遮蔽已有短词。单章正文变化只重算该章，删除章移除旧缓存。实例关闭或缓存丢失后冷计算，持久资料不依赖缓存。

P1世界资产整轮结束及单章提取收尾使用共享统计入口，连续同名集合操作复用已算章节。实际重扫时继续让出主线程；缓存命中不逐章固定等待。当前世界资产lane原本就只在整轮结尾统计一次，保持此触发时机。资产保存仍核执行权，失败不伪报统计已保存；取消保留已提交提取结果。手动分层用于结果参照，不改其快照与事务体系。

量化使用临时本机库200个8000字分块（100原章），固定模型响应依次执行冷提取、热重提、另一workspace修改单章且长度不变、新增长名称、同名归属变歧义、无关字段变化。记录实际正文返回行数、字符数、响应字节和耗时；每轮逐字段对照原updateFrequencies。必要的本章提取/重提校验读取仍计入，不能把整步报告为零正文读取。

## 第7项：关系完成记录使用内容指纹
字段结构和备份无变化。修复BUG-47：submit_relation_review完成当前人物时，将relationItems.contentFingerprint写为提交后reviewContext.scan(characterId)；pairChecks.fingerprint写为同一提交后上下文pair(pairKey)。两者与创建整理清单、刷新及复用判断共用内容算法。写入冲突的expectedFingerprint仍是含修订号的版本指纹，二者用途不混用。

保存位置仍为pipelineRuns.organization，和关系修改、任务确认保持原事务；只在完成成功时更新人物完成指纹。旧完成记录缺少或保存错误内容指纹时保持原失效规则，重新核查一次后记录正确信息，不凭旧成功状态猜测可复用。例：A/B朋友改为师徒并完成A，未外部编辑立即重启复用，A及该人物对可复用；之后改关系或人物资料则重新待处理。待核对及失败仍不复用，空changes完成与部分提交的语义不变。

固定样本通过真实工具及复用入口，记录立即复用、重新加载复用的完成人物和人物对数量，并检查后续关系/人物资料改动失效。基线为各0/1，目标各1/1；不以模型输出质量或费用作推断。
