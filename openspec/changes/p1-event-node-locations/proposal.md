# REQ-031 P1 事件节点记录地点

## Why

P1 的世界提取会记录地点资产，叙事提取的事件节点目前记录人物、经过和来源章节，缺少行动发生的地点。用户希望先给事件节点加「地点」字段，为阅读节点和后续剧情大纲汇总提供依据。地点按小说能确定的精度记录，皇宫、宁国府这样的范围就可以，有具体房间等细节时保留。

## What Changes

P1 叙事提取在原有 `submit_result` 的每个节点上返回可选的地点名称。事件节点详情显示「地点」，沿用现有节点编辑入口更正。地点内容随节点保存和备份，[REQ-032](../p3-persistent-story-outline/proposal.md) 后续直接读取它。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `extraction` 增加事件节点地点的提取、保存、展示和兼容要求。

## 确认依据

2026-11-20 用户要求先优化 P1 的事件节点提取，增加「地点」，原文给了具体房间等位置就记录，只能粗略定位时记录皇宫、宁国府等大致地点。本文把复数、空值、旧节点处理和展示方式写为评审方案。

2026-11-20，完成 P3 及事件网络方案评审讨论后，用户指示「开始施工」。先按本提案实施节点地点的提取、兼容和编辑，再接入 REQ-032。

## 讨论结论

- 记录本节点行动实际发生的地点。地点可由同一场景的上下文确定。谈话中回忆、计划或顺口提及的其他地点随经过保留。
- 只知道在某府或宫中就记录该处。正文给出更具体的地点时保留，并在同名地点容易混淆时带上可确定的上级地点。
- 同一个节点确有多地发生的连续行动时按出现顺序记多项。同一地点的宽泛与具体描述属于同一个场景时，记录原文能确定的具体名称。完全无从确定时留空。
- 建议先存地点名称。地点资产仍由 P1 世界提取维护，节点地点允许保存原文称呼或概括名称。旧节点按缺省兼容，是否补提由用户使用现有提取入口决定，沿用该入口的影响预览。

## 数据流转

章节标题与正文 → P1 叙事节点提交 → 提取契约校验并整理地点数组 → 与节点内容和成功凭证一起保存 → 节点详情、备份与后续 P3 读取。

例如，[第145章](../../../tests/fixtures/红楼之挽天倾-赖家线.txt#L2429) 贾珩在荣庆堂谈到去翠华山前查过东府账簿。调整前该节点只有人物、经过等字段，调整后地点为 `["荣庆堂"]`。若正文只有「宁国府中」，地点可为 `["宁国府"]`。提交事务失败时保留提交前数据，继续后由原提取任务重试。
