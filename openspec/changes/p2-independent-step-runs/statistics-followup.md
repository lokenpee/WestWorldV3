# 人物自动分层入口与执行权修复

## 需求与确认范围

REQ-022补充，关联REQ-019；故障BUG-40，中型、project-local。2026-11-12用户要求解释“更新出场统计”的作用，将人物分层入口移到人物列表层级筛选旁、位于新增人物左侧，改名“人物自动分层”，并确认手动层级应受保护；报告点击后出现`CONFLICT:人物整理会话执行权已转移。`。

位置、名称及人工层级优先是用户明确要求。2026-11-12用户回复“开始吧”，确认以下方案实施：人物列表入口、全书本地分层、人工层级保护、独立执行权及反馈测试。

## 当前行为与根因

- `world/service.ts:updateOrganizationStatistics`依赖最近一次人物整理run/session，新建world租约owner，却没有取得该session的对应leaseOwner。
- `world/organization.ts:finalizeStatistics`写事务调用`renewOrganizationLease`，要求session.leaseOwner等于新owner；已结束会话已释放owner，所以会抛出上述错误。此路径本身即可触发，不代表真实发生跨窗口抢占。
- 当前统计还会改旧organization.step、activeWork及revision，因此不宜只补领旧Agent会话来绕过校验。
- 当前入口异常分支无条件删除world租约；拒绝并发任务时也可能删除不属于自己的锁，需要一并改成只释放本次持有锁。
- 统计从正文计算人物/地点出场频次，人物据章节数、提及次数的分位分成主要人物/重要配角/NPC/路人，不调用模型。
- `assets/service.ts`在人工选择层级时写`roleWeightSource=manual`；`assets/derive.ts`保留manual和agent来源的层级，只刷新频次。既有`world-frequency.test.ts`两项通过，包括人工路人即使高频仍保持原层级。

## 已确认实施方法与影响

| 范围 | 修改 | 检查 |
|---|---|---|
| WorldPanel、AssetsPanel、BookOverview | 删除P2旧入口，在人物层级筛选右侧、新增人物左侧显示“人物自动分层”；独立进行中/成功/失败反馈 | 桌面与窄屏按钮顺序、重复点击、其他资产不显示 |
| world/service及统计复用逻辑 | 对当前全书人物计算，独立于历史Agent会话和模型配置；复用既有频次算法，保留地点频次更新；不结束或改写旧整理任务 | 没运行过P2也可分层；已完成、已暂停历史不被改写；模型调用0次 |
| 任务执行权与事务 | 本次本地操作独立取得书籍world锁，沿用同书并发保护；保存前复验所有权和数据版本，失败回滚，仅释放自身锁 | 他人占用、保存冲突、失败释放、零部分写入 |
| 人工层级 | 沿用manual标识和原保护算法，不新增自动覆盖人工入口 | UI手选层级后反复分层仍保留；自动人物正常更新 |

有效规格：[资产维护](../../specs/asset-management/spec.md)、[世界整理](../../specs/world-organization/spec.md)。技术契约：[频次与层级算法](../../../docs/v2/04-Spec-流程接口与算法.md#alg-05-主名出场与层级)、[锁与存储](../../../docs/v2/03-Spec-数据与存储.md)。技术算法正文已对照既有称呼规格校正为主名和已核实别名；匹配算法本次无修改。

## 字段变化

无新增持久字段或数据库/备份版本变化。沿用人物`frequency`（章节数、次数、范围及分位）、`roleWeight`（四种层级）、`roleWeightSource`（来源），由本地统计保存，人物列表/筛选读取。手工来源原值保留。内部一次操作的租约ID仅用于执行权，不复用人物整理run/session；事务保存仍核全部人物/地点集合及revision。服务返回total、changed、manual三个必填非负整数，由完成统计时赋值，界面读取；仅临时反馈、不保存到书库。

## 数据流转

正文＋当前人物及核实别名 → 既有频次计算 → 非manual/agent来源的层级计算 → 同书有锁且数据版本有效时保存派生字段 → 人物列表刷新。地点频次沿用当前计算。例：人工“路人”甲出现100次，统计次数更新为100，层级仍为路人；自动层级乙按现有分位重新计算。旧Agent消息、队列和整理报告不作为本次动作的完成目标。

## 触发逻辑与验收

点击按钮（对全书人物，不受当前搜索/层级筛选影响）→ 禁止重复触发，申请本次本地执行权 → 计算与原子保存 → 显示修改人数/保留手工层级信息并刷新列表。没有可处理人物时给出空态；已有同书执行任务时拒绝本次操作，不清掉对方租约。失败显示具体原因，数据回滚，用户可重试。无模型请求、不启动P2或P3下游。

实施依赖：先拆统计计算/保存与旧Agent收尾 → 独立本地执行权 → 接人物列表入口 → 固定测试与浏览器验收 → 用户副本自测。检查包括新书无P2历史、历史完成/暂停不被改写、手工层级保护、自动更新、跨标签锁冲突、重复点击、窄屏位置。使用隔离样本，不调用真实模型，不修改正式书库。
