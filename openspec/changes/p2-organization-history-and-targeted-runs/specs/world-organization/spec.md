## ADDED Requirements

### Requirement: WORLD-ORGANIZATION-HISTORY-01 三步骤详情与对象索引

系统 SHALL 在 P2“整理详情”中固定显示第一步识别与合并、第二步整理人物资料、第三步整理人物关系；三个步骤始终可切换，不随当前执行步骤隐藏。

#### Scenario: 运行在第三步

- **WHEN** 完整 P2 运行当前处于第三步关系整理
- **THEN** 打开整理详情仍可切换查看第一、二步的历史记录、人物和 API 请求，不只显示第三步。

#### Scenario: 步骤对象索引

- **WHEN** 第二步已经整理 138 个人物并产生超过 50 条请求，用户第一次打开第二步
- **THEN** 立即显示该步骤全部人物、运行入口和状态，不只显示最近 50 条请求涉及的人物；对象索引不等待请求分页。

#### Scenario: 对象请求分页

- **WHEN** 用户点击一个有较多请求的人物并加载更早请求
- **THEN** 首次显示该人物最近 50 条请求；加载更早只追加该人物请求，不清空、不重排其他对象或人物。

#### Scenario: 旧运行没有请求明细

- **WHEN** 打开没有 `request_trace` 的旧运行
- **THEN** 使用该运行已有的目录页、疑似组、人物项、人物对和修改记录生成步骤摘要，并明确标注“旧版本未保存 API 明细”；不伪造 SYSTEM、USER 或工具记录。

#### Scenario: API 详情保持原样

- **WHEN** 展开任意请求记录
- **THEN** SYSTEM、USER、ASSISTANT、TOOL CALL、TOOL RESULT 的顺序、参数展开、Token、耗时、费用和修改前后对比保持现有形式。

### Requirement: WORLD-ORGANIZATION-HISTORY-02 单人物整理入口与历史归属

系统 SHALL 在已存在人物的编辑页底部操作栏提供“AI 整理人物资料”和“AI 整理人物关系”，分别复用 P2 profiles 和 relations 工作逻辑，并把结果归入对应步骤历史。

#### Scenario: 单人物资料整理

- **WHEN** 用户打开一个人物编辑页并点击“AI 整理人物资料”
- **THEN** 创建一次只包含该人物 profile 工作项的独立运行；运行记录归入整理详情第二步；不启动完整目录扫描、关系整理或全书统计。

#### Scenario: 单人物关系整理

- **WHEN** 用户点击“AI 整理人物关系”
- **THEN** 创建一次只包含该人物 relations 工作项及其人物对的独立运行；运行记录归入第三步；不自动进入资料步骤或全书统计。

#### Scenario: 同一人物多次整理

- **WHEN** 同一人物先后运行资料整理或关系整理多次
- **THEN** 每次生成新的运行记录并按时间保留；整理详情显示多条历史，不覆盖、不合并旧运行。

#### Scenario: 运行中查看

- **WHEN** 单人物运行尚未结束
- **THEN** 可以从整理详情打开该次运行并查看已经产生的 API 请求；按钮在运行期间禁用，结束后恢复。

#### Scenario: 临时候选不拆散运行记录

- **WHEN** 单人物资料运行中发现了疑似重复人物，内部插入 candidate 工作项完成核实或合并，然后继续资料整理
- **THEN** 这次运行的全部 API 请求，包括 candidate 请求，仍显示在第二步该人物的同一次运行记录下，不被拆到第一步；单人物关系运行同理归入第三步。

#### Scenario: 完整运行的后续候选

- **WHEN** 完整 P2 在第二步或第三步发现并处理临时候选组
- **THEN** 候选组和请求按 `originStep` 保留在发现它的步骤下；`candidate:` 工作项前缀不能单独把请求划入第一步。

### Requirement: WORLD-ORGANIZATION-HISTORY-03 进度隔离与并发保护

系统 SHALL 将单人物整理记录与完整三步运行进度分离；单人物运行只增加执行记录，不累加或覆盖完整运行的统计。

#### Scenario: 完整运行已完成

- **WHEN** 完整三步运行完成后又对某个人物单独整理资料或关系
- **THEN** 完整运行的 `organizationSummary`、checked/modified 数量、compileProgress 和旧报告保持不变。

#### Scenario: 并发运行

- **WHEN** 完整 P2 或另一个单人物整理正在运行，或世界资产被锁定
- **THEN** 拒绝启动新的单人物整理并说明原因；不得写入半成品状态。

#### Scenario: 修改冲突

- **WHEN** 单人物运行期间人物或关系版本已变化
- **THEN** 使用现有版本校验和关系重检规则拒绝或重新读取；已提交修改不回滚，失败记录保留。

### Requirement: WORLD-ORGANIZATION-HISTORY-04 稳定分页与实时追加

系统 SHALL 在运行中追加新请求时保持更早历史分页稳定，不因 offset 变化重复或遗漏记录。

#### Scenario: 新请求追加

- **WHEN** 用户正在查看某对象的历史请求，运行又产生新的 API 请求，随后用户加载更早请求
- **THEN** 新请求追加到当前对象并按 requestId 去重；加载更早使用 `(startedAt, requestId)` 游标，不重复、不遗漏旧请求。

#### Scenario: 切换对象

- **WHEN** 用户从一个对象切换到另一个对象再返回
- **THEN** 各对象保留自己的加载游标和已显示请求，不重建、不覆盖另一对象的记录。
