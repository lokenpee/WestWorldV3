# 实施设计

本设计对应 [REQ-025 提案](proposal.md) 的已授权最终方案。新入口采用 `story_pages_v3`：首次提供当前页，后续通过模型导航；原 `story_lines_v2` 和历史命令用于兼容旧记录。持久资产继续使用节点、事件线、工作记忆和线索原表。

## 模块与接口
`story/reading.ts` 生成页、核对事实指纹、持久化导航及计算进度；`readingService.ts` 负责启动、执行权、恢复、阶段结果与界面读取；Agent 运行时负责持续工具循环和会话。写入沿用现有事务和命令账本，模型请求不占数据库长事务。

| 工具 | 业务输入与结果 |
|---|---|
| `search_story_context` | 按词语、节点、对象类别、章节范围查找节点、旧线和线索；可分页浏览，摘要用于寻找候选。 |
| `get_story_detail` | 按 `kind`、`ids` 查详情，长内容及成员可分页；事件线可用 `processSegment` 读取指定经过段，返回段号及实际展示内容。 |
| `read_original` | 按章节或已有资产查原文，长正文按现有参数续读。 |
| `save_story_lines` | `operations` 提供 `create/append/update/merge`，字段可按实际修改省略；返回真实事件线编号和保存结果。 |
| `save_story_notes` | 按稳定 `key` 新建或更新线索，可独立保存 `workingSummary`；未提供摘要时保留原值。 |
| `add_story_nodes` | 保存原著漏提的节点；参考引文可省略或改写，程序返回实际保存或复用的节点编号。 |
| `navigate_story_pages` | `direction=next/previous`，可提供 `currentPageId` 和检查理由；返回当前页或完成结果。 |
| `finish_story_batch` | 收尾本轮，程序读取真实提交和阅读进度；还有待读页时返回 `partial` 及剩余页，不代替翻页。 |

完整参数和返回形状由 [11 工具契约](../../../docs/v2/11-AI工具返回与回放契约.md)及其 JSON 资源维护。三个写工具各自批内原子保存，不需要将线、节点和摘要凑在一次提交中。提交键由程序生成；相同调用重放返回原结果，不重复追加经过、补点或修改记录。

| `storyReading` 各阶段 | 增加 | `pages/currentPageId/receipts`：页集合、当前位置、导航回执标记 | 页数组、字符串或 null、字符串数组；未完成时指向可继续页，回执按任务与调用身份区分 | 程序从当前资产生成并在导航后保存 | 恢复时重算当前事实，复用仍有效的页；同调用重放不再推进 |

| 阅读页 | 增加 | `sourceFingerprints`：关联原章的正文指纹 | 可选的章节编号→字符串指纹映射；正文缺失也保存对应指纹，不包含书籍身份 | 页面检查完成时由程序从本页节点、整线成员、事项引用的节点/线及引文章节取得；恢复只核对已检查页关联章节，同章计算结果复用 | 随页状态备份，换 `bookId` 且原文相同仍有效；相关原文变化使该页重新待核，重读完成后更新依据 |
| Agent 内部任务 | 增加 | `workflow=story_pages_v3`：主动阅读路由 | 新 P3 入口使用；内部输入允许空分配清单，实际工作以当前页为准 | 入口赋值，运行时选择八工具和收尾逻辑 | 保留 `story_lines_v2` 及旧任务结构供历史和兼容调用读取 |
| `save_story_lines` 操作输入 | 增加 | `processAppend`：追加发展；`processEdits[{segment,text}]`：局部修订 | 可选字符串、可选数组；段号从 1 开始并指向当前基底的非空段，不重复定位同一段；不校验旧句逐字匹配或叙述篇幅 | 模型按已读详情填写；命令适配器转换为最终 `process` 保存 | 命令意图和回执按原账本保存；历史操作缺省即沿用原值 |
| `get_story_detail` 输入/结果 | 增加 | `processSegment/processSegmentCount/processSegments` | 可选正整数；结果给出段号与当前展示文本，长段沿用字符偏移续读 | 查询从已保存 `process` 按空行分段生成，模型用于局部修订 | 不存另一份经过或永久段 ID；修改后重新读取当前段号即可 |
| 事件线原表 | 修改写入语义，字段不变 | `cause/process/result/lineStatus` 及成员派生字段 | 省略保留；合线省略叙述时保留双方非空叙述；任一合入线为 `open` 且未显式指定状态时保持 `open` | 模型表达因果；程序维护 `nodeIds/chapters/timeRange` 和节点反向引用 | 仍是原文本和多对多结构，旧数据、图和备份直接读取 |
| 命令与整理详情 | 扩展登记，无新表 | 工具名、原提交结果及 `pipelineRuns.assetEdits` | 可选历史记录缺省为空；成功结果按实际写入生成 | 写事务生成对象、字段前后值、理由与提交确认；详情和回放读取 | 新旧命令可读，重放不重复生成修改记录 |

节点与事件线原有业务字段、书籍归属及持久消息结构无变化：沿用原表、原编号和同书持续会话。新工具输入不设置置信度通过阈值，低置信判断可保存为线索或叙述。引用的节点、事件线、章节须属于当前书；写入仍核对实际读取依据、数据版本和执行权。

## 数据流转
1. 用户开始或继续串联，阅读服务读取当前节点、章节、原进度及会话，从当前资料生成有序页；每页最多 10 项，按约 4000 估算 Token 的资料量缩小，单条过长内容可查详情续读。
2. 首个请求提供当前页摘要、相关旧资料和工作摘要。模型按需要搜索、查详情或原文；后续页只经 `navigate_story_pages` 返回。工具保存结果留在当前页，模型可以继续补充。
3. 写工具把本次操作转换为原资产命令，在同一事务核对引用、版本、执行权并保存资产、命令确认和字段差异。失败回滚本次提交，已成功的其他提交保留。工作记忆独立更新。
4. `next` 核对当前资产并登记已检查页，返回下一待检查页；`previous` 返回上一页而不登记离开页。若保存导致页对象变化，返回更新后的当前页或下一个尚未展示的页，不能把未展示内容直接标成已读。
5. 页面事实变化只使相关页待核；保存后再次检查采用保存后的事实指纹。整书初串页检查完成后显示可进行全书复核，等待用户点击独立入口。
6. 全书复核按孤立节点页、逐条事件线的成员段和整线核对页、未解或依据变化的线索页提供资料。长线分段页保留该线概览和承接提示；整线页核对起因、转折、条件变化及结果，允许保留未解问题。

### 跨页续接与叙述组合
第 1 章 `N1` 建立 `L1`：“三河帮来历”，`process="有人提到三河帮。"`，`lineStatus=open`。第 20 章读到 `N2` 后，模型查到 `L1`，读取相关详情，提交 `append`，只带 `lineId=L1`、新成员 `[N2]` 及 `processAppend="三河帮正式介入，早先传闻得到回应。"`。保存后成员为 `[N1,N2]`，经过保留原段并追加新段，章节、时间范围和节点归属同步更新。第 120 章的 `N3` 可继续并入同一编号，按原著更新结果与故事状态；`N2` 属于其他线的关系保留。

`process`、`processEdits`、`processAppend` 可以在同一操作中组合：先以提供的全文或原文本为基底，再对基底的段号应用局部替换，最后追加新发展。仅提供段修订时使用刚读到的已存段号，不要求复制旧句；同时提供全文时段号对应这份新基底。多个修订定位到修改前的同一基底，后面的段不因前段变长而错位。

`cause` 保存必要前因和人物目的，有新揭示时修订；`process` 描述发展及其承接；`result` 更新已经发生的结果和后续影响；`lineStatus` 表示故事状态。文本更新不要求重新读取全部未变成员；实际新增和作为依据的节点仍需有读取依据。合线默认保留两线的有效起因、经过和结果，再允许按段整理。

## 恢复与兼容
`storyReading` 是原运行记录的可选对象，包含在整书备份中；没有新数据库表或迁移。旧运行缺少该字段时，从当前节点构造页，核对原有有效逐项覆盖后复用可证明的初串进度。旧事件线、笔记和消息可继续读取，旧工具调用记录保持原样。

页指纹依据业务事实，忽略导入必然变化的 `bookId/sessionId` 和派生的 `basisFingerprint`。`sourceFingerprints` 另记录相关原章正文的指纹；恢复只读取仍为已检查页关联的章节，并复用同章计算结果。节点、线、事项或关联原文变化时重新核对相关页，重读完成后保存新的原文依据；导入同时按原备份规则更新事项依据并清执行权。导航在执行权事务内保存状态，每个成功返回分支登记调用回执，重放不能把新返回的内容当成已经阅读。

事件线与节点的每次保存仍由原命令账本维护幂等；`assetEdits` 展示真实字段前后值及理由。页检查状态只说明资料处理进度，报告同时展示仍待查证的线索和当前故事状态，不能用“全页已读”代替语义质量结论。

## 验收与接手
依赖现有 Node/npm、fake-indexeddb、固定模型响应和生产构建浏览器测试。按 [任务](tasks.md) 3.1→3.2→3.3→3.4 完成关联工作，结果写入 [验收记录](acceptance.md)。

自动检查入口为 `tests/story-reading.test.ts`、`tests/story-reading-sources.test.ts`、`tests/story-tools.test.ts`、`tests/restore-progress.test.ts`、现有 story/retrieval/coverage 与 Agent 回归，以及 `tests/browser/story.spec.ts`。使用 25 个节点验证三页导航与回看；使用第 1/20/120 章节点验证同线续接和多线共享；长经过验证局部段修订、全文与追加组合；长线验证分段后整线核对。补点导致页变化、导航同调用重放、同响应多导航、取消继续、备份换书籍身份都须保留真实进度。两章分别完成检查后仅修改一章原文，验证只有对应页待核，重新阅读后更新依据。

类型、非 live 测试、构建、提示词同步、治理及本变更严格校验分别记录。用户在小说副本检查前后因果、漏接和误接、实际修改及遗留问题；用户通过后才同步差异规格与归档。
