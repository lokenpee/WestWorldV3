# P3 完整事件线与工具整理

2026-11-13用户“按你说的来”确认[精简输入](lightweight-input-discussion.md)和[简化保存](simple-line-save-discussion.md)。随后确认[重新开始复用规则](restart.md)，关联REQ-026。以下为当前实施方案。

## Why
REQ-025，大型需求。用户要把整本书分散的铺垫、发展、转折和回收串成完整的原著事件线，一个节点仍可属于多条线。后续游戏 Agent 才能根据人物动机、前置条件和事件后果，判断玩家跳过节点或改走路径后需要怎样接续剧情。

原有流程按大窗口自动分配批次，模型必须在批次结束时汇总；跨批更新长线容易反复读取旧成员或整段重写。提示词、工具和结束契约没有清楚区分“这一页看完”与“故事已经结束”。本变更让模型主动阅读小页、随时保存进展，再逐条复核事件线的整体因果。

## What Changes
- 首次提供按章节和节点顺序排列的当前页，每页最多 10 项，按约 4000 估算 Token 的内容预算缩小。后续页由模型调用 `navigate_story_pages` 获取；支持下一页与上一页，保存不自动翻页。
- 下一页登记当前页已检查；上一页仅回看。当前页可查询和保存多次，也可无修改翻页。页面检查完成、事件线故事状态、遗留疑点分别记录。
- 直接提供六个业务工具：搜索、详情、保存事件线、保存线索与摘要、导航、收尾。程序维护提交键和真实回执。
- 同一事件线可跨页续接。保存只需名称、节点和整线概述，理由可选；追加只填新增成员，省略概述保留旧值。成员、章节、时间范围和节点反向归属由程序维护。
- 全书复核保持独立入口：先看孤立节点，再逐条检查事件线的成员段和整线核对页，最后检查未解或依据变化的线索。串联与复核使用各自的任务 Markdown。
- 暂停恢复提供当前未完成页、已保存成果及工作记忆。新流程不按固定五分钟催促收尾；保留网络超时、取消、会话压缩和执行权控制。
- 不以置信度阈值、引文逐字一致、叙述篇幅或重读全部未变成员阻碍保存。结构、归属、引用、版本与执行权仍按真实资料核对。

## 确认依据
2026-11-13，用户对完整事件线、旧线检索、分用途工具、补点后接线及保留原资产结构的方案回复“开始吧”。随后明确选择“AI 主动调用翻页工具”，要求考虑模型注意力、允许分批串联，并讲清并入旧线后的字段变化。用户最终授权：“你可以改，但要注意 agent 的输出不要加强硬的校验……不要出现一定要输出跟原文一模一样的字段，不然报错”。

最终确认内容为本提案、[实施设计](design.md)及[主动阅读与分段复核结论](reading-review-discussion.md)：六工具、主动往返翻页、分次保存、简短概述更新、逐线复核与恢复；不增加逐字、置信度和篇幅的语义硬门槛。没有尚待确认的业务取舍。

## 讨论结论
事件线按同一持续事件、目标或矛盾组织；同组织或同人物不足以判定同一条线。页面是控制输入和恢复的位置，事件线可以跨任意多页发展。未结束的故事保持 `open`，未解决的线索保留；模型可先登记疑点、继续其他工作，再补查。

已有节点优先复用，P3依据概述和节点详细经过连接；缺少节点时保存待补线索。游戏中根据玩家选择编写替代节点由 REQ-003 游玩能力使用这些资料完成。固定响应测试验证接口、保存和恢复，因果质量由用户以小说副本核对。
