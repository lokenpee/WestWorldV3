# BUG-42复发：P3启动失败没有提示

## 用户反馈与授权

2026-11-13用户反馈“P3点击串联没反应”，补充“没有任何提示”。按中型缺陷处理，关联REQ-025、REQ-026和既有BUG-42单行状态要求；继续修复已批准的按钮启动、重启和异常反馈，不改变整理业务规则。

## 已定位原因与实际范围

StoryPanel只在running或已经存在P3进度时渲染AgentActivity。readingService在读取配置、核对会话或准备阅读状态失败时会记录state.error并恢复running=false；如果尚未创建P3进度，错误随状态行一起被隐藏。旧进度为cancelled时，AgentActivity优先显示旧取消状态，也会盖住新启动错误。

这些是可通过固定场景复现的显示缺陷；用户当前书籍的具体启动异常尚未取得，不能据此断言是密钥或会话问题。

## 修复方法、字段和数据流

- readingService的内存运行状态增加可选runId，只在启动事务成功后赋值，每次点击启动先清空。无数据库字段、工具接口、提示词、备份变化。
- StoryPanel单行状态也接收启动失败和读取失败；当前启动失败不使用旧轮cancelled终态及API计数。真正取消已运行任务仍显示取消结果。
- 用户点击→当前尝试进入准备态→校验及读取资料→成功取得新/原runId并运行；失败保留实际error并恢复按钮。错误不要求必须存在任务或进度记录，修正原因后可以再试。
- AgentActivity在没有实际API请求时不把启动错误称为API失败；存在请求的错误沿用原语义。
- 沿用现有互斥与资料校验，保留历史结果，不自动绕过执行权或清空用户资料。

## 验收场景与任务

在隔离浏览器中准备提取完成的固定样本，清除测试密钥：首次点击无P3进度时立即显示原因；有旧取消进度时重新开始同样显示本次原因；均未发API。恢复测试密钥后再次点击，固定响应正常完成。另核对正常串联、取消和复用路径未变。

实现入口src/features/story/StoryPanel.tsx、readingService.ts、agents/activity.ts；tests/browser/story.spec.ts与tests/story-reading.test.ts、agent-activity.test.ts。针对性类型、业务、浏览器、治理/OpenSpec校验；真实用户启动原因和用户复测待确认。


## 开发检查结果（2026-11-13）

修改前：生产构建浏览器两个回归用例均失败，断言“请先保存整理模型与密钥。”时找不到任何alert，分别覆盖没有P3进度及旧取消记录。

修改后：相同两例通过，并验证未发API、保留旧成果、补回测试配置后可正常重试；连同正常三页串联/复用/全量重启、取消恢复，共4项生产浏览器测试通过。相关单元测试25项通过。生产构建、治理检查和本变更OpenSpec严格校验通过。

用户实际书籍此次被什么条件阻止启动仍待取得提示；本次仅已证明并修复错误显示缺陷，没有把测试用的缺少密钥原因归因到用户环境。待任务6.3用户刷新复测；未调用真实模型，未修改正式书库。
