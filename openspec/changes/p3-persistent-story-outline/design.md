# REQ-032 剧情大纲实施设计

本设计对应[提案](proposal.md)和[差异规格](specs/story-organization/spec.md)。现行 P3 已能翻页、带相关候选，并在用户启动后进行全书复核。本变更复用这些入口，将归类和续接的单位改为故事线及事件。

## 字段变化

| 对象与存储位置 | 变化 | 字段标识与含义 | 类型、默认及校验 | 赋值与读取 | 旧数据、接口及备份 |
|---|---|---|---|---|---|
| 单书 `eventLines` 故事线 | 新增事件引用 | `eventIds`，成员事件编号；`outlinePending`，旧线大纲待核对；`role`，主线或支线标记 | 编号列表去重并引用本书有效事件。缺省 `eventIds` 表示旧结构。可选布尔值 `outlinePending` 为真时仍展示旧线成果。缺省标记表示尚未标记 | P3 通过大纲工具修改。旧线首次整理时标为待核对，通过核对后切换。新线保存即生效 | 沿用旧线稳定编号，保留旧文本和直接成员。大纲生效后以事件引用计算当前成员 |
| 单书新增 `storyEvents` | 新增事件 | `id` 事件编号、`title` 事件名称、`nodeIds` 成员节点、`revision` 版本 | 标题必填，编号由应用生成，成员按原文位置排序去重并校验同书归属。新建时至少有一个节点，后续移空可保留待整理的事件。版本沿用资产修订约定 | P3 依据节点新建或修订。候选、大纲、复核及备份按编号读取 | 旧书无事件记录时仍可读旧线。整书备份新增事件和对事件的引用 |
| 节点详情和事件网络的读取结果 | 新增只读归属 | `storyMemberships`，每条含 `lineId`（故事线编号）和 `eventId`（事件编号） | 默认空数组，按编号组合去重。旧线条目的 `eventId` 为 `null`；未归线事件的 `lineId` 为 `null` | 数据读取时根据已生效的线与事件引用、兼容旧线和未归线事件生成。节点详情显示名称，网络读取归属用于高亮和生成边 | 原节点编号及 `eventLineIds` 兼容读取。新数据的线编号从实际归属去重取得，备份恢复后根据引用重算 |
| 线与事件的目录和详情 | 新增派生结果 | 章节、涉及人物、地点和成员计数 | 遍历现有节点汇总。章节沿原章定位排序，人物优先使用稳定编号并保留未绑定称呼，地点来自 [REQ-031](../p1-event-node-locations/proposal.md) 的名称并去重 | 节点或归属变化后由程序更新相关展示或计算结果。P3 提交结构改动时不填写汇总 | 缺地点按空处理。派生结果可由备份中的引用与节点重新计算 |
| P3 页输入和写工具 | 修改 | 当前大纲、本页节点、事件及节点引用变动、保存回执 | 大纲列出已保存的线和事件名称、编号和归属。新增、移动或移除以具体引用为单位 | 启动和翻页读取现有大纲。写入由现有会话执行权约束，工具返回实际变更和回执 | 历史运行继续按当时使用的工具格式查看。旧检查结果不能证明三层归属已检查 |

### 复核说明字段

- 故事线复用 `eventLines.summary` 表示「概况」，新增可选文本 `eventLines.coreClue` 表示「核心关键线索」。旧结构故事线的 `summary` 及 `cause/process/result` 按原用途兼容；只有已进入三层大纲的线由新版复核写这两个字段。
- 事件在 `storyEvents` 新增可选文本 `summary` 和 `coreClue`。已有事件和旧备份缺少字段时读取为空；新版创建故事线和事件时初始化为空，串联阶段不要求模型填值。
- 概况说明该对象覆盖的剧情进展；核心关键线索说明贯穿它的关键问题、目标、人、物或事项。两者均为自由文本，不增加节点编号，因为事件和故事线的节点已经由 `storyEvents.nodeIds` 与 `eventLines.eventIds` 关联。
- 共享事件只核一次成员。事件说明按对象保存，可在一次阅读中核对多件短事件。故事线说明在事件说明之后。事件及已转换的故事线必须有非空 `summary` 和 `coreClue`，此前误标完成或从旧轮复用的空白说明重新待检。旧线保留原文，切换后才可写新版说明。字段含义和正反例由复核提示词维护，检索匹配两项说明。两种说明页仍按当前对象和成员节点建立指纹。
- `save_story_outline` 的 `update_line` 与 `update_event` 可提交 `summary`、`coreClue`，但程序只接受 `phase=global_review` 的这两字段。归属串联阶段仍可按现有操作建立和修订结构。

**字段值示例。** `eventLines.summary = "围绕查账、追赃及赖家后续处置展开。"`，`eventLines.coreClue = "赖大贪污及其牵连范围。"`；`storyEvents.summary = "核查赖家账目并发现侵吞证据。"`，`storyEvents.coreClue = "赖大是否侵吞公中财物。"`。前两项概括多事件持续进展，后两项概括单个事件，字段由全书复核中的模型更新，程序只校验阶段和字符串类型。

故事线与事件、事件与节点均按多对多引用保存。修改共享事件的成员会更新引用它的所有线。从一条线解除引用只改变该线。事件失去最后一条线的引用时，仍可从大纲中的「未归线事件」查看。节点失去最后一个事件的引用时，仍按原文顺序出现在节点列表及事件网络中，可用「散落节点」筛选。事件和节点均按各自编号去重统计。

## 数据流转

1. 读取已保存的大纲，并按章查看本页节点的编号、名称、概述、详细经过和有值的线索。需要进一步核对时通过编号查阅线、事件或节点的详情。
2. 模型判断新增或续接，情况不明确时展开相关事件或节点经过。P3 继续基于 P1 节点工作，原著查阅沿用 [REQ-025 已确认的原文权限](../p3-continuous-story-lines/lightweight-input-discussion.md)。
3. 调用 [`save_story_outline`](#大纲写入) 校验引用、版本和执行权，并在一次事务保存结构和真实回执。下一页读取最新已保存大纲。当前页有日常节点时，可直接翻页，日后发现承接再追加。
4. 大纲视图按线和事件展开，用户可从节点回到现有详情。事件网络从同一份归属数据生成事件内部的边，详见[事件网络兼容](#事件网络兼容)。整书备份纳入草稿、已生效结构和仍需兼容的旧资料。
5. 节点串联完成后，按[独立全书复核](#独立全书复核)依次核对全书归属与疑点、事件说明和故事线说明。P3 工具在初始串联阶段拒绝写入这两字段；复核进度与字段值一同持久保存，刷新后可继续。

浏览器单书库升级到版本 10 以新增事件表。含大纲结构或大纲运行记录的备份采用格式 13，已有格式 12 及更旧的受支持备份仍可恢复，恢复时补空事件表。旧库升级只增加空表时，迁移摘要仍能识别已经迁移的同一份资料。

**示例**。第120章读到「这个账总要算的」时，建立「赖家线」和「清查赖家」，把该节点作为第一个成员。第126章新节点谈到借整顿贾族处理赖家，本页直接带出旧线、事件和第120章节点。保存只追加第126章的节点编号，界面自动把章节从 `[120]` 更新为 `[120, 126]`。第145章在荣庆堂谈到查账，第146章赖大被拿下，第149章起讯问继续推进清查。贾赦另查西府账、查抄、库银入库和荣府反应按不同进展建事件。田庄、铺子以估价或待折卖记录，已入库银两单独可查。章节号用于说明原文位置，实际成员用 P1 节点编号。 [小说样本](../../../tests/fixtures/红楼之挽天倾-赖家线.txt)

### 旧线切换

初次接入时，从已有节点及旧线成员建立大纲，保留旧线编号、文本和原成员依据。首次往旧线加入事件时生成待核对结构，原有线的展示继续可用。复核通过后由 `activate_legacy_line` 核对旧成员去向并切换成员来源。后续 P1 单章重提或节点删除时，按实际影响更新被移除的节点引用、派生结果和待核对位置。整书重提沿用现有影响预览，预览须覆盖大纲。

### 事件网络兼容

[现有网络交互](../improve-event-network-interaction/specs/event-network/spec.md)继续适用。保留画布、章节列、节点卡片、故事线颜色、节点点击聚焦、所属线选择、筛选、缩放、平移和编辑入口。节点详情在名称下方、事件网络在选中节点区固定展示只读的「所属故事线」和「所属事件」。例如同一行显示「赖家线」和「清查赖家」，多重归属逐行显示，空值保留单元格。旧线仅显示线名，未归线事件仅显示事件名，散落节点保留一行空白。画布继续按所属故事线高亮。

- **读归属。** 资产读取服务按已生效的 `eventLines.eventIds → storyEvents.nodeIds` 反查每个节点的 `storyMemberships`。例如 `N145` 可返回 `[{lineId:"L01",eventId:"E01"},{lineId:"L02",eventId:"E04"}]`。节点详情和网络使用同一口径。该字段由现有引用计算，P1 的节点提交只负责节点内容。
- **生成边。** 对每条已生效故事线，逐个事件取实际可用的成员节点，按章节和章内顺序排序去重，只连接同一事件内相邻的两个节点。同一故事线里两端相同的边合为一条，保留全部提供依据的事件编号；同一事件被多条故事线引用时，沿用各所属线的颜色和高亮。每个节点始终只绘制一次。筛选只显隐已有边。只有一个节点的事件仍显示节点；未归线事件的节点在主图沿用无所属线样式。
- **旧线与切换。** 没有生效大纲的旧线按原成员和原连线显示，其归属只有线编号。旧线切换后，当次刷新使用事件内连线，旧的跨事件连线随之消失。一本书内可并存两种线。旧线仍从原入口编辑；已切换的线从原入口进入编辑器，成员按事件分组调整并写入相应事件引用，平铺后的节点列表只作兼容读取。
- **刷新。** 登记节点、事件与故事线的变更订阅。移动、移除节点或切换旧线后刷新同一份节点归属和连线，保留现有视图状态。备份恢复后按真实引用重建同样的图。

**赖家线示例。** 假设「清查赖家」包含第120、126、145章三个节点，「查抄赖家」包含第151、152章两个节点。图上有 `120 → 126 → 145` 和 `151 → 152` 两段，同用赖家线的颜色。第145章与第151章的节点各自按章定位，中间没有跨事件连线。章节号代表示例中的节点位置，实际画边使用节点编号。

## P3 工具契约

串联装入五个工具。全书复核额外装入 `search_story_context` 和 `read_original`。旧运行可回看实际工具，历史串联流程中的 `save_story_lines` 沿用旧成员和概述契约。新流程的写权限限于本书的大纲结构和线索，P1 节点、人物、地点和章节原文由各自的现有入口管理。本节对应[工具参数清单](../../../docs/v2/resources/v2.2/tool-contracts.json)和[工具返回 Schema](../../../docs/v2/resources/v2.2/tool-results.schema.json)，沿用[现行工具与回放契约](../../../docs/v2/11-AI工具返回与回放契约.md)的兼容和事务约定。

| 工具 | 模型输入 | 成功返回与作用 |
|---|---|---|
| `search_story_context` | 全书复核和历史兼容流程沿用其关键词与范围参数 | 复核按涉及人物、节点线索、地点及剧情文字查找。事件也可通过成员的这些内容命中。全书大纲检索跳过旧版的已开始行动、新增事实。串联按编号使用 `get_story_detail` |
| `get_story_detail` | 必填 `kind`（`node`、`event`、`eventLine`、`note`）和 `ids`。正文用 `char_offset`、`maxChars` 续读，成员用 `memberOffset`、`memberLimit`。可选 `members` 选择事件详情的 `parent_lines` 或旧线详情的 `legacy_nodes` | `data`、`missingIds`。节点返回已保存经过及正文续读位置。事件默认分页返回节点编号，选 `parent_lines` 返回所属线编号。故事线默认分页返回事件编号，选 `legacy_nodes` 返回旧成员。成员页给 `memberCount` 和 `nextMemberOffset`，末页用 `null`。评估删除共享事件时可查完整所属线 |
| `save_story_outline` | 必填 `operations` 及可选批次 `reason`，见[大纲写入](#大纲写入) | 成功返回保存回执、实际变更和新编号。提交保持当前页 |
| `save_story_notes` | 沿用 `notes` 或 `workingSummary`，至少提供一项内容。线索沿现有 `key` 更新，可引用已有线和节点 | 命令回执及 `changed`。用于明确但暂时无法判断的线索。普通日常节点可直接留在原列表 |
| `navigate_story_pages` | 必填 `direction:"next"\|"previous"`，可选 `currentPageId`、`reason`、`notes` | `ok`、`complete`、`page`、`summary`。前进登记本页已检查，回看只改变显示位置。整阶段读完时 `page:null` |
| `finish_story_batch` | 可选 `summary`、`reason`，单独调用 | `accepted`、`status:"completed"\|"partial"`、实际 `commitIds`、待查页 `remaining`。程序由进度得出结果 |

串联首次进入、恢复和翻页使用同一份中文资料。先发送当前已保存的大纲，含故事线数量、去重后的事件数量、线和事件各自的名称和编号，以及事件的成员节点编号。未建线时数量为零，未归线事件单列。随后按章发送本页节点的编号、名称、概述、详细经过及有值的线索。第二页读取第一页面实际提交的结构，用户暂停续跑时读取暂停前的提交。需要补充资料时按编号调用 `get_story_detail`，故事线返回分页事件名称和编号，事件返回分页成员节点名称和概述。串联的保存结构声明共享参数，程序仍对每一项按操作契约校验。实际展示的线、事件和本页节点登记在读集中。

全书复核的进入、恢复和翻页使用中文资料。散落节点与成员分段按章展示节点及详细经过。事件说明页列出该事件的成员概述，故事线说明页列出线下每个实际事件的编号、名称、概况和核心关键线索。疑点随对应对象提供，尚无关联对象的疑点集中展示。复核页面以实际成员关系组织，无通用的自动搜索结果。资料按需读取，能从页内确定的对象直接提交。

### 大纲写入

`save_story_outline({ operations, reason? })` 按数组顺序执行。每项含 `op` 和表列参数。编号和标题用字符串，标题去掉首尾空白后须有内容。创建操作的 `ref` 是本次调用内唯一的临时名称，后续操作通过 `$名称` 引用，实际编号由程序分配。旧对象用已知的实际编号。节点列表要求非空且按编号去重。所有操作只接受表列参数。

| `op` | 必填参数 | 可选参数 | 效果 |
|---|---|---|---|
| `create_line` | `ref`、`title` | `role` | 新建故事线 |
| `update_line` | `lineId` | `title`、`role`，至少提供一项 | 更新名称或层级。层级取 `main`、`sub`，`null` 清除标记 |
| `update_line`（复核） | `lineId` | `summary`、`coreClue`、`title`、`role`，至少提供一项 | 复核阶段更新已启用大纲的故事线说明。更新说明时，保存结果须同时有概况和核心关键线索 |
| `create_event` | `ref`、`title`、`lineId`、`nodeIds` | — | 创建事件并挂到指定故事线，节点可以已属于其他事件 |
| `rename_event` | `eventId`、`title` | — | 更新同一事件的名称 |
| `update_event` | `eventId` | `title`、`summary`、`coreClue`，至少提供一项 | 更新事件名称。仅在全书复核阶段可更新说明，保存结果须同时有概况和核心关键线索 |
| `attach_event` | `lineId`、`eventId` | `fromLineId` | 省略来源时增加一处引用。有来源则将该处引用移到目标线 |
| `detach_event` | `lineId`、`eventId` | — | 只解除这条线对该事件的引用，保留事件记录 |
| `attach_nodes` | `eventId`、`nodeIds` | `fromEventId` | 省略来源时追加节点，保留其他归属。有来源则只把指定节点从该事件移到目标事件 |
| `detach_nodes` | `eventId`、`nodeIds` | — | 只解除指定事件内的节点引用 |
| `delete_line` | `lineId` | — | 删除已启用大纲结构的故事线及其事件引用，保留事件及变更记录。尚待转换的旧线从原入口查阅 |
| `delete_event` | `eventId`、`expectedLineIds` | — | 整体删除该事件并解除对它的全部引用。预期所属线必须与事务内实际集合一致，空列表表示当前无归属。原节点及其其他归属保留 |
| `activate_legacy_line` | `lineId` | `excludedNodeIds` | 仅在旧线整线复核页生效。程序校验每个旧成员已归入这条线的新事件，或已被明确列为移出该线。切换后仍可查询旧文本和成员 |

附加已存在的引用、解除已不存在的引用均可返回无变化。移动时来源和目标须不同，来源必须确实含有指定成员。删除前，模型须已读相应对象。删除事件还须取得完整的所属线编号，目录标记截断时按详情续读。事务按本批到当前操作为止的归属判断删除范围。程序从真实成员汇总章节、人物、地点和顺序，剧情经过从成员节点读取。

### 待复核事项保存与关闭

赖家线实际串联时，模型恢复了怜雪故事线原名，创建的「L-怜雪线误改」事项却一直保持待复核。旧保存工具用 `key` 定位事项，成功回执未返回数据库编号。随后模型两次把 `key` 用作详情编号，未取得读取依据，关闭操作被拒绝。

新版大纲的 `save_story_notes` 保存后增加可选的 `notes` 回执列表。每项返回真实 `id`、`key`、状态、内容及关联节点和故事线编号。程序在同一事务记录该版本的读取依据和回执，重放复用原回执。旧回执可缺少该属性。事项持久字段、数据库和备份格式沿用原结构。

`get_story_detail` 的 `kind: "note"` 和 `ids` 沿用原入参，可在当前书籍、当前会话按事项 `key` 匹配。例如 `{"kind":"note","ids":["L-怜雪线误改"]}` 返回该事项真实编号和内容。已有事项未读时，关闭返回 `READ_REQUIRED` 并附可直接调用的真实编号参数。有读集时可直接用原有 `key` 提交解决说明。快速核对缺少已读依据时，提示留到正常串联或全书复核处理。

## P3 真实请求追踪

P3 卡片常驻「P3 整理详情」，弹窗有「事件串联」和「全书复核」两个入口，默认打开当前阶段，尚未运行时默认事件串联。阶段切换只查询执行链，没有记录时显示空状态。每个阶段选最近含对应任务的运行；重新复核后仍可切回读取上一轮串联。

读取增加可选查询参数 `storyPhase`，只接受 `window_link`（事件串联）和 `global_review`（全书复核）。程序根据 `pipelineRuns.tasks.phase` 找任务，由 `taskId` 匹配请求。磁盘分页、单次请求展开和浏览器存储回退统一使用相同阶段范围。已保存且有任务关联的请求可直接归类，缺少任务关联的请求保留在原始日志中。详情展示工具提交回执，归属结果由剧情大纲和事件网络呈现。业务写入、历史记录和备份继续可读。

每个阶段使用同一个 `ExecutionChainView` 界面组件，各从 API 01 开始。首条显示实际发送的 system prompt、程序注入消息、工具定义及其模型回复。后续请求比较该次持久化 `input.messages` 与本阶段上一次，默认只显示新增或变化的消息、模型思考、输出和工具往返。每组请求可展开「查看本次实际请求」，读取实际保存的消息、工具定义、请求参数和返回。分页将选中阶段的第一条请求保留在首屏。

数据直接取自已落盘的 API 请求和会话条目，不用 P3 业务页摘要重写请求内容。举例：第一次请求含节点 `N120` 和完整工具定义；第二次再次发送这些历史消息并新增节点 `N126` 的用户注入时，默认时间线只显示新增的 `N126` 消息及第二次模型返回，展开第二次仍能核对含 `N120`、`N126` 的完整原始消息列表。

**第120章建线及第126章续接**。示例编号用于说明参数，实际编号由工具返回。

```json
{
  "operations": [
    { "op": "create_line", "ref": "lai", "title": "赖家线" },
    { "op": "create_event", "ref": "audit", "title": "清查赖家", "lineId": "$lai", "nodeIds": ["N120"] }
  ]
}
```

```json
{
  "operations": [
    { "op": "attach_nodes", "eventId": "E01", "nodeIds": ["N126"] }
  ]
}
```

例如家宴节点 `N144` 已在庆功事件 `E02`，向人物关系事件 `E03` 调用 `attach_nodes` 时省略 `fromEventId`，即可保留两处引用。以后用 `detach_nodes` 对 `E02` 解除引用，`E03` 内的节点仍可见。若直接移动 `E02` 中的引用，则在 `attach_nodes` 中明确填写 `fromEventId:"E02"`。

成功返回 `{ok:true,commitId,changed,alreadyApplied,created,changes}`。例如 `created:{"lai":"L01","audit":"E01"}` 为临时名称到正式编号的映射。`changes` 每条带从零开始的 `opIndex`、对象 `kind`（`eventLine` 或 `event`）、实际 `id` 和 `action`（`created`、`updated`、`deleted`）。引用变更给出实际 `addedIds`、`removedIds`，一次移接或删除可返回多条变更。整理详情可查真实前后值。命令成功但无实际变化时为 `changed:false`、`changes:[]`。

请求由程序绑定同书会话、提交键和实际读集。批次先核参数、引用、读集及执行权，再同事务保存大纲、变更记录和命令回执。相同调用重放返回原编号和确认，`alreadyApplied:true`。同一键内容不同返回 `IDEMPOTENCY_CONFLICT`。输入或临时引用不合法返回 `INVALID_ARGS`，对象不存在或无访问权返回 `SCOPE`，写入缺少实际读取依据返回 `READ_REQUIRED`，对象版本或预计删除范围变化返回 `CONFLICT`，丢失执行权返回 `LEASE_LOST`。失败返回 `{ok:false,code,message,opIndex?}`，整批回滚。冲突提示定位到需刷新的对象。入库成功但回执丢失时，恢复流程用原调用取得已提交结果。

### 串联主按钮和快检

- 运行时点「暂停串联」，当前在途请求到安全位置后停，新请求停发。进度为暂停，当前大纲、已提交修改、会话编号和原运行编号保留。「继续串联」从该轮持久页恢复。
- 点「取消串联」结束当前任务，结果保留，主按钮回到「串联事件线」。这时再点主按钮，程序在启动事务内新开会话，清空故事线、事件和节点的反向归属，从第一页读取。节点正文和历史请求仍可读取。没有保存模型配置、提取未完成或书籍被锁定时，在清理之前结束启动。
- 点「快速核对后继续」，原会话归档，当前大纲和待复核事项保留，以新会话运行。程序以已完成的节点检查和当前内容确定快检页，阅读状态保存快检页编号和校验依据。快检仅提供节点概述、线索和本页现有归属，只允许对已提供节点增减或移接引用、登记疑点和翻页。最后一张快检页完成后，在本轮会话切回正常串联。
- 例如原 run R01 已检查三页并取消，第 4 页已有部分归属。选继续快检时，R02 的第 1–3 页先查归属，第 4 页的旧归属保留，接着正常处理。若此时选覆盖串联，R02 的首页大纲是零条故事线、零个事件。

## 独立全书复核

串联沿用初始会话。复核以 review 类型和本轮编号建独立会话，parentSessionId 定位串联来源，仅交接事项和大纲。复核阶段的会话消息和摘要按自己的编号读取。旧会话历史保留，旧页码不折算为新任务完成量。活动事项可用可选 eventIds 引用本书事件，与节点和故事线引用一并检查依据。

复核开始先核散落节点、事件成员、整线归属及交接事项。逐项保留具体结论；证据不足可以暂留。归属核对完成后核实事件说明，再写线的说明。详情、写入、翻页及其回执沿用现有工具。暂停保留步骤、对象、分段和回执。复核变更以保存的页面及依据判断重查范围；新增章节须重新考虑散落节点与旧伏笔。例如傅试移出凤姐线时重新核对受影响的两条线。完整重查保留大纲并重建检查进度。

验收使用小说副本核对事项交接、两阶段首请求、暂停和重开、写入与归属顺序及关键线索质量。

复核允许按章查原文。短事件的说明按资料长度合批展示、批量保存，每个事件仍单独记录完成依据。阅读步骤的 questions 保存交接问题，decisions 按事项标识保存判断依据与结论。翻页工具可选的 noteResults 只在当前页存在尚未解决的事项时填写，逐条给出 id 和 conclusion；复核写工具可直接解决已核实的事项。阶段恢复按现有事务、回执和来源指纹执行。

新大纲事项的 basisVersion 为 2。保存工具与复核交接在本书按节点、事件及其所属线记录依据；旧依据仍按原方式验证后转换。当前轮已核实的未解事项以问题、依据和结论展示，再次出现相关章节或归属变化时重新交给复核。
