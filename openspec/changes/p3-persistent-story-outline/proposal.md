# REQ-032 P3 持续维护小说剧情大纲

## Why

现行 P3 在 [REQ-025](../p3-continuous-story-lines/proposal.md) 中按页读取事件节点，保存事件线时直接挂节点，并可编写整线概述。新页可能只看到旧线候选的名称、概述和一部分成员，遇到早先铺垫时有时仍要专门查询。每次续接还要判断是否改写整线内容。

用户提出让 P3 在阅读过程中持续维护本书大纲。遇到「赖家的账总要算」即可建线，后续从同一份大纲找到这条线，跟进清查、查抄和追赃等不同事件。故事线与事件的章节、人物、地点由程序从节点汇总。

## What Changes

- **故事线**围绕持续目标或矛盾组织多个事件。主线、支线是故事线的标记，并行故事线可以各自成立。
- **事件**是故事线中一项可独立描述的剧情进展，可含一个或多个事件节点，允许跨章。
- **事件节点**仍是 P1 按章提取并定位到原文的叙事材料。一个节点可被多个事件引用，一个事件也可被多条故事线引用。日常节点可留在散落节点列表，后来发现承接再归入大纲。
- **事件网络**保留现有展示和操作。每个节点详情列出它所属的故事线与事件，同一事件内的相邻节点才连线。

P3 每页收到本页节点和已保存的大纲。串联提供[五个工具](design.md#p3-工具契约)，其中 `save_story_outline` 接收线、事件和节点引用的增量操作。跨页续接只提交对应事件和新增节点编号。代码保存结构并自动汇总节点信息，情节依据可在成员节点概述及经过中查阅。

节点串联和叙事说明分两个阶段：串联阶段只建立故事线、事件及已有节点编号的归属；节点阅读完成后，全书复核逐条填写和修订故事线、事件的概况与核心关键线索。节点归属已经保存在现有引用关系中，不另加支撑节点字段。P3 整理详情沿用 P2 的真实请求追踪，首个 API 展示完整输入，后续 API 默认只展示新增或变化的上下文，并可展开核对每次实际发送内容。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `story-organization` 增加本书大纲、早期建线、跨页续接和逐层复核，接续 REQ-025 的按页阅读流程。
- `event-network` 更新 FR-11 与 EVENT-NETWORK-01 的成员读取、事件内连线和旧线兼容规则。
- 大纲视图、Agent 工具和整书备份随结构变化接入，行为集中记录于本变更差异规格。

## 确认依据

2026-11-20，用户提出「P3 定期维护」小说大纲，模型只处理故事线、事件和节点索引，由代码计算章节、人物、地点。用户指定先记录和评审，再决定开发，P1 地点优先。已授权准备本评审材料，技术和兼容方案待评审。

用户随后要求核对日常散落节点及共享归属，并指出计划需要定义工具接口。已补充具体调用、权限、错误和验收。全局删除事件和旧线切换的规则按下列方案待评审。

用户明确要求与原事件网络兼容，保留展示方式，节点新增故事线和事件归属，不同事件之间无需连线。按该口径补充网络差异规格。

2026-11-20，用户回复「开始施工」。实施范围以当前三层大纲、六工具契约、删除与旧线切换规则以及事件网络差异规格为准。先接通 REQ-031 的地点字段，再实现本变更。

2026-11-20，用户检查前端后要求「就算没分也要有字段空白占着」。在节点详情和事件网络的选中节点区固定显示「所属故事线」和「所属事件」，空值保留位置，多重归属按故事线和事件成对显示。

2026-11-21，用户明确要求故事线与事件各保存「概况」和「核心关键线索」，两项只在节点归属初步完成后的全书复核阶段生成和修订；节点编号沿用现有归属引用。用户同时要求 P3 整理详情真实显示 API 首次完整输入、后续新增或变化输入、模型思考及工具往返，行为与 P2 一致。

2026-11-21，用户确认全书复核两项必填，授权按最小范围修正已发现的问题。概况交代缘由、主要推进和已知结果。线索可来自人物、事件、地点、物品或原文留下的问题，须说明它如何触发、推进或串接剧情。真实小说样本由用户复核。

用户随后要求 P3 整理详情提供事件串联和全书复核两个独立入口，用实际请求和模型返回分别分析提示词。本变更采用 P3 卡片上的常驻「P3 整理详情」，打开后可切换两个阶段，各自查看最近有任务记录的一轮。此调整影响执行记录的查询和展示，模型实际收到的历史、工具及提示词内容仍按存档展示。

## 讨论结论

用户确认串联首次和翻页都提供全书已保存大纲与当前页的中文节点资料。大纲给出数量、名称、真实编号和事件归属。详情按编号读取，工具保留大纲增删改及移接能力，缩短模型侧参数声明。P3 详情撤去逐字段实际修改展示，继续保留原始请求及回执。

用户要求补清楚现有工具的参数与结构操作，并优化全书复核输入和跨章检索。复核成员页使用中文节点资料，故事线说明页直接提供实际所属事件及其说明，取消自动推荐。复核搜索用涉及人物、线索和现有剧情字段匹配，停止使用已开始行动与新增事实。保留已登记工具和已有参数，存储记录与旧流程继续兼容。

用户确认串联主按钮依次显示「串联事件线」「暂停串联」「继续串联」。暂停保留同一轮上下文与大纲，取消结束本轮且暂存已提交大纲。取消后点串联才以空大纲和新模型会话重建；也可点「快速核对后继续」，保留大纲，用新模型会话快速核对有效完成页，再进入正常串联。整理详情页面及按钮、全书复核入口沿用现有交互。

用户确认修复 BUG-56。保存待复核事项时返回已保存内容及编号并登记为本轮已读。此前保存的事项可按当前会话内的标识读取，关闭前的读取校验失败时返回可直接使用的查询参数。

- 对出现明确待处理事项、计划或冲突苗头的节点，可以在第一次出现时建线。后文是否回应由后续章节决定，已经记录的铺垫可继续查看。
- 「赖家线」是故事线。「清查赖家」可收录首次提议、计划、向贾母说明、拿下赖大和讯问等节点。贾赦另查西府账、查抄、追缴入库和荣府反应可以按各自的剧情进展建事件。田庄、铺子的估价或拟折卖写入相关节点，等原文出现实际处置再记录结果。
- 工具提交后即时保存，翻页自动读取更新后的大纲。需要核对时按编号查详情，早先的铺垫可通过成员节点找回。
- 普通日常节点可以无归属翻页。一个节点同时承载两个独立事件时，两个事件各引用同一节点编号。
- 旧线文本和旧成员作为兼容资料，P3 在整线复核页核对旧成员去向后切换。解除某条线上的事件引用只影响当前线，整体删除事件时须核对全部所属线，P1 节点仍在原列表。具体权限见[大纲写入](design.md#大纲写入)。

## 2026-11-21　按大事串联与全书目录复核
用户确认按同一大事引出的准备、阻碍、发现及后果建线，一项具体行动从起因到结果收为事件，可跨章续接。用户以“改吧”确认本轮方案。沿用 REQ-032，两阶段独立会话，先分类再写说明。涉及串联提示词、复核阅读队列、恢复和双阶段验收；使用已有大纲工具。参见设计同名章节及任务 7。

## 2026-11-21 节点读取范围确认

用户要求串联与全书复核都从已解析的节点整理，查详情必须指定编号及一项或多项字段，用户自行进行下一次真实模型试跑。程序先送标题和归属，搜索及事件详情只展开成员索引。复核初查、复查直接提供三级标题。字段选择、错误反馈和续读规则见 P3-NODE-01。已有小说数据和已保存的检查点无需迁移。

用户确认 P3 串联用低档思考，全书目录初查与最终复查用高档。其余复核页按已讨论的低档执行。沿用当前模型连接的能力声明，验收以模拟 HTTP 请求中的实际档位为准。

用户指出当前三份 P3 提示词先列判例和规则，难以辨认角色、输入、任务和后续操作。按原有流程重新组织串联、独立复核、续跑快检的任务说明。旧流程仍使用 p3-story.md。p3-review.md 仍在选择分支中，现行全书复核固定采用新版大纲。

用户确认 P3 串联和全书复核共用取消入口，旧版已暂停的复核也能取消。暂停保留同一轮会话。取消结束当前轮，用户再次点击重新复核后，从当前大纲和交接事项开始完整独立复核。缺陷 BUG-57。
