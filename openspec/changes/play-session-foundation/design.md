# 游玩接口与扩展约定

本设计定义后续实现需遵守的共用接口。行为见差异规格，具体业务工具随需求确认。

## 身份与状态

应用绑定 bookId（书籍编号）、sessionId（会话编号）、runId（本次运行编号）和 capabilityId（能力标识）。模型参数只包含工具公开业务输入。每条异步事件携带启动时绑定的身份；窗口按选书订阅，结果保存到事件所属会话。

整理会话继续使用现有职责和结构。游玩存储方案须明确职责字段、索引、升级及备份映射后实施；复用底层能力时保持各职责的历史和摘要隔离。

## 接口职责

| 操作 | 输入 | 输出与副作用 | 失败与恢复 |
|---|---|---|---|
| 创建或恢复会话 | 应用确认的书籍、能力标识，可选既有会话编号 | 返回所属会话、按序历史、有效摘要及可继续状态；创建动作持久化身份 | 不存在、越书或职责不符时返回明确原因；原记录保留 |
| 追加消息 | 绑定身份、消息类型及原生消息内容 | 保存消息并返回条目编号及序号；消息与会话末端同事务更新 | 冲突时重新读取末端，失败不推进序号；重试核对已保存条目 |
| 启动运行 | 会话身份、用户输入、保存配置快照、能力工具清单、取消信号 | 产生消息、工具、压缩和结束事件；用户输入先保存，模型执行经 Pi | 失败显示原因并保留历史；重复发送按当前运行状态反馈 |
| 取消运行 | 原运行身份 | 停止新请求和未提交写入，停稳后发出结束状态并释放执行权 | 已提交结果持续有效；释放仅作用当前持有者 |
| 调用工具 | 已登记名称、参数及应用绑定的作用域 | 读工具返回规定投影；写工具经领域事务返回提交确认 | 参数、权限、依赖、版本与取消分别校验，失败不伪造确认 |
| 保存与核对提交 | 运行身份、操作键、规范化内容指纹 | 业务结果与确认同事务保存；重放返回原确认 | 同键不同内容拒绝；反馈丢失按原键核实 |
| 构建上下文 | 会话消息链、有效摘要、当前任务、能力提供的资料 | 返回配对有效的消息和容量结果；原始记录继续保留 | 断链或缺失结果给出可恢复信息；中断占位与真实结果区分 |
| 压缩上下文 | 当前消息、摘要边界、模型容量及取消信号 | 成功后保存新摘要和保留边界 | 失败保留原历史和原边界，并提供重试反馈 |
| 导出与恢复 | 完整书籍快照或已预检备份 | 包含会话、工具结果、摘要与提交确认；新书重写归属 | 校验失败保留原书，恢复完成后才发布副本 |

身份字段、消息形状和提交确认分别复用现有数据及工具契约。上述操作名称表示接口职责；公开函数名和类型在具体变更设计中登记。

## 可复用实现入口

- 会话创建及恢复：src/features/agents/sessions.ts。
- 消息链和上下文：src/features/agents/context.ts、compaction.ts。
- 模型与原生执行：src/features/models/、src/features/agents/runtime.ts。
- 工具、作用域和事务：src/features/agents/tools.ts、queries.ts、commands.ts。
- 数据库和备份：src/lib/storage/workspace.ts、src/features/backup/。

当前会话实现绑定叙事整理职责。接入游玩时按具体方案扩展职责并验证隔离，不能直接把游玩消息写入整理会话。

## 新能力登记与拆分

每项已确认能力在对应变更的设计中登记：中文名称、能力标识、职责、输入输出、依赖、可用工具及读写对象、保存位置、界面入口、失败恢复、备份要求和验收场景。工具精确声明在指定工具结构中维护，其他文档引用。

开发 Agent 按需求创建能力规格及模块，更新总入口、归属清单、工具登记和测试。共用接口保持稳定；接口语义或权限改变按 AGENTS.md 判级及确认。拆分保留原条款到新条款映射，已有调用方和备份有对应兼容处理。

## 实施顺序与检查

先确认首批业务工具和存储方案 → 建立会话与身份隔离 → 接窗口和模型执行 → 接工具和提交确认 → 接上下文压缩 → 补备份恢复及跨书回归。

每一步更新关联技术契约及测试。固定模型响应验证流程，真实小说样本验证内容效果。用户自测覆盖两书切换、刷新、工具反馈丢失、重复发送、取消、多标签竞争和跨浏览器恢复。
