<a id="save-source"></a>

资料装载器是为每个游戏任务准备材料的程序。它先从书中取出允许使用的字段，再按存档进度和接收者身份，为导演选取裁定能用的资料，为写手选取这场戏可以公开的动作和事实。

## 从选定资产包到存档

| 玩家操作 | 装载器实际读写 | 进入聊天后使用的资料 |
|---|---|---|
| 选择资产包 | 读取包名、已登记的资产类型与数量，并按本书身份列出存档。已恢复到书库的包使用其当前书籍身份，备份文件经现有整书导入入口恢复后再选取 | 尚未选局时无需为模型准备本局资料，也不生成开场 |
| 新建存档，从头开始 | 服务为此局分配存档编号 `saveId`，创建尚未开场的存档，并把按下表挑出的书中资料和用于校验内容的 SHA-256 值写入 `playSaves.assetBaseline`。这两步在数据库同一次写入中一起成功或一起撤销。玩家重复点击或重发请求时按[存储设计](storage.md)检查已保存的记录。保存成功后才启动开局导演 | 建档时保存的书中资料沿用书中的对象编号、顺序和关系。同一包的 A 局和 B 局各自保存一份。两局分别确认开局且生成成功后，各自有一个已结算的第 0 版。开局成功前可恢复到该局的准备状态 |
| 继续已有存档 | 取建档时保存的书中资料和当前生效版本，再从该版向前读取各轮记录，载入聊天正文、地点、人物状态和人物所知。若还没有已结算版本，未选卡时恢复原卡片；已选卡时恢复开场进度或手动重试入口 | 进入后可直接读已保存的聊天。确认开局、提交行动、申诉或改写时才按相应任务装载模型请求；单纯续玩不重新扫描资产包 |
| 资产包后来被编辑或补充 | 此后新建局采用编辑后的书中资料。已有局的开局、资料查询、历史回放和下一轮仍使用建立该局时保存的书中资料 | 同一存档的模型输入可追溯到它自己的资产版本；每轮只保存本局新结果，复用同一份建档资料 |

书库恢复会处理整书备份内的文件。游戏装载器从已导入的书库选择逻辑资产表，不接收备份 ZIP、正文文件或原始提取请求。正式环境和开发测试环境均从 `workspace.openBook(bookId)` 取得当前书库，续玩从指定 `saveId` 取同一份持久数据。[现有书库接口](../../../src/lib/storage/workspace.ts) · [整书导入与恢复](../../../src/features/backup/service.ts)

### 建档时，从原书复制哪些字段

| 输入对象 | 本局保留或查询的资料 | 使用时核对 |
|---|---|---|
| 章节目录元数据 | 章节编号 `chapterIndex`、显示名称 `chapterName`、排序值 `order` | 只用于排序及显示节点属于哪一章。节点优先使用自身的 `chapterIndex/chapterName`；旧数据缺显示名时以目录补齐 |
| 人物、地点与合并映射 | 人物的编号、名称、别名、来源章、版本、身份、外貌、性格及背景；地点对应的编号、名称、别名、来源章、版本及描述。查询资产是否已合并或改号时只取对象类别、旧编号、当前编号和状态 | 全书合并的背景和别名可能来自后文，开局及当前场景只采用能用已发生节点或本局记录支持的部分。同名多命中须保留各候选编号；遇到旧编号时，按建档时保存的编号对应关系查询 |
| 人物关系 | 有效人物对、正反关系标签、方向及可核对的来源资产 ID 和来源章。按编辑状态覆盖原关系 | 节点里两人共同出现只构成关联线索。要判定某人已经知情，需要有可描述的现场或本局获知记录。关系字段里的证据引文不复制到存档 |
| 事件节点 | 节点编号 `id`、修订号 `revision`、名称 `name`、所属章编号和名称 `chapterIndex, chapterName`、章内顺序 `order`、概述和经过 `summary, process`、参与人物 `actorIds, actors`、地点名 `locationNames`、线索 `clues`。旧数据的 `world_delta, new_facts`（提取时记录的世界变化和新事实）如存在，只供核对 | `process` 用于了解已经整理的经过；节点名、概述、经过、线索先从允许的字段中取出，再按角色权限和本局已发生的节点筛选。与别的字段或节点先后矛盾的候选不能直接写入本局 |
| 原著事件和故事线 | 包中若有，保存编号、标题、概况、关联成员、进展或适用状态等结构化字段 | 导演可沿已发生节点与事件的关联查证现场事实。包中没有事件或故事线时，仍可用有依据的节点、人物和地点开场 |
| 本局事实与记忆 | 读取已结算版本表 `playVersions`，从当前生效版本往前查找场景、持有物、实际事件、人物知情、新遇到的角色与地点、承诺、聊天正文；从该次请求记录读取玩家最初输入的全文、申诉理由和改写方向 | 读取和写入都绑定当前存档编号 `saveId` 和计算本轮所用的版本。选定起点后，尚未在本局发生的后续事件不能出现在导演可查的标题、经过或写手材料中。某项事实只有在本局有对应经历时，才能进入本局事实记录 |

实现时按类型构造新对象，只赋允许的字段，再针对筛选后留下的资料建立检索和分页索引。禁止先把原始表行、编辑器详情或整份合并档案缓存下来供模型搜索。排除 `chapterTexts`、提取输入、整理会话、当时保存的完整提示词、`node.quote/offset/quoteStatus`、关系 `evidence[].quote`、人物逐字对白样例以及其他摘录字段。旧资产的经过或关系说明偶尔夹带逐字对白，建档时去掉可识别的引语和摘录段，保留整理后的叙述；无法可靠分离的字段整项略去，回退至概述及其他结构化资料。排除在装载、建索引、生成目录和写日志之前执行。为资料分配编号、返回工具结果、发送模型请求、保存回合状态及回看执行记录，均沿用这些已筛选的字段。编辑侧的“搜索全部字段”包含引文，需传入游戏可用的资料和允许检索的字段名才能复用其匹配逻辑。[资产结构](../../../src/features/assets/types.ts) · [名称及合并映射](../../../src/features/assets/relations.ts) · [现有叙事检索字段](../../../src/features/assets/narrativeSearch.ts)

## 从哪件事之后开始

本次样本使用[《红楼之挽天倾-赖家线-仅第15至25章节点》资产包](../../../红楼之挽天倾-赖家线-仅第15至25章节点.wwv2)。已只读检查其清单和结构化资产 JSON。包为格式 12，有 36 条章节目录、131 个人物、83 个地点、48 个节点、628 条原人物关系和 88 条人物关系编辑。`eventLines` 为空，包中没有 `storyEvents` 数据文件。48 个节点分布在书内第 15 至 25 章。书内第 1 章和最早有节点的场景是不同位置。

1. 程序按章目录的 `order`、章内节点的 `order` 和稳定节点 ID 排序。首个可介入场景需有能核实的原著主角、可指认的地点、与该主角有关的已发生经过，以及玩家接下来可以决定的事。不可用候选继续查同章或后面的节点；全部查完仍缺材料时显示缺项，玩家可换包或补资产后另建局。
2. 本包首个候选是书内第 15 章《第一百三十三章 剿匪翠华山》、章内 `order=0`、`C15-N001`，节点标记为版本 32，名称为“贾珩闯云光官厅问罪”。按该节点已经整理的概述，程序可推荐从节点结束后接手贾珩。人物编号为 `C1-P001`，云光为 `C13-P011`。`summary` 可核对贾珩在官厅问责、云光先硬后软，改称恩主。按 `process` 的先后，其后贾珩又问了翠华山匪情，得知贼寇约四五百人，官兵进剿时对方闻风逃走。`phase="after"` 取在匪情谈罢之后。该处公开经过没有指名这句情报由谁回答。蔡权、黄泰等人属于节点关联人物，具体谁亲历或知道某事还要按该条经过及本局行为判断。
3. 该节点的 `locationNames` 明确给出“长安节度使府官厅”。样本的 83 个地点中查不到同名主记录或同名别名，因此程序以节点地点字段为证据，在**当前存档**建立一个局内地点 ID，并保留该字段引用。不能按地名猜造一个书内地点编号。节点间材料有歧义时亦须保留区别。例如 `C15-N001.world_delta` 已提到云光应承筹备舆图等事，而下一个节点 `C15-N002` 才详细记载索要舆图。开局没有“舆图已交到贾珩手中”这一事实。
4. 准备页展示包名、节点名、实际章名、候选主角、地点和一条依据节点概述与最后一段公开经过写成的现场说明。一个可靠候选也由玩家点“开始游玩”；有多个符合身份的候选时可先选定其一。程序把玩家选择的节点、资产版本和节点结束位置固定到此局，保存所选卡后进入聊天，将导演给出的开场动作链和停笔点交给写手，并为可向玩家公开的资料分配本次写手请求专用的编号。样本 `openingAnchor` 取 `nodeId="C15-N001", nodeRevision=32, phase="after"`；`assetRefs` 指向本档该节点的 `summary`（此前的称谓变化）、`process`（随后问及的匪情）、`actorIds` 和 `locationNames`。导演以这些字段确定已选卡的起点。写手另取本次请求的公开资料编号，能读到先前改称恩主、随后问过匪情、官厅里现在轮到贾珩决定下一步；云光的私下念头不随 `process` 传入。32 是检查该包时记录的修订号，实际建档以 `assetBaseline` 中保存的节点修订号为准。`assetPins` 记录该轮实际采用的书中条目、字段名和内容校验值，供回看或恢复时逐项核对。[存储设计](storage.md)
5. 以本包为例，`C15-N002` 的准备工作以及 `C16-N002`“贾珩逼问黄泰供出云光通贼”均晚于选定起点。开局正文、普通目录、拒绝理由及人物对白不应提前透露后一个节点的标题或结果。程序根据本局实际发生过什么决定何时允许查用某条资料；回合序号增加不会自动让原著后面的节点成为已发生事实。

## 一次请求怎样装载

1. **确定是谁在读。** 调度程序指定书籍、存档、请求和执行编号（`bookId, saveId, attemptId, runId`），同时指定计算本轮所用的版本 `baseVersionId`、任务 `task` 和模式 `mode`。从建档时保存的资料取原著信息，从该版本及其之前仍生效的回合取本局事实。末轮改写从原行动发生前读取。申诉时把玩家最初输入的全文和后来补充的理由一同交给导演。切换聊天页不改变已经启动的请求归属。
2. **产生候选。** 先围绕玩家输入、主角和相关在场者、当前地点、所问对象、线索词及有效约定，查建档资料和当前生效的游玩历史。可按明确连线从人物追到相关节点、地点与关系。少了一条关联时，可在角色允许的目录内换词、翻页和读详情。按关键词查文字、按对象编号找相关记录都可独立使用。现有的原著事件整理流程（P3）可按节点查找相关原著事件。若用向量相似度调整搜索结果顺序，计算范围仅限该任务可见的资料。[现有事件候选排序](../../../src/features/story/eventCandidates.ts)
3. **筛选后才生成目录。** 搜索哪些文字、展示哪些标题和摘要、如何说明找到某项资料的原因，都按接收任务的可见范围处理。按同一资产与字段、同一本局版本和同一可见范围合并完全重复项；不同人物对同一件事的看法保留两条。当轮直接对象、实际发生的前事和未了事项优先，并以章序或回合序及稳定 ID 排同级项目。首次请求发送必需材料和第一批目录条目；其余保留可继续查询的引用。
4. **把这场戏交给写手。** 程序沿导演使用的资料编号查到对应的建档字段或已结算事实，核对来源，按顺序保留本轮剧情动作链的步骤编号、行动者和经过，为每一步允许揭示的资料重新分配写手可用的编号，再附导演指定的停笔点。某个非玩家角色私下怀疑什么，可供导演判断反应；只有本轮允许向玩家揭示的表现才交给写手。模型查过资料不会让故事中的人物自动知道这件事。
5. **保留实际请求。** 执行记录保存存档编号、计算本轮所用的版本、模型可见字段及来源编号，以及首次请求的实际内容和各项工具返回值。回放直接读取已保存的游戏请求，不重新去原著书库补材料。原始聊天文本属于本存档的游玩历史，与包内小说原文分开取用。

| 角色任务 | 首次请求中的材料 | 追加读取 |
|---|---|---|
| 开局导演 | 建档资料中最早一批合格节点的结构化概述、关联人物和地点，章名及排序；输出可选起点、资产依据、状态、可向玩家展示的剧情步骤和下一步停在哪里 | 当前候选及必要的结构化关联。明确显示哪个结果在选定节点结束时已成立 |
| 行动导演，包括申诉和改写 | 玩家本次意图、相关有效交流、现场事实、各人物的知情或误解、近期正文、与本轮有关的已发生事件、约定及可查资料目录 | 本局其他有效历史和当前可用的资产。拒绝理由只能展示主角有依据知道的条件；依据仅对后台可见时给公开的中性反馈 |
| 每轮写手 | 开场用已选卡，行动用已核准的裁定。主角的行动、可见反应和本轮后果按 `beats[]` 顺序给出；每步含 `id, actorIds, text, revealRefs`。另附停笔点 `stopAt`、人物可用口吻、公开事实和最近正文，字段及贯通样本见[模型契约](agent-contracts.md) | 没有资产读工具。写手交小说段落，按步骤写到玩家该接话的位置 |
| 历史摘要 | 从当前生效版本向前追溯，取指定的已结算回合、原始游玩消息、局内事实和来源 ID | 没有资产读工具。摘要只在它覆盖的版本都属于当前进度所经历的连续回合时采用；可凭局内 ID 找回被摘要省略的旧事 |

## 工具一　browse_play_sources 查游戏资料目录

**调用者**　开局导演、行动导演。应用绑定本局、运行、任务用途及可读范围，模型不能指定角色、数据表、书籍、存档、版本或另一人物的访问范围。

| 参数 | 类型与默认值 | 用法 |
|---|---|---|
| `query` | 必填字符串；空字符串表示当前候选目录 | 输入人名、地点、线索、局内事项等。直接 ID 也需通过当前任务的权限检查 |
| `kind` | 可选枚举；默认查当前任务可用类别 | 人物 `character`、地点 `location`、关系 `relation`、节点 `node`、事件 `event`、故事线 `line`、局内记忆 `memory`。没有对应资产或者在当前任务不可用时不显示该类项目 |
| `cursor`、`limit` | 可选字符串（下次查询时原样传回）、可选整数；默认首页和 10 条；每页 1～50 条 | `cursor` 是工具返回的下一页位置标记。它只适用于同一次查询、资料类别、任务、建档资料和排序规则版本，`limit` 指每页条数。更换查询从首页开始 |

```json
{"tool":"browse_play_sources","arguments":{"query":"官厅","kind":"node"},"result":{"items":[{"ref":"asset_7kw","kind":"node","title":"贾珩闯云光官厅问罪","summary":"贾珩当面问责，云光改称恩主；随后贾珩问过翠华山匪情。","reason":"与本局开场地点和主角相关"}],"nextCursor":null}}
```

返回当前任务可见的条目列表 `items` 和下一页位置标记 `nextCursor`。每项有本次资料编号 `ref`、资料类别 `kind`、标题 `title`、简述 `summary`、入选理由 `reason`。末页为 `null`，没有可见命中则返回空数组。未授权的后续标题和秘密不作为命中理由返回，查询结果不修改存档。

## 工具二　read_play_source 读获准资料详情

**调用者**　与目录工具相同。`ref:string` 必填，填程序为当前任务分配的资料编号。`offset:integer` 和 `limit:integer` 可省略，`offset` 为开始位置，`limit` 为单次读取长度；默认从 0 开始读 2000 个 UTF-16 码元（JavaScript 计算字符串长度使用的单位），单页范围 2～8000。偏移相对**本条已过滤的资产字段展示文本或局内记录**计算；原书页码、章节正文或原文位置均不能作为读取目标。一个字符若占两个码元，翻页和起点均须保留该字符完整。

```json
{"tool":"read_play_source","arguments":{"ref":"asset_7kw"},"result":{"ref":"asset_7kw","text":"节点 C15-N001（版本 32）\n归属 第一百三十三章 剿匪翠华山，章内顺序 0\n场景 长安节度使府官厅\n概述 贾珩当面问责，云光改称恩主。\n可公开的经过 随后贾珩问及翠华山匪情，得知贼寇约四五百人，官兵进剿时对方闻风逃走。开局从这段交谈结束后接手。","offset":0,"nextOffset":null,"evidenceRefs":["asset_7kw"]}}
```

返回本次资料编号 `ref`、已过滤的正文 `text`、本页起点 `offset`、续读位置 `nextOffset` 和依据编号 `evidenceRefs`。若能从建档资料核实某个旧编号已合并到新编号，同时返回对应的 `resolvedRef`。续页按 `nextOffset` 读取，末页为 `null`。详情只含本任务可用字段；节点详情始终不给引文、逐字对白摘录及原始章节。参数错误、无效的下一页位置标记返回 `INVALID_ARGS`；跨局、跨角色、已失效或无权使用的资料编号返回 `SOURCE_UNAVAILABLE`；本次执行编号已失效返回 `STALE_RUN`。建档时保存的资料缺失或内容校验值与记录不符时报告 `SOURCE_CHANGED` 并停止本次生成，不转向原书获取内容。同一有效查询及分页重复调用不会推进时间或改变任何人物所知。

## 节点里的“查看所选章节原文”

现有资产编辑器在事件节点内有「查看所选章节原文」按钮。按钮由人点击后调用 `repository.readChapter(bookId, values.chapterIndex)`，结果放入阅读器的本地界面状态。[节点编辑器的按钮与阅读器](../../../src/features/assets/AssetEditor.tsx) · [资产列表与节点选择](../../../src/features/assets/AssetsPanel.tsx)

游玩中提供核查入口时只传 `bookId,nodeId`，带人进入对应节点。聊天、工具目录、开局卡或执行详情均不能展开原始章节。游玩侧的节点详情使用允许玩家查看的只读字段，隐藏资产编辑表单默认展示的参考引文；节点内的按钮复用现有的人工阅读操作。打开和关闭阅读器都不向聊天流派发消息，不在 `playRuns` 记录所看内容，也不改变人物认知。节点若已从原书删除，界面提示当前节点不可打开，本局仍可读取建档时保存的书中资料。关系等其他资产的游戏详情不接入章节阅读。

## 容量、缓存和改写

当前整理任务在每次请求前显式检查模型容量，必要时调用 `compactSession` 压缩**同一次整理执行中的消息和工具往返**。游玩方案另有 `play-compact` 历史摘要任务，读取**同一存档中已经结算的连续回合**，便于下一轮导演回顾过去。两者的触发位置、读写对象不同。导演查询工具时产生的临时消息与返回结果只属于这次请求，不能作为已发生的剧情写进历史摘要。方案按任务选用 Pi 的工具循环或一次结构化生成，相关入口见[游玩任务与模型调用](agent-contracts.md)、[整理任务的容量处理](../../../src/features/agents/runtime.ts)。

- 用模型一次请求可容纳的总量减去系统说明、工具声明和预留的输出空间，先放玩家本次意图、必要的当前事实、各人物已知的事及本轮剧情步骤，再放候选和近期正文。容量不足时缩减首批目录、分页读资产或按有效历史生成带来源摘要。仍放不下时保留完整玩家输入、建档资料和上个已结算版本，展示可重试原因。字段不会因分页而被截短保存。[现有中文容量估算](../../../src/features/agents/context.ts)
- 程序可以暂存筛选好的材料，供后续请求复用。查找时同时核对书籍编号 `bookId`、存档编号 `saveId`、建档资料内容校验值、计算本轮所用的版本和角色用途。每次执行仍按执行编号 `runId` 和任务重新分配资料编号。即使备份副本沿用原存档编号，也可凭新书编号区分。同一资产包产生的两个存档也各用自己的资料编号。上游资产修改不会改变现有局的查询结果。改写成功后，下一轮从改写后的版本读人物、关系和知情。旧轮独有的结果仍在旧版记录中。书中资料仍取自建档时保存的副本。
- 恢复为新书时，将存档和局内资料关联到新书。下次调用工具时重新分配资料编号。回看旧请求直接显示当时发送给模型的材料；刷新、打开旧聊天、查看原著人工阅读器均不会重新运行模型。[版本、整书备份与恢复](storage.md)
