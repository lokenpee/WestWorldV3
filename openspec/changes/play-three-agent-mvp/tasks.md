## 1. 实施与检查

- [ ] 1.1 **T1，REQ-039/034，存储和提交。** 核对[存储字段与保存顺序](storage.md)，先更新数据、备份和运行说明。为浏览器和本机数据库登记表、索引及升级步骤，实现开局草稿、记录负责执行的页面、暂存角色结果、保存新版本并返回版本号。检查浏览器旧书升级、本机 SQLite 写入失败时撤销该次写入、两个标签页同时发送、同一离厅动作重复提交，以及旧执行不能释放新执行占用的存档。记录测试名、前后版本号和四张表中实际保存的记录。
- [ ] 1.2 **T2，REQ-034/039，开局与资料装载。** 使用 T1 定义的版本号和资料编号。建档时保存允许游戏读取的人物、地点、节点、关系和事件字段；玩到某一轮时再读取本局历史。列出可读的数据表，按角色返回其可见的资料和供后续翻页、读详情的编号。按[装载器验收](context-loader.md)核对候选、详情、节点边界、后续剧情能否提前查到、合并前的人物编号能否查回、过往约定能否找回、原文章节读取次数是否为零及资产包编辑只影响新存档。分别保存准备开局时导演实际收到的请求，以及确认开局卡后写手实际收到的请求。
- [ ] 1.3 **T3，REQ-039/034，角色任务及权限。** 依赖 T1、T2。先更新[技术入口](../../../docs/v2/项目技术说明.md)、AI/工具契约，再登记开局导演、行动导演、写手和历史摘要四个任务的独立正文、声明、输入输出字段约束（Schema）、提示词调用清单和请求示例。扩展提示词同步脚本覆盖新任务，执行 `npm run prompts:sync`，对照模型调用组件 Pi 发出的请求，核对工具名称、用途、提示词内容校验值以及输出错误时重新提交的步骤，确认已有整理调用仍加载原约定。每项至少保存一次合法和不合法交付的结果。在请求中逐一核对 `submit_result` 只声明本任务的参数，并对照写手收到的每步剧情、公开依据和停笔位置。
- [ ] 1.4 **T4，REQ-039，导演向写手交戏及整轮保存。** 依赖 T2、T3。实现准备/确认开局、自由输入、拒绝及一次申诉、按行动裁定结果准备公开的现场、剧情动作链和停笔位置，校验写手交付与按需摘要。延迟写手、让回合保存失败或在写完前取消，检查预览、输入锁定及刷新重试。对照[导演交戏及写手正文](agent-contracts.md#dramatic-chain)，逐步核对出场人、动作与反应的顺序、何处交还玩家。记录模型调用次序、触发理由、用量、从发送到正文首次可见和整轮保存完成的时间。
- [ ] 1.5 **T5，REQ-039/003，游玩页与完整回合。** 依赖 T1、T4。将游玩服务接入应用启动入口和验收环境，按已评审的准备页、聊天页和流程图，接入选包、包内新建/继续、单列聊天、底部输入栏、撤回/申诉、末轮改写、刷新和重试。通过游玩导航发送消息，验证切书、同书两局、运行中取消、改写尚未成功时是否仍显示之前保存的回复及首次开局失败。
- [ ] 1.6 **T6，REQ-039，整书生命周期。** 依赖 T1，交付前与 T5 联调。升级整书备份格式、导入前检查与恢复流程。在活动运行、待选择开局卡及已结算状态分别导出，检查原书继续运行、副本执行权清理、各回合能顺着父版本追到开场、旧备份缺少的四张游玩表按空表处理、运行中删除书籍会提示哪一档正在执行。另验 P3 重建专项副本及指向错误存档的记录，记下备份格式版本和报错指向的字段。
- [ ] 1.7 **T7，REQ-039/034，开发回归。** 依赖 T1～T6。用同一份样本和预设的模型返回内容调用游玩服务，在本机存储和浏览器中分别走一遍。保留单元测试、两种存储的事务测试、浏览器操作及类型检查结果。从实际请求核对各角色收到哪些资料、获准、驳回、申诉、改写各调用哪些任务及多少次和写手是否在该由玩家决定的位置停下。记录实测耗时分布，不把资料检索调用算成另一名 Agent。

## 2. 用户验收

**环境和样本。** 实施后运行 `npm run dev`，在独立验收库通过备份预检与恢复装入[指定的赖家线包](../../../红楼之挽天倾-赖家线-仅第15至25章节点.wwv2)。正式游玩入口选择恢复后的包。不得用同名的全量节点备份替换。先让测试模型返回指定结果，分别检查留在官厅追问和直接告辞两种行动，再用设置页配置的聚合模型复核叙事；两轮检查分别记录。包中已核实有 48 个节点、131 个人物、83 个地点，首节点 C15-N001 的修订号（revision）为 32，无需重新提取作者素材。

| 用例 | 操作 | 检查界面、数据与运行记录 |
|---|---|---|
| A 选包、建档、续玩 | 选指定包，点新建；接受从 C15-N001 结束后扮演贾珩的开局，点开始。关闭，再选同包同档继续 | 新建时得到独立存档，并保存本档可用的书中资料；聊天中开场显示已在官厅质问云光。继续时直接恢复消息和状态，确认没有新增开局或模型调用。让测试模型返回两张可用的开局卡。双击同一卡片，或在两个页面同时确认不同卡片，都应只启动一次开场。另测选择第二张卡后写手超时，刷新重试，核对仍是同一张卡、依据相同、开局导演总共只调用一次，最终只保存一个开场版本 |
| B 开局及回合资料 | 追问云光刚才的答复，再在另一档告辞离厅 | 检查导演和写手实际可读的字段和工具返回。贾珩为 C1-P001，云光为 C13-P011，官厅地点来自节点。不自动把 C15-N002 或 C16-N002 的未来结果写进本局事实。比较两种行动会调用哪些角色、何时可以发送下一句。将[逐任务样例](agent-contracts.md#sample-requests)和真实请求逐字段对照。核对写手收到的本轮结束位置（stopAt）、留厅版本 V1 保存的位置和刷新后下一轮导演收到的结束位置一致 |
| C 撤回与申诉 | 在尚未取得某物的状态下要求直接交出该物，被驳回后补充自己原想先询问下落 | 检查公开理由、原行动、申诉和最后采用的动作；再次申诉被拒，技术重试不能再获得一次业务申诉 |
| D 改写与存档隔离 | 同包甲档留厅，乙档离厅。查看甲档以前的执行记录，再改写甲档的末轮并刷新。另编辑资产包后新建丙档 | 只切换甲的有效版本，废弃回合的回应、知情和停笔位置不会继续出现。先对 V0 至 V1 生成摘要，再把 V1 改成 V1b 并刷新。核对下轮只取现行版本的摘要或原回合，摘要任务记录为 `stage=play-compact, role=null`，不会生成新的游戏版本。乙档仍在离厅后的位置；甲乙各自使用建档时保存的书中资料，丙档可以读到后来编辑的字段 |
| E 失败和竞争 | 分别模拟写手超时后迟到、正文返回后保存失败、两个标签页重复发送同一操作、保存新版本后页面漏收成功通知 | 聊天预览撤下，未保存的行动可用最初输入重试；已保存的行动按原尝试编号查询时返回同一版本号；旧执行无权覆盖新档或新版本。再暂停提交，在预览已显示时取消：取消先成功则撤下预览并保留旧版，提交先成功则返回同一新版本且能继续这局 |
| F 备份 | 分别在选开局、生成中和已结算时导出，恢复为另一书，再测试跨局父版本的损坏包 | 每局建档时保存的资料、游玩历史和证据出处均可在恢复出的书中查到；恢复副本没有执行权，不会自动重发。恢复待选卡草稿时显示原卡组，尚无开场版本，打开后模型调用数为零。损坏包显示错误并保留原库。多档长局分别覆盖压缩字节、展开字节、条目数三项上限：其他项合规时，测上限减一、恰等和超一（字节或条目）；核对超限原因及无下载文件。用有效长局成功导出后跨浏览器导入，对比各档建档资料的内容校验值、当前生效版本、完整正文及执行记录 |
| G 原文入口 | 将章节读取接口设为调用即报错，完整走新建、继续、分页检索、申诉、改写、摘要、回放。再单独打开节点，从详情点「查看原文」并返回聊天 | 游戏链路章节读取计数为零，首次发给模型的资料和工具返回内容均不含节点引文。人工按钮仅访问所选节点的来源，关闭后消息数、版本、知情及 Agent 请求数均不变 |
| H 聊天交互 | 分别从新档和已有档进入，查看历史、发送行动、取消生成、改写已结算的最后一条回复 | 对照[界面线框与流程图](ui.md)实测头像、发言人、消息顺序、底部输入、消息菜单、窄屏、锁定与恢复 |
| I 导演交戏与写手成文 | 输入“我留在这里，问云光方才为什么改口”。对照导演提交、写手收到的场景与玩家看见的正文 | 依次找到贾珩追问称呼、云光欠身解释方才失礼、云光收声等答。正文没有揭晓改口动机，也没有替贾珩选择下一步。改用直接告辞时，再核对新的动作及位置 |
| J 编剧独立留档 | 验收环境不登记编剧任务，用同一资产包完成选卡开局、留厅、离厅、驳回、申诉、改写、摘要、刷新重试和整书导入导出 | 查任务注册、模型请求、工具参数、运行日志、快照和备份。编剧调用次数为零；均能在缺少编剧和大纲数据时完成，存档中不预留空计划字段 |

- [ ] 2.1 **真实模型与玩家自测。** 用户从「游玩」完成 A～D、G～I。依据实际资产字段、真实请求、正文和存档检查身份、知情、自由行动和介入点，记录实际输入、存档编号、游戏版本号和结论。
- [ ] 2.2 **恢复与备份复核。** 开发提供 E、F、J 的可复做证据，用户复核中断恢复和副本续玩；通过后同步规格并归档。
