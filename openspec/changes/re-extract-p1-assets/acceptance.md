# 验收清单与证据

关联 [REQ-018](../../需求池.md) 和[提案](proposal.md)。当前仅完成方案文档，应用场景均待实施验证。

## 环境与样本

- Windows / Node / npm，依赖以 `package-lock.json` 为准；开发服务用 `npm run dev`，自动浏览器用 `playwright.workspace.config.ts`。
- 固定短样本：2–3 章，每章包含明确人物、地点、关系和事件节点。至少准备一组跨章节合并人物，用于单章清空和凭证校验。
- 真实模型先在副本或短样本执行，记录模型配置、章节数、用量、费用和耗时；用户确认后再对原书执行。
- 测试生成的临时备份放系统临时目录或工具忽略目录，不覆盖用户原库和原始备份。

## 应用场景

| 场景 | 前置与样本 | 操作 | 界面与数据必须结果 | 失败/恢复检查 |
|---|---|---|---|---|
| E01 整书世界重提 | P1 完成；人物、地点、关系有凭证 | 点击重新提取世界资产并确认 | 旧世界资产和P2结果清空；按新Schema逐章重建；节点保留并重新绑定；P3进度失效 | 失败保留新章节和继续入口 |
| E02 整书叙事重提 | P1 完成；节点有凭证；存在P3事件线 | 点击重新提取叙事资产并确认 | 旧节点、事件线和P3结果清空；逐章重建节点；人物地点关系保留 | 失败保留新章节和继续入口 |
| E03 单章重提 | 第12章两类成功；其他章节有资产 | 点击第12章世界/叙事回收按钮 | 不弹确认，直接清空并重提第12章；其他章节和另一类资产不变 | 失败可继续 |
| E04 失败与继续 | 多章样本，注入第2章模型失败 | 整书重提 | 已完成章节保存，失败章节显示原因 | 旧资产不恢复；主按钮继续重提 |
| E05 取消与刷新 | 重提运行中 | 取消、刷新或关闭页面 | 已保存的新资产和凭证保留；`reExtract`保留 | 不自动恢复旧数据 |
| E06 合并后单章清空 | 第1章人物已合并到第2章编号 | 点击第2章世界回收 | 第2章编号和第1章映射改为deleted；第1章凭证仍有效；新人物不继承其他章节事实 | 其他章节资产保留 |
| E07 清空后立即备份 | 清空后首章请求失败 | 立即导出并恢复 | 备份校验通过；无悬空人物、关系端点、生命周期目标 | 恢复后继续重提 |
| E08 下游失效 | 有P2队列、合并、关系编辑和P3事件线 | 世界重提成功 | P2旧编号结果清除；P3进度失效；事件线保留 | 旧报告不当作当前结果 |
| E09 前置不足 | 无成功凭证、模型未配置或已有待继续重提 | 查看或调用重提 | 按钮禁用或请求拒绝 | 旧数据不变 |
| E10 整书确认取消 | 点击整书重提按钮 | 在确认框取消 | 不清空、不发请求 | 按钮恢复 |
| E11 运行中禁用 | 提取任务运行中 | 查看重提入口 | 整书和单章按钮均禁用 | 不并发启动 |
| E12 整书失败后继续 | 整书重提首章失败 | 点击继续重提 | 只补该步骤缺失章节；不重新清空；不转到另一类步骤 | 完成后清除`reExtract` |
| E13 单章刷新后继续 | 单章重提第12章叙事中刷新 | 重新进入 | 仍显示第12章叙事继续入口；范围不丢失 | 不重新清空 |
| E14 备份往返 | 重提成功后 | 刷新、导出、恢复副本 | 新资产、凭证、进度和`reExtract`状态一致 | 恢复后不自动运行模型 |
