# P1 世界资产与叙事资产重新提取

## 结论

P1 增加整书重提和单章重提。整书重提先清空对应范围的旧资产，再重新调用模型，执行前弹出确认框；单章重提直接清空该章对应资产并重新提取，不弹确认。两者都不做合并检测，用户已知合并后重提会丢失合并进来的内容。

关联需求：REQ-018。级别：大型，采用 project-full。当前状态：待确认。

## Why

当前 P1 只补未成功的子步骤，成功步骤不会再次调用模型。用户现有资产格式不符合新要求，需要让 AI 按当前提示词和 Schema 重新提取，而不是逐个人工修改。现有界面也没有整书重提入口，单章只能对失败或中断项点“重试”。

## What Changes

1. “P1 逐章提取全书”标题右侧、主提取按钮旁增加两个按钮：
   - **重新提取世界资产**：清空全书人物、地点、关系及相关结果，再重新提取。
   - **重新提取叙事资产**：清空全书事件节点、事件线及相关结果，再重新提取。
2. 整书重提执行前弹出确认框，列明清空范围、资产数量和下游影响；确认后才执行。
3. 章节概览中，世界资产、叙事资产状态为“成功”时，状态标签旁显示回收图标按钮。点击后直接清空该章该子步骤资产并重新提取，不弹确认。
4. 单章世界重提按该章成功凭证的 `originIds` 认定“属于该章的资产”。即使该编号已被其他章节合并进来，也一并清空；重新提取的新人物不会继承其他章节合并过来的事实。
5. 重提使用现有提取模型、提示词、字段 Schema、每项 3 次请求预算和逐章顺序执行。
6. 清空后逐章提取，成功结果照常保存；失败、取消或刷新时，旧资产已经清空，保留已完成的新结果和失败进度，用户可继续提取。

## 业务规则

### 整书重提世界资产

执行前确认框列出：

- 将清空全部人物、地点、人物关系、关系编辑、旧关系迁移归档和世界资产成功凭证。
- 人物、地点生命周期改为 `deleted` 并去掉 `currentId`；不保留指向已删编号的悬空目标。
- 删除事件节点中引用旧人物编号的字段，保留称呼文字；新人物提取后按称呼重新绑定。
- 将清除 P2 整理进度、队列、报告和资产核对结果。
- 事件节点保留；P3 进度标记失效。
- 清空后立即逐章重新提取；失败或取消不会恢复旧资产。

### 整书重提叙事资产

执行前确认框列出：

- 将清空全部事件节点、事件线、叙事资产成功凭证和 P3 结果。
- 节点和事件线生命周期改为 `deleted` 并去掉 `currentId`。
- 人物、地点、关系及 P2 整理结果保留。
- 清空后立即逐章重新提取；失败或取消不会恢复旧资产。

### 单章重提世界资产

- 该章资产按世界资产成功凭证的 `originIds` 认定。
- 清空这些人物、地点和关系事实。
- 生命周期映射不删除：本章编号和 `currentId` 指向本章编号的其他章节来源，统一改为 `state='deleted'`、去掉 `currentId`、保留 `originId`。其他章节成功凭证因此仍能通过来源校验。
- 删除由本章人物承载的关系事实，包括其他章节合并到本章编号的来源；保留的关系按剩余人物重新绑定目标。人物对编辑结果中涉及已删编号的记录一并删除。
- 节点中涉及已删人物的编号从绑定中移除，保留原称呼文字；新人物提取后按称呼重新绑定。
- 不检查是否已经合并，不弹确认。
- 其他章节资产保留；被删人物和地点编号都加入下游失效清单，相关 P2/P3 结果失效。

### 单章重提叙事资产

- 该章资产按叙事资产成功凭证的 `originIds` 认定。
- 删除这些事件节点；节点生命周期改为 `deleted`，保留 `originId`。
- 引用节点的事件线移除节点；空线删除并把事件线生命周期改为 `deleted`；保留的线更新成员、章节和修订号。
- 不弹确认。
- 其他章节节点和人物地点不变；P3 相关进度失效。

### 失败与取消

- 清空后旧数据不可恢复。
- 清空前在 `compileProgress` P1 写入本次重提范围 `reExtract`，记录整书/单章、世界/叙事、章节编号和开始时间。
- 清空后主按钮改为“继续重提世界资产/叙事资产”；刷新或重新打开后仍按该范围继续，不重新清空。
- 模型失败：该章该步骤记为失败，已完成的新结果保留，用户可点击主按钮继续。
- 取消、刷新或关闭页面：已完成的新结果保留，未完成步骤待继续；不自动恢复旧资产。
- 本次范围的全部成功凭证完成后清除 `reExtract`，恢复普通提取入口。
- 清空前先校验模型配置、章节原文和执行权；这些条件不满足时不执行清空。

  step: 'worldAssets' | 'narrativeAssets'

### 数据流转

用户点击整书重提 → 确认框 → 校验模型与执行权 → 写入 `reExtract` → 事务清空对应范围资产、凭证和下游结果 → 逐章调用模型 → 每成功一章保存资产和凭证 → 更新进度 → 全部范围完成后清除 `reExtract` 并失效下游。单章重提跳过确认框，其余相同。失败或刷新后，主按钮按 `reExtract` 继续原范围。

## 已确认业务规则

2026-11-04 用户确认：

1. 整书重提就是把世界或叙事资产清空再提取，必须有二次确认，防止误触。
2. 单章重提只清空属于该章的资产再提取，不需要二次确认。
3. 不做合并前或合并后的限制。即使重复人物都已合并到某一编号，点击该章重提也会清空该编号并重新提取；新结果不会继承其他章节合并过来的内容。
4. 用户已知并接受合并后重提会丢失合并内容，建议尽量不要在大量合并后重提。

## 确认依据

2026-11-04，用户要求：在 P1 右侧提取按钮旁增加“重新提取世界资产”“重新提取叙事资产”，并在章节概览的“世界资产成功/叙事资产成功”标签旁增加回收按钮，单独重提某章某一类资产。随后明确上述清空、确认和合并处理规则。用户要求先写文档审核，再按文档实施。

2026-11-04 审核意见：删除其他章节生命周期映射会破坏凭证校验；清空后的节点、关系和事件线关联未闭合；失败后再次重提入口和范围不明确。本稿已改为映射保留为 deleted、清空事务同步维护节点/关系/事件线、增加 `reExtract` 范围字段和继续重提入口，并补充清空后立即导出恢复场景。
