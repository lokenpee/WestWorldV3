## 字段变化

下表记录本轮持久化方案。业务名称以[原稿 §2–4](../../../docs/P3-叙事大纲重建Agent-设计方案%20%282%29.md)为准。具体字段见[存储契约](../../../docs/v2/resources/v2.2/storage.schema.json)的 NarrativePlan 和 NarrativeTask。

| 对象与存储位置 | 字段、类型与校验 | 写入时机、读取方、旧数据处理 |
|---|---|---|
| P1 节点 nodes | 沿用 name、summary、process、actors、locationNames、chapterIndex、order、quote、offset、clues、new_facts、world_delta 等字段，数组缺省按空，旧书沿用已有 targets 与引用定位状态 | 启动准备由 P2 的人物合并事务更新 actorBindings、targetBindings 及相应人物编号。进入 P3 后，模型只读节点事实、经过、线索和位置；节点与事件的成员关系在第一阶段编辑 |
| 事件 storyEvents、故事线 eventLines | 复用 id、title、成员数组、summary（概况）、coreClue（核心关键线索）。名称为非空文本；创建和更新可各自提交任一说明，创建时未提交的字段默认为空。对应全书复核逐项核对，两项均为非空文本后才确认该对象的说明。旧值保留并可作为核对材料 | 事件说明由第一阶段写入，故事线说明由第二阶段写入；目录、网络、详情及旧备份继续读取。每个父级成员 ID 在本书存在且去重，解除一条引用只改该父级 |
| 运行 pipelineRuns 与进度 compileProgress | 新增工作流版本、配置快照、书及运行 ID、阶段、当前任务、两个阶段各自的已确认批数（初始 0）、本期批次 ID 列表 | 启动时固化配置；每批确认后以实际批次记录计数，复核段和工具轮不计。恢复时读取原配置与清单 |
| 任务与对象待办，pipelineRuns 的 V4 专用记录 | 以 runId、taskId、模式、目标类型与 ID 识别；保存重点范围、实际已处理 ID、操作影响 ID、对象依据版本、状态、逐项结论。初始待处理；确认要求说明及所需目标齐全，普通节点批次独立保留需理由，同一版本的处理与复核分别记账 | 调度器生成，受控编辑记录影响，confirm 更新覆盖和检查点；恢复、报告读取。仅新增 V4 记录按新版备份格式序列化。运行内记录分开保存，避免每次操作重写全书清单 |
| 疑点 storyEditorNotes | 复用 id、sessionId、key、statement（描述）、已有目标数组、status；新增 V4 分类 NODE_ASSIGNMENT、EVENT_ASSIGNMENT、OTHER 及有依据的解决说明。模型 OPEN/RESOLVED 映射为存储 active/resolved；初始 active，支持多目标，重开沿用 ID | manage_doubts 创建、查询、更新、解决、重开、合并或删除。先保存关联再关闭归属疑点；变更后检查依赖它的待办。旧事项原样读取，历史未记载的分类不推断 |
| 周期复核清单，属于当前运行 | 周期 ID、阶段、本期有序批次 ID 和实际处理/影响对象 ID，三项有序子任务（结构、疑点、未归类），每项保存当前状态、目标 ID 与版本、分段位置、结论和回执 | 调度器在周期到期时创建一次；每项开始时基于前项提交后的库生成材料。确认当前项最后一段后切换；重复回执、刷新和恢复按清单 ID 与子任务继续 |
| 任务上下文与日志 storySessionEntries、运行追踪 | 新增任务 ID、固定起始输入、已完成轮序号、轮次原始条目引用、首次生成的精简表示。任务内轮号连续，固定记录写一次；模型请求、工具调用 ID、原文和提交回执仍可回查 | 每个子任务或其分段重新组装输入；同一任务在当前版本内保持快照稳定。费用按任务归集输入、缓存读写、输出与估算费用 |

备份在包含 V4 状态时写入格式 14，保留此前格式的导入路径。同步 [序列化与完整性检查](../../../src/features/backup/data.ts)中运行记录的导出筛选、会话条目类型、对象引用、配置和状态校验；恢复副本重绑书 ID，活动任务按现有方式暂停，原始请求内容保留。浏览器存储与本机 SQLite 都须经过同一字段往返检查。

### 前端操作与请求回放

主按钮随运行状态显示开始、暂停、继续或重新整理。运行中和暂停时可取消，已有运行可打开整理详情。详情固定当前运行编号，依次选择阶段、批次或复核分段，以及该任务中的请求序号。尚未进入的阶段显示本轮空状态。

选中请求即展示服务商快照中的任务目标、目录、未决疑点，以及按发送顺序排列的系统提示词、历史占位、此前回复和工具返回。可用工具取自该请求的工具快照；本轮回复、工具调用参数和执行结果显示在输入下方。可展开核对原始消息及请求参数。尚无服务商快照时，明确标出内容为调用前保存的上下文。

## 运行参数

由[叙事任务配置](../../../src/features/story/narrativePlan.ts)提供默认值，创建运行时校验并保存快照。调度、模型起始材料、工具、进度界面和测试均读取这份配置。提示词中展示的数量也从快照生成。

| 参数 | 默认值及含义 |
|---|---|
| nodeBatchSize / eventGroupSize | 分别为 20 个 P1 节点、20 个重点事件。两者可分别修改。末批按实有数量下发，跨组额外确认的事件按 ID 记账 |
| eventReviewInterval / lineReviewInterval | 两阶段各为 10。每阶段的周期同时决定何时复核及本期覆盖范围，从上次周期结束后的第一批计起。改一处即可同时调整触发与范围 |
| segmentSize | 默认 20 项，正整数。疑点或未归类对象超过 20 项时分段给模型；确认当前段后再发下一段，任务按全部目标和动态补充项完成 |
| outlineThreshold / keepRecentRounds | 第二阶段待发目录的紧凑 JSON 默认超过 2000 字符时，保留故事线与所引事件以及当前组事件，事件只带编号与名称。同任务保留最近 2 轮 |

各项数量须为合法整数，启动前报告具体无效参数。已有运行按启动快照续跑，调整默认值后新运行生效。例：只把 eventGroupSize 改为 12，新运行每批 12 个重点事件，其周期仍为十批。根据实际批次成员生成清单，不能从连续编号或固定的 200 条反推。

## 数据流转

P1 全书覆盖及同书空闲 → 本地合并同名人物并更新节点引用 → 取得 P3 执行权并复查启动依据 → 读取本书节点与当前大纲 → 按任务快照发送模型请求 → 编辑工具按权限和版本提交业务变更 → 模型调用 confirm → 程序校验并原子保存逐项结果、计数、检查点及确认回执 → 调度下一任务、刷新进度。

例如 N038 同时记载“宫中告退”和“回家告别”。第一阶段将它加入已有的 E005 和新建的 E006，确认后节点处理数增加 1。第二阶段把已审 E005 挂入 S001、S004，两处引用同一事件。工具写入后归线处理数仍为原值；本组 confirm 成功后 E005 只计一次。从 S004 解绑只调整故事线归属，E005 的真实节点成员和说明继续沿用第一阶段的结果。

### 周期复核的三项任务

例如第一阶段第 20 批确认后，取第 11–20 批，满批时有 200 个输入节点。保存这十批及实际影响的对象，依次建立下列任务。每项只发送完成该项所需的工作材料和共用起始信息，模型可查详情、编辑、确认。一个任务分多段时，全部分段完成才进入下一项。

| 顺序 | 第一阶段 · 节点整理为事件 | 第二阶段 · 事件整理为故事线 |
|---|---|---|
| 1 审查串联 | 给本期节点索引、涉及的事件 ID 与名称、每个事件的实际成员节点目录。成员包含此前批次中已处理的节点。例如 E005「营帐审问」下列 N111、N112，E006「回府告别」下列 N117。模型先对照已发成员简况检查错挂、漏挂、重复或转场，必要时按编号补查并修订 | 给本期重点与实际处理事件，列涉及故事线 ID、名称及各线成员事件目录，纳入跨组处理和迁移影响的来源与目标。模型检查篇章归属和合理共享 |
| 2 审查疑点 | 读取本轮复核表中所有当前未解决疑点，逐项给出编号、目标及问题。按最新关联查证，可解决的修正后关闭，证据不足的保持未决并记下本次结论 | 同样核对整张未决疑点表，包括节点和事件归属疑点。保留已有 ID，记录本次结论 |
| 3 再查未归类 | 用本期已处理节点与当前有效事件成员关系求差集，给每个对象的 ID、名称、概述。模型按需查详细经过，判断能否加入已有事件；已有独立保留结论且仍无归属的节点也列入 | 在本期实际处理过的事件中查询仍无故事线归属的事件，给 ID、名称、概述，检查能否加入已有故事线。已有有效归线的共享事件按唯一 ID 去重 |

任务 1 调整了归属后，任务 2 读取更新后的疑点与关联；任务 3 再查当时的未归类集合。某项为空时记录 0 项并推进；存在有依据的未决疑点可完成“已审查”。最后一批恰逢周期时，全书复核可承接这三项并保存覆盖记录。末批不足一个周期时，全书复核承接尾批涉及的对象和未完事项。

## 触发逻辑

| 触发及前置 | 工具、状态与下游 |
|---|---|
| 用户点击启动 | P1 已全书完成且同书空闲时，按下文启动顺序处理同名人物，再读取当前资产及已有目录生成第一批。界面显示合并进度、失败原因或首批范围 |
| 节点批次确认 | 节点逐项满足“有事件、对应未决归属疑点、明确独立保留”之一。确认后进入下一批；每十批先做周期检查，最后一批触发全书事件复核并合并到期检查 |
| 全书事件复核 | 遍历结束后可查全书，逐条核对当时所有孤立节点，包括没有疑点或先前独立保留的节点；修订后新增的孤立节点追加到清单。结合 P1 线索、事实和经过，保存归属、独立保留理由或未决疑点及本次核对结论。逐个检查全部存续事件的两项说明，变动项按最新依据复核。全部分段成功确认后冻结事件与节点，再开始归线 |
| 事件组确认 | 默认每组下发 20 个重点事件，按 handled_event_ids 确认实际处理结果。每十组生成刚完成十组的三项复核清单；末组进入全书最终复核 |
| 全书故事线复核 | 按归线关系检查故事线、未归线事件及未决事项。逐条核对存续故事线的概况与核心关键线索。线成员变动后重开受影响项；各段确认后生成报告。事件及节点作为只读依据 |
| 暂停、失败、重复、取消 | 暂停保存回执、清单子项与分段，释放执行权；恢复核对运行、依据与租约。重复确认返回原回执。取消保留已提交操作；迟到响应不得再写入。首次 V4 在副本启动新任务 |
| 模型输入 | 四个共用工具为 get_detail（查字段）、get_outline（查目录）、manage_doubts（记疑点）、confirm（确认任务）。第一阶段另给 edit_events（编辑事件与节点成员），第二阶段改给 edit_storylines（编辑故事线与事件成员）。后台绑定书、运行、任务与字段权限；目录按成员首次原文位置排序，长详情按段续读 |
| 同任务第 n 次请求 | 在当前版本内保持系统提示词、工具及起始输入稳定。最近两轮原样，较早的完整轮次按固定模板转换一次；待返回的调用暂不转换，同一回复的全部工具结果配对。成功确认后新任务从第一轮开始；失败沿用本任务，无额外模型摘要请求 |

### 说明字段的写入权限

| 当前模型任务 | 事件概况、事件核心关键线索 | 故事线概况、故事线核心关键线索 |
|---|---|---|
| 节点批次、周期事件复核 | 创建和更新时可写 | 关闭 |
| 全书事件复核 | 可写，说明分段逐项核对当前目标 | 关闭 |
| 事件归线批次、周期故事线复核 | 关闭 | 创建和更新时可写 |
| 全书故事线复核（最终复核） | 关闭 | 可写，说明分段逐项核对当前目标 |

编辑工具和提交服务分别按阶段校验对象、操作和说明字段。第一阶段的节点概览取自 P1，事件成员发生变化时重开相关事件的说明核对。第二阶段只能通过故事线成员数组引用或解除引用已有事件。服务端拒绝直接构造或夹带的事件创建、改名、拆分、删除、说明写入及节点成员变更，整次请求回滚。兼容视图按真实关系派生。

编辑参数 summary 为概况，coreClue 为核心关键线索。提交的字段须为非空文本，省略时更新保留旧值。例：首批创建 E005 时写 summary 为“信使在村口交信”，全书事件复核再对照成员核对该句并补齐 coreClue。全书复核按已有覆盖逻辑处理，已有值也逐项确认。


### 已有事件目录与阶段交接

旧故事线直接引用节点时，启动事务解除直连并重算兼容列表。只在旧线直挂的 N002 成为孤立节点；若 N001 已属于 E005，S001 通过 E005 引用 N001 的关系继续有效。首批使用转换后的目录，批次确认计数从零开始。

- 按批遍历时列出全部已有事件的 ID 和标题。已有 E005 含本批 N008、后批 N078 时，本批可看 E005 标题和 N008 的成员记录与详情。N078 的编号、标题、详情，以及可能带出后批内容的旧事件概况等字段，均受同一读取范围约束。轮到 N078 时可见原归属；首批确认只计本批。
- 修改已有事件时按可见成员的增量落库。例如向 E005 添加 N009，应同时保留 N078。会改动未开放成员的整事件删除、拆合或全量替换需等相关成员进入可读范围后再执行。全书事件复核可查完整成员并修订。
- 孤立节点的全书核对在第一阶段完成。进入第二阶段后，最终复核围绕故事线、未归线事件和归线疑点收尾；如发现事件层问题，可记下依据供报告查看。

### 启动时的人物合并

1. 点击启动时检查本书 P1 全书覆盖和执行权，复用 [完整主名分组](../../../src/features/world/candidates.ts)与[P2 机械合并](../../../src/features/world/mechanical.ts)。以本书人物去除首尾空格后的完整主名分组，仅处理人物；别名相同和名称相似不触发。沿用 P2 的保留编号、版本校验、按组事务、来源映射、节点重绑和合并记录。此步不调用模型。
2. 例如人物 A、B 的主名都是“贾珩”，节点 C1-N004 同时引用 A、B；若 P2 选定 A 存续，提交后节点只引用 A，其他不同主名人物的引用保留。零组直接进入首批。P3 启动不执行其他待合并组或地点任务。
3. 写入失败或候选被队列占用时显示具体组与原因，保留已提交组，尚不发送 P3 请求。重试重读现状。世界资产执行权释放后，在 P3 启动事务中重新核对同书空闲、人物合并结果与节点绑定，再取 P3 执行权，防止抢占或资料变化。连点或恢复只进入一次首批。

### 确认与上下文

每个下发给模型的任务只能由当前任务的 confirm 成功收尾。查询、编辑、文字总结和经过时间均不增加批数。缺项返回缺失编号，继续当前上下文；单次网络请求失败沿用调用层重试或暂停恢复规则。重复确认返回原回执。系统确定的空清单记为零项并跳过，不生成待模型确认的分段。上下文版本适配见[会话差异规格](specs/agent-session/spec.md)。

## 请求与批次回放

网关在传输边界将每次尝试的正文交给 V4 请求记录，原文按尝试编号读取。输入区使用发送快照还原角色和次序，稳定工具与参数独立置顶。首条任务材料包含任务目标、确认格式、可见的归属目录及本批资料。历史占位按工具调用编号匹配结果。确认事务保存目标名称、父项及独立或疑点结论；旧任务按当时的写入回执显示可还原的更改。网络从事件成员按阅读顺序连边，未归线事件仍可查看。

运行记录内的 input.rawBodies 为可选的尝试编号到请求正文字串映射。V4 通过协议构造器将 messages 或 input 放在固定参数之后，按传输时收到的字串原样保存。界面的新增标记取自同任务相邻两次实际发送的消息指纹；已有旧记录按其保存的消息和工具快照回放。任务记录的可选 outcome 在确认事务内赋值，按父项编号、当时名称及本批成员分组。

每次新建任务只从系统提示词模板选取通用段、当前阶段和当前任务环节；确认条件与本次 confirm 声明采用同一规则。恢复未完成任务使用启动时保存的快照。

确认参数在 Pi 接收工具调用时先按当前任务检查，返回允许的字段与提交方法。按节点、事件、故事线分别发布查字段清单，与读取器共用字段映射。每段开始按当前数据计算各环节已核、待核及本段编号，分段确认的回执用于绘制逐项目标、结论和依据。

### 六种任务的编辑与复核判断

调度器选定模式和环节后，从同一提示词资源取通用规则、当前层规则、任务范围和本段判断标准。周期结构段给出本周期编号，全书结构段给出全书范围内的分段目标。疑点资料从会话记录读取关联编号，节点按可见范围过滤，第二阶段携带关联故事线。例：只关联 S1 的疑点在故事线复核资料中带有 lineIds 为 ["S1"]。

复核整段确认时，程序读取已保存的事件、故事线和疑点状态，生成每个目标的处理结果。各段的工具与回执见下文“整段空参确认与简短说明”。

### 任务恢复与推理记录

恢复旧批时保留任务编号、回执及历史请求，活动任务使用当前系统提示和工具声明。模型支持推理时请求低档，解析后沿用逐次模型返回日志保存；详情标明有推理返回、请求已关闭或未返回可展示的推理内容。

### 工具声明与执行校验

说明分段仍使用本层编辑工具，参数只接受对应更新操作、该对象编号和两项说明。其他分段保留本层结构及说明写入。查目录时，展开编号仅适用于事件或故事线，未归属列表按页读取。疑点操作分别声明编号、陈述、归属目标或解决依据，保留可用的疑点操作并按层限制节点、事件和线的关联。字段查询逐项返回现有 values、不可用字段 unavailable 和可选 message（缺项说明），例如 N01 的 summary 可返回，text 放入 unavailable 并提示 quote 或 process；另一项超范围编号仅报告不可读。无持久化字段迁移。编辑参数不合法时按实际操作报错，执行仍原子化，越界读写和缺项确认继续核验。

### 各任务先发目录与复核材料

事件层目录包含事件编号与名称、成员编号、可见节点的编号与名称。故事线层额外包含故事线名称及成员事件，两层都按编号连接名称索引。第一阶段及第二阶段未超阈值的目录包含节点名称索引。结构段发目录、结构目标与成员简况，疑点段只发待复核表，第一阶段节点归属复查同时发送候选及事件与节点目录，第二阶段归属复查同时发送候选及故事线与事件目录，说明段发当前说明和成员简况。疑点和孤立段的 task.reviewProgress 保存于历史任务快照。四段各自组装系统指令，说明段仍只改本层说明。任务确认触发下一个分段，空段跳过。新版恢复旧活动段时，从当前数据重组首包，用任务记录的可选整数 taskInputVersion（材料版本）与 contextStartOrdinal（本次上下文起始消息序号）确定恢复边界。既有备份缺这些字段时在首次继续时赋值，既有请求、工具回执和任务编号可回查。推理请求沿用低档。两层的结构段及归属复查首包带目录。各段可以按编号补查，孤立段可查询归属候选目录。

### 新运行优先处理未分配对象

取消只保存运行取消状态。新运行将 reuseAssigned（是否复用已分配对象）写入计划，首次调度每个阶段时把已有有效关联纳入覆盖，再按原文顺序从其余对象取满 20 项。例：原前 20 项剩 3 项，21–40 剩 5 项，继续从 41 起取 12 项组成首批。跳过的对象不增加已确认批次数；已有归属的正确性仍由全书复核逐项检查。老计划缺省该字段时按原任务恢复。工具失败回执仍为 isError，正文为 JSON，含工具、错误码、原因、任务及适用时的参数路径、对象、操作序号和纠正方式。写失败整次回滚，缺项确认停在原任务。

### 复核成果与整段确认

复用分段快照和已完成回执。存储、备份字段及工具协议无变化。成功写入触发已有的整理记录刷新，读取当前段的回执，按对象呈现实际成员变动、名称、说明和疑点修改。同一成员的移出与移入合成一条，例如「乔迁赴宴从推举族长移到东园酒宴」。对象名称优先使用快照和该段回执，缺名时查当前对象或显示编号。旧回执直接适用。

系统用确认回执显示「本段已确认」并补上逐项结论和依据。未确认时标题显示「本段未确认」，行内显示已保存的改动。开段统计留在历史任务材料。暂停和失败保留成功写入的成果，切换分段只读取该段。整理详情使用现有请求区。

### P3 输出额度与工具执行

请求沿用已配置模型声明的输出能力和上下文大小，P3 不另设 8192 或通用工具调用输出上限。服务商标记输出截断时，从原始工具增量严格解析参数。完整调用进入正常执行，不完整调用的详情显示未执行原因，后续只补发漏项。同轮存在未完整调用时先补齐再确认。日志保存工具名、已解析参数及未执行回执。工具详情以名称或调用编号标识对象，空占位不显示。活动工具定义使用当前版本，旧请求按发送时的版本回放。移除 40 项编辑、临时编号字符集和独立的结果格式拒绝层。确认可放在同一回复的最后，前序编辑失败时保留当前任务。继续检查实际业务权限、成员、外键和确认先决条件。

### 未归属节点和单节点事件复查

按真实事件成员数识别单节点事件，按节点编号去重。周期取本期节点及受影响事件中的可见单节点，全书按全量重新选取。目标材料列出入选原因及所属事件。使用确认回执的 no_change 保存保留单节点事件的结论，independent 用于无事件归属的独立节点。原始所属单节点事件信息随任务快照保存，恢复时检查移空的来源事件是否已处理。

## 整段空参确认与简短说明

复核编辑的操作可带 reason（简短修改理由），沿用编辑回执和复核表读出。模型传入空对象，代码按快照中的目标、当前成员及疑点状态写覆盖和结论。新增可选回执字段 reviewResults，由确认事务为每个目标保存编号及当前处理结果；工具返回仍只含确认状态和任务编号。历史回执由 arguments.review_results 读取。例：20 个事件中只移动 1 个节点，编辑工具记录实际移动和理由；下一次 confirm({}) 覆盖整段。未变化目标免填理由。恢复旧任务重组任务材料，并保留已保存修改。

## 两阶段整理和复核对齐

第三项按本层父对象的成员集合计算。第一层以节点为候选，第二层以事件为候选。singletonSources 在两层均保存本段开始时单成员父对象编号；旧任务恢复时沿用原目标并重组材料。空参确认默认核验本组编号，handled_event_ids 仅用于额外确认组外事件，兼容旧版全组数组。
