# REQ-032 第一阶段重铸审阅

2026-11-24，关联 BUG-73。用户要求比较直接调整与重建第一阶段。审阅对象为本机 D:/mic 下的《P3事件串联_PRD.md》和《P3事件复核_PRD.md》。以下是设计建议，实施方案待确认。

## 路线判断

建议给新运行建立独立的第一阶段工作流。串联按一个节点派发，全部串联结束后按一个事件复核。复用事件编号、节点成员关系、书级执行权、磁盘事务、模型网关、请求回放、备份框架和第二阶段归线能力。新任务需接入暂停恢复、备份校验与进度展示。当前 V4 的可见范围、跳过已分配节点、周期复核、整段确认分别对应旧行为。两层共用调度和确认，直接删除共用代码会影响第二阶段。[调度与确认](../../../src/features/story/narrativePlan.ts) · [运行与恢复](../../../src/features/story/narrativeService.ts)

## 验收与实施顺序建议

1. 在书籍副本按原文逐节点重跑。先确认旧书重跑时如何保留、替换或重新生成原故事线；已有暂停任务要按工作流版本恢复。
2. 完成单节点串联、单事件复核与六项工具，先用固定候选验证场景内两件事、跨章同一件事、多归属、未归属及补挂、复核后仍待核实、拆合中断恢复。再接入真实候选生成。
3. 用赖家线副本对照已知误分。范仪申冤的承诺、陈情、议定查办应能从同一事件追溯到三处节点；云光定罪及封赏要按各自依据判断。另测剿匪大线仍能容纳多件独立事项。第二阶段读新版事件、旧备份恢复、旧运行回放均需检查。[原运行记录](acceptance.md#v063-赖家线成品核对)
4. 用相同节点比较候选前十命中率、错并、漏挂、重复立件、后文结果提前写入，以及每节点耗时、请求量和费用。向量检索与重排的模型和权重按串联 PRD 标注属于候选实现，正式采用范围待确认。
