# 第一阶段与叙事资产浏览设计

## 字段变化

| 对象和存储 | 字段、类型和写入 | 读取与兼容 |
|---|---|---|
| storyEvents 事件 | 沿用稳定 id、bookId、revision、title、summary 和 nodeIds。新增 latestProgress（最新进展）、unresolved（待解决问题）两个文本字段，clues（核心线索）为文本列表，status（剧情状态）为进行中、暂时搁置、已闭环。新建事件时由模型给齐业务字段；名称5–20字，概况、进展和非空待解决问题各10–30字，闭环且无遗留时待解决问题填空字符串，每条线索2–20字；服务校验成员均为本书现存节点、去重、按原文排。 | 串联、复核、事件页和第二阶段读取。旧记录缺失的进展、状态不可推断；旧 coreClue 可作展示或读取时的一条线索。第二阶段事件资料与说明完整性检查适配线索列表，故事线本身沿用原字段。 |
| 运行、任务及回执 | 新运行记录工作流版本、当前节点或事件 ID、进度、已保存操作、确认结果、未归属原因、待核实事项及范围。成员变动以事件及节点为标识记录理由，可回查同一节点在不同事件的作用。 | 执行器、恢复、备份与整理详情读取。旧任务和新任务需按版本识别，旧检查点不能作为新版单节点的进度。 |
| 列表查询 | 页面发出书籍、对象类型、字段、关键字、偏移和页长；字段选择与关键字为浏览状态。 | 在查询侧读取对应字段并完成排序和分页；浏览器与磁盘端使用相同语义。涉及人物、地点、节点章节及所属故事线按已有成员关系取数。 |

## 数据流转

逐节点读取本书节点 → 装载当前节点、随后最多5个节点概况及最多10个候选事件 → 模型必要时查节点、查事件或搜索 → 保存事件及成员差异和依据 → 确认本节点 → 全部确认后按最早成员顺序复核每个事件 → 测试期间在故事线整理前暂停。

事件全部复核通过时，调度器将本轮 pipelineRuns.narrative.awaitingStorylines（等待归线，可选布尔值，缺省视为假）设为 true。运行与 compileProgress 在同一事务内保存为 paused，阶段仍为 window_link。工作台读取这一标记展示完成状态，允许查看整理详情。存在待核实事项时按原逻辑显示问题和重试入口。临时开关同时拦住已有第二阶段进度的继续操作。解除后可以从原运行继续。

节点线索、参与人物、地点分别按 50%、30%、20% 作为查询词；事件的名称、概况、最新进展、待解决问题、核心线索各占 20%。按完整词条的出现频次及字段长度计算 BM25。另一条路线比较节点详细经过和事件待解决问题的向量。将两路各自前 20 名以事件 ID 去重，按 RRF（k=60）融合取 30；以节点概述和事件五项正文重排取前 10，加载最新事件字段和全部成员的 ID 和名称。两路不设最低分，检索服务不可用时走本地关键词排名并记录原因。最终数量为事件库总数与十的较小值。全库已列出时显示实际总数并要求停止补搜。

每书派生缓存表 eventRetrievalVectors 保存 id（模型标识和输入文本 SHA-256）及 vector（数值数组）。初始读取本书节点经过与事件待解决问题，跳过空文本并按内容去重。缓存缺失的文本由当前 Embedding 配置生成，成功的批次单独落库。完整初始化后清理没有来源的旧缓存。相同正文跨次启动复用。已有书籍自动获得空表，整书业务备份恢复后可重新生成，整库 SQLite 备份包含缓存。

当前节点开始调用 Agent 时预取下一待办节点，关键词匹配统计、相似度和重排分保留到交接。交接时重新读取来源，按最新事件集合更新 BM25 的文档频率和两路排名。新入围或重排正文变化的事件重新评分，只变成员时直接加载最新成员。任务快照提交前再次校验本书节点及事件版本。暂停、取消或失去执行权时终止预取，恢复时以持久向量及最新资料继续。

例如 C19-N001 记录申冤承诺，C23-N005 和 C24-N001 分别记录陈情、议定查办。第一阶段形成同一范仪案事件，事件详情按原文顺序列出三条节点及依据。第二阶段仍用故事线的 eventIds 引用该事件。

## 触发逻辑

- 启动新版第一阶段时按原文顺序处理节点。普通串联开放 get_nodes、get_event、search_events、edit_events、confirm；search_nodes 仅事件复核可用。前瞻材料仅供判断范围。串联允许基于证据补挂历史节点，全书检索、移除旧成员及删并事件按复核权限处理。
- 复核从全部有效事件开始，检查过大、偏题、断连、过碎。删除、合并、拆分后更新实际受影响的队列；在收尾核对未归属节点。已闭环事件仍可补充早期证据。每次写入和确认可独立恢复；跨调用拆合在恢复时读取已提交结果。
- 新版进度显示“节点串联、事件复核、事件归入故事线”。旧第一阶段的按幕提示词、周期任务和操作说明从可执行入口清除。针对共享提示词、工具声明、请求示例、设置测试、运行详情、当前技术契约分别检查；第二阶段的周期复核仍属其本阶段流程。
- 选择事件时从本书读取详情；按原文顺序列成员节点，点击可查看节点。右侧展示名称、状态、概况、最新进展、待解决问题、关键线索、成员和所属故事线。首选列表首项；选中项仍在结果中则保留，移出结果改选首项，无结果清空详情。事件页本次提供浏览。
- 三页统一为“字段下拉框 + 输入框”。默认“综合”，匹配本页可检索字段；选择单项后仅匹配该字段。清除前后空格、统一英文大小写和全半角，逐字包含匹配；切换字段保留输入并回到第一页。输入为空显示全部。先查本书全量再分页。

| 页面 | 拟提供的单项字段 |
|---|---|
| 节点 | 编号、名称、概述、详细经过、涉及人物、地点、章节、线索、原文引文 |
| 事件 | 编号、名称、概况、最新进展、待解决问题、关键线索、状态、涉及人物、成员节点名称 |
| 故事线 | 编号、名称、概况、核心线索、涉及人物、成员事件名称 |

“涉及人物”匹配行动者和涉及对象中的人物，包括已绑定人物的主名和已登记别名，以及节点中的人物称呼；普通物件不能因是行动对象而作为人物命中。事件沿成员节点取人物，故事线沿成员事件取人物。每条记录最多返回一次。旧线若只有节点归属，读取有效旧成员。涉及人物的查询须跟随人物改名、合并及成员变动刷新。

## 验收与接手

使用赖家线副本对照原文，检查同一事件包含三处范仪节点，云光案和封赏有独立证据。用两条同含“范仪”的节点验收字段筛选，一条绑定人物范仪，另一条只在摘要提到范仪；“涉及人物”仅命中前一条，“概述”按摘要命中。设置超过一页的数据，检查后页命中、换字段、零结果、事件切换及所属故事线。旧书保留，在副本重建。验证存在待核实事件时暂停归线，处理问题后从同一副本恢复。

### 资产字段迁移

SQLite 启动升级和旧备份导入复用同一转换。节点将旧对象的已绑定人物和书内姓名、别名的明确命中并入 actors、actorIds 和 actorBindings。只靠编号或人工选择的关联归入 manualActorIds；移除非人物对象和原“开始的行动”字段的文字，节点原有详细经过保留。事件仅存 clues 字符串数组；已校对的旧事件按编号和旧文指纹复用校对结果，其余旧备份取原线索中能与本书人物及成员节点资料对应的名词。故事线旧三段文字若有内容，则去重并入 summary。原有节点编号、事件编号、成员顺序、故事线核心线索及节点详细经过保留。可重复运行转换。SQLite 在同一事务更新资产和版本；新备份使用格式 15，读取旧格式时先转换资产，再按当前约束校验。历史会话和模型请求按原样回看。

### 运行时规则文件

节点串联读取 [p3-event-link.md](../../../docs/v2/resources/v2.2/prompts/active/p3-event-link.md)，事件复核读取 [当前复核提示词清单](../../../docs/v2/resources/v2.2/prompts/active/README.md)。任务模式决定装载的文件。串联保留已发送的完整成员，允许追加当前或早期节点；后文节点已在既有成员中时可保留，尚未归属的后文节点不能提前追加。复核的完成与待核实参数按提交结果分别校验。

### 两组检索模型设置

“设置 → 模型与 API → P3 事件检索”分别保存 Embedding、Rerank 两组 API 基础地址、模型 ID 和密钥。普通配置存入全局 appSettings 的 llm.retrieval.embedding 与 llm.retrieval.rerank；凭据按角色单独保存。旧版硅基流动配置仍可在原地址使用；改地址须提供该地址的 Key。拉取目录只读，实测成功才在同一事务中替换这一组的配置和凭据。测试失败可修改重试，原配置继续有效。

硅基流动根据 sub_type 单独查询；兼容服务根据接口提供的类型和模型名称筛选。服务未标注类型且无法识别时，可输入目录实际返回的 ID 测试。Embedding 发送一句样例并检查数值向量；Rerank 发送一个问题与两个文档，检查文档编号和分数。例：两组地址分别为 A/v1、B/v1，模型为 vec、rank；启动或恢复后节点经过发给 A/v1/embeddings 的 vec，节点概述与候选文本发给 B/v1/rerank 的 rank。

每次启动或恢复时读取配置快照；任务保存两组配置版本，不含密钥。恢复未完成节点时如已切换检索配置则重做召回。向量按地址、Embedding 模型和正文隔离；同一模型默认硅基流动地址继续复用旧缓存。切换 Rerank 后继续复用现有向量。降级按现有本地排名处理。

继续串联时，已有候选快照也会进入向量检查。按当前模型统计全书节点详细经过及事件待解决问题的非空去重文本，读取缓存，分批补算并保存。首页 P3 显示已就绪数与总数。配置改变、上次降级、来源版本不同或旧快照缺少来源指纹时更新候选。快照的 retrieval.sourceFingerprint 保存按原文次序排列的节点与事件编号、版本的哈希。输入及候选一起刷新，来源一致可复用。向量失败时在节点处理期间显示降级原因，保留已落库批次。用户主动暂停则中断，不触发降级继续。

### 串联专用前序搜索
事件和节点存储字段无变化。串联 Agent 调用只读 search_prior_nodes(groups, return_fields?)，当前任务确定截止位置。按原文次序倒查此前全部节点（含已有归属），仅在详细经过中作组内全中、组间任选的字面匹配。返回总数、截断标记及最近 20 项的 node_id、summary，也可指定返回字段；已知编号可用 get_nodes 核对。例：在 C15-N003 查云光和通贼，只有更早记录可入结果；同一关键词出现在本节点及下一章也不返回。搜索不写书库、不调用外部模型、不作为保存前置条件。

### 复核成员依据与历史回放
成员读取依据按事件版本登记。收到完整候选、读取完整事件或成功提交完整成员后才可沿用；仅改状态时只延续已有的同版本依据。恢复旧任务时丢弃旧实现可能误授的成员标记。底层凭据保存完整操作，模型短回包记录编辑后的归属。旧凭据缺失布尔值时，使用原始任务输入中的 event_ids 与本任务截至该调用的已提交编辑还原；同一时刻的多次调用按会话调用顺序排列。任务快照的可选 initialNodeAssigned 在刷新输入前保留原始归属。暂停和取消只覆盖活动任务的展示状态。

### 串联检索与任务成果

成功编辑或确认事件时，在同一事务的运行回执 result 中附加界面快照，保存事件原字段、当时的成员编号、书中顺序、名称和已有概述；编辑后字段及增减沿用实际保存结果。失败回滚，重放沿用已有回执。书库业务字段、模型回包及工具写权限无变化。旧备份没有快照时仅展示回执可证明的操作，未记录的原值和成员位置保持未知。按任务和事件汇总首次保存前与最后保存后，保留逐次记录。例如原有 N1、N3 的事件增加 N2，列表依次显示 N1、N2（新加入）、N3。仅前端本地展开、切换，成果生成及读取均无模型调用。

### 文本字段字数与分支报错

书库表、键和字段类型沿用现状。移除业务文字的长度边界、前端输入长度及导入时仅按字符数拒收的条件。模型建事件或更新事件，先按实际操作验证；例如 update 仅带 latest_progress 的 31 字新值，原样进入事件表和回执；值为数字时报对应 changes 项的字段，整批回滚。摘要过长的判断依据为组装后的真实上下文容量。导入校对章节正文与 charCount 的一致性，分章分块照常进行。备份及旧数据沿用同一语义。

### 复核任务装载
本地从最新事件和按原文顺序排列的节点生成全书目录、与重点事件直接共享成员的事件补充字段、成员并集时间表。由复核输入装载器统一拼成 JSON，附重点 ID、待核实事项（如有）和任务指令。原生工具与独立系统提示词继续由模型入口装载。业务字段、备份和工具参数无变化，输入和凭据参见[项目技术说明](../../../docs/v2/项目技术说明.md#p3-事件工具)。
首轮资料与已读版本取自同一事务。仅完整装载的事件取得成员及完整读取凭据。旧版暂停任务升级输入并保留落库编辑；同版重试沿用原凭据。关联事件边界变化时重新判断受影响事件。删除记录退出调度，合法共享成员继续保留。
验收以相交 A、B、只与 B 相交的 C 和孤立事件构造模拟复核。检查目录完整、分组仅一层、时间表不重复、目录项无完整已读权、并发改写须刷新、删除后可确认并继续。实书效果由用户在原暂停任务继续后验收。

### 两步事件复核
当前书的事件、节点 → 成员倒排和具体线索倒排 → 疑似组 → 宏观保存 → 按存续事件逐件主审。运行状态保存在 P3 运行计划；资产、节点 ID、备份格式无变化。新增模式 review_boundaries 和 review_sequence 分别记录两种任务、版本和证据。旧版连带确认只保留历史。每次写入沿用现有事务与工具回执。
例如 A、B 共享 6 个成员，C 只与 A 的其他部分相交。先按最长连续共享段、共享数、覆盖比例及原文顺序选对，扩组要求命中原共享锚点至少两个，锚点不外扩。独特共同线索排除人名地名，零共享或只共享一个非单例节点的线索候选一起双向重排，服务不可用时降级本地。每轮只发组内事件和成员时间表。宏观疑似组处理完直接进入微观主审。未归属节点可以通过原有搜索工具被找回；旧运行停在未归属节点页时，继续后保留已写入数据并退出旧任务。微观只更新当前事件，转回宏观须提供事件、证据和理由。一次只运行一个任务，同书共用写锁。完成后维持故事线阻隔。
