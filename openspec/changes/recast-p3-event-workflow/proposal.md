# 重写 P3 第一阶段与叙事资产浏览

## Why

REQ-032 / BUG-73。按场景整理的旧事件把范仪申冤的许诺、陈情与议定查办分开。用户决定以两份 PRD 重写第一阶段，让不同章节、不同场景的节点围绕同一事项形成事件。

REQ-037。用户要单独查看事件，并在节点、事件、故事线列表里选择检索字段。例如在节点页选择“涉及人物”，输入人名即可找到相关节点。

## What Changes

第一阶段依次执行逐节点串联、逐事件复核。替换旧第一阶段的调度分支、运行提示词、可调用工具、设置页测试示例、进度标签及帮助内容。第二阶段继续接收复核后的事件。沿用本书 SQLite 存储、模型配置及调用网关。

叙事资产导航依次提供“节点、事件、故事线”。事件页左边列事件，右边显示当前事件。三个列表使用同样的字段选择和输入方式。具体字段与交互见[设计](design.md)。

## Capabilities

### New Capabilities

事件浏览纳入现有资产维护能力。

### Modified Capabilities

- story-organization：替换第一阶段，调整向第二阶段交付的事件内容。
- asset-management：新增事件页和三个列表的字段检索。

## 确认依据

2026-11-24 用户明确选择重写第一阶段的串联和复核、复用存储与模型调用及第二阶段、删除第一阶段旧规则，同时要求独立事件页和三页可选检索字段。两份 PRD 来源为 D:/mic/P3事件串联_PRD.md、D:/mic/P3事件复核_PRD.md。用户随后确认保留原书，在副本中从节点重建事件并重新归线；复核仅余待核实事项时暂停进入第二阶段，展示原因和已查范围，补充材料后可重试。后续业务取舍须询问用户。

## 讨论结论

删除规则包括产品中的旧执行路径和当前说明。旧运行保存的原始请求属于实际发生过的记录。旧书及其已有成果保留，重建在副本中执行。复核仅余待核实事项时暂停交接，在详情展示具体问题，用户补充材料后重试；未归属且已有合理理由的节点可完成串联。
