# P3 第一阶段实现核对

2026-11-24，REQ-032。依据当前工作区的调度器、工具、请求组装、落库逻辑和整理详情核对。对照稿是用户提供的《P3事件串联_PRD.md》和《P3事件复核_PRD.md》。下表把文稿中的设想和已接入运行的功能分开，优先采用用户随后确认的五段输入与详情范围。

## 一个节点怎样处理

1. 从本书节点按章序、章内节点顺序、ID 排序，取第一个尚无串联结论的节点。从事件表取当前有效事件，三种剧情状态均参与。装载当前节点，取后续最多五条 ID、概述，跨章连续取；缺概述保留该节点的位置。
2. 以当前节点 ID 查找候选。启动时将已有节点详细经过和事件待解决问题的向量装入缓存，缺少的向量从所选 Embedding 服务取得并持久保存。关键词与向量按以下顺序产生节点的候选事件。
3. 系统规则和原生工具在前，首条用户消息依次装载当前节点概览、后文节拍概览、排序召回事件和本轮任务。模型可查证、保存事件、补挂有依据的历史成员；当前节点已形成归属或给出保留理由后调用 confirm。
4. 当前节点开始调用 Agent 时后台处理下一节点。交接前重新核对事件与节点的版本，刷新受影响的候选和全部成员，再保存任务快照。

| 步骤 | 模型或算法的输入 | 输出 |
|---|---|---|
| 本地关键词 | 节点 clues、actors、locationNames 的权重为 50%、30%、20%。事件的 title、summary、latestProgress、unresolved、clues 各占 20%。按完整词条匹配，分字段计算 BM25 | 按关键词得分取前 20，含零分 |
| 向量 | 设置页所选 Embedding 模型分别向量化节点 process 和事件 unresolved。跳过空值、比较余弦相似度 | 按相似度降序，取前 20 个有向量的事件，含零分和负分 |
| 名次融合 | 按事件 ID 合并；第 r 名贡献 1/(60+r)，未入榜的路线贡献 0 | 最多 40 个不同事件，按融合分取前 30 |
| 重排 | 设置页所选 Rerank 模型以节点 summary 查询，候选文档为事件名称、概述、最新进展、待解决问题、核心线索 | 按重排分取前 10，同分沿用融合顺序 |
| 装载 | 取入选事件的最新字段，按 nodeIds 装入该事件全部成员的编号和名称 | 有序事件—节点列表。外部服务失败改用本地排序并记录降级原因；有事件就返回，最多十条，列出全库时提示停止补搜 |

## 一个事件怎样核验

节点串联完成后，按事件最早成员的原文位置、事件 ID 取待复核项。系统把当前事件完整字段、成员 ID、名称和概述交给模型；恢复待核实任务时还提供上次的问题。模型按过大、偏离核心、缺少衔接、过碎四项判断。它可按需查全书节点的详细经过、事件名称和概况，读取完整记录，再决定保留、增减成员、拆分、合并或删除。每次编辑调用的操作在同一事务内提交。涉及新事件 ID 的后续操作使用前一次成功回执。

例如事件 E1 拆为两件事，模型可更新 E1 并新建 E2。程序依据受影响事件的最新字段和成员重新安排复核。确认完成会记录当前事件的内容快照；待核实会保存问题、已查范围和原因，尚有待核实问题时阻止进入第二阶段。具体查询由模型决定，当前事件收到初始完整材料后允许直接确认。后台能核对版本、范围和操作结果，不能据此证明模型确实逐项判断过所有文学问题。

## 对照原稿的差异

| 对照处 | 目前运行行为 | 差异及影响 |
|---|---|---|
| 串联 §一、§六，P2 队列 | 检查全书逐章提取覆盖，启动时做人物同名机械合并，从本书节点表调度 | 未接入 P2 输出的专门节点队列，也未以 P2 人物整理完成作为启动条件 |
| 串联 §三，后文与预取 | 当前任务取其后最多 5 个节点，列表为 JSON；当前节点的 Agent 运行时预取下一节点，交接前校正 | 后文仍无窗口数量配置及逐行文本排版 |
| 串联 §二、排序 §六 | 三种状态都可入候选，最终排序按重排分；同分保留融合顺序 | 文稿另写“进行中优先”。当前未设置状态加权，两条排序口径需决定优先级 |
| 串联 §三，中断再装载 | 已完成检索的活动任务恢复其提示词和工具记录；编辑及确认检查资料版本 | 保留同一任务的首轮证据，不会在每次恢复时主动重做候选或重装前瞻 |
| 串联排序 §四 D、§七，历史未归属列表 | 用户确认删除自动推送，仍可由模型主动查证 | 原稿内有额外历史列表建议，已被本轮决定取代 |
| 串联 §七，未归属收尾 | 检查无归属且缺原因的节点并重新调度；有原因的节点仍可被全书搜索找回 | 没有为每个已有原因的旧节点安排一次对后续新事件的系统性复查 |
| 两稿，规则与首轮呈现 | 运行时各取 3 段活动规则；复核首轮以 JSON 装载当前事件 | 包含基本判断、工具和保存约束。两份 PRD 的长篇判断示例、逐项说明未完整接入，复核也未采用示例中的首尾标签 |
| 两稿，搜索与读取工具 | 搜索按指定字段、区间、排除条件、组内全中/组间任一、前 100 条执行。返回 JSON 字符串。读事件同时返回 nodeIds 和 members；同一未知或已删除 ID 返回 not_found | 未提供规定的搜索文本排版及显式返回条数；串联搜索全部现有事件时范围描述仍为“已处理历史”。成员 ID 重复展示，未区分已删除及从回执回查替代 ID；部分缺失节点字段在 JSON 中直接省略 |
| 两稿，原文和大纲 | 6 个工具中可以读节点经过、摘录、事件完整资料 | 第一阶段未向 Agent 暴露独立的整章原文或大纲查阅工具。两稿同时写了六工具和复用原文、大纲能力，需要明确摄取范围 |
| 两稿，保存与确认回执 | 单批编辑原子提交，工具失败返回 ok=false、code、reason 等；confirm 成功返回 confirmed、result、taskId | 与文稿的 error.code、error.message 及 confirm 的 ok、task_status、outcome 结构不同。原始工具返回可在整理详情核对 |
| 复核 §六、§八，连带结论和成员作用 | 连带确认要求存在的事件且已读最新详情。理由记在每个编辑操作，可附证据节点 | 没有额外校验“原任务事件”身份，刚创建且已完整读取的事件也可被列入。一次操作变更多个成员时共用理由，无法从结构化字段逐条验证其作用 |
| 串联 §八，效果验收 | 已有模拟输入输出，实书联调另行安排 | 尚无人工标注的 Recall@10、归属正确率、重复立件、伏笔回收、错误闭环和有无前瞻的对照结果 |
