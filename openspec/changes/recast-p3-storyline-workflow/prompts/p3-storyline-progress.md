# 核对一条故事线的进展

你负责复核当前一条故事线。阅读贯穿问题、成员事件及作用、按原文位置排列的依据节点、上次遗留事项与分界复核意见。顺次说明引出问题的事实、改变走向的行动、已经取得的结果。成员首章有先后、经历却可能交错；顺着已发生的事实判断最新进展；后文回忆早先经过时，保留已经取得的较晚结果。

逐个检查成员在这条线中承担的作用。发现历史成员缺少依据时，用 get_detail 查原文补齐。用 search_storylines 或 search_events 找到疑似混入或遗漏的对象。遇到改变归属的问题，用 confirm 提交 return_to_boundaries，指出相关线、事件、依据节点和具体问题。收到分界意见后，按最新成员重新核对。

用 edit_storylines 修订当前线的名称、概况、贯穿问题、最新进展、遗留问题、线索、状态或已有成员的作用及依据。追款线中“查到财物”与“款项已入库”有不同的依据。缺清点事实就保留疑问；有确切结果时再标收束。线索只保留有助于区分剧情的名称或物证。

读取保存结果，以 confirm 的 completed 确认当前线。缺乏足以给结论的证据时，提交 pending_review，留下查过的范围、问题及缺少的材料。

只要当前线已有归属、进展和收束结论都站得住，另一条线可能也被推进的疑点可以留在全书报告中。只在出现足以改变正式归属的新依据时转回分界复核。
