# REQ-032 第二阶段任务

[需求池](../../需求池.md) · [提案与接手说明](proposal.md#接手说明) · [叙事验收场景](specs/story-organization/spec.md) · [资产验收场景](specs/asset-management/spec.md)

## 实施与检查

- [x] 0.1 REQ-032 对照第一阶段实际实现，写出三份完整提示词、工具参数、同一事件的跨任务样例及完成条件。两项用户决定见[确认依据](proposal.md#确认依据)，工程与可读性审查见[审查记录](proposal.md#gstack-工程方案审查)，现状检查见[验收与接手](design.md#验收与接手)。
- [ ] 1.1 REQ-032 按已确认的单事件开线规则，核对线字段、初次归属及两步复核的审查与确认记录。先更新项目技术说明、存储、工具、提示词、调用及备份契约，标明拟生效版本。验收以新旧请求对照和字段清单为据。
- [ ] 2.1 REQ-032 按任务 1 的契约调整资产类型、SQLite 及备份转换、成员校验与旧接口。用旧单值线索、无依据成员、旧直挂节点、跨线共享做幂等迁移和导入导出比对。
- [ ] 3.1 REQ-032 在任务 2 的字段上实现模型首次收到的事件材料、候选故事线、前序事件搜索、编辑及确认。检查空库、候选未列全、交错章节和后来对早期事件的回忆、独立事件、资料变化、排序服务故障和写后重试；记录模型实际输入和保存结果。
- [ ] 4.1 REQ-032 接入线组分界、逐线复核及必要转回。三类任务各自加载独立正文，运行提示词同步并核对生成请求。检查首次归属缺证时停在待核，已归 A 线且只有 B 线缺证时可完成、报告仍可查看。恢复后正式成员、报告项及确认计数须一致。
- [ ] 5.1 REQ-032，关联 REQ-037。接入工作台交接、任务结果、线详情、按字段检索、网络投影及历史回放。对照真实归属和界面逐条核查，并验证第一阶段暂停及既有事件工具回归。

## 用户验收

- [ ] 6.1 REQ-032 在同一份已审事件的副本上做新旧归线对照，记录固定判例、逐件差异、总用量和费用。[样本与评价方法](design.md#验收与接手)
- [ ] 6.2 REQ-032 用户在副本核对原文节点、线成员和进展。分别记录用户验收结果及是否解除第二阶段测试阻隔。

用户验收、关联回归和任务完成后同步差异规格与需求池，归档本变更。
