# REQ-033 实施设计

## 字段变化

| 对象 | 新提取与界面 | 兼容读取 |
| --- | --- | --- |
| 人物、地点、节点 | 提交体去掉 `confidence`，新资产不要求分数 | 旧库和旧备份中的数值允许保留 |
| 人物年龄 | 可选 `profile.ageText` 字符串，原文表述统一保存，界面显示「年龄」 | 旧 `profile.age` 数字可读取并回显为年龄文本，兼容旧编辑及导入 |
| 人物关系 | 提交体仅提供正反标签等关系内容，代码由标签填充原存储方向 | 已保存的方向和历史待核对信息保留 |
| 事件节点 | `actors` 字符串列表必填，含事件中的行动人物和人物对象，可空列表。去掉新提取的 `targets` 和 `started_actions` | 旧人物对象照常参与匹配和展示，其他对象仍能从经过查阅。旧开始行动可被历史流程读取 |
| 事件节点 | 可选 `clues` 字符串列表，缺省等同空，按原顺序去空去重。P1 只记录原文中具体可查证、可追踪或用于辨认的线索，人工可在节点编辑时赋值 | 无线索的书库和备份照常读写，新线索随节点备份 |
| 事件节点 | `new_facts` 和 `world_delta` 的存储类型沿用原字符串列表，提示词区分新获知的信息与已经发生的状态变化 | 已有值照常保留 |

存储格式沿用现有表和备份版本。[资产存储格式](../../../docs/v2/resources/v2.2/storage.schema.json)及[详情工具返回格式](../../../docs/v2/resources/v2.2/tool-results.schema.json)均接受无分数的记录，节点详情工具接受线索。P2 等既有调用方可以读取有分数和无分数的资料。历史的数字年龄和人物关系方向可继续由原有工具读取。

[世界资产提示词](../../../docs/v2/resources/v2.2/prompts/active/p1-world.md)与[叙事提示词](../../../docs/v2/resources/v2.2/prompts/active/p1-narrative.md)列出逐字段的填写条件、长度、条数和原文提交示例。长度和条数属于提示词输出约束；提交字段类型、必填校验、关系证据接收规则和储存结构沿用原契约。章节总项数按实际提取。

## 数据流转

章节正文 → P1 世界及叙事提取 → 校验和兼容转换 → 原有单书写入事务 → 资产详情、现有大纲和备份。旧节点仍可包含 `targets:['信件']`，详情能看到信件；新节点遇到需要凭信上印记查证的情节，可提交 `actors:['沈青','顾衡'], clues:['信封上的梅花印']`，普通送信节点可省略 `clues`。线索在节点编辑时保存到原节点记录，备份恢复后显示相同名称。正反标签相同时写入双向对称标记，标签不同时分别保留两侧身份及方向。省略分数的资产可以被详情工具读取，P3 采用现有检索规则。

## 触发逻辑

新提取和重新提取使用新提交格式，历史执行记录按原格式读取。用户打开旧节点可编辑现有字段，保存时保留其余旧数据。沿用原有事务、回执、取消与失败重试。模型缺失可选字段时可正常完成提取，错误类型沿用结果修正流程。新增线索不触发下游。

## 验收与接手

固定响应分别覆盖当前字段、旧字段兼容及缺少可选字段。使用人物、地点与新旧节点执行编辑和整书副本恢复。节点详情核对涉及人物、地点、线索、事实与状态。用赖家线样本人工核对「这笔账总要算」进入概述、追回后的款项入库进入状态变化、转述保留来源。

## 叙事节点重提编号

用户确认重提覆盖旧提取结果。叙事重提沿用现有清理范围、失败继续及保存事务。新结果按本章提交顺序从 `N001` 编号，可复用本章已删除的提取编号。写入时更新其生命周期和版本，先前归属、待核线索引用、历史检查凭证不能自动继承到新内容。其他章节、人物地点、手工资产和备份格式沿用现有契约。例：本章旧提取 `C1-N004`、`C1-N005` 被两条新节点覆盖后，新凭证登记 `C1-N001`、`C1-N002`。核对其他章的回执和大纲成员，以及失败后恢复重提。
