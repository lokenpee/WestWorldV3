# 人物关系与绑定实施设计

需求范围和已确认选择见[提案](proposal.md)。本设计给出完整实现建议，随提案审核。

## 当前实现与触发位置

| 现有动作 | 当前代码 | 当前结果 |
|---|---|---|
| P1新节点保存 | [提取服务](../../../src/features/extraction/service.ts)调用人物绑定 | 对节点行动人物、对象人物做唯一名称匹配；人物关系按称呼原样保存 |
| P3补建节点 | [智能体命令](../../../src/features/agents/commands.ts)调用人物绑定 | 新节点按当前人物表匹配；不处理人物之间的关系 |
| 人工新增或修改节点 | [资产服务](../../../src/features/assets/service.ts)调用绑定或人物选择处理 | 指定编号与暂存称呼保存，名称自动匹配仍限唯一候选 |
| 人工新增、改名、删除人物 | 资产服务更新人物后调用引用重定向 | 更新已有节点编号和显示名称，部分未绑定称呼在唯一命中时补齐 |
| 人工、机械合并 | 资产服务的合并事务 | 融合人物、写映射、重定向节点；队列调用该入口 |
| AI合并 | 智能体命令中的资产提交 | 共用[资产融合](../../../src/features/assets/merge.ts)，但另行保存人物、映射和节点 |
| 查询资产和事件线 | 资产服务及[工具查询](../../../src/features/agents/queries.ts) | 旧无编号节点有查询时补算；事件线人物从成员节点汇总 |

现有[人物绑定](../../../src/features/assets/characterLinks.ts)的唯一候选条件同时出现在普通绑定、人工暂存称呼和重定向补齐中。现有[引用查询](../../../src/features/assets/derive.ts)将多候选显示为歧义。这些位置需一起改动。

## 模块职责与接口

| 职责 | 输入 | 输出与职责 |
|---|---|---|
| 人物资产存储 | 本书人物及修订号 | 当前资产、名称和稳定编号；保存真实合并结果 |
| 关系存储 | 原始双方称呼、方向标签、依据、来源身份 | 独立关系记录；不依附某一条将被删除的人物行 |
| 名称与编号解析 | 本书资产、来源原始编号、目标称呼或节点称呼、已有绑定及生命周期映射 | 来源返回一个当前编号或空值；目标及节点返回全部有效命中，统一过滤删除和跨书编号 |
| 绑定更新 | 变更前后资产、受影响名称及旧编号映射 | 更新关系端点和节点涉及人物；返回实际变化的对象编号 |
| 共用合并核心 | 事务存储适配、同类成员、保留编号、主名、时间和来源 | 融合资产、保存编号映射、调用绑定更新，返回结果和变动清单 |
| 入口与报告 | 人工确认、机械队列或AI工具请求 | 分别检查版本、执行权或证据；调用共用核心后记录自己的报告与提交确认 |
| 查询与展示 | 关系记录、节点编号及当前人物 | 有向关系列表、人物详情、节点参与者和事件线人物集合 |

共用核心位于资产模块，可用现有 Dexie（数据库访问库）和智能体仓储的适配器调用。它接受调用方已有事务，不自行启动独立提交；关系绑定不调用页面、模型或合并入口。纯匹配与关系汇总函数可独立测试。

人工、机械、AI入口保留各自合法性校验。AI写入的命令意图和确认与业务更新共用原事务；手工和队列保留已有报告结构。频次计算沿用各任务的调度位置，关系和引用更新共用同一核心规则。

## 字段变化

### P1关系输出

人物的其他提取字段保持现有契约。关系数组的每项调整如下。

| 字段标识（含义） | 变化及类型 | 赋值与校验 | 消费者 |
|---|---|---|---|
| target（目标原文称呼） | 保留，非空字符串，必填 | 模型从本章给出称呼；代码按完整名称匹配本书人物 | 关系入库、绑定 |
| relation_type（关系类型） | 保留，非空字符串，必填 | 统一去首尾空白并转小写；用于关系标签分类 | 汇总与查询 |
| relation_label（本人物对目标的关系） | 改为非空字符串、必填 | 例如“父亲”，表达“本人物是目标的父亲” | 正向关系 |
| reverse_label（目标对本人物的关系） | 新增，非空字符串、必填 | 例如“子女”；明确性别时可为“女儿”；对称关系与正向相同 | 反向关系 |
| direction（方向性质） | 改为必填枚举 directed、bidirectional、unspecified | 分别表示方向明确、对称、原文方向未明确；未明确时两侧保留原关系描述 | 展示与校验 |
| quote（关系依据） | 新增，非空字符串、必填 | 取本章原文片段，代码验证片段存在；保留能解释关系的上下文 | 来源展示、回归 |

代码将该提取人物实际分配的编号写入 originCharacterId（原始来源人物编号），其原始 name（主名）仅保存为来源文字；章节来自当前提取任务，模型不提供人物编号。新结果缺必填值或引文不存在时使用已有结构修正额度，失败只影响当前提取子步骤。

方向明确时两个标签描述相反视角。例如“张三暗恋张蕾”的反向是“被张三暗恋”的关系含义，不自动推成张蕾也暗恋张三。父亲与子女、朋友与朋友分别按确定的逆向和对称含义表达。方向未明确时显示原描述及“方向未明确”，不凭类型 parent_child（亲子）猜定哪一方是父亲。

### 单书关系表

建议单书数据库从版本5升级为6，新增 characterRelations（人物关系表）。主键 id，索引 bookId、originCharacterId、sourceId、targetName及多值 targetIds；sourceName只用于来源显示和搜索。每书由15张表变为16张表，全局3张表保持原结构。

| 字段标识（含义） | 类型、必填与默认 | 来源、更新时间及读取者 |
|---|---|---|
| id（关系记录编号） | 非空字符串，必填，创建后稳定 | 新提取按书籍、原人物编号、规范关系内容及章节计算稳定指纹；重复提交复用 |
| bookId（所属书） | 非空字符串，必填 | 应用绑定；全部读写核同书 |
| originCharacterId（原提取人物编号） | 非空字符串，必填、保留原值 | P1使用实际落库人物编号；旧关系使用原承载人物行编号。合并后仍保留该值作来源 |
| sourceName、targetName（原始双方称呼） | 非空字符串，必填 | 原提取人物主名和关系目标；改名与合并时保留原值作来源 |
| relationType（关系类型） | 非空字符串，必填 | 输出类型规范化，供去重分类 |
| forwardLabel、reverseLabel（两个方向的标签） | 非空字符串，必填 | 对应模型输出；旧资料方向缺失时采用原标签或原类型说明 |
| direction（方向性质） | 三值枚举，必填 | 新提取校验；旧资料无法确定时 unspecified |
| evidence（依据） | 数组，默认空；元素为 chapterIndex、quote | 新提取至少一项；旧记录缺引文时保留章节且 quote 为空，不伪造原文 |
| sourceId（当前来源编号） | 字符串或null，必填；创建时为原始人物编号 | 仅从 originCharacterId 沿生命周期映射解析；终点删除或缺失时为null，不回退名称匹配 |
| targetIds（当前目标编号） | 字符串数组，必填，默认空，稳定排序且去重 | 目标名称全命中并结合已有目标编号重定向；只含本书存在的人物 |
| revision（修订号） | 整数≥1，必填，初始1 | 原始内容或绑定集合实际改变时递增；重复处理不递增 |
| createdAt、updatedAt（创建与更新时间） | ISO时间字符串，必填 | 应用生成，更新实际变动时记录 |
| legacyPayload（旧关系原值） | 可选JSON对象 | 仅旧资料迁移保留，便于核对原方向和标签 |

sourceId是原始来源编号及生命周期映射的派生值，由应用维护。保存、升级和备份预检均核对两者一致；合法映射解析不到有效人物时保存null并保留来源记录。不同原始来源即使已合并为同一当前来源，原始关系编号仍分别保留，标签只在查询结果中汇总。

每条记录保存一份来源事实，稳定指纹包含 originCharacterId；不同来源人物即使同名、标签相同，也分别保留记录。人物合并只更新 sourceId，原始来源和事实编号保持。多条记录可以生成同一条有向关联；查询按端点及标签去重，保留全部来源记录编号和依据。原 characters.relations（人物行关系数组）在迁移成功后从持久人物行移出，人物详情的兼容关系字段由关系表读取生成，避免维护两份正文。

### 节点人物绑定

现有 actorIds（行动人物编号）、targetCharacterIds（对象人物编号）继续保存当前有效结果；actors、targets 保存当前显示名称及未命中的原称呼。新增以下字段保存绑定来源，使改名或合并后的显示名称不覆盖原始匹配意图。

| 字段标识（含义） | 类型与默认 | 写入与使用 |
|---|---|---|
| actorBindings、targetBindings（两类称呼绑定来源） | 数组，默认空；每项含 mention（非空原始称呼）、ids（编号数组，默认空）；按称呼去重 | P1/P3保存原始称呼及其全部命中；每项独立保留绑定编号，后续新增补齐、合并重定向；人工移除称呼时删除该项 |
| manualActorIds、manualTargetCharacterIds（人工明确指定编号） | 字符串数组，默认空 | 人工直接选择或移除编号时更新；名称变化仍跟随编号及合并映射 |
| legacyActorIds、legacyTargetCharacterIds（旧资料保留编号） | 字符串数组，默认空 | 迁移保留已有编号，来源未知时不冒充人工选择；按生命周期重定向或删除 |

新提取的人工编号和旧资料编号数组为空。旧节点的显示称呼成为初始称呼绑定项，已有编号进入旧资料编号字段；其全部命中集合由绑定器重建。每项单独保存编号，使两个称呼命中相同人物时，移除一个称呼仍能保留另一来源。node.revision（节点修订号）仅在持久内容实际变化时递增。

人工界面按原始称呼显示自动绑定的全部条目，可查看各编号。移除自动绑定的称呼时移除整组自动来源；人工明确指定的条目按编号管理。两种来源重合时合并成一个有效编号。旧资料编号可单独移除；与自动来源重合时提示还有哪一来源保留关联。原非人物对象继续保留在 targets 及详细经过中。

### 查询结果与备份

| 对象 | 字段与处理 |
|---|---|
| 有向关系结果 | fromId、toId（两个端点）；labels（去重中文标签）；types（去重类型）；relationIds（来源记录）；evidence（去重依据）；directionUnclear（是否含方向未明确来源）。按端点稳定排序，每个有序端点对一条 |
| 人物详情工具 | 增加 relationEdges（本人物有关的有向关系）与 unresolvedRelations（仍有未命中端点的原记录摘要）；已有 relations 字段由表投影生成。采用既有详情分页与字节限制，更新返回结构、读集校验和回放样例 |
| 事件线 | 人物集合仍从成员节点的两类编号汇总去重，界面及工具共用同一规则，读取当前名称 |
| 备份 | 格式从5升级为6，增加关系表数据文件，节点新字段随节点保存；校验端点、来源、引用与修订号 |

标签按去首尾空白后的完整字符串去重，类型按规范值去重；不同说法及其依据保持可查。关系结果生成器提供总量及稳定分页，人物详情工具继续使用现有详情分段方式承载大结果，界面使用分页读取；二者共享相同排序和汇总规则。引用查询原有 ambiguities（歧义列表）保留返回字段兼容性，完整同名命中返回全部编号，其对应歧义列表为空。

## 数据流转

1. P1解析本章 → 校验关系语义字段与原文片段 → 在世界资产子步骤事务内保存人物、关系记录、生命周期及成功凭证。
2. 绑定器读取本书当前人物和编号映射 → 根据原始来源编号解析唯一 sourceId → 为目标名称匹配全部条目 → 更新关系端点，并检查受影响的目标及节点称呼。
3. 节点保存时读取原始人物称呼 → 匹配全部编号 → 合并人工指定和旧资料保留编号 → 保存有效编号与当前显示名称。
4. 合并入口完成权限、版本或证据检查 → 共用核心融合人物及写旧编号映射 → 绑定器将关系和节点的旧编号改为保留编号并去重 → 同事务保存报告或AI确认。
5. 页面和工具从底层资料读取关系结果及节点；事件线通过节点汇总人物。更新不触发额外模型调用或自动启动P2/P3。

### 名称命中和编号解析

- 下述名称匹配用于人物关系的目标端及事件节点称呼。来源端只按原始编号和合并映射解析。
- 同书主名去首尾空白后完整相等即命中，收集全部编号。主名即使是已有“太后”等称呼，也遵循用户确认的全部同名规则。
- 别名沿用现有稳定称呼清理后完整匹配，同样收集全部命中；通用代词或亲属称谓不新增为匹配别名。名称匹配不使用包含或相似度，不因“张三”包含于“张三丰”而连接。
- 来源端从 originCharacterId 开始解析生命周期映射：仍存在则返回自身，已合并则返回最终保留人物；终点已删除或缺失则 sourceId=null。来源改名不改变编号；新增相同来源名的资产不继承其关系。
- 目标端解析已有 targetIds 的合并映射，并加入 targetName 当前命中的全部编号；已有目标发生合并后，也收集保留目标当前主名的全部同名条目。有限集合合并、去重，避免循环扩展别名链。这一名称展开只用于目标端。
- 既有编号关联在人物改名后保持，显示读取当前资产名称。修改目标称呼或节点人物来源时按新输入重建对应匹配。来源人物删除后，原关系保留并显示来源失效，不转交其他同名人物；目标删除时过滤其编号，目标和节点原始称呼继续保留。
- 节点自动来源在后续新增同名人物时补齐；人工明确编号和旧保留编号按映射维护。自动来源的历史绑定按现有编号保留至来源被明确移除或人物被删除，普通改名不会切断已有联系。
- 单条关系由唯一有效 sourceId 与每个有效 targetId 生成正反两个方向；来源为空或两端编号相同则不生成对应关系线，原记录保留并说明原因。反向结果只交换本条关系的两个实际端点及标签，不作为新来源事实，也不再次按来源名扩展。
- 一条关系有N个有效非自身目标时产生2N条结果。多条关系最终按有序端点对汇总，因此总量按实际关系并集计算；多个同名来源只有各自确实拥有关系记录时才分别产生结果。

### 具体数据示例

书中有张三 A1=C3-P002、A2=C8-P001，张蕾 B1=C1-P003、B2=C5-P001、B3=C10-P002。先只有A1提取“张蕾的父亲”，正向标签父亲，反向标签子女；之后A2单独提取“张蕾的杀母仇人”，反向按对应受害关系含义表达。

| 操作 | 关系结果 | 节点及事件线结果 |
|---|---|---|
| 只有A1的父亲关系，节点A提及张蕾 | A1连接3个目标及反向，共6条；A2没有父亲关系 | 节点A关联B1、B2、B3；含A的事件线汇总3个编号 |
| 后续新增张蕾B4 | A1连接4个目标及反向，共8条；来源仍只有A1 | 节点A自动补上B4 |
| A2另提取杀母仇人关系 | 另增A2的8条，合计16条；A1仍只有父亲，A2只有杀母仇人 | 人物编号保持 |
| B2、B3、B4先并入B1 | 4条有向结果，A1→B1父亲、A2→B1杀母仇人及各自反向 | 节点A只含B1，两个来源仍独立 |
| A2再并入A1 | 2条有向结果；A1→B1汇总父亲、杀母仇人，反向汇总对应标签 | 涉及A1、A2的节点收敛到A1，事件线去重 |
| A1并入张三丰C7-P005 | 原关联端点改为C7-P005，显示张三丰 | 原先关联A1的节点改为C7-P005，事件线跟随 |

## 触发逻辑

| 触发 | 前置条件与处理顺序 | 写入与反馈 | 失败、取消及重试 |
|---|---|---|---|
| P1世界资产子步骤成功 | 校验→写人物及其原始编号关系→目标全命中和节点补齐→写凭证及进度 | 来源归属不扩散；关系目标尚未入库时保留原称呼 | 同事务失败不留半份结果；沿用子步骤重试及幂等凭证 |
| P1/P3或人工新建节点 | 本书与章节有效→保存称呼绑定项→解析全部人物→写节点 | 所有命中编号可查，未命中称呼可见 | 写入失败保留输入或对应任务错误 |
| 后续P1新增人物、人工新增或改名 | 当前人物更新→关系来源仅按编号更新显示；目标及节点按名称补齐 | 同名来源不继承旧关系，既有目标及节点无需重新提取 | 域锁与版本规则沿用，实际改动同步修订号 |
| 人工保存节点涉及人物 | 校验选择→更新称呼组与明确编号→重算结果 | 自动组全命中，人工编号来源独立 | 无效编号拒绝，表单保留 |
| 人工/机械/AI合并 | 各入口校验→共用核心→映射→绑定→报告/确认 | 关系、节点和事件线读到统一保留编号 | 整个事务成功或回滚；相同AI操作键重试返回原确认 |
| 人物删除 | 校验→删除及墓碑→来源解析为空或目标编号过滤→节点更新 | 来源失效的事实保留、不转给同名人物；其他人物关系保留 | 事务失败保持删除前状态 |
| 备份恢复或当前书库升级 | 结构转换→编号归属检查→关系及节点重建→提交/发布 | 恢复后与新结构一致 | 失败保留原书；不自动调用模型补关系 |
| 切书、刷新、读取详情 | 读取当前资产和已保存绑定→生成有向结果 | 界面和工具一致；查询不另写业务数据 | 错误提供重试，不以旧缓存冒充当前书 |

## 合并、并发与完整性

共用核心的存储适配只暴露本书事务中的人物、关系、节点、生命周期和报告读写。入口负责取得相应执行权，核心再次检查成员版本与目标存在性。AI已有的读集、证据、操作键和提交账本继续生效。

人物融合、生命周期映射、关系端点、节点引用及本次报告或确认在同一事务完成。取消只阻止未提交部分；已提交结果由同一确认返回。源编号映射展开为直接指向，循环映射或跨书目标拒绝。

关系绑定变化会改变人物详情投影和受影响节点修订号。工具记录实际返回指纹，提交前使用相同查询重新核对关系结果；P3仅在本批实际依赖受影响时重读。旧查询契约与工具声明的指纹变化使相关旧覆盖重新检查，真实业务提交确认继续有效。

对同名全匹配建立本书名称到编号的索引，按变更名称与编号查找引用。生成有向列表时按端点稳定分页；内部可以缓存，但输入变化后失效。按实际有来源记录的端点并集检查关系总数与分页，截断必须保留可继续读取的位置。

## 升级与兼容

1. 当前版本5书库增加版本6升级事务：新增关系表，将每个人物的旧 relations 转成稳定关系记录，originCharacterId固定为原承载行编号，sourceId仅按该编号解析。记录指纹包含原承载编号，避免同名人物的不同来源被提前合并。保留原内容后移出人物持久行，成功后一次完成版本升级。
2. 旧节点名称、编号分别进入称呼绑定项和旧资料编号字段，再按全部命中重建结果。已有编号即使无法从称呼恢复，也通过保留字段和生命周期继续关联。
3. 旧方向明确且有可确定逆向标签时填入对应标签；只写“父子”或缺方向时保留原描述，标为方向未明确。迁移不使用模型猜测身份或关系。
4. 备份格式6完整保存关系和节点来源字段；格式5恢复时执行相同转换，格式4先走已有转换再进入新结构。旧数据库低于版本5仍按已有提示与REQ-006安排处理。
5. 新书副本重写 bookId，保留库内关系编号、originCharacterId及人物编号，依据映射重算sourceId，核对其与原始来源的对应关系；目标端及节点重建全部命中。来源缺失只保留原记录并报告，不以同名人物替代；修复索引或绑定不重复生成原始关系事实。提取成功凭证和已有业务确认保留，过期的依赖或覆盖按实际规则重新检查。
6. 数据结构、表清单、备份校验、工具返回、运行时提示词及资源归属哈希随实施同步。旧应用遇到格式6备份应明确报版本不支持，原文件保留。

## 验收与接手

### 基础修复实施方法

本轮沿用版本7书库和格式7备份。字段存储无新增表或版本变化：人物对编辑表继续覆盖原始事实；修复记录使用pipelineRuns已有asset_edit类别、asset_edit阶段和result对象。result.kind为relation_binding_repair，version为1，before保存本次实际变动的关系/节点原值，after保存对应新值，供核对和备份保全。记录只在发生修复时写入，不替代业务提交确认。

地点合并只融合地点与地点生命周期，不重算人物关系。P1世界资产子步骤保存人物后，无论是否产生新关系，都按当前人物和生命周期同步原关系及旧节点；新增结果、关联修订、实际依赖覆盖失效与成功凭证在同一事务提交。例：第一章节点关联C1-P001张三，第二章出现C2-P001张三及C2-P002张蕾，旧节点补第二个张三，原先目标为张蕾的关系补C2-P002；重复提交不增记录。

旧关系有显式reverse_label时保留。缺少反向且为明确“父亲/母亲”时使用“子女”，“儿子/女儿/子女”使用“父母”；“暗恋”使用“被暗恋”。对称关系沿用原标签；只有“父子”等不足以判断端点角色的有向标签改为unspecified，保留原描述。新迁移使用该规则；已迁移记录只有仍符合旧复制特征且legacyPayload证明原值时才修正，保留关系id。人物对显式编辑结果始终不被修复覆盖。

节点保存时，用户移除的旧编号从legacyActorIds/legacyTargetCharacterIds中移除；其余旧编号、人工指定及其他保留称呼组继续参与当前结果。已有数据检查仅补齐可追溯的自动称呼组，不把新的同名人物加入人工明确编号来源。

打开书库→检查活动租约→无活动任务时生成修复计划→保存变动前值、关系与节点新值及实际覆盖失效→事务成功后开放读取。活动任务存在则跳过，任务结束后再次打开会检查；失败保持旧值，重试不重复修复。来源按originCharacterId与生命周期恢复；目标按保留的targetIds及原targetName补齐。丢失旧编号且名称已改变、现有资料不能确定目标时保留待关联状态，供用户依据原文核对。

备份在校验完整结构、归属及校验和后，共用相同修复计划处理可确定的旧错误；未知编号或其他不合法内容仍拒绝。导出保留asset_edit记录，恢复为新书时随其他资料重写bookId。修复不调用模型，也不新增工具写权限。检查方法和证据见任务7及验收记录。
